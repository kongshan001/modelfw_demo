# Gameplay Innovation · 可调用工作流

> 结论先行：**玩法创新不是“想点子”，而是一条可杀项目的流水线**：
> `20+ 发散 → 五项评分 → 最小原型 → 5 人 playtest → kill / iterate`。
> 创新的最小单位是**新动词 / 新约束 / 新信息结构**，不是题材、美术或内容量。
>
> 方法与案例：`docs/design/gameplay-innovation-research.md`（T-033）。
> 样片：`docs/design/gameplay-innovation-portfolio.md`（T-034，30 seeds / top 3 / 8 条否决）。
> 角色：策划只做设计与验收口径，不写代码、不做美术评审/QA，不自我批准。

---

## 1. 何时用 / 不用

**用**：

- 新玩法立项、老玩法“同质化/不好玩/没差异”；
- 竞品拆解后需要提出可验证的新方向；
- 需要评审“这个 idea 值不值得做原型”；
- 需要给美术/工程/QA 一个可执行、可 kill 的 brief。

**不用**：

- 纯视觉整改（走 `game-art-director` / `game-artist`）；
- 已批准方案的实现/性能/QA（走 `game-engineer` / `game-qa-lead`）；
- 只改文案、数值微调、修 bug（不属于玩法创新）。

## 2. 输入 / 输出

### 2.1 必读输入

| 输入 | 要拿到什么 | 缺失时 |
| --- | --- | --- |
| 项目上下文 | 路径、引擎、平台、现有系统/资产、真实截图/录屏 | 从 `context_paths` 读；仍缺则标假设 |
| 目标玩家 | 谁、什么设备、单次多久、为什么玩 | 不接受“所有人”；写假设 + 置信度 |
| 约束 | 1–3 人、4 周、Godot 4.6、性能/许可/品牌 | 明确写“待确认”，不编造 |
| 参考作品 | 1–3 个，写“取什么/为什么/不取什么” | 不机械套用；只借抽象结构 |
| 非目标 | 本轮明确不做什么 | 必须写；否则 scope 会爆炸 |
| taste/否决 | 现有 `docs/templates/ai-taste-doc.md`、旧否决记录 | 先冻结 3–5 条不可妥协项 |

### 2.2 输出（写到任务指定路径，默认 `docs/design/`）

| 文件 | 用途 | 模板 |
| --- | --- | --- |
| `gameplay-innovation-portfolio.md` | 20+ seeds + 评分 + top 3 + 否决 | 本 skill §3–§6 |
| `gameplay-innovation-scorecard.md` | 可复现的评分表与决策记录 | `docs/templates/gameplay-innovation-scorecard.md` |

| `gameplay-taste-rejection.md` | ≥5 条否决（taste） | `docs/templates/gameplay-taste-rejection.md` |

## 3. 流程（90 分钟工作坊 + 原型/验证）

| 时间 | 步骤 | 产出 | 通过条件 |
| --- | --- | --- | --- |
| 0–10 min | 写体验支柱 / 核心动词 / 三层循环 | 一句话 + 3 个动词 | 删故事测试仍成立 |
| 10–25 min | 抽 3 张约束卡，强制组合 | 3 个“删掉 X”方案 | 每个写“玩家放弃什么” |
| 25–45 min | 组合矩阵：动词×对象×约束×反馈 | 10 个一句话方案 | 不是新按钮/新数值 |
| 45–60 min | What if X but Y：跨域类比 | 10 个组合 | B 影响资源/风险/信息 |
| 60–75 min | 五项粗评分 + 门槛 | 3 个进入 L0/L1 的方案 | 无 ≤2 未解释项 |
| 75–90 min | 写一页 brief + kill 条件 | 3 张假设卡 | 每个有可证伪 H1–H4 |

### 3.1 步骤 0：体验支柱与核心动词

- 2–3 条支柱，每条能拒绝方案；一句话：`玩家反复做 ___，因为 ___，但 ___。`
- 只留 1 个核心动词；画 30 秒 / 5 分钟 / 30 分钟循环。
- 失败信号：能写 5 个动词但说不出核心；核心是“点下一步/看剧情”。

### 3.2 步骤 1：发散（≥20 个，硬门槛）

至少用 3 种方法：

1. **约束卡 / 减法**：删动词、删资源、加时限、隐藏/公开信息、限制身体/背包、永久后果、规则可改写。
2. **跨域类比**：`What if [成熟系统 A] but [非游戏流程 B]?`；B 必须改变资源、风险或信息，否则只是皮肤。
3. **组合矩阵**：动词 × 对象 × 约束 × 反馈；每组合写“玩家会因此放弃什么”。
4. **反套路 / 信息结构**：违背品类默认契约，但 10 秒可感知。

**每个 seed 一行必须写**：核心动词/约束、参考模式（抽象）、N/D/C/F/A、风险。禁止只写题材/氛围。

### 3.3 步骤 2：评分（五项 1–5）

| 维度 | 1 | 3 | 5 |
| --- | --- | --- | --- |
| novelty | 换皮 | 有效组合出新取舍 | 改写品类契约，10 秒可感知 |
| depth | 无选择/单一解 | 每局 3–5 个取舍 | 高技巧上限/可讨论流派 |
| clarity | 需教程/文档 | 一句话+演示 | 10 秒 GIF 就懂 |
| feasibility | 6 个月+/多人/大量原创 | 1–3 个月/1 个新系统 | 1 周灰盒，复用现有 |
| audience | 与目标玩家冲突 | 品类可接受 | 核心喜欢且能破圈 |

**门槛**（与 T-033 一致）：

- 任一项 ≤2 → 必须书面解释，否则不进入原型；
- ≥20 且无 ≤2 → L1；
- 18–19 且无 ≤2 → fast track L1（额外满足：10 秒可演示、复用现有系统、书面理由）；
- 16–17 → L0 补最弱项；
- <16 → kill/换组合。

评分对象是“当前团队做 L1 原型”，不是作品排名；必须写证据/不确定性，不编造实测。

### 3.4 步骤 3：Top 3 一页 brief

每个 brief 必填：一句话 What if、目标玩家/场景、三层循环、独特动词/约束、首 10 分钟、最小原型（L0/L1/L2 + 天数 + 复用系统 + 不做）、H1–H4、成功指标、kill 条件、IP/来源、评分与结论。

**没有 kill 条件的 idea 不许进入原型。**

### 3.5 步骤 4：最小原型与 playtest

| 级别 | 成本 | 做什么 | 通过标准 |
| --- | --- | --- | --- |
| L0 纸面 | 0.5–1 天 | 卡牌/棋子/流程图 | 3/5 能玩完一轮并说出取舍 |
| L1 单机制数字 | 2–4 天 | Godot 一场景、灰盒、只做核心动词 | 10–15 分钟可玩；≥4/5 做出取舍；≥3/5 想再来 |
| L2 单场景 slice | 1–2 周 | 完整循环 + 基础美术/UI/音效 | 5 人中外放 ≥3 人主动要链接 |
| L3 内容扩展 | 2 周+ | 新卡/敌人/关卡/剧情 | 只有 L2 通过后才做 |

**playtest 通过线（5 人 × 2 轮）**：首操作 ≤60 秒 ≥4/5；说得出核心动词 ≥4/5；至少一次有意义取舍 ≥4/5；想再来 ≥3/5；因“不知道点哪”卡住 >30 秒 = 0 次。

> 纸面原型适合验证规则/理解，不适合验证手感/节奏/留存；不要把 L0 的“想再来”当产品结论。

### 3.6 步骤 5：kill / iterate

**硬 kill**（任一命中即停/换方向）：

1. **Clarity**：5 人中 ≥3 人在 60 秒内说不出“我在做什么/为什么”；
2. **Depth**：2 次迭代后，≥4/5 在相同局面做相同选择且说不出取舍；
3. **Novelty**：换灰盒后，玩家说不出与竞品区别；
4. **Feasibility**：4 周内做不出可玩 10 分钟的 L1，或需新增 2 个以上未验证系统；
5. **Audience**：<2/5 愿意再来一局且不愿推荐；
6. **IP/伦理**：与现有作品 1:1 对应，或需复制他人角色/UI/素材/商标；
7. **AI**：关闭 AI 后核心循环不成立，且延迟/成本/安全未解决。

**Iterate 条件**：核心动词成立（≥4/5 说得出）+ 至少一次有意义取舍（≥4/5）+ 想再来 ≥3/5；**只改一个变量**再测 5 人。

**软 kill（降级/延后）**：clarity 低但 depth 高 → 先做教学/UI；audience 窄但 novelty 高 → 换主题小测；feasibility 低 → 缩到单场景/单机制；只有“加内容/数值”才能维持乐趣 → 回核心动词重做。

## 4. 案例引用（只借结构，不借素材/IP）

| 案例 | 借什么结构 | 不借什么 |
| --- | --- | --- |
| Balatro | 玩家已会的判定表 + 修正器/乘法 + 槽位稀缺 | 扑克/Joker 具体牌面、UI、150 张内容量 |
| Slay the Spire | 路线即资源 + 敌人意图公开 | 卡池/遗物/敌人具体设计 |
| Baba Is You | 把规则暴露为可操作对象 | 词块美术/关卡布局 |
| Outer Wilds | 知识即进度 + 恒定世界 + 知识保存 | 时间循环剧情/星球内容 |
| Hades | 死亡推进叙事 + hub 作为休息区 | 希腊神话角色/全语音体量 |
| Inscryption | 类型转换作为章节节奏 | 作者风格/叙事诡计/多套系统成本 |
| Vampire Survivors | 删掉攻击键，让技巧转到走位/构筑 | 自动攻击+经验条的具体表达 |
| Into the Breach | 公开意图 + 确定性推拉 + 第二血条 | 机甲/虫子美术与具体关卡 |
| Papers, Please | 极简核对动词 + 经济压力 + 道德代价 | 边境检查题材/文本/UI |
| Lethal Company | 信息不对称 + 共同目标 + 配额 | 怪物/美术/多人网络实现 |

**共同规律**：成功的创新能用**一个动词/一个约束**说清；小团队可复制的是**结构**，不是**内容量**。

## 5. 反模式（看到就停）

| 反模式 | 快速测试 | 修复 |
| --- | --- | --- |
| 换皮 | 换灰盒后还有人想玩吗？ | 改动词/约束/信息，不改皮肤 |
| 功能堆叠 | 删掉新功能，游戏更清楚吗？ | 做减法，先修核心循环 |
| 不可感知 novelty | 10 秒 GIF 能展示差异吗？ | 把新动词放到首 60 秒 |
| 深度靠数值 | 玩家能说出“为什么选这个”吗？ | 加风险/信息/资源取舍 |
| Scope 爆炸 | 4 周内可玩吗？ | 砍到 1 机制/1 场景 |
| 无法验证 | 能写出“失败会看到什么”吗？ | 写成指标 + kill 条件 |
| 创新税 | 新玩家更快理解吗？ | 熟悉输入层，创新放修正器 |
| IP 风险 | 法律/品牌检索 + 原创替换 | 只借抽象结构；素材原创/CC0 |
| AI 装饰 | 关闭 AI 后游戏一样吗？ | 让 AI 进判定层，或别放核心 |
| 一次性惊喜 | 第二次玩还成立吗？ | 把惊喜变成可重复系统 |

## 6. 停止 / 迭代规则

- **输入不足**：先写“假设 + 依据 + 置信度”；高风险（改玩法方向、引入新资产/依赖、版权）→ 返回 `needs_input`，不硬做。
- **发散不足**：<10 个方案时不许评分；<20 个时优先补约束卡/跨域类比。
- **全部低分**：若所有方案 <16，不要降低门槛；回到体验支柱/核心动词重新定义问题。
- **分数高但无演示**：novelty ≥4 却做不出 10 秒演示 → 降级到 L0，先把差异可视化。
- **实现者自评**：无效；必须找未参与的独立评审（T-035 红队 / game-qa-lead / 真人 playtest）。
- **两次迭代无改善**：检查是否改错层（玩法 vs 表现）；不要继续加内容。
- **IP 风险**：与现有作品 1:1 → 直接 kill，不做“法律上应该没事”的赌博。

## 7. 上下游交接

```text
Game Designer：竞品拆解 → portfolio/scorecard → top 3 brief → playtest 计划
      ↓（独立评审 T-035 红队）
Art Director：只对“通过 L1 的方案”做视觉 brief
      ↓
Game Artist：L2 才做资产；L1 用灰盒
      ↓
Game Engineer：按 L1 规格实现单机制原型
      ↓
QA / Playtest：按计划记录；按 kill 条件淘汰
      ↓
Art Director 独立复评 / 人类 owner 决策
```

- 一个任务一个角色；实现者不能同时是裁判。
- 策划不写代码/不做美术评审；美术不做玩法裁决；QA 不替实现者自测。
- 通过 L1 前，不承诺上线、不扩内容、不做美术量产。

- [ ] 五项评分有定义、有证据/不确定性；门槛与 T-033 一致。

- [ ] 有 L0/L1 原型范围、5 人 × 2 轮 playtest 计划与通过线。
- [ ] 未复制 IP/素材/商标；参考仅抽象结构。
