视频的答案

随机只是原料

CA 负责洞穴，房间模板负责手工感，BSP 负责结构，醉汉漫步负责有机隧道。真正的“可玩”来自约束与后处理。

最值钱的一句

先路径，后装饰

Spelunky 先刻一条保证存在的路径，再填模板。洞穴类算法也一样：先保证连通，再撒敌人和宝藏。

最值钱的警告

变化 ≠ 体验

程序化燕麦粥：技术上无限变体，体验上没有区别。堆系统不等于好玩。

02

元胞自动机：4-5 规则

视频 0:43–2:48 · Brogue 同族

一句话：随机撒墙，数邻居，迭代到洞穴出现。墙格子周围墙 ≥4 就保留，地板格子周围墙 ≥5 才变成墙。这个不对称的 4/5 阈值，是它能产出连通洞穴而不是纯噪声的关键之一。

LIVE · 4-5 RULE

拖动参数，直接看拓扑变化

60×30 网格；越界按墙处理；同种子可复现。默认参数复刻视频的 45% / 4-5 / 5 次迭代。

起点 / 终点地板墙同一 seed 的生成结果固定

默认 4-5 规则通常能形成连通洞穴；切到“单一阈值 4”会看到视频 2:00–2:21 的碎洞现象，点“修复连通”用走廊连接。

初始化

45% 墙 / 55% 地板

视频的起点。低于 40% 容易过大空地，高于 50% 容易碎洞；45–48% 是常用区间。

更新

8 邻域，同时更新

墙 ≥4 保留；地板 ≥5 才变墙。必须用旧网格计算、写入新网格，否则顺序会影响结果。

终止

形态稳定，不是固定次数

视频演示了 1 次几乎不变、多次后洞穴出现；4–6 次是经验起点，最终看形态。

阈值实验

4/4 → 碎洞

视频把规则换成单一阈值 4，得到散落小块，再用走廊连接。阈值直接决定拓扑。

参数视频 / 建议调参直觉
初始墙比例45%低 → 大空地；高 → 碎洞/封闭。先固定 45% 再动阈值。
墙保留阈值4越小墙越顽固，洞穴越封闭、越碎。
地板变墙阈值5越保守，地板越不容易被吞；4/5 的不对称是“4-5 规则”的名字来源。
迭代次数4–6 次1–2 次噪声还在；太多会过度平滑，洞穴变大变圆。
邻域 / 边界8 邻域 / 越界算墙换 4 邻域会更方正；边界算地板会吃掉地图边缘。
常见坑与适合的玩法
  • 只迭代一次：看起来没效果；重复到稳定。
  • 生成与寻路邻域不一致：8 邻域生成、4 邻域寻路，会“看起来连着但走不过去”。
  • 不清理小碎洞：1–7 格的地板像噪点；可以填回墙或连接。
  • 不做 BFS：4-5 规则通常不错，但不保证 100% 连通。
  • 适合：洞穴探索、生存、Brogue 式传统 Roguelike。不适合：需要严格房间/门/锁结构的战术关卡。
03

房间 + 走廊 + 模板：手工感是怎么来的

视频 2:49–4:38 · Spelunky / Gungeon

视频的答案不是“更复杂的噪声”，而是 换一种生成顺序：先铺 4×4 房间槽位，入口在顶、出口在底；只允许左/右/下走出一条保证存在的黄金路径；路径确定之后才从模板库填房间。模板提供“像人设计”的房间，随机只负责选哪个、怎么转、里面撒什么。

LIVE · GOLDEN PATH

先路径，后房间，最后装饰

4×4 槽位；入口顶行，出口底行；只左/右/下。切步骤看生成顺序。

黄金路径房间模板装饰出口始终在底行：路径保证可达

Spelunky

4×4 + 黄金路径

入口顶、出口底；路径只左/右/下，保证从入口走到出口。路径存在后才填房间模板，模板再按连接方向选门。

Enter the Gungeon

手工房间池

每个房间手工设计 + 少量随机，按战斗/陷阱/隐藏/Boss 分类；生成器只决定这一局选哪些、放楼层哪里。

BSP：把矩形切成一层楼

视频 4:39–5:28

BSP 的名字吓人，做法很简单：拿一个大矩形，随机横切/竖切，递归切到房间大小；每个叶节点放一个房间；再用走廊连接。视频总结它自动保证两件事：房间不重叠、布局整洁易连接。

LIVE · BSP

切分线 / 房间 / 走廊分开看

64×32 格；最小叶节点 8 格；最近邻生成树连接，保证连通。

切分线房间走廊 / 起终点

BSP 保证“房间不重叠”；全图连通仍需要连接策略 + BFS 验证（这是本文扩展，视频没有展开）。

参数建议起点直觉
最小叶节点8–12 格太小切出细条；太大房间少、重复感强。
最大深度4–6控制房间数量；越深房间越多。
切分比例0.35–0.65避免极薄长条；太居中则布局太规整。
房间内边距 / 最小尺寸1–2 格 / 3×3留墙，避免房间贴边；小于 3×3 基本不可玩。
连接方式最近邻生成树 / BSP 兄弟最近邻简单且连通；兄弟连接更有层次感。
走廊宽度1–2 格1 格紧凑，2 格更适合战斗/寻路。
常见坑与适合的玩法
  • 切出 1 格宽长条：用最小叶节点和切分比例限制。
  • 只连 BSP 兄弟，漏掉跨子树连接：BFS 会发现多个连通块。
  • 走廊直穿房间中心，破坏房间形状：在房间边缘开门或沿墙走。
  • 每局都像同一张图：加入随机切分、尺寸变化、非矩形房间。
  • 适合：结构化地牢、战术/回合制 Roguelike。不适合：追求有机洞穴的游戏。

醉汉漫步：最便宜的有机隧道

7.2 种子与可复现性

视频片头

落地策略

随机流拆分

布局、敌人、掉落、装饰各用独立 RNG；否则多放一个敌人就会让整张地图变样。

规则原因
禁止全局随机 / 未播种 RNG同 seed 无法复现，QA 无法回放。
记录 seed + 算法版本 + 参数存档、回放、bug 复现都靠它。
独立 RNG 流布局变化不应影响敌人/掉落；反之亦然。
黄金种子测试固定 seed 列表，断言地图 hash / 连通性 / 距离不漂移。
跨引擎锁版本浮点、取整、哈希顺序可能不同；用整数 RNG + 黄金样本。

7.3 难度曲线：按预算，不按随机

视频没有讲难度曲线。落地时建议给每个深度一个 预算区间，并用“安全房/商店”形成呼吸节奏；路径越长，补给越多。

Godot 落地清单：最小实现顺序

Godot 4.6 · 代码骨架

不要一上来做 WFC。先把一种拓扑跑通，再加验证与装饰。下面的顺序可以让每一步都有可验收的结果。

阶段做什么验收
1网格 + 瓦片枚举 + 种子 RNG 封装同 seed 两次生成一致
2先实现一种拓扑：CA 洞穴（最快出效果）或黄金路径（最像手工关）看到一张可走地图
3BFS 验证 + 连通修复 + 起点/出口所有可玩种子 100% 连通
4房间模板 / 装饰 / 敌人；模板声明连接口与不可占用格装饰不堵路
5难度预算、房间类型权重、特殊房3 层难度曲线可复现
6调试叠层：连通块着色、路径、房间编号、seed 显示出问题能定位
7再考虑 BSP / 醉汉漫步 / 多算法组合每种都有黄金种子测试

地图

TileMapLayer

Godot 4.3+ 用 TileMapLayer.set_cell(coords, source_id, atlas_coords, alternative_tile)；墙/地板/门/装饰分图层。

随机

RandomNumberGenerator

var rng := RandomNumberGenerator.new(); rng.seed = level_seed；不要用全局 randi()。

验证

BFS / AStarGrid2D

连通性用简单 BFS 最直接；寻路/巡逻可用 AStarGrid2D；两者邻域规则必须一致。

模板

PackedScene / Resource

每个模板导出 connectors: Array[String]（N/E/S/W）、blocked_cells、room_type、weight。

复制# 最小 CA（GDScript 伪代码）
const WALL := 1
const FLOOR := 0
@export var level_seed: int = 2137
@export var width := 60
@export var height := 30

func generate() -> Array:
    var rng := RandomNumberGenerator.new()
    rng.seed = level_seed
    var grid := []
    for y in height:
        var row := []
        for x in width:
            row.append(WALL if rng.randf() < 0.45 else FLOOR)
        grid.append(row)

    for iteration in 5:
        var next := grid.duplicate(true)
        for y in range(1, height - 1):
            for x in range(1, width - 1):
                var n := count_wall_neighbors_8(grid, x, y)
                if grid[y][x] == WALL:
                    next[y][x] = WALL if n >= 4 else FLOOR
                else:
                    next[y][x] = WALL if n >= 5 else FLOOR
        grid = next
    return grid
复制# 最小 BFS 验证（GDScript 伪代码）
func reachable(grid: Array, start: Vector2i) -> Dictionary:
    var seen := {start: true}
    var queue: Array[Vector2i] = [start]
    while not queue.is_empty():
        var p: Vector2i = queue.pop_front()
        for d in [Vector2i.RIGHT, Vector2i.LEFT, Vector2i.DOWN, Vector2i.UP]:
            var q: Vector2i = p + d
            if q.x < 0 or q.y < 0 or q.x >= width or q.y >= height:
                continue
            if grid[q.y][q.x] == FLOOR and not seen.has(q):
                seen[q] = true
                queue.append(q)
    return seen

func validate(grid: Array, start: Vector2i, exit: Vector2i) -> bool:
    var seen := reachable(grid, start)
    return seen.has(exit) and floor_components(grid).size() == 1

Procedural Oatmeal：变化不等于体验

视频 6:25–7:07 · Kate Compton

视频最后把话题从算法拉到设计：你可以用数学生成 一千碗技术上各不相同 的燕麦粥，但吃起来的体验仍然只是燕麦粥。纸面上的多样性，如果体验上没有区别，就没有意义。

变体 A · 不同分布
变体 B · 不同种子
变体 C · 不同参数
技术上 3/3 不同体验上 同一种 燕麦粥差异是否可感知：否

为什么是个陷阱

变化只是必要不充分

随机种子、不同参数、不同布局，只能证明“不一样”；玩家感知不到差异，就等于没有内容。

怎么做更好

少量聪明选择

手工锚点（Boss 房、地标、剧情）、节奏（安全房/高压房）、可读性（一眼看懂往哪走）、预算（难度曲线）。

视频的落点

开发者的手

不是堆更多系统，而是选对框架、做对约束，让生成结果值得探索（7:00–7:07）。

检查单：去掉 seed 后，玩家能描述这一局的不同吗？如果不能，先加“可感知的差异”，再加算法复杂度。
