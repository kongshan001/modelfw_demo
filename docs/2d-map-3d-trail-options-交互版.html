#结论为什么
01正交俯视下，抬高 z 不产生屏幕位移z 只影响深度；3D 感来自 ribbon 截面、朝向、明暗、描边、地面影子。只有等轴/斜俯视/透视才把高度映射到屏幕 y。官方投影推断
022D 精灵默认不写深度，3D pass 无法逐树遮挡纯 2D Canvas 里，3D mesh 与 Sprite 不在同一排序系统；必须投影成 2D、深度/Stencil 代理、Viewport 分层，或按遮挡物切段。推断
03移动端先算 overdraw，再算顶点50 条 160×40px 拖尾 ≈ 720p 的 35% 覆盖；两层 ≈ 70%。顶点通常只有几千个，真正贵的是透明填充率、混合带宽、全屏 RT。Arm/Qualcomm推断
04拖尾是纯本地 cosmetic只同步移动/技能事件；远端用插值后的可视位置重建；传送/重生/重连清历史，否则会拉出跨地图长带。推断
05风格化在网格/材质阶段做，不靠后处理补救无光照/ramp、色阶量化、抖动、硬边/描边、屏幕像素宽度；soft additive glow 会把风格拉回写实特效。推断
063渲2 的拖尾默认不进角色 RTRT 是角色的“胶片”，单排序点 + 边框裁剪；拖尾要逐树穿插就必须在地图 2D 层（R2）。RT 内只留短刀光（R1），跨层像素级遮挡才上 R3。推断待实测

决策树

拖尾 ≤0.5s 且完全在 RT 框内？
是 → 需要被手臂/身体自遮挡：R1；不需要：R2（更便宜/更好排序）。否 → 下一步。
需要近端绝对贴合可见刀尖？
是 → R4（短 R1 + 长 R2）或 R2b 校准；否 → R2（默认长尾）。
同一屏内跨层/像素级遮挡？
是 + ≤3 单位 + 中高端 → R3（独立 3D pass + 深度/Stencil 代理）；否 → R2 + 分段 y-sort / 树冠 overlay / 2D 遮罩。
低端 / 同屏 50 单位？
是 → R2 精简（8–12 段/30Hz/1 层）或 R5/G；否 → 按上面结果。
默认永远是 R2，除非拖尾短到完全在角色 RT 框内且“自遮挡/绝对贴手”比“逐树遮挡”更重要（R1），或者跨层像素级遮挡是核心卖点且预算允许（R3）。角色有 RT/3D 相机，不代表 2D 树/建筑会自动写深度；R3 必须额外做深度/Stencil 代理。

怎么看 / 边界

2D 地图的四个关键难点

投影 / 排序 / 风格 / 性能

4.1 相机与投影：z 高度怎么映射

原创示意：H 方案把“高度”投影到屏幕 y，再用影子/curtain 伪造体积；纯 2D 地图不需要真 3D pass。

2:1 等轴常用公式　screenX = (x − y) × tileW / 2　　screenY = (x + y) × tileH / 2 − z × heightScale
正俯视正交时，z 不进入 screenX/screenY；只有倾斜相机/透视才有高度位移。〔推断/通用公式〕

4.2 排序与遮挡：3D pass 和 2D y-sort 是两套系统

原创示意：左图是 C/H 的 y-sort 切分；右图是 A/B 在纯 2D 地图里最常见的翻车方式。E 的 Stencil/深度代理是为右图补“遮挡信息”。

解法做法适用代价结论
1. 投影成 2D（C/H）3D 位置投影到屏幕，生成 2D 条带，按脚底 y 进入 y-sort纯 2D 地图、同屏多人无真实深度/光照；投影要跟相机一致默认推荐
2. 深度/Stencil 代理遮挡物用 3D 代理/alpha scissor 写深度或 Stencil；3D 拖尾测试3D 场景 + 2D 美术面片；遮挡物可代理额外 pass；alpha test 破坏 early-Z；纯 2D Canvas 不适用只有 3D 层已存在时
3. Viewport 分层合成3D 拖尾渲染到透明 RT，在某个 2D 排序层合成主角/技能；需要统一 bloom/描边全屏 RT + resolve；单 RT 只能对应一层中高端、少量单位
4. 按遮挡物切段用 2D 遮罩/射线把拖尾切成前后段少量固定遮挡物实现脆、维护贵、运动时跳变最后手段

4.3 风格：把 3D 拉回 2D 的六个开关

问题做法不要做
光照割裂无光照/Unlit、2–3 阶 ramp、固定方向高光PBR 高光、环境反射、真实阴影
颜色割裂从地图色板取 4–8 色；沿长度量化；尾部同色降明度全彩渐变 + 大面积 bloom
边缘割裂1–2px 深色描边/硬边 alpha；像素风 1px 对齐软边、羽化、景深模糊
体积感竖向 curtain + 地面影子 + 头部高光；宽度按速度拉伸只靠“抬高 z”
像素风屏幕像素宽度、2–4 色阶、Bayer 抖动、关闭抗锯齿亚像素宽度、平滑渐变

单条拖尾屏幕尺寸1 单位覆盖10 单位覆盖50 单位覆盖50 单位 × 2 层

同样的“50 条拖尾”，长度/宽度翻倍就会从“可接受”变成“填满屏幕”。 先限屏幕面积，再谈段数；顶点/内存通常不是瓶颈，draw call、每帧 mesh 上传、透明填充率才是。〔推断/估算〕
GPU 粒子

30 粒子/单位 × 20 单位 × 64×64px ≈ 2.46M px ≈ 720p 的 267% 覆盖；软边/additive 更贵。

全屏 RT

720p RGBA8 ≈ 3.7MB；加深度 ≈ 2.8MB；MSAA 4× 约 4 倍颜色带宽；每帧 resolve/采样是额外成本。

CPU 采样

50 单位 × 30Hz × 3 float ≈ 4.5k float/s，本身很小；真正贵的是每帧重建 mesh、GC、材质实例、排序。

4.5 多人 / 网络 / 回放

  • 只同步移动/技能事件：位置、速度、朝向、状态、技能触发；拖尾顶点、段数、颜色、粒子都不进网络包。
  • 远端重建：用网络插值后的可视 Transform 采样，而不是原始 10–20Hz 网络位置；否则拖尾会抖/折线。
  • 采样频率：视觉 60fps，拖尾采样 30Hz（每 2 帧）或按距离（4–6cm）；时间制寿命保证 30/60fps 长度一致。
  • 传送/重生/重连：清空历史，带 `respawnEpoch`/`teleportId`，避免跨地图长带；死亡/隐身停止发射并让旧段自然消失。
  • 回放：记录位置时间线/技能事件即可重建；要逐帧一致再记录采样种子/采样点，不为常态加网络负担。

S3 · 必须真 3D / 遮挡复杂

3D 网格 + 深度代理

方案：A + 深度/Stencil 代理 + 排序组；或 E 在主角色层合成。

  • 32–64 段；1–3 个单位；3D 场景/角色层
  • alpha scissor 遮挡物写深度；Stencil 只给关键遮挡物
  • 全屏 RT 只给主角色，不给 50 单位
  • 中高端机型；团队能维护多相机/RT
结论：纯 2D Canvas 不要为“真 3D”三个字上 E；H 的观感/成本比更好。

何时才值得上 Viewport/Stencil（判定清单）

□已有 3D 角色层/3D 相机/深度，而不是纯 2D Canvas
□遮挡是逐对象（树、柱、屋檐、建筑），且 2D 投影/切段无法接受
□需要统一后处理（bloom/描边/色彩空间）或真实深度
□目标机型中高端，且同屏高价值单位 ≤3
四条全部满足才考虑 E；任一不满足 → H/C；低端 → G。 单个全屏 RT 只能对应一个排序层；拖尾要在多棵树之间前后穿插时，单 RT 不够，需要多 RT/Stencil/切段，成本会继续上升。
3渲2 注意：角色有 RT/3D 相机，不代表 2D 树/建筑会自动写深度；R3 必须额外做深度/Stencil 代理。默认仍是 R2，短刀光 R1，跨层才 R3。〔推断〕

Kill criteria（什么时候停）

  • 50 单位低端机 C 仍 >33.3ms → 切 G/减少可见数量，不再优化 3D。
  • H 在中端机 60fps 下增量 GPU >2ms 且降段仍不达标 → 降到 C。
  • E 的 RT 成本 >1.5ms 或不能解决逐对象遮挡 → 放弃 E，改 H + 切段/遮罩。
  • 任何方案在目标低端机持续 GC/每帧 mesh 重建 → 先修池化/环形缓冲，再谈观感。
  • 风格盲评 <2/3 认为“和地图一致” → 先改材质/色阶/描边，不加特效层。
  • 3渲2 R1 在最长拖尾下裁剪率 >5% → 该效果不适合 RT 内，改 R2/R4。
  • 3渲2 R2b 校准后 origin p95 >4px 且换装/换向后跳变 → 先修锚点/校准，不进入美术量产。
  • 3渲2 R2 在 50 单位低端机 p95 >33.3ms → 降段/关 NPC/切 R5，不再堆 3D。
  • 3渲2 R1 为拖尾把角色 RT 扩大 >1 档 → 直接改 R2；不要用 RT 尺寸换尾长。
