结论先行

默认方案 / 不推荐什么

路线 A · 默认推荐

高度场 + 岛屿遮罩 + 分块 LOD

FastNoiseLite 生成 2D 高度场，岛屿 mask 保证四周是海，海岸塑形 + 顶点色分层；ArrayMesh 分块、HeightMapShape3D 碰撞。适合可走、可远眺的主岛。

CPU 生成Compatibility ✅MVP 首选

路线 B · 风格化

低多边形 Stylized 岛

同一高度场，粗网格 + 平面着色 + 受限色板；三角数可压到 5–50k，生成 <0.5 s。适合小岛、浮空岛、战棋/卡通项目。

视觉上限高成本低小体量首选

路线 C · 后续扩展

体素 / Marching Cubes / Transvoxel

可挖洞、悬垂、破坏，但 GDScript 逐体素不可行；Voxel Tools 的 GPU 特性需 Forward+ compute，Intel HD + Compatibility 不推荐进 MVP。

成本高Compatibility 受限

问题结论
最短落地路径？257×257 高度场 → 8×8 分块 ArrayMesh → HeightMapShape3D → 水面平面 + 预生成岸线深度图 → 2–4 个 MultiMesh 植被。
为什么不用体素做 MVP？体素的成本在“块重建 + 碰撞/导航同步 + 材质/UV”，不在生成本身；可破坏性对海岛 MVP 不是刚需。
为什么高度场能看？海岛的视觉 70% 来自海岸线、色带、雾、植被密度，不是三角面数；高度场 + 顶点色就能做出可信的沙滩/草地/岩壁。
Compatibility 能做吗？能：CPU 生成 + 普通材质 + MultiMesh + Depth/Height Fog。不能用 compute、SSR、体积雾、SDFGI/VoxelGI；水面反射用天空/Fresnel 近似。
最大风险？接缝、法线、LOD 裂缝、碰撞网格不匹配、GDScript 生成卡顿；本文 §3/§7 给出逐项规避。
一句话：先用高度场做出“形状正确 + 海岸可信”的灰模，再加水/树/雾；不要一上来写体素或 WFC 3D。

高度场不是“低配”：把 1024 m 岛的 257² 高度场、8×8 分块、顶点色、雾、2000 棵树和一层好水做扎实，在 1280×720 的 Intel HD 上已经能做出“像游戏”的画面。低多边形则把预算从三角形转到色板/轮廓/构图。

高度场解剖：噪声、遮罩与海岸线

拖动参数，观察海岸线怎么变

推荐管线：domain warp → 椭圆径向 mask → 基底 FBM → ridged 山脊 → 海岸塑形 → 台地/侵蚀 → 高度 LUT。下面的演示是同一套公式的 CPU/Canvas 版，用来建立“参数 → 形状”的直觉；Godot 里换成 FastNoiseLite 即可。

海岛高度场实验室

拖动滑杆即时重算；Canvas 160×105，同种子可复现。视图可切换“高度 / 遮罩 / 坡度 / 着色”。

陆地 — 最高 — 海岸线 — 生成 — 种子 —
浅/深水 沙滩 草地/森林 岩石 雪 亮线 = 海岸线 · 剖面位置滑杆可调
怎么调：
  • 海岸太圆 → 提高“域扭曲”、降低“海岸硬度”，或换 seed
  • 岛太碎 → 降低频率、提高岛屿半径/海岸带宽
  • 山不够 → 提高山脊权重/octaves；太尖 → 降山脊或加台地

先把“岛屿半径/海岸带宽/海岸硬度”调出喜欢的轮廓，再调频率与山脊。

03

网格、LOD 与碰撞

接缝是第一优先级

ArrayMesh

运行时批量生成优先用数组接口：VERTEX / NORMAL / COLOR / INDEX，add_surface_from_arrays()。本机 8×8 分块 / 131k tris 构建约 0.30 s。

SurfaceTool

原型/小网格更顺手，generate_normals() 只在必要时用；逐块算法线会在块边缘产生硬边。

HeightMapShape3D

1 m 格点、居中；257² 构建约 15 ms。比分块三角网碰撞快得多；调缩放或单独 1 m 碰撞场。

防接缝铁律：所有 chunk 共享同一张高度场 H[iz*N+ix] 与同一张法线表；
边缘顶点坐标 = ix * spacing，绝不在块内重新采样/偏移噪声。
LOD 裂缝用 2–4 m 裙边 遮住；距离切换留 5–10% 滞后。
项目MVP 预算实测/说明
高度场257×257 / 4 m66,049 采样；1.0–1.6 s 单线程（含网格/碰撞）
分块8×8 chunks × 32×32 quads每块 2,048 tris；共 131,072 tris / 64 draw calls
法线中心差分257² 约 0.24 s；可和高度场同循环合并优化
碰撞1 个 HeightMapShape3D257² 约 15 ms；不要用 trimesh 地形
侵蚀离线热力 3 次 257² 实测 2.72 s，运行时不可接受
LOD2 级 + 裙边4 m 近 / 8 m 远；`visibility_range_begin/end` 切换

绕序：Godot 正面是顺时针。地形从上方看不见就把索引顺序反过来；先做 2×2 测试块确认。顶点色若发暗，检查 sRGB→linear。

水面与海岸：Compatibility 安全做法

预生成深度图 > 实时深度纹理

植被、岩石与生物群系

MultiMesh + Poisson + 过滤
项推荐说明
MultiMesh 数2–4 个（树/岩石/草）一次 draw call，但单实例不单独视锥剔除
树木1,200–2,000，间距 6–12 m每棵 80–200 tris；远 LOD 20–40 或 billboard
岩石400–800，间距 3–6 m40–80 tris；只有大岩石给碰撞
过滤高度 2–45 m；normal.y > 0.72；湿度 > 0.45；离岸 2–4 m先拒绝水下/陡坡/沙滩，再按密度接受
碰撞只给玩家附近的大树/大石每棵树碰撞会把物理服务器拖垮
分桶按 8×8 区块或距离环拆 MultiMesh弥补“单实例不剔除”
总量100k–200k tris / 4 draw calls加地形 131k，总 ≤300k

群系规则

单岛用「高度 + 坡度 + 湿度」：沙滩 0–2.5 m；草地 2.5–25 m；森林要湿度 >0.45；岩石看坡度 >0.62 或高度 >25 m；雪 >55 m。边界用 smoothstep 混色。

Poisson Disk

Bridson O(n)；树 r=8 m、k=30；用 RandomNumberGenerator 固定种子。同 seed 同点集，便于回归。

远景

billboard + visibility_range；草不投影不碰撞；雾把 300 m 外的细节吃掉，省下的预算给近景。

验收门槛

  • 同 seed 高度场 hash 一致；相邻 seed 明显不同
  • 陆地 20–45%；主岛占陆地 ≥90%；四周 50 m 内无陆地
  • 块间无裂缝/亮线；碰撞贴合视觉
  • 水面浅深色/泡沫正确；无 z-fighting
  • 平均 ≥30 FPS，P95 ≤33.3 ms（vsync off）
  • 生成 ≤2 s 或预烘焙加载 <300 ms

五个坑

  • 块边缘各自采样 → 接缝；共享高度场/法线表
  • 逐块 generate_normals → 硬边；用中心差分
  • LOD 无裙边 → 裂缝；2–4 m skirt + 滞后
  • HeightMapShape3D 缩放/格点错 → 浮空；先做 1 m 碰撞场
  • GDScript 侵蚀/噪声卡加载 → 离线/线程/预烘焙
