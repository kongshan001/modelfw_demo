### 可保留的优点（不抵消失败项，最多 4 条）

1. 核心动作的视觉路径可走通：手牌行 → 棋盘高亮 → 结束回合，主次明确；19px/204×54 的“结束回合”是全场最稳的 UI 锚点。
2. 色彩骨架统一：深蓝底、金标题、绯红对手色与 CC0 卡框天然相容，没有廉价撞色；玩家/对手左右面板的冷暖偏色（蓝 / 紫红）是有效的小设计。
3. 凤火与伤害数字是完成度最高的视觉：100% 与 25% 都能读出爆炸位置；“-2”加描边后在混战里仍可读。
4. 合规记录完整：LICENSE + SOURCE + commit + 文件清单 + 商标说明；在同类“资产复用”项目里属于范本级。

## 2. 逐项证据（截图区域 / 数值 / 目标尺寸）

### 2.1 卡面可读性（当前 4.0）

- **实测字号**（`card_view.gd`，1280 设计 / 1920 输出）：名称 11 / 16.5；类型 8 / 12；描述 8 / 12；费用 15 / 22.5；攻血 13 / 19.5；卡 104×144。
- **证据 A**：`gridbound/02_hand_legibility.png` 顶部 100% 卡列。名称下的蓝色晶面有亮斑；名称带背景 L* p50 47.5 / p90 76.1，奶油色 `#f6ecd2` 在 p90 亮斑处仅 **1.62:1**，靠 3px 黑描边“抢救”；在 11px 原生尺寸下描边已吃进字面。
- **证据 B**：描述区背景 L* p50 29.2 / p90 47.2 → p90 亮斑 **4.22:1**（正文线 4.5:1），且字号仅 8px。裁切：铁崖守卫描述 3 行、前阵弓手 3 行，末行都贴卡底；悬停 1.34× 时中卡底部超出屏幕 **16px（1280）/ 24px（1920）**，卡框/底边被裁。
- **证据 C**：6 张手牌占宽 694/1280 = 54%，中心间距 118、扇角 ±5.5°；费用、攻血徽章（27px / 21px，15/13px 数字）是最可靠的信息层。描述与类型行重复关键词（类型写“嘲讽”，描述又以“嘲讽：…”开头），浪费了最稀缺的文字面积。
- **25%**：文字全不可读；只剩卡形、阵营/法术色与费用/攻血色点。对缩略图可接受，但不能作为“卡牌可读”的证据。

### 2.3 UI 信息结构（当前 4.5）

- **重复**：法力出现 3 次（顶栏文字、左下“法力 9/9”、9 颗水晶）；回合状态 2 处常驻（顶栏中心、右栏标题），AI 行动时底部状态行再重复一次；牌库/手牌出现 3 次（左栏、顶栏、右下 Seed 面板）。左栏“战斗记录”区高 320px，开局只有 3 行（约 90% 空白），AI 回合后 6 行仍有 >70% 空白；右侧固定帮助约占面板高度 1/4。
- **状态文案**：AI 行动过渡（MP4 t≈6.4s，`gridbound/support/ev_ai_turn_header_1280.png`）顶栏与右栏标题仍为“你的回合”，同时下方写“对手正在行动…”；胜利覆盖层（`gridbound/support/base_05_win.png`）背后同样保留“你的回合”。全场最大字号在错误状态下给出错误信息。
- **调试/演示文案**：`演示局面：双方在棋盘中部交火。`、`GRIDBOUND · 9×5 卡牌战棋 · 原创 vertical slice`、`卡牌/战棋 · 固定 seed 可复现`、`已换牌 否`——四处直接暴露“工程/演示”口吻；右下 `Seed 20260227` 也是内部信息。均不适合外放截图（Seed 可只留在结束覆盖层）。
- **AI 回合手牌**：手牌不降亮、不锁输入（仅按钮禁用），仍然“可点”，与“对手正在行动”冲突。

### 2.4 字体与排版（当前 4.0）

- 字级实际使用 8 / 9 / 10 / 11 / 13 / 15 / 16 / 19 / 23 / 30（逻辑 px），其中 8–11 四档挤在 3px 内，面板标题 15 与正文 10 的差距不足以形成清晰阶梯；8px 的卡面类型/描述是最需要可读性的规则文本。
- 字体为 `SystemFont`（PingFang SC → Hiragino Sans GB → … → sans-serif），**不随项目分发**：没有字体文件，换机/导出会出现字宽、行宽、字重差异，卡面 3 行排版可能变 4 行或被裁；导出到无 CJK 字体的环境直接方框（README 已知）。
- 排版可取的：标题 30 + 副题 10、回合 23、按钮 19 的主次成立；“格间牌战”40px 金字的轮廓处理有效。问题是**中间层太密**、**最小层太小**。
- 字重/描边：名称 `outline_size=3` 对 11px 字过重；UI 面板文字 `alpha 0.9–0.95`，实测对比度 7.4–10.8:1，说明面板文字不是“对比”问题，是“字号/密度”问题。

### 2.5 色彩 / 光照 / 风格一致性（当前 6.0）

- **统一的部分**：整体 60-30-10 大致成立（深蓝 60 / 面板灰蓝 30 / 金-绯红-青 10）；玩家金/对手绯的阵营色贯穿 HP 条、面板边框、徽章高光；卡框与精灵来自同一 CC0 套件，材质语言一致。
- **断裂的部分**：卡框是雕花晶体（高频细节）、单位是 80–100px 像素图（硬边）、面板是无纹理的扁平矩形（1px 边框）——三种材质语言并存。面板与卡框之间没有共享的金线/切角/纹理母题，UI 仍像“工程 HUD”。
- **区域色**：行 0 紫 `#2a2235` / 行 4 橄榄 `#2b2a23` 没有图例，且行 4 与金色召唤/选中高亮同为暖色，削弱高亮；建议去掉整行染色或压到 3px 边线（见 brief）。
- **光照**：无方向光/环境光/接触影（阴影是 28px、38% 黑的圆）；棋盘的“台面感”不足。整体对比度本身健康（面板文字 7.4–10.8:1），问题不是“脏/灰”，而是单位与台面之间的价值层级。

### 2.6 VFX（当前 6.0）

- **命中**：斩击包围盒 220×133px = **1.67×1.01 格**，亮青（`tile_hover` 同色系）；目标红闪 `modulate → (1,0.55,0.5)` 仅 **0.06s**（30fps 约 2 帧），截图 0.18s 抓帧时红闪已结束；冲刺 13px（0.15 格）；“-2”字号 19（28.5px@1920）+ 4（6px）描边，对比 6:1，清晰。
- **凤火**：与 01_board 差分后的高饱和火焰包围盒 **247×139px = 1.87×1.05 格**（图集帧 150×150×0.95 ≈ 1.6 格；含飞散火星时视觉更大）；38 帧 @24fps = **1.58s**；AI 法术动作间隔 0.68s → 特效会跨到下一步。单目标 3 点伤害配出约 1.9 格宽的爆焰，语义上像 AOE。
- **召唤**：26 帧 @24 = 1.08s，动作间隔 0.48s；0.62×（约 1.27 格）——同样超时。
- **可读性**：100% 下攻击/法术都读得出，25% 下凤火是全场最强信号；问题在“命中帧太短/特效尺度与节奏不匹配”，不是“看不见”。
- **颜色语义**：斩击青与移动高亮青同系；伤害数字用红、治疗绿、加攻金——语义正确但红/绿是唯一编码；`+/-` 前缀可缓解。

## 3. Top 5 gaps（P0→P1）

### P0-1 · 单位与格面：明度分离不足 + 没有常驻阵营标记

**问题**：暗色单位（灯笼狐、日石骑士、敌方将军、四方法师）在深蓝格面上“消失”；25% 下无法稳定区分敌我与将军；同行单位精灵/徽章互相压叠。

**证据**：`gridbound/01_unit_value_separation.png`；11 个单位中 9 个中位对比 <3:1；灯笼狐/日石骑士 52% 像素 <1.5:1；敌方将军 35.3%；25% 缩略图。单位溢出 34px（100px 帧 ×1.22 / 88px 格），z 序 10+y。

**根因**：格面 L*13–17 与精灵暗部 L*25–40 的明度窗重叠；单位没有基座/轮廓/队伍色；阴影 28px/38% 黑过弱；同行绘制顺序由节点树决定；徽章与精灵未分层。

**改法（参数）**：
- 每个单位加**队伍色基座环**：椭圆 26×12px，3px 描边，玩家 `#e8c56a` / 敌方 `#d4657a`，α0.85；将军 30×14 + 内环 2px + 6px 冠饰；基座下加 1px `#0a0d12` @α0.6 暗环，保证橄榄行上也分离。
- 单位**外轮廓**：2px（将军 3px）队伍色 α0.65；GL Compatibility 下用 8 方向偏移剪影（±2px）实现，不用 shader；11 个单位开销可忽略。
- **格面明度 +4**：`#1b2636→#253448`、`#192232→#222d40`；行 0 `#2a2235→#312a3f`、行 4 `#2b2a23→#332f26`；网格线 α0.10→0.12。
- **接触影**：半径 28→30px，α38%→55%，偏移 (0,3)；仍画在精灵下。
- **徽章独立层**：所有精灵一层，所有攻血徽章/关键词一层，徽章 z 永远在精灵之上；22×22、数字 12px、2px 深色外环。
- **将军**：9px“将”字 → 12px 冠形图标或 6px 金色冠饰 + 双基座环；将军的 HP 徽章放大到 24×24。
- 精灵比例 1.22 可保留（这是本作风格的一部分）；若仍拥挤，再考虑 1.12，但需同步调 badge 偏移与待机阴影，不要只缩身体。

**验收**：每个单位中位对比 ≥3:1、<1.5:1 像素占比 ≤10%；25% 盲测 5 人，5 秒内为每个单位指出归属、3 秒内指出将军；11 个单位并排截图无“融成一团”；同机 FPS 仍 ≥30（Intel HD 6000）。

### P0-2 · 手牌：类型/描述 8px、亮斑低对比、悬停被屏幕裁切并遮住指令

**问题**：卡面最需要读的“类型/描述”在 1280 只有 8px，在 1920 也仅 12px，且放在高频蓝晶背景上；悬停 1.34× 时卡底超出屏幕 16px，卡框被裁，状态提示被卡面遮住，只剩“放 凤火”。

**证据**：`gridbound/02_hand_legibility.png`；名称亮斑 1.62:1、描述亮斑 4.22:1（WCAG 正文线 4.5:1）；手牌基线 564、外卡下沉 17.5px、悬停 top 543、状态提示 y=545；卡 104×144。

**根因**：文字直接压在卡框亮面上，没有内衬/暗幕；手牌基线按“卡高 144”算到 720，没有计入扇形下沉与悬停放大；状态提示放在手牌正上方；字级阶梯过密（8/9/10/11）。

**改法（参数）**：
- **布局**：手牌基线 564→**546**；悬停 1.34→**1.24**；状态提示从 (236,545) 移到顶栏 **y=64**（12px，颜色 `#b8e6df`，宽 792 或 340 居中），不再被卡面遮挡；胜利覆盖层隐藏顶栏状态。
- **文字底衬**：类型/描述区局部 y=86–144 加 `#081018` @72% 圆角 4px 内衬；名称带 y=0–28 加 55% 暗幕；名称描边 3→**2px**。
- **字号**：名称 11→**12**（18@1920）；类型 8→**9**；描述 8→**9 / 行高 11.5**；最多 3 行。描述压到 **≤16 字**（例：`远程 2 格 · 视线阻挡`、`嘲讽：相邻敌人优先`），关键词不再在类型行与描述里重复。
- **可选（+代价）**：卡面 104×144 → **116×160**，间距 118→**130**，6 张占宽 **766/1280=60%**，可容纳名称 13 / 描述 9.5；代价是手牌更挤、扇形/悬停参数需重调。
- **悬停详情**：在棋盘右侧/上方开 **300×200** 详情面板（名称 16 / 类型 9 / 描述 13 / 行高 18），彻底解决“卡面只够放缩写”的信息密度问题。
- **字体**：内置 OFL 字体（Source Han Sans SC / Noto Sans SC，子集化到实际用字），锁定字宽；字级统一为 **9 / 11 / 13 / 18 / 26 / 34**（+覆盖层 44）。

**验收**：1280 100% 下 5 人盲测可读名称/费用/攻血 + 描述首行；卡面文字对比 ≥4.5:1（按亮斑 p95 计），名称 ≥7:1；静止/悬停均无任何像素裁切；只要有选中卡，状态提示可见；25% 缩略仍能数出 6 张牌。

### P0-3 · 高亮层级：移动盖过攻击，攻击/法术只靠色相区分

**问题**：青色移动格整格染色（ΔL* +24.4），红色攻击目标只有 2.5px 环（格面 ΔL* 0.0）；攻击与法术圈同为 r=27 的圆；金色选中环与金色单位/金色召唤圈混在一起；召唤态一屏 10 个金圈同时亮，图例却写“金色格”。

**证据**：`gridbound/03_highlight_vfx.png` A/B；补拍 `gridbound/support/ev_highlight_unit_1920.png`、`gridbound/support/ev_highlight_summon_1920.png`；格面中位 ΔL*：青 +24.4 / 红 0.0 / 金选中 +7.6。

**根因**：状态编码主要依赖“颜色 + 填充面积”，没有形状/图标语义；移动用满格填充，攻击只用细环，视觉权重与决策权重相反；选中/召唤共用了金色；图例与实现不一致。

**改法（参数）**：
- **攻击**：4px 环（r=30）+ 4 个向内箭头（8×3px）+ 18% `#e5484d` 填充 + 0.6s 呼吸（1.0→1.06）；必须是全场最高 chroma。
- **法术**：虚线环（8 段，4px 间隔）+ 中心符心（6px `#7aa2ff`），与攻击“同半径不同结构”。
- **移动**：去掉 55% 整格填充 → 2px 边框 `#6ff2cf` α0.9 + 四角 8×2px 刻度 + 22% 填充 + 4px 中心点。
- **选中**：近白双环 `#f7f2df`（3px + 1.5px，r=34）+ 4 角括号；不再使用金色。
- **召唤**：金圈 2.5px + “+”符 + 15% 金填充 + 1px 暗外环；图例改为“金圈 = 召唤位置”（或保留“金色格”但必须真的给格面 15% 填充）。
- **顺序**：把攻击/法术/召唤/移动的绘制与 z 序固定为“攻击 > 选中 > 法术/召唤 > 移动”；不要让同色叠加。
- 颜色之外必须有形状差异，满足色弱；同时保留现有四色（金/青/红/蓝）以免推翻美术方向。

**验收**：在同时出现“青移动 + 红攻击 + 金选中”的 1920 截图里，5/5 人在 2 秒内第一眼指向攻击目标；灰度化后仍能区分三种状态；deuteranopia 模拟下攻击/法术/移动可区分；10 个召唤圈不再压过选中/攻击。

### P1-1 · 信息结构与状态文案：最大的字在错误状态上

**问题**：AI 行动开始与胜利覆盖层期间，顶栏与右栏仍显示“你的回合”；法力/牌库各重复 3 次、回合状态 2 处常驻 + AI 时底部重复；日志区 320px 大部分空置；4 处调试/演示文案进入玩家可见 UI；AI 回合手牌不降亮不锁。

**证据**：`gridbound/support/ev_ai_turn_header_1280.png`（MP4 t≈6.4s，顶栏“你的回合”+ 右栏“你的回合”+ 下方“对手正在行动…”）；`gridbound/support/base_05_win.png`（胜利覆盖层背后仍“你的回合”）；`gridbound/support/base_01_board.png` 的四处重复。

**根因**：状态条只绑定了右栏 `_turn_status`，而 AI 行动过渡期间 `core.turn_owner` 尚未切换；各区域各自生成同一份文案，没有单一数据源；演示用 log/副标题未做 debug flag。

**改法（参数）**：
- **单一 HUD**：顶栏中心只保留“你的回合 / 对手回合”（26px，玩家金 `#f2dfb0` / 对手绯 `#ecc9cc`），左侧回合数/法力/牌库合成一行 12px；删掉右栏“你的回合”和顶栏副标题里的重复法力/牌库/已换牌。每个数据只出现一次（Seed 只放在结束覆盖层）。
- **状态矩阵**：`PLAYER_TURN` → 顶栏“你的回合”金；`AI_TURN` → “对手回合”绯 + 手牌 modulate **0.55**、输入禁用、结束回合禁用；`WIN/LOSE` → 顶栏“对局结束”，覆盖层 z 1000，隐藏 HUD 交互。
- **日志**：字号 10→**12**、行高 16、保留最近 8–12 行；左栏不再写“演示局面”；把战斗日志做成信息主体（图标 + 伤害数字），利用原本空着的 320px。
- **帮助**：右侧固定说明改为 4 个“颜色块 + 6 字”图例（11px），其余收进“?”悬浮层；同时把左栏 320px 的日志区改成 12px / 8–12 行的主体信息，给棋盘腾回视觉重量。
- **调试文案**：`演示局面`、`原创 vertical slice`、`固定 seed 可复现`、`已换牌 否` 从玩家 UI 移除，或加 `DEBUG_STRINGS` 开关；外放截图必须关闭。
- 卡池/套牌等数据移到结束覆盖层或“详情”面板。

**验收**：状态矩阵测试（玩家回合/AI 回合/胜利/失败）逐一截图，顶栏文字全部正确；每个数据只出现一次；玩家可见字符串里 0 处调试词；AI 回合手牌降亮 + 不可点；日志在 12 行内不溢出。

### P1-2 · VFX：命中帧、尺度与节奏

**问题**：斩击虽大（1.67 格）但颜色与移动高亮同系、命中红闪仅 0.06s；凤火主体近 1.9 格宽、总 1.58s，是 AI 动作间隔（0.68s）的 2.3 倍；召唤 1.08s vs 0.48s；特效会叠到下一次行动。

**证据**：`gridbound/03_highlight_vfx.png` C/D；`gridbound/support/capture/measure_gridbound.py` 的包围盒；`main.gd` 的 24fps / 6 个 FX 帧数 / `_action_delay`；MP4 抽帧（10fps：凤火峰值 5.1s，5.8s 回落到基线）。

**根因**：FX 按 24fps 全帧播放，没有和动作节奏对齐；命中反馈仅依赖 0.06s 的受击 tint；同一粉色/青色系同时服务高亮与特效；凤火视觉体量未按“单体 3 伤”收束。

**改法（参数）**：
- **斩击**：保留 1.7 格跨距；核心改白热 `#fff3d0` + 外焰 `#ffb347`；命中帧停留 0.10s，整体 0.22s + 0.12s 淡出；冲刺 13→20px，ease-out；受击红闪 0.06→**0.10s**（`#ff6b5e`）+ 白闪 0.03s；伤害数字 19px 保持，增加 0.06s 的 0.8→1.15 弹出。
- **凤火**：AI 施放时裁到 **≤1.1s**（跳尾帧）；或把 AI 法术间隔 0.68→1.0s；scale 0.95→**0.85**（主体约 1.4–1.7 格）；保留“最强特效”的地位，但不要像 AOE。
- **召唤**：26 帧裁到 14 帧（0.6s）或把召唤间隔 0.48→0.7s；0.62→0.7 scale（约 1.4 格）让 25% 也能看见。
- **并发**：同时存在的 FX >2 时，最旧的一个立即进入淡出；所有 FX 淡出统一 0.12s，不再 0.18s。
- **语义**：伤害/治疗/加攻的 +/- 已存在，保留；颜色不是唯一编码。

**验收**：25% 下取 100ms 单帧，5/5 人能识别“谁打了谁”；伤害数字至少存在 0.5s 且单帧可读；凤火 AI 版本 ≤1.1s，且不与下一次行动首帧重叠；召唤/攻击/法术动作链无 FX 叠加。

## 6. 风险

- **改 UI 常量的连锁风险**：P0-2 涉及 `main.gd` 的手牌位置、hover、HUD；必须回归 65 项冒烟 + 5 张截图 + AI 回合状态，避免“修好卡面、弄坏手牌扇形/点击区域”。
- **暗精灵 + 暗台面**：仅靠加亮格面可能让整屏发灰；团队色基座/轮廓要控制在中性色之外，不把“选中/可攻击”语义永久点亮。
- **字体**：内置字体会改变换行与卡面截断；需在 macOS + Windows 各看一次；子集遗漏会出现方框。
- **性能**：外轮廓 8 方向偏移约 88 个额外精灵，理论开销低，但必须在 Intel HD 6000 上复测；不要改用昂贵的全屏 shader。
- **语义过载**：金色已同时承担“玩家阵营 / 选中 / 召唤 / 法力 / 标题”；P0-3 后应把“选中”改为近白，别再新增金色状态。
- **合规/品牌**：CC0 与商标边界记录良好；继续避免把 Duelyst 名称/Logo/官方语录放进商店页或宣传语，避免暗示官方关联。
- **评审边界**：本次只证明“可读性/呈现”问题；没有验证手感、平衡、AI 长局与音频，不能据此判断“好玩”。

## 7. 仍不足（即使 P0/P1 完成）

- **世界与原创身份仍依赖借用资产**：单位、卡框、tile、FX 都来自 CC0 的 Duelyst 素材；面板是工程师 UI。即便可读性全修，外放时仍会被读成“用 Duelyst 素材做的 demo”。真正的作品感需要**原创卡框/阵营徽记/UI 套件 + 1 张英雄主视觉 + 棋盘材质（石/沙/金属）**，这超出当前 vertical slice 范围，但是商店页之前的必经项。
- **光与氛围**：没有方向光/环境光/暗角/尘埃/接触影；棋盘是纯平面，缺少“战场”叙事。P0 只解决价值分离，不解决氛围。
- **VFX 深度**：特效为 2D 图集精灵，无命中停顿、无屏幕震动、无音频；目前“读得出”，离“打得爽”还有明显距离。
- **内容层**：16 卡、单一棋盘、无稀有度/闪卡/关键词图标/卡组编辑/将军技能视觉；这些不影响本次可玩性，但限制外放物料与长线吸引力。
- **可及性/多端**：未做正式色弱模拟、键鼠/触屏尺寸、其他宽高比与外置字体验证；25% 下卡面文字必然不可读，商店缩略图需要单独构图，不能直接裁整屏。
