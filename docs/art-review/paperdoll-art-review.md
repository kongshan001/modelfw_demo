# 《纸偶工坊》美术评审 · 严格版

评审编号：T-20261120-007 · 评审日期：2026-11-20 · 评审对象：`godot-paper-doll/`（T-20261120-006 产出）
评审方式：实机截图 + 录屏逐帧 + 参考片抽帧对比 + 像素/对比度/剪影量化。**未修改任何游戏代码。**

---

## 0. 一句话结论

**当前 4.2 / 10，不达“可外放给玩家体验”的美术门槛（公开试玩门槛按 7.0 计）。**
系统完成度（17 槽 / 8 向 / 4 动作 / 35–55 FPS）是加分项，但画面仍停留在**“工程样机的彩色贴纸”**：重墨平涂、缩略图无抗锯齿、16 个角色共用一条剪影、8 方向正背难分、舞台没有光。UI 比角色更专业，反而放大了角色的不足。**先做 5 个 P0，美术分可到 6.0–6.2；做完 P0+P1，约 7.4–7.6。**

> 参考片为 B 站 `BV1dbxc6aEyU`（零号su《独立游戏 | 一个木头人，怎么变成16个角色》，69s）。本项目与它同题；本评审只对标“可读性结果”，不要求复制其深蓝舞台或角色造型。

### 1.2 量化口径（可复现）

- 角色包围盒：对 `01_studio.png` 试衣镜区域取“与纸面底色距离 >60 或墨色”的像素，得 **185×317px**（1280×720，占屏高 44%）。
- 墨色族占比：与 `#3a2f43` 距离 <40 的像素 / 角色包围盒 = **21.1%**（含深发/靴/暗部，作为“线/暗块主导”的代理指标，不是精确描边面积）。
- 量化色数：RGB 每通道 24 级分箱，角色包围盒内 = **53 色**；参考片 45s 巫师同法 = **357 色**（口径不同，仅作量级参考）。
- 描边宽度：`PaintUtil.ow()` = 1.6（`mini` 0.95），绘制层实际环宽 = 3.2 local；试衣镜 `set_display_scale(2.10)` → **6.7px**；角色高 317px → **1.9% 身高**。
- 缩略图：`DollThumbnail` SubViewport = 卡片尺寸（约 126×130），`msaa_2d=DISABLED`，纸偶 `0.56×` → 角色约 **95px** 高，描边约 **1.8px**，硬边。
- 8 向剪影 IoU：在 `04_directions.png` 上按同一窗口裁切、纸面底色分割，交集/并集，未做姿态对齐。**正面 vs 背面 0.818**；相邻方向 **0.64–0.89**；8 对里 5 对 >0.80。
- 阵容剪影 IoU：16 张卡的剪影归一化后两两比较；**精选阵容均值 0.40 / 中位 0.41 / p90 0.60 / 最大 0.71**；**随机阵容均值 0.52 / p90 0.72 / 最大 0.84**。
- WCAG 对比度：相对亮度公式（sRGB 线性化）；下文所有 `x:1` 均可复算。
- 参考片：1280×720、30fps；45s 帧巫师含帽/法杖约 300px，与本项目试衣镜角色（317px）同量级，可直接对照“同样大小下能读多少信息”。

## 2. 先肯定（但不加分太多）

- 三栏信息架构清楚：试衣镜 / 衣柜 / 阵容；标题、页脚、弹层的层级稳定，首次使用能理解 80%。
- 奶油纸面 + 墨色 + 珊瑚/青绿/芥末的 UI 色板是统一且舒服的；不是“默认 Godot 控件”。
- 17 层 z 序、8 向镜像、4 动作共用同一 pose、16 预设、JSON 存读——这是本项目的真正壁垒；**问题是画出来的结果没有把这个壁垒变成可看的卖点**。
- 批处理把 Intel 集显从 2 FPS 拉到 35–55 FPS，说明后续加 AA/层影仍有性能空间（但必须按 P0-2 的方式做一次性烘焙，而不是每帧重绘）。

**注意：** 这些是“工程/结构”优点，不是“美术已达标”的理由。外放看的是画面，不是 z 序表。

## 3. Top 问题（按收益排序）

排序原则：影响屏幕数 × 玩家第一眼可见度 × 修复成本。

### P0-1 · 角色渲染语言仍是“重墨平涂贴纸”，不是纸偶/木偶

**问题**
1. 所有部件都套同一根 3.2 local（试衣镜 6.7px）墨线，外轮廓与内轮廓同宽；部件之间靠互相叠盖，形成“每个零件都是一张带黑边的贴纸”。
2. 填充只有 `base` + `shade` 两档（`DrawKit.make_palette`：shade = darkened 0.24，deep = 0.42，light = lightened 0.34），没有中间调、没有高光、没有材质差异；大面积色块在纸面上“陷进去”。
3. 缩小后细节全部保留（木纹、缝线、铆钉、眼睛高光都 <2px），既糊又脏。

**证据**
- 墨色族像素 **21.1%** 的角色包围盒（含深发/靴）；参考片同尺寸巫师“极暗像素”约 **1.7%**（口径不同，量级差 10 倍）。
- 量化色数 **53**（本项目）vs **357**（参考片）。
- 皮肤 `#d9a86c` / 纸面 `#f7eddc` = **2.05:1**；青绿布 `#4fa58a` / 纸面 = **2.83:1**；只有墨线 12.02:1。换言之：**轮廓完全靠墨线撑着，去掉线，填充就融进背景**。
- 试衣镜放大 4× 看：帽子/头发/头/耳各自有完整墨线，重叠处形成 2–3 层黑边；肩甲是两个大圆 + 金点，读成“车灯”；剑刃 30 local（约 63px）但只有 7 local 宽、用 `light` 色，且被披风/手臂遮住；可辨认的“剑形” <8px，主体读成一根奶油色板条。
- 材质：木头只有 `body:grain` 两段小弧线；金属和布的 fill 同一套 `make_palette`；皮革只有一条 0.7px 缝线。**没有“木/布/皮/金/纸”的材质语言。**

**改法（具体参数）**

A. 线宽层级（“只让剪影有墨线”）：

| 层级 | 用途 | 1280 下宽度 | 颜色 |
| --- | --- | ---: | --- |
| L0 外剪影 | 整个纸偶的最外缘 | 2.4–3.0px | `#3a2f43` 100% |
| L1 结构分界 | 头/躯干、披风/衣、靴口 | 1.2–1.4px | `shade` 的 0.8×，不是纯 ink |
| L2 细节 | 木纹、褶、缝线、铆钉 | 0.8–1.0px | `deep` 60% 或 `#3a2f43` 45% |
| L0-mini | 缩略图（95px） | 1.2–1.6px | L0 色；L1/L2 删除 |

- 去掉每个部件自带的 ink：`DrawKit.circle/ellipse/rrect/capsule` 的 `outline` 参数在**内层部件**传 `0` 或 `0.55×ow`，只有最外层 silhouette 传 `ow`。实现上建议在 `PaintUtil` 加 `outline_for(slot, is_silhouette)`。
- `ow` 1.6 → **1.15**（试衣镜 2.42px）；mini 0.95 → **0.62**（95px 卡约 1.3px），并配合“删细节”而不是“只变细”。

B. 五档色阶（每槽位从 primary 生成；不要只用 darkened）：

| 色系 | deep | shade | base | light | highlight |
| --- | --- | --- | --- | --- | --- |
| 青绿 #4fa58a | #2c5f50 | #3c8270 | #4fa58a | #86c4b3 | #c9e5dc |
| 珊瑚 #e86a5c | #8f3030 | #bd4b45 | #e86a5c | #f4a196 | #ffd8cf |
| 芥末 #f2b34c | #8f5f1f | #c98a2f | #f2b34c | #f8d391 | #fff0cd |
| 蓝 #5a7fb8 | #2c4268 | #43628f | #5a7fb8 | #9bb6db | #dbe6f5 |
| 紫 #8a6fb0 | #46356a | #67518c | #8a6fb0 | #b8a4d4 | #e6dcf2 |
| 木/肤 #d9a86c | #7e5638 | #b07a4a | #d9a86c | #efcf9f | #fff0d6 |
| 皮革 #8a5a3a | #4f3020 | #6b432b | #8a5a3a | #b9855c | #e0bd97 |
| 金属 #b9c0c8 | #5e6670 | #7d8794 | #b9c0c8 | #e0e6ec | #fffaf0 |
| 纸 #f7eddc | #c9b394 | #ddc7a5 | #f3e7d4 | #fff9ee | #fffdf7 |

- 每个大部件（躯干、披风、帽、裙）至少用 3 档：受光面 light、基色 base、背光 shade；转折处 1 条 deep 的 L2。
- 金属不要复用布料 ramps：金属的 S 降到 8–14%，L 拉高，高光用 `#fffaf0` 2px 条；金色只做扣/饰，不做整把剑。

C. 面部（最影响“像不像人”）：

| 项 | 当前 | 建议 |
| --- | --- | --- |
| 眼睛直径 / 头宽 | 13.4 / 75.6 = **17.7%**（虹膜仅眼白的 58%） | **20–22%**；虹膜占眼白 68–72% |
| 眉毛 | 无 | 1.5–2px 深色短眉，角度跟随表情 |
| 鼻 | 1.1px 点（正面）/ 2.6px 侧 | 正面 1.5px 阴影三角；3/4 侧 3–4px 鼻梁 |
| 嘴 | 2.8px 弧 | 6–8% 头宽；微笑/张口两态 |
| 脸颊 | 2px 淡粉 | 保留，但加 1px 下巴/颈下 shade |

验收：在 95px 缩略图上，眼≥4px、嘴≥2px、眉可见；在试衣镜 1× 图上，遮住颜色只看明度，仍能读出头、脸、躯干、四肢四块。

D. 材质细节预算（只在屏幕长度 ≥3px 时画）：

| 材质 | 允许的细节 | 参数 |
| --- | --- | --- |
| 木 | 2 条年轮弧 / 肢体；端面 1 组同心弧 | 0.8px `#9a653f` 45% |
| 布 | 1 条褶 / 25px 宽；下摆 2px 阴影 | 0.9px shade 50% |
| 皮革 | 1 排针脚 / 6px；1 个孔 | 0.6px `#d1a06a` 50% |
| 金属 | 2px 高光 + 3 颗铆钉（带 0.5px 高光） | `#fffaf0` / `#5e6670` |
| 纸 | 纸纤维 4% + 切边 0.8px + 层影 1.5px | 见 P1-1 |

**验收标准**
- 同口径墨色族 ≤ **9%** 角色包围盒（从 21.1%）。
- 角色包围盒量化色数 ≥ **80**（从 53），但颜色数增长必须来自**有意的明度/材质分层**，不是噪点。
- 躯干/披风在 1× 下有 3 个可辨明度层；在灰度模式下仍能分出前臂/躯干/披风。
- 任意细节在最终显示尺寸下 <1.5px 的，一律不画。
- 4× 放大截图：内层部件不再出现“双层黑边”；外轮廓仍完整。

### P0-2 · 阵容/8 向/动作缩略图无抗锯齿、细节糊成一团

**问题**
`DollThumbnail` 把纸偶画进与卡片同尺寸的 SubViewport（约 126×130），`msaa_2d = DISABLED`，纸偶 0.56×（约 95px 高），而 `mini` 仅把描边从 1.6 降到 0.95（约 1.8px），细节（木纹/缝线/眼睛高光）全部保留。结果是**硬边 + 高频噪声**，在 16 张卡同时出现时尤其像“像素风草稿”。项目 UI 的圆角和字体是抗锯齿的，纸偶不是，反差明显。

**证据**
- 放大 `01_studio.png` 的角色卡：所有轮廓有 1px 阶梯，头发/帽子边缘呈锯齿；眼睛是一团 2–3px 的色块。
- `04_directions.png` 8 个 190px 角色同样硬边；`03_actions.png` 弹层里 4 个 280px 角色也是。
- 参考片 4×8 网格里 90px 的角色，帽檐、法杖、手臂仍然清楚；不是靠“像素感”，是靠抗锯齿和更少的细节。

**改法（具体参数）**
1. **2× 超采样烘焙**（推荐）：`SubViewport.size = card_size * 2`；纸偶 `display_scale = 1.12`（0.56×2）；`TextureRect.texture_filter = TEXTURE_FILTER_LINEAR`，`stretch_mode = STRETCH_SCALE`；外层显示尺寸不变。一次性烘焙，签名不变不重画，性能影响可忽略（16 × 4 倍像素，仍是一次性）。
2. 如果引擎/驱动允许，项目设置 `rendering/anti_aliasing/quality/msaa_2d = 2`（4×）优先；GL Compatibility 不支持时走 2× 超采样。**上线前用 Intel 集显实测**。
3. `mini` 模式做“符号化”，而不是“只变细”：删除 <1.5px 细节；眼睛保留眼白+虹膜+1 个高光；木纹/缝线/铆钉全部删除；内层 ink 全部改 shade；描边统一 1.3px（超采样后 2.6px）。
4. 若卡片尺寸允许：角色从 95px 提到 **108–112px**（卡片 126×130 → 132×142，右侧面板宽度 548 可容纳 4×132+3×6=546；高度 4×142+18=586，body 604 内勉强，需把卡片间距 6→4 或标题行压到 18px）。**优先级低于 AA**，不要为了放大而牺牲 4×4 的完整展示。
5. 生成缩略图时用 `Linear` 过滤、不启用 mipmap（静态 1:1 显示）；若以后做缩放动画再加 mipmap。

**验收标准**
- 1280×720 截图上，角色卡边缘无 1px 阶梯（放大 200% 检查）；眼睛、嘴、帽檐三类信息在 95px 下仍可辨。
- 16 张卡在 25% 缩放下不靠颜色也能分出至少 10 个不同轮廓（剪影测试，见 P0-3）。
- 烘焙耗时不超过一次换装操作的 16ms；阵容帧率不低于当前 35 FPS（P0-2 不应让性能回退）。

### P0-3 · 剪影与道具预算：16 个角色像同一个纸偶换颜色

**问题**
- 16 个预设共用一具身体、同一头身比、同一站姿；主要差异是帽子/颜色/朝向。
- 4/16 没有帽子；3 顶叶帽、3 顶珊瑚帽，帽型重复；6/16 使用同一深色发色 `#2f2a36`。
- 武器/盾/背包大多又小又被身体遮住；16 张卡第一眼是“同一人换衣服”，不是“16 个角色”。
- 随机阵容更糟（05/06 截图）：蓝帽 + 红披 + 粉裤 + 黄鞋，没有色彩纪律。

**证据**
- 精选 16 卡剪影 IoU 均值 **0.40**、p90 **0.60**；随机阵容均值 **0.52**、p90 **0.72**、最大 **0.84**（0 = 完全不同，1 = 完全重合；同一骨架理论上有下限，但当前明显偏高）。
- 预设统计：4/16 无帽；帽色红 3、叶绿 3；发色 `#2f2a36` 6 次；主色 hue 桶：红 17、蓝 10、橙 9、绿 6、青 6（红/蓝过度集中）。
- 参考片 60s 的 16 人阵容：同样约 100px 高，靠**帽/角/杖/披风/盾**区分，几乎不需要读颜色。
- 试衣镜“苔藓骑士”：剑刃完全在披风后，剑柄也仅露 8px；盾读成奶油色椭圆；远看像“带两个车灯的绿桶”。

**改法（具体参数：每个角色至少 1 个“破形件”）**
1. **剪影预算**：每个预设必须有至少 1 个形体突破件，在 2.1× 试衣镜下超出身体轮廓 ≥ **18px**（约 8.5 local）：
   - 帽檐 ±14 local / 帽尖 +18 local；
   - 披风外扩 +10 local；
   - 法杖高出头顶 +30 local；
   - 盾/背包侧向 +12 local；
   - 长武器横向 +24 local。
2. **道具可见性**：所有武器在 1× 试衣镜下，可见长度 ≥ **24px**，且与身体至少有一侧分离 ≥3px；背向时横跨背部/露出刀鞘；侧向时前手武器在身体前。现在读成板条的剑直接重画：加长到 34–42 local、加剑尖三角、加 1.5px 深边；握把沿手部 +2px，保证剑身在轮廓外可见 ≥24px。
3. **帽子/发型 3 档高度**：无帽、短檐、长尖；16 人里 ≤2 人完全无帽（当前 4 人）。头发至少 2 种“非球”外形：后脑发束、侧马尾、帽下露发。
4. **色板纪律**：每角色 ≤3 个有彩色相 + 中性色（纸/木/皮/金属）；面积 60/30/10（主/辅/点缀）。禁止“帽子/披风/裤/鞋各一个随机高饱和色”。随机器先选 8 套预设 scheme，再给槽位分配 primary/secondary/accent/neutral；拒绝 ΔHue<20° 的大面积相邻、拒绝 >2 个高饱和色、拒绝肤色被同色帽子吞掉。
5. **16 预设手工过一遍**：每张卡写 1 句“这个角色靠什么被认出”（帽/杖/盾/围巾/尾巴/背包）；没有答案的重新设计。定稿后再拍 01 截图。
6. **阵容展示**：4×4 卡从“等权网格”改成“1 张 hero + 15 张次级”（或按 role 分组），但仅作为展示层的改动；不影响核心工具。

**改法（具体参数）**
A. 8 向：
- yaw：正 0.0 / 斜 0.55 / 侧 1.0（斜向从 0.78 降下来，让正/斜/侧三档真正分开）。

- 背向：必须画双臂（袖子连接手套）、后发束 3 缕、披风 2 条褶 + V 形下摆；武器/刀鞘横跨背部或明确隐藏（有刀鞘可读）。当前“手套悬空”一票否决。
- 8 向弹层改成**罗盘布局**（3×3 环，中心“方向”），或两行“面向屏幕 / 背向屏幕”，不要 4×2 的奇怪顺序。

B. 动作（30fps 下）：

### P0-5 · 舞台没有光：角色和纸面同明度，阴影是平椭圆

**问题**
- 角色填充与舞台太近（皮肤 2.05:1，青绿 2.83:1），只能靠 6.7px 墨线“抠”出来；这会把 P0-1 的线宽问题放大。
- 阴影是 `DrawKit.shadow` 的 alpha 0.16 平椭圆，没有接触/环境两层，脚底“飘”。
- 背景的太阳盘 `#f8e2b9` 正好压在头后，头部（皮肤/帽子）与太阳同亮，边缘互相吃掉。
- 没有主光/轮廓光/环境反光；纸面舞台和角色没有“同一空间”的感觉。

**证据**
- 角色 bbox 平均亮度 174.6，舞台约 230（sRGB 亮度，0–255）；参考片巫师角色 74.8 vs 背景 41（角色比背景亮 1.8×，且有辉光）。方向相反不是问题，问题是**没有方向**。
- `01_studio.png` 4× 裁切：脚底与阴影之间没有暗部；阴影边缘 1px 硬切；太阳边缘与头重叠处没有轮廓光。
- 参考片 45s：巫师有清楚的左上主光、右侧青绿轮廓光、法杖辉光；同样的角色约 300px（含帽/法杖），体积感完全不同。

**改法（具体参数）**
- 舞台底色：`#f4ddc0` → `#e4c7a5` 的纵向渐变（比当前纸面暗 6–8 L*），左上 35% 暖光池（`#fff3d6` 35%），四周 10% 暗角；纸纤维噪声 σ2.2。
- 主光：左上 35°；角色受光面 `#ffe2b0` 20–26% 叠加；背光侧 `#5a6478` 26–32%；轮廓光右侧 2px `#ffe0a8` 190–215α，左侧 1px `#a8d4dd` 80–110α。
- 接触影：两层——接触 168×32、`#463426` 80–90α、blur 8；环境 223×34、30–40α；整体下移 2px。
- 纸层影（若走纸艺方向）：每个槽位 1.5px 投影，偏移 (4,7)，blur 6，60–70α；只出现在层与层压叠处，不要绕整个剪影一圈（否则像外发光）。
- 太阳：移到头后偏上/偏侧，降到 15% 不透明度，或裁掉与头相交的部分；头部右缘加 2px `#ffe0a8` 轮廓。
- 舞台装饰：纸屑 6→3、20% 不透明度；虚线缝 12% 墨；底边加 2px 纸胶带（可选）。
- 验收：灰度截图里，角色调 median 与舞台差 ≥ **25 L***；能在不靠颜色时看到“脚踩在地上”；100% 裁切能看到 2px 暖轮廓；阴影不是单一平椭圆。

> **示意**：`docs/art-review/03_lighting_mock.png` 只做了光/影后处理（不改形、不改线、不换色），用来证明“方向光 + 接触影 + 层影”能补多少体积感。它**不是**最终效果；P0-1 的重绘仍是前提。

## 4. P1 整改项（品质线，决定“像不像作品”）

### P1-1 · 把“纸偶”真的做成纸（风格落地）

**问题**：页面有纸胶带、缝线、虚线，但角色本身是纯矢量平涂。名字叫“纸偶工坊”，角色却不是纸，也不是木——“材料虚构”没有落地。参考片的角色明确是“木头人”（木纹、关节、漆面），你的 UI 明确是“纸”，两者中间缺一个决定。

**证据**：200% 裁切角色，没有纸纤维/切边/层影；材质只靠 ink 区分（见 P0-1）；UI 的纸胶带在页面层，角色层没有任何对应的纸语汇。

**选择（必须二选一，推荐 A）**
- **A. 剪纸纸偶（推荐，和现有 UI/命名一致）**
  - 每个槽位 = 一张纸：1px `shade` 切边 + 1.5px 层影（60α）+ 128×128 可平铺纸纤维（4% multiply）+ 大件 1–2 条折痕（1px shade 25%）。
  - 关节用黄铜两脚钉（`#e0c27a` + `#7d5236` 影），解释“为什么能动”；肩/肘/髋 4 处。
  - 外缘允许 0.3–0.5px 的不规则（8 段 jitter），避免完美矢量圆；但脸部不加噪点。
  - 层与层之间可以有 0.5px 的错位（slot offset），强调“叠纸”。
- **B. 彩绘木偶**：木纹、漆面高光、关节球、磨损露木；舞台改为木质台面。可行，但与现有纸 UI 的冲突要一起改。

**验收**：200% 裁切能看到纸纤维/切边；25% 下像“多层纸片叠起来”，而不是“贴纸 + 外发光”；不增加 >3px 的新噪点。

### P1-2 · UI 可读性：激活态对比度、9px 小字、内部术语

**证据（完整表见 `04_ui_contrast.png`）**
- 白字/珊瑚 `#e86a5c` = **3.16:1**（上衣行、右下方向按钮）；白字/青绿 `#3f9c8a` = **3.32:1**（护甲）；白字/紫 `#8a6fb0` = **4.22:1**（待机）；白字/青绿色块勾 = **2.97:1**；MUTED `#837586` / `#f3e7d4` = **3.54:1**；头部公式珊瑚/`#fff3df` = **2.88:1**。全部低于小字 4.5:1。
- 字号：标题 25 / 面板 14 / 常规 **11–12** / 提示/状态 **9–10**；9px 中文在 1280×720 上不可读，底部状态“已保存 JSON · 15:02:21”几乎消失。
- 信息层级：17 个槽位同权重；`z 40` 是内部术语；`9.0×10^26` 是程序写法；`本槽随机` 与 `随机纸偶/随机阵容` 三个入口语义重叠。
- 键盘：所有 Button `focus_mode = FOCUS_NONE`，无可见焦点环；有快捷键但无法用 Tab 浏览。

**改法（具体值）**
- 激活态：珊瑚底换 **`#c2473c`**（白字 4.93:1）或保留亮色但改深色字 `#3a2f43`；青绿换 **`#2f7a6b`**（5.10:1）；紫换 **`#6c5490`**（6.35:1）；MUTED 文字换 **`#5f5260`**（6.01:1 on `#f3e7d4`）。
- 字号：标题 25→**28**；面板标题 14；正文 12；提示 **≥11**；底部状态 **≥11**；英文小标 9→10。中文最小 11px。
- 槽位分组：4 组（头 / 身 / 手 / 饰）或 2 列 × 9 行；行高 32–34；激活行左侧 3px 珊瑚竖条 + 行底 `#fff3df`；变体 chip 高 30–32；色块 28px，选中加 2px 白环 + 深色勾（不要白勾压青绿）。
- 删除 `z 40`；如需显示，用“层级 40”放在 debug/? 里。头部数字改 **`9.0×10²⁶`** 或“约 1 亿亿”，并把它从主 CTA 旁降为说明文字。
- 卡片：名字 10→11；重掷按钮 20×16→24×24；选中边 3px 珊瑚 + 2px 外部纸影；名字前的小箭头保留，但选中卡加“已载入”角标。
- 键盘：所有可交互控件 `focus_mode = FOCUS_ALL`，焦点环 2px `#3a2f43` + 2px 纸色偏移；Tab 顺序 = 左→中→右→底。
- 8 向弹层：罗盘布局；动作弹层：3 关键帧/动作；关闭按钮 ≥32px 高。
- 验收：重新截 1280×720，激活态对比度 ≥4.5:1；9px 文本清零；键盘可走完所有控件；`z 40` 不在玩家视图。

### P1-3 · 换装可读性：把“17 层”变成看得见的卖点

**问题**：17 层 z 序是核心，但界面只给了一个密集列表；玩家看不出当前 17 层怎么叠、改了哪层、层间关系。4×4 卡太小，换装差异在缩略图上不可见。

**证据**：`01_studio.png` 的衣柜是 3 列 × 6 行按钮 + 变体条；没有层视/分组；卡片角色 95px；`02_wardrobe` 换装后，试衣镜与卡片之外没有“改了什么”的提示。

**改法**
- 在试衣镜右侧加 **“层”开关**：开启后 17 个槽位沿右下方向偏移 14px，层间 1px 连接线；hover/选中某槽，其他层降到 55% 不透明；槽位名 + z 显示在 chip 上。
- 衣柜面板加分组 tab 与“当前外观 17 层”计数；变体 chip 旁放 48px 预览（同一 pose、无阴影），让玩家看到“换成什么”。
- 试衣镜底部加 **改动 diff**：最近一次换装用 1.5px 珊瑚描边高亮 0.6s。
- 验收：新用户 5 秒内能说出“当前选中的是哪个槽、它在第几层”；一张截图能展示 17 层结构（可作商店页第 2 张图）。

### P1-4 · 随机搭配的色彩纪律

**问题**：每个槽独立随机颜色，产生“蓝帽+红披+粉裤+黄鞋”；`本槽随机` 鼓励局部乱配。组合数 9.0×10²⁶ 是数学事实，但 99% 的结果不可用，不能当卖点。

**证据**：`05_lineup.png` 同屏出现蓝帽/红披/粉裤/黄鞋；16 人里 6 人同深发色、4 人无帽；主色 hue 红 17/蓝 10/橙 9（见 `05_annotated_lineup.png`）。

**改法**
- 建立 8 套 **outfit scheme**：每套含 primary / secondary / accent / neutral（纸/木/皮/金属固定中性）；面积 60/30/10；高饱和色 ≤2；相邻大面积 ΔHue ≥20° 或同色系明度差 ≥15。
- 默认“**和声随机**”，`野随机` 作为隐藏选项；每个预设也过同一检查。
- 验收：连续 10 次随机，10/10 通过；16 卡里不超过 2 张使用同一 primary hue + 明度区间；不再出现“帽子=皮肤同色”。

### P1-5 · 展示物料：先给玩家看角色，不是看工具

**问题**：6 张截图全是工具 UI；05/06 的阵容与 01 的精选预设不一致（疑似随机/重掷后的状态）。对外第一屏会让人以为这是“换装器后台”，不是“纸偶游戏”。参考片靠深色舞台+角色+光建立情绪，你的截图没有一张“干净舞台”。

**证据**：`docs/shots/` 6 张全部包含三栏 UI；没有无 UI 的 hero 图；05/06 的角色卡与 01 不一致。

**改法**
- 增加 **舞台模式（F11）**：隐藏所有 UI，保留试衣镜舞台；1920×1080 或 1280×720 输出。
- 出 3 张对外图：① 1 个 hero 角色（全身、舞台光、无 UI）；② 8 向罗盘（剪影清楚）；③ 16 人海报（2 行，角色 160–200px 高，背景同舞台）。
- 出 1 个 6s GIF：idle → walk → attack → hit，640×360，30fps；再出 1 个 15s 竖屏/横屏短视频（可选）。
- 截图规范：只用精选阵容或固定 seed；不拍随机阵容；所有文字在缩略图下可读。
- 验收：陌生人看第一张图能说出“这是一个纸偶换装/收集游戏”，而不是“这是一个编辑器”。

## 6. 角色资产路线（外部资产 / 替换意见）

### A. 继续程序化 2D（推荐）
这是本项目的差异化和成本优势。P0/P1 的参数都在现有架构内可实现，不需要换资产管线。

### B. 外部 2D 剪纸层（可混合）
如果请外援画，不要按“16 角色 × 17 槽 × 8 向”全量外包（16×17×8 = 2176 张，成本爆炸）。建议：
- 基础身体 1 套（8 向 × 4 动作）+ 6–8 套服装/头饰（每套 17 层）+ 程序化 tint。
- 源文件 2048×2048/层，命名 `char_{role}_{slot}_{dir}.png`；导出 2× 显示尺寸（试衣镜 300px → 600px 源），`Linear` 过滤，预乘 alpha。
- 线宽：1024px 源上外轮廓 3px（≈0.9px @300px）；墨色 `#3a2f43`；色板按本文 §3 P0-1 的 5 档。
- 轴心：脚底中心 (0,0)；每层同一画布、同一轴心；8 向 × 4 动作必须由同一骨架生成，否则换装会错位。
- 验收：17 层对齐误差 ≤1px（300px 显示下）；8 向剪影 7/8；95px 缩略图不糊。

### C. 3D 模型（KayKit / Quaternius，不推荐用于本 UI）
本作是 2D 工具 + 纸偶；3D 会破坏“17 层纸片”的叙事，并引入相机/灯光/材质成本。若只做背景舞台或片头：
- 角色高 1.55m，脚底 pivot；相机 orthographic，画面高 2.4m，俯角 18–20°，FOV 35°（如透视）。
- 贴图 512 px/m，`Linear` + mipmap；金属/粗糙度贴图；主光 35° 左上、轮廓光右侧，色温 5200K/6500K。
- 与 2D UI 合成时，3D 渲染到 SubViewport，颜色空间 sRGB，关闭 Tonemap 或固定 ACES；确保与纸面色 `#f3e7d4` 的对比在 ±5 L* 内。
- 结论：仅作为“舞台/宣传”可；不要替换 17 槽纸偶。

## 7. 外放判定与“仍不足”

### 7.1 判定
- **不达可外放门槛（4.2 / 7.0）。**
- 当前最适合的定位：**内部工具 / 开发日志素材**，不是商店页。
- 如果把现在的截图直接发到 itch.io：第一印象会是“换装实验/课设”，而不是“纸偶游戏”；UI 的完成度会提高期待，然后被角色质量拉低。
- **达到公开试玩（7.0）的最短路径**：P0-1 + P0-2 + P0-3 + P0-5（约 2–3 人周），再补 P1-2（UI 对比度/字号，1–2 天）与 P1-5（舞台截图，1 天）。P0-4（8 向/动作）若目标是“系统演示”，也必须一起做；若只是“换装玩具”，可以先做 P0-1/2/3/5，但 8 向仍会被玩家一眼看穿。
- **达到商店页/正式外放（7.5）**：再加 P1-1（纸艺落地）、P1-3（层视）、P1-4（色彩纪律）和动画的 authored keys。

### 7.2 仍不足（必须写清楚）
1. **身份/叙事**：16 个名字有趣，但画面上没有“职业/性格/世界”的证据；去掉名字，玩家分不清“河灯渔夫/树洞邮差/露珠药童”。需要每个角色 1 个可读道具 + 1 个姿态习惯。
2. **纸艺尚未发生**：P1-1 只是方案；没有纸纤维/切边/层影的实际管线，角色仍是矢量贴纸。
3. **动画是程序化的“对”而不是“好看”**：缺少 authored 的预备/过冲/跟随；走路像滑步，攻击缺 smear；这不是加参数能完全解决的。
4. **8 向仍是 2.5D 近似**：侧向/背向的解剖和服饰转折不如真正的 8 视图资产；如果外放，必须接受“剪影可辨”而不是“每向都精美”。
5. **UI 是工具，不是游戏**：没有 onboarding、收藏、目标、反馈循环；外放需要至少一个“玩什么”的答案。
6. **展示物料未做完**：没有 hero 图、没有海报、没有无 UI 舞台；现在的 6 张截图不能当商店页。
7. **可访问性/本地化**：9–12px 中文、无焦点环、无触屏布局、无英文版；外放前需补。
8. **参考片是“表达标杆”，不是“素材库”**：只学剪影/光/节奏，不复制角色、UI、配色；本项目应保留纸艺工坊的原创身份。

## 9. 风险

1. **AA/超采样的性能风险**：Intel 集显 + GL Compatibility 的 MSAA 2D 支持不确定；必须用 2× SubViewport 兜底并实测。一次性烘焙可控，实时试衣镜不要 4×。
2. **描边变细后的可读性风险**：现有填充对比只有 2.05–2.83:1；减墨线会暴露填充太浅。必须同时加 5 档色阶/轮廓光，否则会“变干净但更糊”。
3. **纸纤维/层影的噪点风险**：4% 纸纤维可能让 95px 缩略图更脏；在 mini 模式必须关闭纤维/层影，只保留 AA。
4. **视觉改动 vs 17 层架构**：改 z 序/层影会影响所有槽位；先在 1 个角色、1 套服装验证，再批量。不要一次改 17 槽。
5. **外部资产的授权风险**：只使用 CC0 / MIT / OFL 或明确商用授权；参考片仅作评论/对标，不复制其素材、UI、名称。字体先查 OFL。
6. **“更好看”与“更清楚”冲突**：外放第一优先级是 25% 缩略图和 3 秒 GIF 的可读性，不是 4× 细节；所有评审先看目标尺寸，再看放大。
7. **AI/外包一致性风险**：如果引入外部美术，必须锁定 ink 色、线宽、色板、轴心、8 向/4 动作矩阵；否则 17 层会错位。
