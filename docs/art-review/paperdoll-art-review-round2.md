## Top 问题（P0 → P1；每条：问题 → 证据 → 根因 → 改法 → 验收）

### R2-P0-1 · 16 人剪影没有过门，且“25% / 3 人”证据缺失

**问题**
16 个角色的剪影区分度仍不足：IoU **0.412**（门槛 0.30），p90 **0.590**（门槛 0.48）。更关键的是，原验收线写的是“3 名未见过项目的测试者，在 **25% 缩放、纯黑剪影**下 2 秒认出 ≥12/16”；QA 的 13/16 是 **240px/格** 的单人目检，不是 25% 协议，不能当通过。

**证据**
- 复算：`mean 0.4124 / p90 0.5923 / max 0.7223`（120 对）。
- `silhouettes_16_25pct.png`：320×320 接触表（单格约 45px，接近 poster 25% 口径）上我目测约 **11–13/16** 可辨；游戏内 4×4 卡在 25% 下角色约 **24px**，比这更小，且没有正式测试。07 夜巡猫、12 露珠药童、15 香菇小贩在 25% 下最弱。
- 16/16 都有破形件（P1-5 海报也证明），说明“加帽子/道具”已接近边际收益；共享骨架仍让 120 对里大量重叠。

**根因**
一套骨架 + 一套站姿；`body build` 只在 0.90–1.16 之间改宽窄，头身比、腿长、肩宽、站姿几乎不变；破形件只占轮廓周长的一部分。0.30 不是再换一顶帽子能到的，需要**体型 archetype**。

**改法（下一轮，具体参数）**

| Archetype | 身高 | 肩宽 | 腿长 | 头宽 | 角色数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A 高瘦 | 1.10× | 0.90× | +12% | 0.92× | 2–3 |
| B 敦实 | 0.92× | 1.15× | −10% | 1.08× | 3 |
| C 长腿 | 1.06× | 1.00× | +18% | 0.95× | 2–3 |
| D 幼小 | 0.82× | 0.88× | 0 | 1.18× | 2 |
| 其余 5–6 人 | 标准 | 标准 | 标准 | 标准 | 每人 1 个 ≥18px 的专属破形件 + 1 个习惯站姿 |

- 习惯站姿：手扶帽檐 / 拄杖 / 单臂前伸 / 驼背，关节 6–10° 偏移，不只改颜色。
- 07 夜巡猫：尖耳 +16px、尾 24px；12 露珠药童：翅 ±20px + 1 个高光水滴；15 香菇小贩：菌盖 ±22px + 背篓侧向 12px。
- 保持 17 槽 / z 序 / 8 向 / 4 动作不变；archetype 只改 joint 常量与衣物宽度，不拆架构。
- 禁止用“更多帽子/更花颜色”代替体型；禁止把 IoU 目标降到 0.35 来过关。

**验收**
3 名未见过项目者，25% 纯黑剪影 2 秒 → **≥12/16**；IoU **mean ≤0.30、p90 ≤0.48**；16/16 破形件；8 向/4 动作/UI 无回归。

### R2-P0-2 · walk 支撑脚滑步 45.26px（硬门 2px）

**问题**
右向 walk 的支撑脚在“踩地”阶段仍横向扫过 45.26px；正面也有 5.42px。在 640×360 GIF 里角色像“原地蹬腿”，不是走路。

**证据**
- `QA_WALK dir=6 left_px=45.26 right_px=45.26`；`dir=0 5.42`；阈值 2px。
- `walk_contact_strip.png`：帧 42–78，脚接触点跟身体一起平移；`paperdoll_6s.gif` 只有正面，正面漂移小，侧向问题被隐藏。
- `P0-4` 的“无滑步”是外放硬门；这不是 P2 打磨。

**根因**
walk 只在 hip/knee 上转角度，没有“支撑脚锁定 / 根位移 / 地面滚动”；舞台也不动，所以支撑相必然滑。

**改法**
- 支撑相（脚底距最低点 ≤1 local）锁定脚的世界 x：允许 ±0.4 local 误差，把差值反加到 root 或舞台偏移上。
- 二选一：**根位移**（角色前进、地面滚动）或**原地踏步 gait**（支撑脚不动，摆动脚收）。展示物料建议根位移 + 背景滚动。
- 保留 0.82s / 8 keys；脚掌 −15° → 全掌 → +22°；披风/发滞后 2 帧、4–5 local。
- 重录一条 **侧向 walk 2s** 进 GIF 或另发验收录屏，不要只用正面。

**验收**
`qa_motion_probe.gd` 8 向全部 **≤2px**；640×360 侧向 walk 肉眼无滑步；6s GIF 重录；8 向/4 动作无回归。

### R2-P0-3 · FPS 门未签：4/4 实测 <30

**问题**
当前 build 在本机 4 次实测 `steady_min` 13–27、`avg` 28.3–30.0，全部 `<30`；T-010 文档写的 “30–45 / min 30” 本轮无法复现。同机 T-009 基线也 `<30`，说明主要是环境负载，但**“Intel 集显 ≥30”仍不能签发**。

**证据**
`PAPERDOLL_FPS samples=[33,37,31,28,24,28,31] steady_min=24.0`；三次独立 13/27/26；后台 Lark/WebKit/XProtect 20–68%；T-009 基线 20/28。烘焙 p90 在负载下 16.02/19.15ms（阈值 16）。

**根因**
24Hz 试衣镜 + 16 张 2× 卡片同帧重烘焙 + 后台 CPU 抢占；T-010 的优化有效，但没有在洁净环境留下可复现的 ≥30 证据。

**改法**
1. 关闭 Lark/WebKit/XProtect 等后台，连续 3 次 `perf_paperdoll.gd`；保留原始 samples。
2. 若仍 <30：试衣镜 24→20Hz；气场/披风/兜帽预烘焙；16 卡烘焙排队（每帧 ≤2 张）；避免同帧 16 张 2× 重烘焙。
3. 不要用降低 AA/超采样来换帧率；P0-2 的 AA 是已过门的品质线。
4. 口径：**公开门 30，内部目标 35**；不要再用“35 下限”和“30 门”混着写。

**验收**
3/3 次 `PAPERDOLL_FPS_OK`（steady_min ≥30）；`PAPERDOLL_BAKE_OK` p90 ≤16ms；`verify.sh` 全链路 `PAPERDOLL_VERIFY_OK`；把 6s GIF 纳入 verify。

### R2-P0-4 · T-013 公开试玩 P0-1/2/3 未实现，产品门 BLOCKED

### R2-P1-1 · 16 张阵容卡键盘不可达 + 方向键与焦点冲突

**问题**
66 个 Button 全部可聚焦，但 16 张 `LineupCard` 是 `PanelContainer focus=0`，Tab 永远到不了；有焦点时 ←→ 只移动焦点、不切方向，违背界面提示“←→ 方向”。

**证据**
`QA_INPUT buttons=66 focusable_buttons=66 lineup_cards=16`；`arrow_with_focus dir_changed=false focus_moved=true`；`QA_INPUT_FAILED failures=1`。截图里卡片只有鼠标/单抽入口。

**根因**
LineupCard 不是 Button、没有 focus/键处理；全局方向键没有让位于 UI 焦点导航。

**改法**
- `LineupCard.focus_mode = FOCUS_ALL`；复用 `AtelierTheme.focus_style()` 2px 墨色环 + 2px 纸色偏移；Enter/Space 载入；选中卡加“已载入”角标。
- Tab 顺序：左栏 → 中栏 → 右栏 → 底部；16 卡按 4×4 顺序。
- 方向键：焦点在按钮/卡片上时用 Tab/上下导航；←→ 切方向只在不聚焦时生效，或改 **Ctrl+←→** 并在提示里写清。
- 点击区域保持 ≥32px；卡面不变。

**验收**
`qa_input_probe.gd` **QA_INPUT_OK 0 failures**；Tab 可达 16 卡并载入；←→ 行为与 UI 文案一致；焦点环在 1280 截图可见。

### R2-P1-2 · 8 向在验收边缘；斩击的“3:1”证据口径不成立

**问题**
正/背 IoU **0.6948** 只比 0.70 低 0.0052；相邻方向归一化 max **0.7506** 比 0.75 高 0.0006。斩击的 `6.85 / 5.03` 是色值 WCAG 比值，不是斩击弧 ROI 的可见性；金核 `#ffd27a` 只有 **1.22:1**。目检斩击弧存在，但偏细、偏后，像一条拖在腰后的带子，不是“挥砍”。

**证据**
- `metrics-qa.json`：front_back 0.6948；adjacent normalized max 0.7506；`directions_compass_black.png` 背向组 3/4/5 最接近。
- `slash.png`：`#8f3030` / `#b23c33` 命中像素集中在角色衣摆/靴子附近（x 213–306, y 475–651），不是唯一的斩击弧。
- 640 帧 102：弧线可见但细；`03_actions` 的冲击帧弧线更明显，说明效果存在，强度不足。

**根因**
8 向是 2.5D：yaw 只做横向压缩，远臂/近臂/腿的遮挡差异不够；斩击弧的半径/位置没有跟剑尖路径绑定；验收只统计色值，不统计效果像素 ROI。

**改法**
- 8 向：侧向近臂在身体前、远臂只露肘/手（隐藏 ≥70%）；背向披风 V 形下摆 + 后发 3 缕 + 刀鞘/背包在轮廓外 ≥18px；头前探 5.2 local 保持；目标正/背 ≤0.65（门 ≤0.70），相邻 ≤0.72。
- 斩击：ROI 只取弧线带；弧线与剑尖路径对齐，半径 52–62 local；核心改为 `#8f5f1f` 2px（对 `#f5edde` 约 5.6:1）或加 1px `#8f3030` 深边；`#ffd27a` 只做 1px 装饰高光，不计入 3:1；640×360 下弧带宽度 ≥4px、寿命 0.22s。
- 验收指标改为“ROI 内斩击色带 ≥3:1 + 弧带可见面积”，不要用整图颜色计数。

**验收**
3 人 7/8 方向；正/背 ≤0.70（目标 0.65）；相邻 ≤0.75；斩击 ROI ≥3:1、640 GIF 不读字可辨；无穿模/悬空。

### R2-P1-3 · 材质语言在 1× 不可读（纸/木/布/皮）

**问题**
材质 ramp 和细节都加了，但在 1×（试衣镜 317px 高）只读得出“金属剑 + 帽缝 + 金扣”；纸纤维 4%、木纹 0.4px、缝线 0.6px 在目标尺寸都低于 1px，等于没画。角色仍更像“矢量贴纸”，不是“纸偶/木偶”。

**证据**
`hero.png` 100%：剑有高光/剑尖，帽有 1 条接缝，其余大面积纯色；200% 卡才看到少量线。`01_face_4x` 的帽缝/眉毛可读，但脸外没有材质证据。

**根因**
细节预算按 local 尺寸给，没有按“最终屏幕像素 ≥3px”折算；五档色阶解决明度，不解决材质识别。

**改法（只做 5 个可读签名，不铺满）**
| 材质 | 1× 可见签名 | 参数 |
| --- | --- | --- |
| 木 | 2 条年轮弧 / 裸露肢体或腰 | 0.8px `#9a653f` 60%，间距 3–4px |
| 布 | 1 条褶 / 25px 宽 + 下摆 2px 阴影 | 0.9px shade 50% |
| 皮 | 1 排针脚 / 6px + 1 孔 | 0.8px `#d1a06a` 60% |
| 金 | 2px 高光 + 2 颗铆钉 | `#fffaf0` 2px；`#5e6670` |
| 纸 | 1px 切边 + 1.5px 层影（只在层压叠处） | `shade` 60%；纤维只在大面积 ≥40px 区域 |

- 95px 卡片继续删 L1/L2，只保留 L0；不要在 mini 上补材质。
- 不要为了材质加噪点；每个大件最多 2 个签名，脸不加。

**验收**
3 名测试者在 1× 角色上能说出 **≥4/5** 材质；200% 能看出纸纤维/切边；95px 卡不糊；墨色族 ≤9% 不回归。

## 风险

1. **FPS 的环境敏感性**：4 次 <30 与后台负载强相关，同机基线也 <30；但“未验证”不等于“通过”。洁净机仍 <30 时必须优化，不得以环境为由放行。
2. **剪影 0.30 可能要求二次角色设计**：若不愿做 4 个体型 archetype，就只能在“12/16 人眼门”上补 3 人证据；**不能既不做体型、又不做 3 人测试**。
3. **降墨线后的填充可读性**：当前靠轮廓光/接触影撑住；下一次加材质/改色板时必须复测墨色族与 ΔL\*，否则会“变干净但更糊”。
4. **8 向仍是 2.5D**：正/背余量 0.0052、相邻归一化 0.7506；任何进一步压缩/镜像都可能把方向组重新压回 0.8。
5. **产品门比美术门更重**：T-013 产品 P0 未做，公开试玩无法开始；不要把剩余预算全花在角色重绘上。
6. **随机色彩口径未统一**：T-007 “≤3 色相簇” 10/10 过；T-013 “≤2 有彩色相” 仅 6/10 过。需要策划/美术拍板，否则随机阵容会继续出现“蓝帽+红披+粉裤”。
7. **3 人测试缺失是证据风险**：单人目检 13/16、7/8 不能写成“通过”；下一轮必须先补协议，否则任何“可外放”结论都不成立。
8. **字体/分发**：当前用系统 PingFang；正式外放如需打包字体，换 OFL（Noto Sans SC / 得意黑），随包授权文件；这是 P2，不阻塞本轮。

## 仍不足（即使下一轮全过，也仍存在）

1. **身份/叙事**：16 个名字 + 道具能区分“职业”，但还没有“性格/世界/故事”；去掉名字后，部分角色仍只是“纸偶 + 帽子”。需要每个角色 1 个姿态习惯 + 1 句人话，不是再加道具。
2. **纸艺尚未真正发生**：纸纤维/切边/层影主要在 UI 与 200% 裁切里；1× 角色仍偏“矢量贴纸”。P1-1 的纸艺管线只完成了一半。
3. **动画是“对”的，不是“好看”的**：walk 滑步、attack 弧线偏弱、idle 次级运动未验证；缺 authored 的预备/过冲/跟随。修参数能过门，但要“好看”仍需动画关键帧设计。
4. **8 向是 2.5D 近似**：背向有兜帽/肩披/刀鞘，侧向仍靠压缩；远侧手脚的解剖转折不足。公开外放要接受“剪影可辨”，不是“每向精美”。
5. **UI 仍是工具，不是玩具**：17 槽平铺、组合数在头部、随机入口语义重叠、无命名/卡片/阵容收藏；这是产品门，不是美术门，但它决定“玩家是否想玩”。
6. **外放物料不完整**：hero 无 UI 但构图空、没有标题/品牌；poster 可看；GIF 只有正面，没有背面/侧向；没有 3 人陌生人测试。
7. **可访问性**：16 卡键盘不可达、方向键冲突、无触屏/色盲/缩放；系统字体；中文最小 11px 是达标线，不是舒适线。
8. **参考片只是表达标杆**：本项目的身份应是“纸艺工坊”，不要复制参考片的深蓝舞台、木头人造型或 UI；下一轮也不要引入外部素材。

## Verdict：**REJECT**

**理由（按权重）：**

1. 美术加权 **6.2 / 7.0**；P0-3 剪影 0.412 > 0.30、P0-4 滑步 45.26px > 2px 是明确未过；P1-2 键盘未过。
2. FPS 4/4 <30（可复现性未签）；P0-2/P0-5 的通过不代表整体可外放。
3. T-013 公开试玩 P0-1/2/3 未实现，T0–T8 无法执行——即使美术 7.0，也不能进入公开试玩。
4. 3 人测试未执行；25% 剪影/7 向/陌生人测试都是单人目检或 BLOCKED，不能按 PASS 计。

**这不是对美术实现的否定**：P0-1/P0-2/P0-5 真落地，4.2 → 6.2 是实质进步；但“可玩 demo”不是“可外放”。按硬门槛规则，任一 fail → REJECT；带病发布不是 APPROVE WITH CONCERNS。

**下一轮最短路径**：先做 R2-P0-1（体型/剪影）+ R2-P0-2（防滑）+ R2-P0-3（洁净 FPS）→ R2-P1-1（键盘）+ R2-P1-2（8 向/斩击口径）→ 3 人测试 → 产品 P0-1/2/3 → 提交 T-013 T0–T8 与 T-007 §8 全量证据，再复评。
