## 0. 结论先行

**这条视频真正可复用的，不是“某个风格模型”，而是一条五段式顺序：**

```text
布局锁定 → 只换题材（先别洗） → 低强度风格洗 → 4K 修字 → 设定表切零件/同名替换 → 进游戏
```

| 问题 | 结论 | 等级 |
| --- | --- | --- |
| 最关键的顺序是什么？ | **先别洗**：先用“全能编辑/Theme only”拿自己的界面当布局参考，只换题材；再用风格模型洗。上来就洗会把布局洗坏。 | A |
| 风格强度取多少？ | 战斗界面 **0.30**；字多的大厅/商城 **0.25**。视频里 0.65 的反例“整张图都会重画”。 | A |
| 文字怎么处理？ | 4K 放大后修字；**参考图只给洗过的那张**；每一处文字都写进提示词；最终必须人工校对。 | A/B |
| 零件怎么切？ | 角色背面、怪物、技能图标、HUD 组件出“设定表”，一键抠图切 **32 个零件**，文件名与原文件一一对应。 | A/B |
| 换皮等于玩法创新吗？ | **不等于**。它是内容/成本策略，改变的是题材、风格、素材与文案；不改变动词、约束、信息结构。 | D（呼应 T-033） |
| 开源能替代多少？ | 工程上可覆盖约 **70–85%** 的步骤；最弱的是“中文文字正确 + 一键切图命名 + 游戏 UI 专用风格模型”，需要脚本与人工补齐。 | D |
| 本仓库先拿谁试？ | `godot-inventory-ui/` 最合适：29 个资产（27 个现用）、84 个文本节点/73 条唯一文案、完整 manifest；可组成 **32 个替换件**。 | A/D |

**三句话判断：**

1. **换皮是“乘法”不是“加法”**：布局、玩法、数值不变，只换题材/风格/素材；乘法系数取决于原玩法是否已经成立。
2. **强度是硬约束**：0.25–0.30 是“洗”，0.40 以上开始“改布局”，0.65 是“重画一张别人的游戏”。生产管线必须把强度写成 gate，而不是口味选项。
3. **文字是 AI 换皮的头号事故源**：中文尤其如此。能保留运行时文字就保留；必须烘焙时，OCR + 人工逐字校对 + 字体许可记录，一个都不能省。

### 1.3 五步流程（逐帧还原）

#### 第 1 步：先别洗——布局锁定，只换题材

- **输入**：自己原创的战斗界面截图（布局参考）+ 题材/风格样图（只取题材，不取构图）。
- **操作**：在“全能编辑”里用 **Theme only**，把僵尸换成妖僧/虫子/骷髅，把枪械换成法杖/剑，把现代街道换成青石古镇/花园/王陵。
- **约束**：HUD 位置、按钮数量、角色站位、伤害数字位置、画幅比例全部不变。
- **为什么**：风格模型直接洗会把“布局”和“风格”一起改；先做语义/题材替换，布局才有稳定锚点。
- **证据**：00:30 的布局参考；00:33 同一布局并排三种题材；00:24 的 0.65 反例。

#### 第 2 步：风格洗——用低强度换“味道”

- **战斗界面**：strength **0.30**；边框、按钮、线条、角色材质都洗成目标风格，但“布局一点没动”（00:42）。
- **字多的大厅/商城**：strength **0.25**；0.30 会把布局改掉（00:51 红框 vs 绿框）。
- **反例**：0.65 时“整张图都会重画”，UI 位移/构图变化，已经不能叫同一套界面（00:24）。
- **工程解释（D）**：这里的 strength 相当于 img2img 的 denoise 强度；数值越高，模型越自由。视频没有公开工具内部参数定义，按“重绘强度”理解即可，不要把它当成固定的跨工具参数。

#### 第 3 步：4K 修字——只给洗过的图，逐条写文字

- **参考图策略**：只给“洗过的那张”；不要同时给原图/草稿。画面标注“参考图给两张 / Reverts to the draft”（00:45）；可理解为给两张会让模型回退到草稿，机制属于推断（A/D）。
- **放大**：先把界面放大到 4K，再修文字区域；这样文字边缘、描边、字重才有足够像素。
- **逐条文字**：每一处文字都写进提示词（标题、波次、资源数、按钮文案、页签、提示语等），不能只说“修复文字”。
- **结果**：00:54 右侧绿框版本文字清晰，位置/字号基本保持。
- **注意（D）**：AI 修中文仍可能造字、错字、缺笔画；生产上应优先保留运行时文字，AI 只修背景/装饰，文字用引擎字体重新排版。

#### 第 4 步：设定表 + 一键抠图切零件

- **设定表内容（画面观察）**：角色背面（3 个）、怪物（4 个）、技能图标（9 个）、HUD 组件（血条/横幅/按钮/城墙/框/水晶/环等）。这是从画面能数到的类别，不是完整 32 件清单。
- **切图**：一键抠图，透明背景，切成 **32 个零件**。
- **命名**：文件名和原文件一一对应。画面可见 5 个：`back_hero.png`、`z_walker.png`、`z_boss.png`、`sk_fire.png`、`gem.png`。
- **命名结构（观察）**：`<角色/类别前缀>_<对象>.png`；`back_` = 角色背面，`z_` = 怪物（zombie 系列），`sk_` = 技能图标，`gem` = 宝石/货币。完整 32 件清单视频未展示全，不能凭 5 个名字反推全部。
- **风险（D）**：设定表里零件间距过密、描边/光晕被裁、半透明边缘会被抠图吃掉；必须在 manifest 里记录 bbox、padding、pivot。

#### 第 5 步：进游戏——同名替换，切一套皮

- **操作**：把新零件按同名覆盖进游戏，运行时“切一下就是一套新皮”（01:09）。
- **结果**：01:11 四张运行时并排——原版“废弃商业街”、国风“青石古镇”、萌系“向日葵花园”、欧美卡“王陵内部”；波次、血条、技能按钮、伤害数字、2× 速度等 HUD 结构保持一致。
- **边界**：视频只证明“这套素材能替换并运行”，没有给出帧率、内存、包体、机型、崩溃率数据；不能据此推断性能或商业表现（D）。

> **重要**：三套皮共用同一五步配方；视频完整演示的是国风这一套，萌系/欧美卡主要在并排结果与最终运行时出现。不要理解成三套各自独立的流程；差异在风格 token、参考图和所选模型，而不是步骤。

## 4. Reskin Kit 规格（引擎无关）

### 4.1 目标与非目标

**目标**：给定一套原创布局与一套风格 token，稳定产出一套可替换的 UI/场景/角色/图标/组件资产，且能验证“布局没坏、文字没错、零件没漏、许可清楚”。

**非目标**：不做玩法改动；不做数值/关卡设计；不做“AI 一键出完整游戏”；不负责商业发行合规的最终法律判断。

### 4.2 输入契约

#### A. 布局参考 `layout_ref`

| 要求 | 说明 |

| 机位 | 同机位、同分辨率、同画幅；不要透视/裁剪变化 |

#### 4.5.1 去字 / 加字策略

| 场景 | 推荐做法 | 不推荐/禁止 |
| --- | --- | --- |
| 原界面文字可保留 | `live text`：换皮只换字体/颜色/字号；文字永不进图 | 把整屏文字烘焙成贴图 |
| 原图有字，必须先洗背景 | 先做文字 mask（外扩 2–8 px），局部 inpaint 提示“移除文字、保留背景/边框/布局”；洗完再用引擎排版文字 | 让风格模型“顺手把字修好” |
| 必须烘焙文字 | 4K 放大 → 逐条文字提示 → OCR → 人工逐字校对 → 字体许可记录 | 只写“修复文字”；用英文/拼音替代中文 |
| 需要加新文案 | 用设计稿/引擎文本排版；AI 只做草稿/占位 | 让模型自由发挥文案；让模型“加一行字” |
| 多语言/本地化 | 文本清单按 `language` 分行；live text 优先 | 把中文烘焙进图后再翻译 |

**原则**：AI 负责“背景/装饰/材质”，人负责“文字/字号/对齐/许可”。中文换皮的头号事故不是风格不对，而是字错了。

### 4.6 提示词模板（可直接复用，非作者原文）

### 4.7 质量控制与验收

| 检查 | 方法 | 通过标准 | 失败动作 |
| --- | --- | --- | --- |
| 布局锚点 | 对比 bbox（HUD/按钮/页签/角色） | 漂移 ≤1% 或 ≤2 px | 降强度/加 ControlNet/回到第 1 步 |
| 文字正确性 | PaddleOCR + 人工逐字 | 0 错字、0 缺字、0 多字 | 重新排版/引擎文字 |
| 文字可读性 | 对比度 + 25% 缩略 | 正文 ≥4.5:1；大字 ≥3:1；缩略可读 | 调色板/字号/描边 |
| 命中区 | 运行时点击测试 | 位置/尺寸不变 | 回退 UI 布局 |
| 九宫格 | 1×/2×/4× 拉伸 | 角不糊、边不裂、中段可拉伸 | 调 margin/改整图 |
| 零件完整性 | 数量/alpha/bbox | 32/32；无裁切；pivot 正确 | 重切/补 padding |
| 命名映射 | manifest diff | 0 缺失/0 多余/0 错名 | 改名/补文件 |
| 风格一致性 | 色板 ΔE + 人工 | 同主题色板/线宽/光照一致 | 固定 seed/修 token |
| 字体许可 | 许可清单 | OFL/自有/已购；可嵌入 | 换字体 |
| 性能 | 引擎 profile | FPS/内存/包体在预算内 | 降分辨率/合图/关 mipmap |
| IP 风险 | 相似度/人工 | 无第三方案例角色/Logo/UI | 重做/替换 |
| 数据安全 | 上传清单 | 无 NDA/未公开内容 | 移除/改本地 |

- [ ] 同机位 before/after 截图（1× 和 25% 缩略各一份）

- [ ] FPS/内存/包体在预算内
- [ ] 字体/模型/参考图许可记录齐全
- [ ] IP 相似度检查通过（无第三方角色/Logo/UI）

### 5.7 风险清单（dry-run 结论）

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 面板不是九宫格设计（整图 2× 拉伸） | 风格洗后角饰/云纹被拉伸或洗糊 | 先按 120 源 px margin 试九宫格；不行就保留整图 + 只换色板 |
| 运行时渐变 UI vs 烘焙贴图 | 两套视觉语言不一致（按钮/页签/格子） | 先做 A 策略统一色板；B 策略统一定义圆角/描边/阴影 token |
| 73 条唯一文案 + 物品描述 | 错字/漏字/字重不一致 | 保留 live text；4K 修字只修背景；OCR + 人工逐字 |
| 系统字体未打包（PingFang/KaiTi） | 分发/跨平台字形不一致；许可不明 | 换 Noto Sans SC / 思源宋体（OFL）；随包附许可 |
| 20 个 SVG 图标线宽/视角不一 | 换风格后像拼贴 | 先统一 2px 线宽/圆角/光源；再做风格化 |
| 品质边框靠颜色区分 | 色弱/缩略图不可读 | 加形状/角标/文字；不要只用颜色 |
| 344 draw calls / GL Compatibility | 换 4K 贴图后内存/带宽上升 | 控制 max texture；合图/atlas；实测 FPS |
| F1 对齐覆盖层 / 现有截图 | 对比时误把诊断层当成品 | 验收截图关闭 F1；另存 overlay 图 |
| 参考图/生成图版权 | 侵权/下架 | 只用原创/CC0；记录来源；相似度检查；不复制案例 UI |

**预估（D）**：A 策略 1.5–2 人日；B 策略 4–6 人日；若含 4K 中文修字与人工校对，再加 1–2 人日。AI 生成能省“画”的时间，但省不了“校对/切图/命名/验收”的时间。

## 6. 边界与判断

### 6.1 换皮 ≠ 玩法创新

呼应 `docs/design/gameplay-innovation-research.md`（T-033）的判断：

| 维度 | 换皮 | 玩法创新 |
| --- | --- | --- |
| 玩家重复的动作 | 不变 | 出现新动词，或旧动词的代价改变 |
| 决策结构 | 不变 | 新的取舍、风险、信息差 |
| 30 秒可教 | 靠题材解释 | 一句话 + 一个可试的演示 |
| 删掉这个“创新” | 只是换回原主题 | 核心循环不成立 |
| 验证方式 | 截图/宣传语/CPI | 可证伪的 playtest 假设 |
| 典型失败 | 版权/同质化/买量疲劳 | 新颖但不可读、不可行 |

**结论**：换皮是**内容/成本策略**，适合“核心循环已验证、需要低成本获取新用户/新渠道”的场景；不适合用来掩盖“玩法不成立”。先有 D1/D7/付费/留存数据，再决定是否换皮；不要用“换了三套皮”当作创新证据。

### 6.2 IP 与素材边界

- **不复制**《末日小队》或其他游戏的角色、怪物、技能图标、HUD、Logo、UI 布局、文案；参考只用于“流程/参数”层面的分析。
- 风格描述用**通用词**（国风水墨/萌系治愈/欧美卡通）；**不点名模仿在世艺术家**，不写“像某某画师”。
- 生成/参考素材必须是**原创、CC0、MIT 或已获授权**；在 `CREDITS.md`/manifest 记录来源、许可、访问日期。
- AI 输出要做**相似度/商标/角色**检查；模型可能复现训练数据中的角色/Logo；不能假设“AI 生成 = 无版权风险”。
- 字体：只使用 OFL/自有/已购字体；记录许可；不要用系统商业字体做分发素材。
- 平台规则：不要把换皮做成“马甲包/欺骗性克隆”；应用商店对重复内容、图标/名称混淆、虚假宣传有政策风险。

### 6.3 文字与数据

- **中文文字必须人工校对**：AI 修字可能造字、缺笔画、错别字；OCR 只能查“像不像”，不能替代人读。
- **能 live text 就 live text**：文字由引擎渲染，换皮只换字体/颜色；这样分辨率、 localization、无障碍都更好。
- **必须烘焙时**：4K + 逐条文字提示 + OCR + 人工逐字 + 字体许可，四件套。
- **云端工具**：上传 UI/角色前确认 NDA、数据留存、跨境、是否用于训练；保密项目优先本地/私有部署。

### 6.4 什么时候不该换皮

- 核心循环还没验证（留存/付费/时长不达标）：先修玩法，换皮只会放大问题。
- 没有原创资产能力/授权链：换皮会变成侵权。
- 团队没有 QA/本地化/字体能力：文字和 UI 事故会吃掉收益。
- 平台/发行商明确禁止重复内容：不要做“马甲包”。

## 附录 C：术语

| 术语 | 含义 |
| --- | --- |
| strength / denoise | 图生图重绘强度；越高越自由，越容易改布局 |
| ControlNet | 用线稿/分割/深度等条件锁结构的扩散模型附件 |
| IP-Adapter | 用参考图注入风格/内容的适配器 |
| Inpainting | 只在蒙版区域重绘 |

| pivot / 锚点 | 贴图旋转/缩放/对齐的参考点 |
| OCR | 光学字符识别，用于文字验收 |
| manifest | 资产/文本/零件的机器可读清单，用于同名替换与验收 |
| fail-closed | 任何一项验收不过就不放行 |
