问题结论
主流方案有哪些？4 族：约束求解（WFC/图语法）、空间划分（BSP/房间模板/黄金路径）、随机生长（CA/醉汉漫步）、场与采样（噪声/Voronoi/Poisson/L-System/Marching Squares/Cubes）。
哪些效果最好？2D：噪声生物群系 + TileSet Terrain 自动过渡 + 手工瓦片美术；3D：WFC 岛屿/城镇（Bad North/Townscaper 路线）或体素 + Marching Cubes/Transvoxel（godot_voxel）。
该复刻哪 2–3 个？A BSP + 自动过渡（先做）；B 噪声生物群系 + Poisson（第二做）；C CA+BSP+WFC（可选，不重写 WFC）。
最容易被高估？纯 WFC。局部邻接不等于全局连通/锁钥/可玩；大图回溯可能爆炸；Godot 插件多为 2D，3D 要自研。
最低成本“像商业游戏”？把钱花在瓦片接口 + 自动过渡 + 受限色板 + 装饰层；算法复杂度不是视觉上限，瓦片一致性才是。
本轮不要重复？不再做纯 WFC 演示（已有 godot-wfc/）；不再做 CA/BSP/醉汉漫步的纯算法拆解（已有 teardown + generators.py + HTML）；不做 3D 海岛（T-022 已立项）。
Godot 4.6 有新能力吗？4.6 是打磨/工作流版本，没有新的 WFC/地形生成 API。依赖 4.x 稳定栈：TileMapLayer（4.4+）、TileSet Terrains、FastNoiseLite、AStarGrid2D、NavigationRegion2D、MultiMesh、SurfaceTool/ArrayMesh、Geometry2D、WorkerThreadPool。4.6 增量是可旋转场景瓦片、GridMap Bresenham 画线等。
GL Compatibility 能做吗？2D 可以，且是低端机首选；核心 3D 可以。但不支持 MSAA 2D、2D HDR、Compute Shader、RenderingDevice、SDFGI、SSR、体积雾、CompositorEffects。因此不要走 GPU compute 体素路线。
三句话选型：要稳要快 → BSP/模板 + 自动过渡 + BFS；要视觉世界感 → 噪声多通道 + 岛屿遮罩 + Poisson + Voronoi + 河流；要约束美感/城镇细节 → WFC 只做细节层，全局结构/连通/锁钥先用 BSP/图语法定。执行顺序：A → B → C（可选）。
本报告边界：只调研与给 brief，不改游戏代码；不复制任何商业游戏画面/素材/关卡；无公开算法细节的案例一律标“推断”。原始 URL 访问日期 2026-11-21；T-040 于 2026-11-22 复核：3 个 demo 无 console error，案例表中未证实的细节已改为“未证实/推断”（见 §04 复核记录）。

L-System 河流/道路/植被公理+重写规则+角度/步长 → 折线/分支中–高；规则/角度/长度/扰动河流需入海；道路需 A*/图连接中；规则变则整体变低–中；O(步数×符号数)2D/3D原生无节点；Line2D/Curve2D/ArrayMesh 自写

3D Marching Cubes/体素3D 密度场 → 三角网格（+法线/UV）中–高；密度/阈值/LOD/材质体素连通需额外验证；洞穴可能断开中–难；改地形要重建 chunk高；GDScript 逐体素很慢；C++/GDExtension 才实用3D插件 godot_voxel（MIT，4.6 有 v1.6）；SurfaceTool/ArrayMesh 自写；Compatibility 无 compute
图语法/任务图房间/任务节点 + 重写规则 → 锁钥/循环/分支图很高；规则即设计意图由构造保证；可强制锁钥/环路/Boss 路径中；改图后重映射空间中；O(规则×图节点)2D/3D 抽象层原生无节点；自写；驱动 BSP/模板/场景拼接
房间模板/黄金路径模板库 + 路径/连接口约束 → 可玩关卡很高；模板/连接口/难度预算由路径先验保证；模板匹配门中；换模板/重排中；O(房间数×模板数)2D/3DTileMapLayer + 场景实例 + set_pattern；自写选择器

可控性 ↔ 惊喜

BSP/模板可控但容易“整齐”；CA/噪声惊喜但难保证可玩；WFC 在中间，但全局约束弱。

商业项目都是混合管线

Caves of Qud：分段 + WFC + A* + 后处理；Bad North：路径优先 + WFC 填岛；Townscaper：3D WFC + 二次 WFC。

连通性是后处理

除 BSP/图语法/模板外，CA、噪声、WFC、醉汉漫步都必须 BFS/并查集验证，失败时修复或确定性重开。

动态修改成本

CA/噪声/醉汉漫步最便宜；BSP/Voronoi/WFC 中等；Marching Cubes 最贵（chunk + 碰撞/导航同步）。

2.3 GL Compatibility 的限制与预算

支持

2D 渲染、核心 3D、TileMapLayer、MultiMesh、SurfaceTool/ArrayMesh、SSAO、SSAA、全屏 quad 后处理。

不支持

MSAA 2D、2D HDR Viewport、Compute Shader、RenderingDevice、SDFGI、SSR、SSIL、体积雾、CompositorEffects。所以 GPU Marching Cubes / GPU 噪声 / GPU WFC 不可用。

成本特征

低基础成本、高扩展成本；控制 draw call、材质切换、过度绘制。瓦片图集 + MultiMesh + 分块加载。

30 FPS 预算

33.3 ms/帧。生成放后台；交互步进单帧逻辑 ≤ 8–16 ms；TileMapLayer 批量写；不要每格一个 Node2D。

6.2 Brief A：BSP 地牢 + TileSet Terrain 自动过渡

Brief A · 64×48 可玩地牢 slice · 1–2 天
地图尺寸64×48 格（32 px/格，世界 2048×1536，相机滚动）；可选 80×60 压力档
瓦片/材质3 层：地板、墙体、装饰；TileSet Atlas 32×32；地板 6–8 变体、墙 3 变体、门 2 变体；原创程序化瓦片或 CC0（Kenney）并在 CREDITS.md 记录
自动过渡TileSet Terrain wall，模式 Match Corners and Sides；set_cells_terrain_connect 批量刷墙/地面过渡；地板/墙保留概率变体
算法BSP 递归切分（最小叶 10×8，最大深度 6，房间 5×4 起，内缩 1–2）→ 每叶放房间 → 房间中心“最近未连接房间”连 L 走廊（MST 近似）→ 可选 10–15% 环路 → BFS 验证 → 未达房间连最近可达点 → 死胡同剪枝 → 起点/终点取 BFS 最远点对
种子RandomNumberGenerator 固定 seed（如 hash("T-021-dungeon")）；独立流：split/room/corridor/decor/loot；记录 seed + size + signature
步进可视化阶段：split → rooms → corridors → connectivity → decor；暂停/单步/速度 1–20 阶段/秒；当前阶段高亮；完成后可切成品/调试
调试叠加BSP 切分线、叶节点矩形、房间 ID、走廊图、BFS 连通分量、未达房间红框、起点/终点、种子/签名、生成耗时 ms
验收100 seeds：房间可达 100%、房间不重叠、走廊不出界；同 seed 两次签名一致；64×48 生成 ≤ 50 ms（后台/加载）；步进播放 ≥ 30 FPS @1280×720；draw call ≤ 10；600 帧 headless 无 ERROR
版权不复制商业地牢布局/瓦片/UI；瓦片原创或 CC0；参考算法但不复制无权代码

6.3 Brief B：FastNoiseLite + Poisson + Voronoi 生物群系

Brief B · 96×64 世界地图 · 3–5 天
地图尺寸96×64 格（32 px，世界 3072×2048）或 128×96 压力档；TileMapLayer 分块 32×32 加载
瓦片/材质6 生物群系：深水、浅水、沙、草、森林、岩石/雪；每类 4–6 变体；水/岸/草/林/岩/雪自动过渡；原创调色板
场FastNoiseLite ×3：海拔（FBM/Simplex，0.012，octaves 4）、湿度（Simplex，0.02）、温度（Perlin，0.03）；岛屿遮罩 = 径向衰减 + 域扭曲；可选细节噪声
分类海拔阈值 → 水/岸/陆地；陆地按湿度分草/森林；高海拔/低温度 → 岩石/雪；所有阈值暴露为导出参数
河流从高海拔格沿最陡下降走到水/边界；合并相邻河流；限制 3–6 条；避免 1 格断头
植被/POIPoisson Disk（Bridson，r=2.5–4 格，k=30）撒树/石头/遗迹；POI 3–8 个；独立 RNG 流
区域（可选）Voronoi（Poisson 种子 + 最近点距离场）做王国/生态区边界；边界噪声扰动；Geometry2D 裁剪/合并

6.4 Brief C（可选）：CA 洞穴 + BSP 锚点 + WFC 细节层

Brief C · 80×60 混合关卡 · 复用 godot-wfc
地图80×60 格；BSP 房间作为“锚点/安全区”，房间之间用 CA 洞穴连接；边界墙
算法BSP 房间 → 房间外区域 CA（45% 墙、4-5 规则、5 次）→ BFS 验证 → L 走廊连接孤立房间/洞穴 → WFC 只在房间边缘/道路节点做局部填充（固定格/预条件）
复用godot-wfc/scripts/wfc_solver.gd、wfc_tileset.gd、tile_baker.gd；CA 参数来自 teardown；BSP 来自 generators.py
种子BSP/CA/WFC 三段独立 seed；WFC 重开预算 ≤ 48 次回溯；总生成预算 ≤ 100 ms（后台）
验收100 seeds：BSP 房间 100% 可达；CA 洞穴最大连通块 ≥ 95%；WFC 无未坍缩格/矛盾；同 seed 一致；30 FPS 播放；无不可达 POI
风险WFC 与 CA 边界/预条件最容易出矛盾；先固定房间边缘为 WFC 的 allowed set，再局部块；不要全图 WFC
版权复用自家 godot-wfc 代码；不引入 WFC 示例图片/商业瓦片

结论：C 视觉上限高，但工程/调试成本也最高；如果 T-021 只要求“一个能打的复刻”，A + B 足够，C 留作后续。
