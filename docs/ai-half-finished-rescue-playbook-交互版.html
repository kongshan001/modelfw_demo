AI 半成品游戏抢救
4 招拆成可执行 SOP

半成品不是“推倒重来”，而是先分清坏在哪一层 → 问清意图 → 冻结 taste/否决清单 → 只改这一层 → 让没参与的 AI 独立裁判 → 用证据决定继续/回滚。本页把视频的 4 个方法转成可粘贴进 worker prompt 的模板，并用仓库 Gridbound 的整改数据做 dry-run。

4 个方法 7 步 SOP 12 个症状 10 个诊断层 3 个模板 0 外部依赖

来源：B 站《AI给的半成品差点意思？4招妙手回春！》（UP TP制造好游戏，3:51，案例《烬谷盗火录》）。视频取证见 playbook §9；本页不复制该游戏任何画面/素材/UI。视频观点、仓库验证、本文推断逐条区分。

Rescue Loop
  1. 01分层诊断
    只选一层，先找证据
  2. 02先问清楚
    7 问 + 5 行复述
  3. 03冻结 taste
    3–5 条底线 + ≥3 条否决
  4. 04单层改动
    一个假设、一个指标、一个时间盒
  5. 05独立裁判
    盲评、证据优先、先问题后分
  6. 06证据决策
    继续 / 回滚 / 换层 / 停止
核心：一次只改一层。没有 before/after 证据，就不算“改好了”。

00

结论先行

一句话 + 10 分钟版

半成品最常见的死法不是缺功能，而是一次同时重做玩法、画面、剧情：无法判断哪一步有效，也丢掉了已验证的资产。

正确顺序：分层诊断 → 先问清 → 冻结 taste/否决 → 单层最小改动 → 独立裁判 → 证据决策。视频的 2D→2.5D 案例改的是表现层，不是规则层；“只改一层”是整套方法的地基。

01

四招拆解：视频说了什么，怎么落地

视频观点 / 仓库验证 / 本文推断

先把四个方法拆开。每个方法给：视频里的原意与案例、可直接执行的动作、以及边界（哪些是推断、哪些不能机械套用）。

01

先分清不满意的是哪块

视频 0:45–1:25

“玩法、画面、剧情，哪块不满意就只改哪块；第一步不是动手改。”

视频里的案例：接手时是一个 2D 半成品，判断玩法成熟 ✓、2D 表现 ✗——2D 美术占 80–90% 工作量、画风很难统一，于是换成更擅长的 2.5D。改的是表现层，不是规则层。

落地动作

  • 先写“本次只改哪一层”，再写“本次不改什么”。
  • 用一张“症状 → 层 → 动作”表把抱怨变成证据（本页 02 节可直接用）。
  • 只做一个单层假设；需要改第二层 → 拆 follow-up。

边界

  • 不要因为视频用 2.5D 就机械套用 2.5D；层由证据决定。
  • “全都不满意”通常不是四个问题，而是缺一条设计支柱。
  • 核心动词在目标玩家处不成立 → 这是产品问题，不是美术问题。
02

开工前，先让 AI 问清楚

视频 1:25–1:40

“答完问题再开工，别让它先交一大堆。”十问的第一题：“第一眼希望玩家有什么感觉？”作者的答案：“我希望是，可爱，但不安。”

感受先行，但感受必须继续拆成手段（轮廓/色板/音效/镜头/交互）与约束（2D、分辨率、工期、版权），否则“精致/高级”无法执行。还要问“不喜欢什么样的”“可以告诉它参考什么”。

落地动作

  • 用 7 问模板（04 节）：目标玩家、第一眼感受、核心动词、参考、非目标、验收、禁忌/预算。
  • worker 实现前先复述 5 行：理解 / 只改层 / 不改 / 验收 / 风险假设。
  • 异步任务不能问 → 写“假设 + 依据 + 置信度”；高风险 → needs_input。

边界

  • “可爱但不安”不是规格；要继续拆成具体关系（例如圆润轮廓 + 低饱和 + 不可预测的红色脉冲）。
  • 不要把感受问题变成“先做一版看看”，那会回到盲生成。
03

否掉的东西留下来，就是你的 taste

视频 1:40–2:15 / 3:10

“每次‘不成功’都有价值。”AI 提的方案是“3D 低模角色 + 墨线描边 + 骨骼动画”，他的做法是 2D + 序列帧；“完全不如 2D 加序列帧做出来的强”。

置顶评论里作者公开了完整 taste 文档。视频给的精简 5 条是：

  • 感受 → 手段 → 约束：先说清想让玩家感到什么。
  • “精致、高级”不是规格，要拆成具体关系。
  • 参考作品写清：取什么、为什么、什么不取。
  • 每个新内容：强化了哪条支柱？删掉会失去什么？
  • 评审先说看到了什么，再说哪个设计导致了问题。

落地动作

  • 用 05 节的编辑器，冻结 3–5 条不可妥协项 + ≥3 条已否决方案。
  • 每条否决带：日期、层、被否方案、原因/证据、保留/替代、重审条件。
  • append-only：不删旧条目；过期就标记，保留时间与原因。

边界

  • 不要复制作者的具体偏好；项目要求优先于通用 taste。
  • 只写“不喜欢”等于没写——没有证据，AI 下次还会提同样的方案。
  • 否决太多会变枷锁；每季度或大版本重审一次。
04

让 AI 互相挑刺，找中立裁判

视频 2:15–3:15

“AI 最大的问题：谄媚。”“它肯定会说，你说得对。”

视频流程：开发者 AI 先做完一小段 → 玩家 AI 去体验、写报告 → 第三个 AI 当裁判。案例：开发者 AI 认为“献祭让玩家变强也让敌人变强，有风险收益”；玩家 AI 反驳“我发现不献祭更容易通关，我就不献祭了”；改法是“献祭不删，改到让人想献祭——神谕改变打法，贪得越多，夺回的火越多”。

落地动作

  • 三角色：生产者（实现）/ 体验者（fresh context 或真人）/ 裁判（没参与制作）。
  • 裁判拿到匿名证据 + rubric + taste；先写 ≥3 个失败项，再打分。
  • 06 节的评分器可直接算加权分与 verdict；P0 不清不得放行。

边界

  • “好不好玩/手感”不要交给 AI 裁判；用 5–6 名目标玩家试玩（视频做法）或仓库真人 playtest。
  • 同模型裁判仍有共同盲区；能换模型就换，不能换就换角色/上下文 + 真人补位。
  • 裁判找不出任何问题 → 视为无效评审，不是“通过”。
说法视频观点仓库验证 / 本文推断
只改一层玩法/画面/剧情，哪块不满意只改哪块仓库验证：Gridbound 核心循环可玩，T-018 失败项集中在卡面/单位/UI 可读性；T-019 只改视觉/UI，规则未动，指标提升。推断：扩成 10 层诊断（性能/手感/反馈/UI/需求/支柱）。
先问后做十问；“可爱，但不安”推断：感受必须拆成手段与约束；落成 7 问 + 5 行复述 + 异步 needs_input。
否决 = taste3D 低模 + 描边 + 骨骼 vs 2D 序列帧；置顶 taste 文档本文强化：否决条目必须有原因/证据/替代/重审条件；append-only；模板化。
独立裁判开发者 AI / 玩家 AI / 第三个 AI；5–6 人试玩推断：程序独立 ≠ 认知独立；rubric、盲评、P0 先列、证据优先；AI 不判乐趣。
02

Triage 向导：症状 → 层 → 动作

选症状 · 确认层 · 复制 task JSON

不要从“我想改什么”开始，从玩家实际看到了什么开始。左侧选一个最接近的症状；右侧确认层、勾证据、拿动作清单。选错层会在面板里提示。所有内容与 docs/ai-half-finished-rescue-playbook.md §2 一致。

Step 1 · 选择最接近的症状
← 从左侧选择一个症状开始
例如“有操作，但没选择/无聊”“看不清/糊/不高级”
全部 12 个症状速查表（与 playbook §2 对应）
症状推荐层先补的证据只改该层不要动

视频只给了玩法/画面/剧情三层；性能/技术、手感/反馈、UI/信息是本文为仓库 demo 增加的诊断层——它们经常伪装成“画面不好”，但根因不同。

什么情况不要推倒重来

  • 核心动词已被至少 3 个目标玩家理解，并能重复玩 3 分钟。
  • 失败项集中在一层，且可用参数/局部替换/局部重画解决。
  • 现有资产、规则、剧情中至少有一项明确值得保留。
  • 你有 before/after 证据，能证明问题在收窄。
  • 问题是单点 bug，不是系统性设计缺失。

什么情况才考虑重做（优先只重做该层）

  • 目标玩家 3 分钟后说不出“我在玩什么/为什么继续”。
  • 核心动词缺失，或每次修改都在改规则而不是改表现。
  • 同一层做了 3 次单层迭代仍无改善。
  • 平台/性能/版权/工期是硬约束，当前方案不可解。
  • 目标玩家/品类已经改变——这时是新产品，不是抢救。

04

开工前反问：7 问 + 5 行复述

能问就问；不能问就标注假设

把下面内容贴给 worker，要求它先回答/复述，再动手。第一题不是风格，是“第一眼希望玩家有什么感觉”。

Q1

目标玩家与场景

  • 谁在玩？经验/动机是什么？
  • 什么设备、分辨率、输入方式？单次多久？
  • 成功后他会怎么向朋友描述？
Q2

第一眼感受

  • 希望第一眼感到什么？用 3 个场景说明。
  • 由哪些手段产生（轮廓/色板/构图/音效/镜头/交互）？
  • 什么会破坏它？
Q3

核心动词

  • 玩家重复做的一个动作是什么？
  • 失败/成长如何改变这个动作？
  • 3 分钟内有哪些有意义的选择？
Q4

参考作品

  • 1–3 个参考，每个写“取什么 / 为什么 / 不取什么”。
  • 具体到信息层级/节奏/轮廓/交互/氛围。
  • 不复制素材、角色、UI、Logo、品牌。
Q5

非目标

  • 这次明确不做什么（玩法/内容/平台/美术/音频/联机/商业化）？
  • 哪些是“以后可能”，哪些是“永远不做”？
Q6

验收口径

  • 目标尺寸 + 25% 缩略下哪些指标必须达标？
  • 阈值多少？怎么复现（分辨率/种子/相机/步骤）？
  • 什么算失败（P0）？失败回滚还是再试一次？
Q7

约束、禁忌与预算

  • 时间盒/预算/人力？最多几轮？
  • 性能目标、目标设备、包体/内存限制？
  • 版权/商标/肖像/声音授权？不可妥协项 3–5 条。

5 行复述（worker 实现前必须填写）

我理解你要的是：____
这次只改的层：____
我不改的：____
验收口径：____
主要风险/假设：____

异步任务的降级规则

情况动作禁止
能问一次问 1–3 个最关键的问题；答完再开工先交一大堆
不能问写“假设 + 依据 + 置信度”，只做低风险、可回滚的最小改动假装确定
高风险且无答案（改玩法/叙事方向、引入新资产/依赖、版权、不可逆数据）停，返回 needs_input，列 1–3 个问题硬做
预计超过约定时间 2 倍停，返回已完成部分 + 需要确认的点无限拖

Taste / 否决清单编辑器
否决比“喜欢”更能约束 AI

  
喜欢清单是抽象的、可被任何作品满足；否决清单带着方案、原因、证据、替代与重审条件，能直接阻止 AI 走回错误分支。本节编辑内容只保存在本机浏览器，不会上传。


  

    

      
维度喜欢清单否决清单

      
        
具体性“要精致/高级/有设计感”“不要 3D 低模 + 墨线描边 + 骨骼；目标尺寸下不如 2D 序列帧”

        
因果只给结果带原因和证据，AI 能推广到新方案

        
边界告诉 AI 往哪走告诉 AI 哪些 trade-off 不能做

        
可测试难验收新方案可逐条对照“是否踩了旧否决”

        
差异化容易变成通用参考你的取舍别人抄不走

        
成本一条抽象偏好要反复解释一行否决阻止一整条错误分支

06
独立裁判：rubric + 盲评 + 反谄媚
先问题、后分数；P0 不被平均分掩盖

  
三角色：生产者实现并提交证据，体验者只体验/写报告，裁判没参与制作、只判断不实现。裁判必须：先写看到了什么 → 再列 ≥3 个失败项 → 最后才按 rubric 打分。


  

    
裁判 prompt 的 6 条硬规则
    
      
  • 先描述实际看到/玩到什么（文件、时间码、截图区域、像素/数值）。
    • 
      
  • 再列失败项（P0/P1/P2），每项有证据、影响、最小修复方向。
    • 
      
  • 按 rubric 逐维打分；没证据写“证据不足”，不得猜。
    • 
      
  • 最后给 APPROVE / CONCERNS / REJECT，单列“未评估项”。
    • 
      
  • 禁止开场表扬、用“高级/不错”代替证据、用平均分掩盖 P0。
    • 
      
  • 禁止修改代码/资产；裁判只判断，不实现。
    • 
    

    
反谄媚 / 盲评
    
      
  • A/B 匿名标签、随机顺序、隐藏作者与提交时间。
    •

反例：10 个失败模式
照着做会浪费一轮预算

  

    
1. 一上来“推倒重来”
症状：觉得哪都不对，直接新建工程。
后果：丢掉已验证的核心/资产，无法归因。
正确：先分层；只重做失败层；保留可用资产。

    
2. 把“精致/高级”当规格
症状：brief 只有形容词。
后果：AI 加纹理/光效，越做越糊。
正确：拆成对比度、字号、层级、材质数量等可测关系。

    
3. 让实现 AI 自评
症状：“我觉得已经很好”。
后果：谄媚/盲区，P0 被放过。
正确：独立裁判 + rubric + 证据；实现者不签字。

    
4. 裁判只看总分
症状：平均 6.8 就放行。
后果：P0 被平均分掩盖。
正确：先列 P0/P1/P2；P0 未清不放行。

    
5. 没有 before 基线
症状：只发 after 截图。
后果：无法证明改好了，也无法回滚。
正确：第 0 步同机位、同尺寸、同种子。

    
6. 一次改多层
症状：玩法+画面+剧情一起动。
后果：不知道哪步有效，回归难定位。
正确：scope lock；一层一个假设；跨层拆 follow-up。

    
7. 否决只写“不喜欢”
症状：没有原因/证据。
后果：下一次 AI 还会提同样的方案。
正确：每条否决带原因、证据、替代、重审条件。

    
8. 用 AI 裁判判断“好不好玩”
症状：让模型给“乐趣分”。
后果：分数不可信，误导方向。
正确：AI 判可检查项；乐趣用真人试玩。

    
9. 机械套用参考
症状：视频说 2.5D，就所有项目都 2.5D。
后果：忽略本项目目标/约束。
正确：参考写“取什么/为什么/不取什么”；项目要求优先。

    
10. 指标平均化
症状：平均 FPS 60，但关键帧卡顿。
后果：掩盖最差体验。
正确：记录 p95/最差帧、关键事件停顿、25% 缩略可读性。
