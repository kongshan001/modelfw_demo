01

2D 等距：脚底锚点决定一切

godot-iso-slice

等距不是 3D：它是一张 2:1 菱形网格 + 每帧按 Y 排序 + 把碰撞和排序锚点都放在脚底。

TileSet

形状 + 排列

tile_shape=Isometric + tile_layout=DiamondDown；逻辑 128×64，图集单元 128×160；texture_origin=(0,48)。

漏一个就散架

Y-Sort

树结构 > 属性

玩家必须和墙层是兄弟；World 打开 y_sort，墙层 y_sort_origin=32。z_index 会压制 Y-Sort。

阴影别设 -1

移动

先除 2 再归一化

Vector2(x, y*0.5).normalized()*speed；8 扇区 (angle+22.5)/45 + posmod。

顺序反了斜向变慢

脚底

一个决定治三个病

图集脚底画在单元中心 → 精灵 (0,0) → 胶囊 y=-11；飘/穿墙/遮挡错乱同源。

先修锚点

烛光

2D 光照 + 遮挡

CanvasModulate + 6×PointLight2D（PCF5）+ TileSet occlusion layer + 火星粒子。

GL Compatibility 实测可用
踩坑与修复
  • 忘设 tile_shape/layout：菱形之间出现空洞。
  • texture_origin 符号相反：墙整体下移、角色悬空。
  • 等距“正后方”是 (-1,-1)，不是 -y；遮挡验收站位别用错。
  • 3D 灯光在 Intel + GL Compatibility 不工作 → Mod 场景统一 unshaded + 顶点色。
参数值
tile128×64；atlas cell 128×160；texture_origin (0,48)
玩家50 行；速度 190；胶囊 r9/h22 @ y=-11；8 扇区 +22.5°
场景14×14；196 地面 / 36 墙；6 盏灯；F1–F4 教学开关

02

规则 → 离线资产 → 运行时导入

rules.json / manifest / sha256

同一份 rules.json 由 Python 离线烘焙和 GDScript 运行时各执行一次；同 seed 逐字节一致，运行时产物写盘再导入，形成缓存闭环。

复制rules.json
   ├── tools/bake_pipeline.py
   │      └─ PNG + manifest.json（rules_version / seed / sha256_rgba）
   └── src/sigil_rules.gd
          └─ Image（同 seed 逐字节相同）→ user:// → Image.load_from_file

确定性

整数-only

32 位哈希 + 显式 & 0xFFFFFFFF；不用 float / 噪声库，跨语言不分叉。

证明

5 seeds 全同

Python 与 GDScript 哈希一致；界面显示 MATCH · 0 px diff，并做缓存回环。

色彩空间

导入 ≠ 原始像素

Godot 导入会做 sRGB/格式转换；逐像素证明必须读原始 PNG；显示可用导入纹理。

路线适合做法
A 构建期烘焙正式内容CI/headless → manifest → 运行时加载
B 运行时烘焙+缓存UGC / 无限变体设备端生成 → IndexedDB/OPFS 或 user://
C 运行时导入外部资产Mod / UGCmanifest + PNG/GLB/OGG，校验后热加载

详细：godot-iso-slice/docs/PIPELINE.md · 验收 PIPELINE_OK seeds=5

03

GLB Mod 运行时导入

manifest → 校验 → GLTFDocument

从 user://mods 扫描 manifest，先校验再实例化；坏资产只显示原因，不进场景。

复制res://mods → user://mods → scan manifest
  → sha256 → GLTFDocument.append_from_file → generate_scene
  → measure tris / meshes / bounds
  → validate bounds / footprint / pivot / max_tris
  → instantiate (unshaded + vertex colors)
校验目的
必填字段 + 文件存在id / file / sha256 / bounds / footprint / pivot / max_tris
sha256内容完整性（不是作者签名）
tris ≤ max_tris防超重资产拖垮帧率/内存
bounds/footprint ≤ 声明（±0.02）防尺寸/占位造假
|min.y| ≤ 0.02脚底/底座锚点，防飘/陷地
坑：bounds 必须合并所有 mesh；第一版只取最后一个 mesh，合法资产被自己的校验拒掉。sha 只能证明“文件没变”，不能证明“谁做的”。

详细：godot-iso-slice/docs/MODS.md · 验收 MOD_CHECK_OK

04

通透像素水体

godot-sea-water

关键不是“水 shader 很复杂”，而是分层：只有水底参与折射/焦散，岸上物体和角色画在水面之上。

复制Bottom（沙/石/珊瑚/海草）   ← 只有它“在水里”
Water（ColorRect + hint_screen_texture）
Props（岸、台阶、岩石、棕榈） ← 画在水面之上，不折射
Player（自带水线 shader）
层实现
1 mask640×360 池塘多边形；mask 外 discard
2 折射底屏幕纹理 + 像素级 UV（floor(uv*res)/res）
3 水色深度图混合浅/深 + alpha 0.30–0.66
4 泡沫深度 < 0.16 的岸线 + 可平铺噪声 + 涟漪
5 焦散64×64 Voronoi（9 站点）40px 平铺、滚动
额外8 槽事件涟漪、角色水线、0–24 昼夜/反光
踩坑与修复
  • fragment 里不能 return → if/else 单出口。
  • AtlasTexture 的 shader UV 是整张图集，不是单帧 0..1；水线要传帧 origin/size。
  • 改程序化 PNG 后必须 --editor --quit 重新导入。
  • 深度量化 16 级 → 竖直色带；焦散线粗/红边 → 满屏噪点；低频阈值 → 迷彩块。

详细：godot-sea-water/docs/TECH.md · 验收 SEA_SMOKE_OK

Three.js · 调研

1,423,569 B / 6,193 行；Three.js r180 + 游戏代码（约 47.7%）；零图片/模型/音频文件。

内容能否离线烘说明

关卡/标签/噪声 LUT/音频✅JSON/PNG/WAV/OGG

09

跨引擎可移植性

Godot · Unity · Unreal · Three.js

把“这套效果怎么做”从“Godot 里这段代码”里剥离出来。结论：数据与算法可移植，shader 和编辑器绑定要重写，验收协议完全可移植。

9.1 四层拆分：什么能带走

A 数据 / 协议

100% 带走

rules.json、manifest、深度图、图集布局、JSON 参数；源文件不进引擎格式，PNG/GLB/OGG/JSON 是唯一事实源。

B 算法 / 数学

高

等距变换、Y 排序规则、两骨 IK、平面反射矩阵、确定性哈希；按目标语言重写，测试用例跟着走。

C Shader / 粒子

中

水/雪/焦散、屏幕纹理、图集动画；数学照搬，语法与渲染管线按引擎重写。

D 编辑器 / 工具

低

TileSet 编辑器、导入管线、场景格式；不追求移植，按目标引擎重建。

本项目已做对：三个 Godot Demo 的美术全部由 tools/gen_art.py 程序化生成 PNG，等距资产用 bake_pipeline.py 烘 PNG + manifest——引擎场景只负责“组装”，不是事实源。换引擎时 A 层原样带走，B 层翻译，C 层重写，D 层重建。

9.2 移植契约（先定死，再动代码）

契约规定原因
2D 坐标Y 向下、原点左上；等距 2:1（128×64）2D 引擎一致；3D 是 Y 向上，转换只在一处做
单位1 tile = 128 逻辑像素；像素世界 640×360 @2×；3D 1 unit = 1 m避免尺寸靠猜
锚点角色原点=脚底；GLB pivot=脚底中心；图集脚底=单元中心碰撞/排序/阴影共用同一约定
深度0..1 连续（0 岸/浅 → 1 深），存 8 位 PNG；禁止 16 级量化色带/跳变问题与引擎无关
图集8×3=24 帧、行优先；帧局部 UV = (UV-origin)/sizeAtlas UV 是所有引擎的共同坑
时间全部按秒（dt）；涟漪/脚印 = 起始时间 + 生命周期帧率无关，可跨引擎复现
确定性整数-only 哈希（xorshift + 0xFFFFFFFF）；同 seed 逐字节一致Python/C#/GDScript/JS 都能复现
着色器UV 左上原点；sRGB/线性在导入层解决；内核只产 RGBA8避免同一贴图不同引擎不同色
资源描述manifest 只含通用字段：version/seed/sha256/bytes/bounds/footprint/pivot/max_tris任何引擎都能读
验收数据契约用无头测试；视觉用真实 GPU 截图与引擎无关的质量门

9.5 移植验收清单

① 数据契约无头测试 → ② 同 seed 黄金样张逐字节/逐像素一致 → ③ 同相机/分辨率/参数截图，结构不缺（mask/泡沫/水线/脚印）→ ④ 1280×720 集显 ≥30fps → ⑤ 输入映射与手感一致 → ⑥ 文档记录绑定层差异。

9.6 不要做的事

不要：把引擎场景/材质（.tres/.prefab/.uasset）当事实源；依赖 z_index/渲染顺序的偶然行为；用浮点噪声库做确定性内容；用软件 WebGL 验收 shader；把引擎私有 shader 写法当成方案本身。

9.7 代码落地：portable-core + 适配层

B 层不再只是文档约定：portable-core/ 用同一组算法三语言实现，golden 向量锁死；引擎侧只留薄适配层。

hash32(x,y,seed)整数-only uint32SigilRules.hash32 + bake_pipeline.py（两端 import core）
验证：bash portable-core/verify.sh → PORTABLE_PY_OK / PORTABLE_JS_OK / PORTABLE_GD_OK / PORTABLE_ALL_OK；godot-iso-slice/tools/verify.sh 追加 PORTABLE_SYNC_OK 与 PORTABLE_GD_OK。
精度边界：GDScript 核心返回 Array（float64），避免 Vector2（float32）破坏 golden 逐值一致；适配层再转 Vector2，手感不变。shader/粒子与 GLTF/导入仍留在 C/D 层，不进 core。

详细：portable-core/README.md · spec/functions.md
