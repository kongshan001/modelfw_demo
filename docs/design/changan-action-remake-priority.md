# 《灯下客：长安一夜》优先级补充 · P0 / P1 / P2

> 任务 T-20261121-024（Game Designer） · 2026-11-21 · 主规格：`docs/design/changan-action-remake-spec.md`
> 用途：把主规格 §6 的 P0 与附录 C 的“不做”展开成可排期的 P1/P2；本文件不改变主规格的范围与验收口径。

## 1. 排序原则

**玩家感知收益 × 实现成本 × 风险**；先让“能打”成立，再让“夜街”成立，最后让“故事”收口。P0 ≤3；P1 是“外放前的品质线”；P2 是“验证成功后的扩展”。**P0-1 不过，P1/P2 全部冻结。**

## 2. P0（本轮必须，≤3；详见主规格 §6）

| P0 | 做完玩家看到什么 | 成本/风险 | 完成线 |
| --- | --- | --- | --- |
| P0-1 拳脚落地 | 3 连/翻滚/击倒/起身；命中停顿/震屏/数字；打 2 泼皮有重量 | S–M / 低 | 3/3 打出 3 连；10/10 滚过同一招；3/3 说“有打中” |
| P0-2 夜街成立 | 10–15 分钟完整流程；夜街/3 灯/3 战/Boss | L / 高 | 3/3 通关；Intel avg ≥30；截图 5 层/3 地标 |
| P0-3 故事收口 | 对话/目标/结算/留手；能复述、愿再玩 | M / 中 | 3/3 一句话复述；2/3 记得选择；重玩可用 |

## 3. P1（外放前品质线；按顺序做）

| P1 | 做完玩家会看到什么变化 | 为什么是 P1 | 成本/风险 | 前置/完成线 |
| --- | --- | --- | --- | --- |
| **P1-1 声音层** | 挥空/轻中重命中/翻滚/点灯/环境 loop 让“打中”更实 | 无音效时打击感靠停顿/震屏/闪撑住；有音效才像外放 demo | S–M / 低 | P0-1 后；6 个 SFX + 1 loop；全 CC0/原创；3/3 说“更实” |
| **P1-2 手柄/可访问性** | 手柄图标、按键重映射、震屏开关、宽松模式 | 目标玩家有手柄；外放需要基本可访问性 | M / 低 | P0-2 后；手柄 1 人通关；无 <16px 字；对比 ≥4.5:1 |
| **P1-3 敌人变体** | 第 3 个杂兵变体或精英（换武器/节奏），战斗 2 不再只靠数值 | 增加决策空间，不增加新场景 | M / 中 | P0-2 后；不破坏 30fps；攻击令牌仍成立 |
| **P1-4 支路/线索完整** | 支路有完整小场景、阿禾有 idle 动作、闻九多 1 段对话 | 让“一条街”更像地方，不是走廊 | S / 低 | P0-3 后；不增加第 5 角色；不增加主线时长 >1 分钟 |
| **P1-5 结算分享卡** | 通关后生成 1080×1350 PNG（角色/用时/连击/点灯/选择） | 给 devlog/社媒一个可带走物；复用纸偶工坊导出经验 | M / 中 | P0-3 后；导出 ≤2s；50% 缩放可读；无 UI 遮挡 |

**P1 顺序**：P1-1 → P1-2 → P1-3 → P1-4 → P1-5。**只能做一项时，先 P1-1（声音对打击感收益最高、成本最低）。**

## 4. P2（验证成功后再做；本轮不做）

| P2 | 玩家会看到什么 | 为什么不是现在 | 触发条件 |
| --- | --- | --- | --- |
| 第二场景/第二 Boss | 更长的流程、更多长安地标 | 场景/资产/QA 翻倍；先证明一条街 | P0 全部 7.0+ 且外放反馈正向 |
| 第 5 个角色/更多群像 | 更热闹的灯市 | 群像稀释；资产/动画成本高 | 角色管线稳定、预算明确 |
| 招架/多架势/武器切换 | 更深战斗 | 与翻滚/3 连重复；教学/动画成本高 | P1-3 后仍有玩家要深度 |
| TTS/配音 | 角色有声音 | 声线/许可/演出成本；字幕已够 | 有预算与授权声线；预烘焙 |
| 本地化（英/日） | 海外可读 | 文本/UI/字体/QA 成本 | 外放数据支持海外需求 |
| 手机/触屏 | 手机可玩 | 性能/布局/输入重做 | 桌面版稳定 + 明确移动需求 |
| 在线/排行/分享社区 | 比较与传播 | 后端/审核/隐私；先做本地分享卡 | P1-5 验证分享需求 |
| 存档/章节/成长 | 更长留存 | 与 10–15 分钟 slice 定位冲突 | 决定做完整游戏时另立规格 |

## 5. 明确不做（本轮）

- 不做原作 5 角色（豆姐/梁子/老马/提伯/阿迪王）的名字/造型/剧情/素材；不做 PINOC/JST-2 splat、上传视频舞蹈、一天工期承诺。
- 不做开放世界、多章节、等级/装备/背包/抽卡/在线/多人/手机、招架/多架势/节奏谱面/护送/潜行。
- 不把“内部灰盒/占位模型”放进交付截图/GIF；不把“设计目标”写成“已实测”。

## 6. 变更规则

- 任何 P1/P2 进入本轮 P0，必须由策划改主规格 §6 并说明砍掉哪个 P0；不得“顺手加”。
- 任何新增角色/场景/敌型，先过资产许可门（主规格 §12.3）与性能预算（§12.1）。
- 任何“看起来更酷”的功能，先用 3 人测试验证玩家感知；无证据不加。
