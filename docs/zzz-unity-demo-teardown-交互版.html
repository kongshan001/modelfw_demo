结论先行

先看这 6 条，再看细节

这不是“一个角色打一个 Boss”的展示，而是一份可复用的动作游戏手感协议。它把 ZZZ 的观感拆成“输入窗口 + 帧数据 + 逐对象时间 + 相机构图”，再用现成美术资产把每一帧兑现。

核心 01

0.2s 双缓存

攻击与闪避各 0.2s；顿帧期间继续记账；连段是“命中结算完 + ChainTime”双条件，不是单纯动画时间。

核心 02

帧数据驱动

Attack01 第 12 帧命中；Boss Attack01 第 64 帧预检测、第 76 帧结算；5 段普攻每段都有自己的命中帧/顿帧/伤害。

B 仓库A 视频

核心 03

逐对象顿帧

玩家 3F / 敌人 5F，各用 unscaled 时间；Boss 攻击中受击只叠加 additive HitShake，不打断出招。

核心 04

起手胶囊完美闪避

闪避起手保存 CharacterController 胶囊；Boss 的预检测/命中窗与这个“起点”重叠且仍无敌，才触发 0.6s 局部减速。

Idle 4.0m / Moving 5.4m / Combat 8.2m；命中后维持 15s；Attack04/05 推近与 FOV/肩位变化；完美闪避 FOV +5、暗角 0.32。

B 仓库A 视频

核心 06

资产真相

角色/Boss/场景/UI/音频来自《绝区零》；渲染只是 URP Lit + 烘焙光 + 768px 平面反射 + Bloom/调色。观感主要来自原资产，不是神秘 Toon Shader。

A 视频B 仓库
一句话版本：ZZZ 的手感 = 把“什么时候能输入、什么时候能取消、什么时候冻结、镜头怎么构图”写成可配置的帧数据，再用动画、音频、VFX 把每一帧兑现。换成方块人，只要时间表对，动作也会“有味道”；时间表不对，搬来整套 ZZZ 资产也只会像滑冰。
先划边界：视频与仓库没有角色切换/tag、弹反/格挡、硬锁定、大招/能量、关卡节奏、菜单与联网。这些在本文中一律标注“扩展/未实现”，不把推测写成事实。

03

输入与移动：让动画决定位移

0:32–2:02 · 根运动 + 双缓存 + 5 段连击

核心链路：相机相对输入 → 状态机 → 动画根运动 → CharacterController.Move → 用真实位移反推速度。攻击时根运动只朝目标、只走到剩余距离，既保留重量又不穿模。

3.1 角色切换 / tag：没有实现，也没有展示

事实：视频全程只有 Lycaon 一名可操作角色；仓库 PlayerStateManager 的 17 个状态里没有 Switch/Tag/Assist，输入只有 Move / Look / Dash / Attack 四个 Action。结论：tag 是 ZZZ 的骨架，但不是这份 Demo 的内容。

如果要扩展，最小设计是“3 人队伍 + 切入登场动作 + 0.4s 支援窗口 + 8–12s 冷却 + 切换无敌 6–10F”。不要在 6 周 vertical slice 里同时做 tag 和多角色——先做单角色。

2:02–3:10 · 反馈是配置出来的

Attack01 在第 12 帧（约 0.20s）用 OverlapSphere 查询；Boss Attack01 在第 64 帧 预检测、第 76 帧 正式结算。命中后用 HashSet<Enemy> 去重，再按“玩家 3F / 敌人 5F”各自冻结。

命中查询

Attack01：OverlapSphere，本地中心 (0, 0.9, 1.2)，半径 0.65，只查 hurtboxLayers；终结技改用圆柱 r2.0/2.3。对每个 Collider 取父级 Enemy，用 HashSet 去重。

顿帧

不是 Time.timeScale=0，而是每个对象自己的协程：Time.unscaledTime 计时，冻结 Animator，等 reaction pose 可见后再冻结到结束。玩家顿帧中仍可写下一段缓存。

BA

FarbautiCombat.controller 有 Base Layer + HitShake Layer（Additive，权重 1）。攻击中受击只叠 Hit_Shake，Base Layer 继续出招。

05

闪避算法：全片最值得抄的工程

2:53–3:45 · 起手胶囊 + 局部减速

完美闪避判定的不是“你有没有在窗口内按闪避”，而是“你有没有在攻击原本要打中的位置闪开”：闪避起手保存 CharacterController.bounds，Boss 的预检测/命中窗与这个快照重叠，且玩家仍无敌，才成立。

没有弹反/格挡：这份 Demo 的防御主轴是闪避 + 完美闪避 + 闪避反击/突进；如果复刻时想加弹反，应另做“格挡窗口 + 反伤/削韧 + 失败惩罚”，不要和完美闪避混成一套判定。 A B
01 起手快照闪避进入时保存 controller.bounds；只在无敌期、未确认时可用。
02 预检测Boss Attack01 第 64F 起 0.2s，180°，r4.35，扫“起点胶囊”与当前玩家。
03 命中窗兜底第 76F 正式命中，180°，r4；若没有预检测，也用起点胶囊再判一次。
04 确认相交 + 仍无敌 → ConfirmPerfectDodge；记录时间，防止重复确认。
05 局部减速敌人 0.6s 曲线 1→0.668→0.446→0.515→1；只影响敌人 Animator + 移动。
06 反击 / 突进闪避中按攻击：有完美目标 → DodgeCounter；否则 DodgeRush；恢复后按 → 普通攻击。
状态无敌帧恢复窗口备注

为什么聪明：起点胶囊是不可变快照；判定可复现，不会因为玩家跑到安全区就白给，也不会因为边缘乱按就误判。预检测窗更宽（r4.35）、命中窗更严（r4），既宽容又公平。
早闪会吃伤害：无敌帧结束后 Boss 才命中 → 玩家 100→85（15 伤害）。完美闪避与无敌帧同帧触发，但“提前按”不等于“完美”。

动画：玩家很朴素，Boss 有一层 additive

Animator 层 / 根运动 / 资产体量

玩家 Animator

只有 1 个 Base Layer；没有 Blend Tree、没有 Layered Mask、没有 additive。参数只有 State / Last State / Lateral Speed。动画选择由 C# 状态机驱动，Animator 只负责播放与混合。

B

Boss Animator

2 层：Base Layer + HitShake Layer（Additive，权重 1，Empty / Hit_Shake）。攻击中受击只叠抖动，不打断出招。

B

Root Motion

OnAnimatorMove → ApplyRootMotion → CharacterController.Move；攻击时根运动夹紧到目标方向与剩余距离；只有 TurnBack 开 useRootRotation。

B

Cinemachine / Timeline

相机用 Cinemachine 3rdPersonFollow + Composer + 自定义 Shake Extension。未发现 Timeline/Playable 资产；角色切换表现不存在。

BC

7.1 过渡与帧率

默认 CrossFadeInFixedTime(0.1s)；闪避 0.05s；从 DashIdle/HitFly 进 WalkStart 0.2s；受击 0.05s（Hurt 后）/0.08s（其它）。所有帧数据按 60fps 常量换算（k_Frame = 1/60）。

复刻清单：12 条可复用模式
  1. 0.2s 双缓存：攻击/闪避都记录“时间 + 方向”，跨顿帧存活。
  2. 帧数据表：每段攻击配 命中帧 / 顿帧 / 伤害 / 形状 / 震屏 / 音效 cue。
  3. 双条件连段：命中结算完 + 动画到 ChainTime，才消费缓存。
  4. 逐对象顿帧：unscaled 计时；攻击者短、受击者长；各自恢复。
  5. Additive 受击层：Boss 攻击中受击只叠加抖动，不打断出招。
  6. 起手胶囊完美闪避：快照闪避起点，预检测/命中窗双重判定。
  7. 局部减速曲线：只慢敌人，不慢全局；有呼吸感的 0.6s 曲线。
  8. 攻击贴近夹紧：根运动只朝目标、只走到剩余距离，防穿模。
  9. 战斗构图相机：Idle/Moving/Combat 三档距离 + 命中后保持 + 攻击推近。
  10. 世界血条挂点：WorldToScreen + 出画隐藏 + 目标线 + 距离缩放。
