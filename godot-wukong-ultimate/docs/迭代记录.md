# 迭代记录 — 齐天大圣 · 极意

> 目标不是复刻首版 chibi，而是做“可以外放给玩家体验”的英雄比例版本。
> 记录只写实际做过的改动与实测结果，失败/返工也保留。

## 0. 起点与对比基线

- 首版：`blender-wukong/`，金色 chibi、程序化球/柱拼装、24 根变形骨、单一蓄力/放波 8 s 动画。
- 本版：新目录 `blender-wukong-ultimate/` + `godot-wukong-ultimate/`；独立原创设计，首版仅作为 before/after 对比素材复制到新工程。
- 设计选择：银白尖发、赤膊肌肉躯干、破损橙裤、蓝腰带/护腕/靴、猴脸/尾巴/金箍棒；避免《龙珠》悟空的脸型/发型轮廓/服装标志。

## 1. Blender：从拼装到单一蒙皮

| 轮次 | 问题 | 处理 | 结果 |
| --- | --- | --- | --- |
| 1 | 原始 chibi 的图元接缝 | 肌肉体块 union → Voxel Remesh → Smooth → Decimate，目标 23.5k tris 身体 | 单一连续皮肤；总 56,072 tris |
| 2 | 所有贴图渲染成黑 | Blender 3.4.1 中先设 `colorspace` 再赋 `pixels` 会清空图像缓存 | 先写 pixels 再保存 PNG + pack；5 张程序化贴图正常 |
| 3 | 头发像海胆、裤子像裙子 | 发片改宽/更少/后掠；裤子半径调整；发现裤腿其实被皮肤包住 | 裤子拉宽；但出现下一项 |
| 4 | **蒙皮权重错位**：裤腿缩在大腿根 | 原始基元带对象位置，join 后身体局部坐标 z 偏移 1.36 m，权重按错误世界坐标计算 | 所有基元 apply location；weight 使用 `matrix_world`；身体权重正确 |
| 5 | 胸口中缝黑洞、腹部像球 | 增加胸骨填充球；缩小腹肌块；Smooth iterations 2→3；去掉蓝脸彩绘 | 躯干更干净；保留肌肉起伏 |
| 6 | 蓄力姿势像“龟派气功”起手且手在右胯 | 改成双手在胸前聚气（原创姿势），胜利姿势改成举拳 | 更符合原创方向 |
| 7 | GLB clip 有 1 帧偏移（Idle 2.042 s） | bake 后把所有 fcurve 关键帧整体 −1 帧，NLA strip 从 0 开始 | 6 段时长精确到 2.0/0.667/1.333/1.208/0.542/2.0 s |

最终资产：

- `wukong_ultimate.blend`：41 骨（含 12 根非变形 IK/控制骨，可继续编辑）；显式蒙皮 + Armature。
- `wukong_ultimate.glb`：29 关节、1 蒙皮网格、15 材质分区、5 贴图、6 动画、56,072 tris、3.17 MB。
- 1080p 定帧 3 张：`poster_front.png` / `poster_charge.png` / `poster_cast.png`（Blender 3.4.1 EEVEE，40 samples）。
- 首版对比图：`before_after.png`（首版海报 vs 极意蓄力定帧）。

## 3. 帧率：23.8 → 39–43 fps（Intel HD 6000）

第一次真实窗口压测：

```text
WUKONG_ULT_FPS avg=23.8 min=4.0 samples=24   FAIL
```

诊断：8 盏光源、方向光实时阴影、环境 glow、1280×720 全分辨率。
优化：

- 关闭方向光阴影 → 玩家/石傀 blob 阴影；
- 光源减为：月光 + 暖色方向光 + 2 Omni + 相机 Spot（5 盏常驻）；
- 关闭 glow；`scaling_3d/scale=0.9`；
- 暖色方向补光 + 曝光 1.6 补回可读性；
- 入场预热（小闪光 + 瞬发蓄力 + 空放气功弹）编译 shader。

中间结果：

```text
avg=39.7 min=8.0   （仍有一次首击卡顿）
avg=45.3 min=21.0  （预热后）
avg=43.3 min=22.0  （补光/预热后）
avg=40.8 min=21.0  （加长光束尾）
avg=39.2 min=11.0  （最终压力采样，采用值；多轮 39–43）
```

结论：**最终平均 39.2 fps > 30**（多轮 39–43）；`min` 11–22 是压力循环中命中爆发的短时低值。若要求所有 0.5 s 窗口 ≥30，需要进一步做 VFX 对象池 / 降低 VFX 数量。

## 4. 录屏：从“跑过头”到正确 8 秒

第一版 GIF 采集按帧号触发事件，但实际渲染 ~10 fps，游戏时间跑得比采集时间快：角色跑出机位，蓄力镜头是空场地。

修正：

- 事件仍按帧号编排，但用 `Engine.time_scale` 动态适配：每帧测量 `scene._t`，把下一帧游戏时间收敛到 1/20 s；
- 采集 timer 使用 `ignore_time_scale=true`，避免计时器本身被一起减速；
- 结果：8 s / 160 帧，intro → run → charge → impact → victory 顺序正确，成品 `docs/wukong_ultimate.gif` / `.mp4`。
