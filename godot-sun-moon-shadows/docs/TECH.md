## 1. 目标与取舍

要在 Godot 4.6 / GL Compatibility / 2D 里复刻视频的四项技术点：

1. 不用额外灯光、不用逐物体 Light2D / Godot 2D 阴影组件，日月共用一条主光通道；
2. 约 40 行等价顶点坍缩，所有地面影合成单一绘制，重叠不叠黑；
3. 单通道高度图做 2.5D 偏移与接收面遮挡；
4. 60% 软膝限长曲线，低角度平滑逼近 3H，不拉穿屏；
5. 夜景冷蓝月影与暖黄路灯共存。

取舍：

- **主光**不是 `Light2D`。视频的 TerrainSunlight / TerrainMoonlight 也只产生
  “方向 / 光色 / 环境扣除量”三组数据，再由所有 shader 读取。我们把这组数据
  做成 3 个工程级 shader 全局向量，实体、地面、天空、影子共用。
- **影子**不是逐物体 Sprite2D 半透明贴片。CPU 端把 12 个投影体的高度层投影成凸包，
  再做多边形并集，合成一个 `MeshInstance2D`（1 个 surface、1 个共享材质、1 次 draw）。
- **高度图**用 `Image.FORMAT_R8`。GLES3/GL Compatibility 对 R16F 的采样/写入支持
  不稳定（部分机器回退或报错），R8 是单通道、256 级、跨设备一致的等价方案；
  本工程在 `World.get_height_info()` 与文档中明确记录这一点。
- **软膝**采用视频的膝点/封顶数值（60% × 3H），曲线形状用 C1 指数饱和，
  避免视频二次式 `u(2-u)` 在膝点斜率翻倍造成的折角（见 §5）。
- **阴影颜色**是 alpha 混合的环境扣除层，不是乘法层；并集保证一个像素只覆盖一次。
  我们额外提供“开影/关影”反解 alpha 的像素探针，直接证明一层覆盖。

## 2. 场景与渲染骨架

- `scenes/main.tscn`
  - `WorldViewport`：`SubViewport` 640×360，`snap_2d_*_to_pixel = true`。
  - `World`：所有 2D 世界节点。
  - `WorldDisplay`：`TextureRect`，最近邻，按整数倍铺满窗口。
  - `HUD`：`CanvasLayer`，设计分辨率 640×360，整体按同一整数倍放大；
    中文像素字体 10px / 12px（Fusion Pixel，OFL）。
- `main.gd::_apply_scale()`：`scale = floor(min(window/640, window/360))`，
  内容和 HUD 都以这个整数缩放并居中/黑边。1280×720 → 2×，1920×1080 → 3×。
  因此世界、HUD、字形都没有非整数缩放；项目全局纹理过滤为 Nearest。
- 固定机位 3/4 俯视。地面是一张 640×272 的程序化像素图（世界 y=88 起）；
  所有房屋/树/石柱/路灯/木桶/角色/前景草都是程序化 RGBA 图。
- 所有实体共用 `lit_sprite.gdshader`；地面 `ground_lit.gdshader`；天空
  `sky.gdshader`；影子 `shadow_union.gdshader`；路灯/窗光/萤火用加法
  `lamp_glow.gdshader`（局部光源，不属于日月主光通道）。

## 3. 日月模型与接力

### 3.1 从视频帧反推太阳参数

从视频帧读取到的标签：

| 视频时间 | 标签 | 高度角 |
| --- | --- | --- |
| 10:46 | 太阳主光 | 66° |
| 12:00 | 太阳主光 | 68° |
| 15:20 | 太阳主光 | 51° |
| 16:32 | 太阳主光 | 37° |
| 17:18 | 太阳主光 | 26° |
| 18:20 | 太阳主光 | 10° |
| 18:40 | 太阳主光 | 5° |

共用 `elev = 68°·cos(|h-12|/7 · π/2)` 时：

| 时间 | 模型 | 视频 |
| --- | --- | --- |
| 10:46 | 65.4° | 66° |
| 12:00 | 68.0° | 68° |
| 15:20 | 49.8° | 51° |
| 16:32 | 35.8° | 37° |
| 17:18 | 25.4° | 26° |
| 18:20 | 10.2° | 10° |
| 18:40 | 5.1° | 5° |

因此本工程采用：**05:00 日出、19:00 日落、12:00 最高 68°、半日弧 7h**。
`sun_arc(h) = (h-12)/7`，`sun_elev = 68·cos(sun_arc·π/2)`。

月亮：视频标签 19:12 ≈3°、22:00 ≈41–47°、00:30 52°、6:30 左右落下。
本工程采用 **18:30 升、06:30 落、00:30 最高 52°**：
`moon_progress=(h-18.5)/12`，`moon_arc=2p-1`，`moon_elev=52·cos(moon_arc·π/2)`。
22:00 = 41.3°，00:30 = 52°，与视频的最大值一致；19:12≈9.6° 比视频标签略高
（视频帧自身 22:00/22:09/22:23 标签在 41–47° 间不一致，且 21:00 截图需要更亮的月影）。

方位角在本工程中显示为“从东起算”：`az = 90° + arc·90°`，日出/月出 0°（东）、
正午/午夜 90°（南）、日落/月落 180°（西）。天空 x = 320 + 180·arc，
y = 92 − 弧高·elev/max；两者使用同一南天 x 扫掠，从屏幕左（东）到右（西）。

### 3.2 影向

屏幕 3/4 俯视，地面 y 方向压缩：

```
shadow_dir = normalize(vec2(-arc, 0.55))
light_dir  = -shadow_dir
```

- 早晨 arc<0：影向 +x（右）/ +y（下）；
- 正午 arc=0：影向 (0,1)（下）；
- 黄昏 arc>0：影向 −x（左）/ +y（下）。

### 3.3 主光接力与淡入

- 主光选择：太阳强度 > 0 时太阳，否则月亮。太阳强度用
  `smoothstep(0, 10°, elev)`，所以日落瞬间降为 0；月亮同理。
- **黄昏**：19:00 切到月亮，但 `moon_handoff = smoothstep(19:00, 20:00, h)`，
  19:00 强度/影 alpha = 0，20:00 满。
- **黎明**：05:00 前仍可能显示月亮；04:30–05:00 先把月亮淡出
  （`1-smoothstep(4.5,5.0,h)`）；05:00 切到太阳，`sun_handoff =
  smoothstep(5:00,6:00,h)`。
- 因此两个交班点附近，主光方向即使翻转，可见影 alpha 也接近 0，没有“整屏影子
  瞬移”的跳变。`LightModel.state()` 的 `handoff / moon_fade_out / strength /
  intensity / shadow_alpha` 都对测试开放。

### 3.4 色温

- 太阳色温关键帧：05:00 暖橙红 → 06:30 金 → 12:00 中性暖白 → 17:30 橙色 →
  19:00 深橙红；环境色与阴影色同步插值，阴影 alpha 约 0.42–0.46。
- 月亮颜色取自视频代码帧的 `Color(.62f,.75f,1f)`：`(0.62,0.75,1.00)`；强度上限 0.55
  （视频 `.55f * strength`），月影环境扣除 alpha 0.46（≤0.5，视频“只扣一半环境光”）。

## 4. 3 个全局 Shader 向量

`project.godot` 注册、`main.gd::_apply_light()` 每帧写入：

| 名称 | 类型 | 语义（本工程） |
| --- | --- | --- |
| `u_light_dir` | vec4 | `(光向.x, 光向.y, 高度/90, 夜权重)` |
| `u_light_color` | vec4 | `(主光 RGB, 强度)` |
| `u_ambient_sub` | vec4 | `(环境扣除/阴影 RGB, 扣除强度)` |

- 光向 = 从物体指向当前主光源的屏幕平面单位向量；影子方向取反。
- 夜权重 0..1：`1-smoothstep(-10°,10°,sun_elev)`，用于天空、实体、灯光氛围。
- 3 个全局量通过 `RenderingServer.global_shader_parameter_set()` 写入；没有逐物体
  light uniform，`get_shader_parameter("u_light_*")` 在所有材质上都是 null。
- `lit_sprite` / `ground_lit` / `sky` 都声明并使用这三个 `global uniform`；
  `shadow_union` 使用 `u_ambient_sub`（环境扣除量）做阴影 alpha/颜色。
- 路灯、窗光、角色小灯、太阳/月亮光晕是局部加法光源（`lamp_glow`），位置/颜色
  属于局部光照，不混入日月主光通道。
- 视频的“所有 Shader 读取的永远是同一组 3 个全局向量”在代码层的验证点：
  `tools/smoke_sun_moon_shadows.gd` 检查项目注册、shader 声明、材质无本地 light
  参数、实体共享材质、6 个时钟点全局值随主光切换。

## 5. 顶点坍缩与零叠黑

### 5.1 每帧投影

`scripts/shadow_builder.gd::update()`（核心约 40 行）：

1. 对每个投影体读取贴地足迹 + 高度层 `bands[]`（树干、树冠 62/104/138px、屋檐、
   灯罩等）。物体的视觉高度 H、影长 L 来自高度角：
   `L = soft_knee(H / tan(elev))`。
2. 第 i 层高度 h_i 的顶点沿影向平移 `L · h_i/H`；越高偏移越大。
3. 足迹（h=0）+ 所有平移后的高度层求 `Geometry2D.convex_hull`。
   效果等价于视频的“背光边坍缩为零面积，迎光边锚在接触点”：
   凸包前沿仍在物体脚下，后沿沿光向拉长。
4. 每个投影体得到一个凸包；所有凸包进入并集合并。

### 5.2 并集，不是叠贴片

`ShadowBuilder._merge_items()`：

- 两两检查是否有面积交叠；有则 `Geometry2D.merge_polygons` 合并，高度取 max；
  重复直到所有块互不相交。结果是一组不相交的多边形。
- 每个多边形用 `Geometry2D.triangulate_polygon` 三角化，写入同一个 `ArrayMesh`；
  `MeshInstance2D` 只有一个 surface、一个共享 shadow 材质、`z_index=30`。
- 每个三角形顶点色 = `caster_height / 160`，shader 用顶点色的 R 做 2.5D 高度判断。
- **零叠黑**的几何保证：并集块互不相交；一个屏幕像素最多落在一块并集多边形里。
  因此即使两棵树的原始投影重叠，最终也只有一次 `u_ambient_sub.a` 的 alpha 混合。

### 5.3 实测（08:00，oak+pine）

- 原始 12 个凸包 → 6 个并集块；顶点 327；原始面积 38614 px² → 并集 35982 px²。
- 18:20：7 块，原始 82317 → 并集 76867 px²。
- 21:00：5 块。
- 并集多边形两两 `intersect_polygons` 面积均 <0.25 px²（smoke）。
- 重叠点/单影点 coverage 都是 1（smoke）。
- GPU 探针在 08:00 渲染“开影/关影”两张图，用
  `result = bg·(1-a) + shadow_color·a` 反解每个通道的 alpha：
  - 单影点 (459.5, 306.5)：a = **0.443**
  - 重叠点 (505.7, 307.9)：a = **0.431**
  - 同一时刻配置 alpha = **0.444**
  重叠点没有出现 2×0.444，差异来自 9 点采样与线性高度图的边缘软过渡。
- 单/重影亮度差分别为 0.107 / 0.088（不同草色背景），alpha 反解一致才是关键。

### 5.4 为什么不用 Light2D / Godot 2D 阴影

- 视频的核心是“主光数据驱动一切”，而 Light2D 需要为太阳/月亮各放一盏灯，
  逐物体/逐灯配置能量、范围、遮罩；夜间还要处理路灯与月光的叠加。
- Godot 2D 内置阴影由 LightOccluder2D 生成，多个灯/多个阴影贴片叠加时容易出现
  重复 alpha；也不方便把“高度层偏移”写进投影几何。
- 自建网格可以把“顶点坍缩 + 并集 + 高度色 + 单次绘制”全部掌控，并且能在 headless
  里用纯几何测试验证零重叠；本工程 smoke 检查场景里 `Light2D` / `LightOccluder2D`
  节点数量为 0，只有 1 个 `MeshInstance2D`。

## 6. 单通道 R8 高度图与 2.5D 遮挡

### 6.1 生成

`world.gd::_build_heightmap()`：

- `Image.create(640, 360, false, Image.FORMAT_R8)`，初始 0。
- 把所有带高度的像素图按 z_index 从后往前盖章；每个不透明像素（alpha≥0.35）
  写入 `(base_y - pixel_y) / 160`。前面的物体会覆盖后面的高度，所以看到的是
  “当前可见表面的高度”。
- 覆盖房屋、橡树、松树、石柱、断柱、路灯、木桶、灌木、角色、前景草；
  地面是 0。
- 归一化上限 160px，对应实际高度：房屋 150、橡树 140、松树 124、路灯 104、
  角色 38、木桶 32、前景草最高约 62。
- 生成后 `ImageTexture` 交给 `shadow_union` 的 `height_map` uniform；
  `filter_linear`（等价视频的 4 点双线性柔边）。GLES3 无稳定 R16F，
  故使用 R8；UI 调试面板和 `get_height_info()` 都显示 `R8 640×360 · 160px`。

### 6.2 采样与遮挡

`shadow_union.gdshader`：

```glsl
float receiver_h = texture(height_map, SCREEN_UV).r;
float caster_h   = COLOR.r; // 并集多边形顶点色 = 投影体高度/160
float pass_mask  = smoothstep(receiver_h + bias - softness,
                              receiver_h + bias + softness, caster_h);
if (pass_mask <= 0.001) discard;
COLOR = vec4(u_ambient_sub.rgb, u_ambient_sub.a * pass_mask);
```

- 接收面低（地面/低矮墙体）→ caster 高 → 落影；
- 接收面高（屋顶/高楼）→ caster 更低 → 截断；
- 房子屋顶采样 112px、墙体 32px、木桶 32px：
  “桶影 32 vs 屋顶 112 → 截断”，“树影 140 vs 地面 0 → 落影”。
- 前景草在 z=25 接收影子（比阴影 z=30 低），另外底部 30px 的草缘再画一遍
  `ForegroundFringe`（z=58）盖在影子之上，作为“前景高草遮挡其后影子”的可见证据；
  高度图里高草 >34px 也会让低矮木桶影在草叶上被截断。
- 调试视图：
  - `G` 高度图（R8 热力 RGBA 叠加，蓝→青→黄→红）；
  - `O` 遮挡热力（影子网格按 caster 高度着色，仍执行接收面测试）；
  - `B` 网格线框（并集轮廓 + 投影方向 + 尖端标记）；
  - `V` 重叠采样（单影/重影十字，HUD 显示 coverage）。

### 6.3 已知限制

并集块的高度色取参与合并物体的 max；同一块里若同时有高树和矮桶的影，整块按
高树高度处理。本场景的矮物影在并集后仍位于地面/草地，不影响可见结果；
更严格的逐像素 caster 高度 buffer 会需要额外的 shadow-height 通道，属于后续工作。

## 7. 60% 软膝限长

### 7.1 视频参数

视频代码帧：

```text
len  = height / tan(clamp(elev, 1°, 89.5°))
knee = cap * .60      // cap = 3 × 物体高度
if (len > knee) len = knee + span * u * (2 - u)
```

我们采用同样的 `cap=3H`、`knee=0.6×cap=1.8H`，但把二次式换成 C1 饱和：

```
raw   = H / tan(clamp(elev, 1°, 89.5°))
cap   = 3H
knee  = 0.6·cap = 1.8H
span  = cap - knee
if raw <= knee:
    L = raw
else:
    t = (raw - knee) / span
    L = knee + span · (1 - exp(-t))
```

- raw=knee 时 L=knee，斜率 1；
- raw→∞ 时 L→cap=3H，渐近而不硬切；
- 指数式的二阶导连续，避免二次式在膝点斜率从 1 跳到 2 的折角；
- 视频的“60% 起弯、封顶 3 倍”视觉行为保留；
- 软膝关闭时用 `min(raw, cap)` 硬截，曲线图用红色虚线做对比。

数值（H=100）：knee=180，raw=600 时 soft=296.4（hard=300），raw=2000 时 soft≈299.9。
场景 18:20：橡树软膝 412.7，硬截 420，raw 779.2。smoke 还检查了膝点左右连续
（值差 <1px）与膝点斜率 ~1。

UI 的曲线图横轴 0–45°、纵轴 0–3.15H，画软/硬两条曲线、1.8H 膝线、3H 上限、
当前主光高度角标记；B 键/调试按钮开关实时对比。

## 8. 夜景：冷蓝月影 + 暖黄路灯

### 8.1 参数

- 21:00：月亮主光，高度 31.66°，方位 38.3°；`u_light_color = (0.62,0.75,1)·0.55`；
  `u_ambient_sub = (0.05,0.10,0.28)·0.46`。
- 月影颜色冷（B>R），环境扣除 alpha 0.46（≤0.5，“只扣一半环境光”）。
- 两盏路灯 + 两扇窗 + 角色小灯 + 10 只萤火，均为阴影之后的加法层：
  - 阴影 `z=30`；
  - 地面灯池/窗光 `z=44`；灯罩光晕 `z=45`；角色灯 `z=46`；
  - 萤火 `z=55`；前景草缘遮挡条 `z=58`。
  因此路灯不会把月影 tint 成蓝色（加法层的色相独立），月影也不会把灯光染冷
  （阴影在灯之前绘制）。
- 灯池颜色：地面池 `(1.0,0.67,0.28)`、光晕 `(1.0,0.80,0.42)`、窗光 `(1.0,0.75,0.38)`。
  夜里灯池强度随 `night` 提升；白天自动关闭；`L` 键/路灯按钮可手动关闭。

### 8.2 像素探针

- 公开月影点 (388,332)：开影 `#102427`，关影 `#a6ab86`，亮度差 0.532，B>R。
- 右灯暖色点 (559,299)：开影 `#ffc165`，R>B。
- **灯池内月影仍可见**：(545,304) 开影 `#e0aa6f` / 关影 `#ffc469`，亮度差 0.097；
  叠加暖灯后仍然是暖色，同时能看出月影的暗带。
- 关灯后灯池点亮度明显下降（smoke + probe）。

这一组数值对应视频帧“只扣一半环境光 · 保留暖黄路灯”的意图：
月光作为主光的强度/扣除量较小，路灯作为局部加法层保留自己的暖色。

## 11. 已知风险 / 未覆盖

1. R8 高度图是 256 级、单值；不是 RHalf 的连续高度。工程按视频“单通道高度图”的
   等价实现处理，并在 UI/文档明确标为 GL Compatibility fallback。
2. 并集块的高度取 max，细粒度的“同一块内不同 caster 高度”不可区分；场景布局
   避开了可见冲突。
3. 阴影是 alpha 混合层；若未来改成乘法环境光扣除，需要重做 GPU alpha 反解探针。
4. 日月不能同时作为主光；交班时刻主光方向翻转，我们通过两端强度淡出到 0 避免跳变，
   但太阳/月亮在天上仍同时可见（这是有意的天象）。
5. 顶部两块 HUD 只覆盖天空，但高角度太阳/月亮在 UI 模式下会被面板部分遮住；
   按 H 隐藏 UI 可看完整天空。21:00 月亮位于左面板右侧，仍可见。
6. 没有移动相机、没有 3D 高度真遮挡；2.5D 遮挡是基于屏幕高度图的近似。
7. 视频的月亮 19:12 标签高度为 3°，本工程模型约 9.6°（为了 21:00 月影亮度与
   00:30 52° 的取舍），文本中已记录。
