## 2026-11-25 · T-20261125-003 续跑

### 1. 先救编译，不重写

在 Godot 4.6 中，`Variant` 推断警告被当作错误。逐处补显式类型，未改动玩法：

- `game_data.gd distance_to_path()`：`PATH_POINTS` 是无类型 `Array`，元素为 Variant；补 `Vector2` / `float` 显式类型（第 348–351 行）。
- `hud.gd`：`main.*` / `state.*` 是动态访问，`:=` 推断出 Variant；为 15 处局部变量补 `int/float/bool/String/Array` 显式类型（波次号、剩余敌人、城墙比例、修理费、按钮可用性、技能充能、塔卡类型、价格判断等）。
- `main.gd on_lord_died()`：`mini(state.gold, …)` 结果显式 `int`。
- 结果：`godot --headless --path . --quit-after 600` 从满屏 SCRIPT ERROR 变为 0 ERROR。

### 2. 运行期 bug：升级面板整块报错

- 现象：进入三选一面板时每帧刷 `Invalid type in utility function "wrap()"`，升级卡文字不绘制。
- 根因：`art.gd` 自定义静态函数名 `wrap()` 与 GDScript 内建浮点工具函数 `wrap()` 冲突；`wrapped()` 内调 `wrap(...)` 实际调用内建函数，参数类型不符。
- 修复：重命名 `Art.wrap` → `Art.wrap_text`，调用点同步。三选一面板恢复。

### 5. 性能

- 压力探针（16 敌人 + 3 塔 + 满特效）draw calls ≈ 700，primitives ≈ 26k（1280×720）。
- 首次测量时测试机同时跑 2 个其他 Godot worker，`load average 24`（4 核），FPS 波动 5–37；同样负载下隐藏 HUD/FX 反而更慢，说明测量被 CPU 争用污染，不能作为结论。
- 同进程层隔离 A/B（16 敌人）：基线 41.7 fps；隐藏敌人后 110.4 fps；隐藏静态 arena 后 47.9 fps（draw calls 689→353）。瓶颈是敌人每帧重建绘制命令。
- 优化：敌人移动仍用变换、绘制指令降到 10 Hz（受击/前摇/击退/翻面 20 Hz）；HUD 15 Hz；`fx` 上限 100。
- 复测（load≈5，同机 2 个其他 worker）：16 敌人 + 3×Lv.2 塔 + 满特效，**avg 39.6 / min 22 / max 81 FPS**，`WAVE_DEFENSE_PERF_OK avg=39.6`，满足“平均 ≥30”。
- 70 敌人合成压力（load≈24）avg 15.8，未崩溃；超出实际关卡峰值（16–19），不作为验收结论。
- 单进程 no-VSync 30s（无塔/无手动加压）：min 50 / avg 85.8 / max 123 FPS。
