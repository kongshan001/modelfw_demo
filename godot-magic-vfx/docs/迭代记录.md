## R1 · 参考拆解与首版链路（21:45–22:30）

- 用 yt-dlp 拉 480p 分段，ffmpeg 抽帧确认：**3D、Godot 4.2.2、GPUParticles3D**；构成 = 头部网格 + 滚动火焰贴图拖尾 + 火星 + PointLight3D。
- 建 `godot-magic-vfx/`：主场景、三系参数表、法师/木桩、程序化头部与拖尾、命中包、HUD。
- 首批 1080p 截图暴露 4 个问题：① 法杖晶体变成 ~0.9 m 的米黄色大球；② 拖尾很细且偏白；③ 命中时木桩被闪白成一团；④ 场景过暗、构图空。
- 证据：`docs/shots/` 的早期截图（已被后续覆盖）；调试帧 `/tmp/magicdebug*`、`/tmp/magicimpact/`。

## R2 · 灯光与构图（22:30–22:55）

- 环境光：`ambient_light_energy 1.05 → 1.85`，ambient color `(0.13,0.17,0.29) → (0.25,0.31,0.50)`。
- 去掉不合时宜的 SpotLight；改为 Directional Key + 暖色 Rim Omni + 冷色 Fill + MageFill；后续再增到 Key 3.0 / Fill 3.8 / MageFill 2.4。
- 地面 base `0.030,0.038,0.062 → 0.055,0.068,0.105`；网格线强度 `0.30/0.42 → 0.14/0.20`；远处淡出到背景色。
- 新增 48×22 背景渐变 + 星点、4 个漂浮光球、角色脚下 additive 光池、9.5 m 地面符文。
- 相机 `(0.15,2.45,8.4) fov44 → (0,2.08,6.8) fov41`；法师/木桩整体内收。
- 结果：overview 可读性提升；但法杖大球、白色闪白和细拖尾仍在。

## R3 · Bug 定位：被每帧覆盖的 scale（23:00–23:05）

- 用分步隐藏调试（`tools/debug_probe2.gd`）确认：大球 = 法杖晶体。`_process` 每帧 `crystal.scale = Vector3(cs,cs,cs)` 覆盖了初始非均匀 scale（0.13,0.2,0.13）。
- 修复：保存 `_crystal_base = (0.17,0.26,0.17)`，每帧 `scale = base × cs`；环绕碎片同样改为 `(0.024,0.075,0.024) × charge_factor`，并把 emission energy 2.2 → 1.15。
- 同时确认画面中央竖直蓝线来自地面网格 x=0 主网格线（隐藏 Ground 后消失）；通过降低线强、加大地面到 120×120、远处淡出来弱化。

## R4 · 拖尾与头部形态（23:05–23:15）

- 焰条贴图：波带厚度 `0.155 → 0.30`（±0.055 抖动）；拖尾宽度 炎爆 `0.62 → 1.25 m`、奥术 `0.46 → 0.90 m`、霜晶 `0.50 → 1.00 m`；`width_scale 1.45 → 0.62`，让纹理带铺满 ribbon。
- 头部网格：脊线 `yc = -0.13+0.30t^1.6 → -0.26+0.52t^1.75`（钩/勺），半径 profile 更饱满；头前缘更白，尾部更暗。
- 拖尾颜色：hot 由 `mid→white 35%` 改为 `accent→white 12%`，边缘压 deep；内层 ribbon 宽度 `0.30× → 0.18×`、alpha `1.1 → 0.8`。
- 结果：飞行帧出现宽幅波浪火舌 + 亮核，接近教程的“头 + 尾 + 火星”构成。

## R5 · 命中反馈与动态光（23:15–23:30）

- 木桩闪白 `albedo alpha 0.65 → 0.16`，受击点光删除；命中光改用池化 `ImpactLight`（5.0×power，0.9 s + 2.2 s 余辉）；测试证明白色“刀片”其实是木桩自身被近距离强光 + overlay 打爆，不是粒子 bug。
- 新增 `FireCore`（glow 纹理 26 粒，0.55 s）填充命中中心；Burst 尺寸 1.0 → 1.25；烟由 16 → 8，alpha 0.5 → 0.34。
- 冲击环收敛：相机环 3.0 → 2.1 m，alpha 0.85 → 0.55；地面环 4.6 → 3.1 m、alpha 0.75 → 0.45；颜色使用 spell ring_color。
- 三系差异：炎爆橙金 + 烬/烟；奥术紫青 + 符文环；霜晶冰蓝 + 冰刺/寒雾。截图 `04/06/07` 可对照。

## R6 · 性能、清理与录制（23:30–23:45）

- 动态光从“每弹体/每命中/每木桩各一盏”改为 **固定 2 盏池化灯**，光源数量恒定；MSAA 3D 关闭。
- 发现并修复粒子泄漏根因：`SceneTreeTimer.timeout` 绑定了即将被 `queue_free` 的 projectile 方法，导致脱落的 Sparks/FlamePuffs 不释放。改为绑定节点自身 `queue_free`，并加 `magic_ephemeral` 组 + `ephemeral_until` 0.5 s 扫描兜底。
- `tools/smoke_magic_vfx.gd` 首轮报 `fx root leaked`，修复后 **MAGIC_VFX_SMOKE_OK**（含发射/命中/切换/慢放/重置/木桩重建/FxRoot 清空）。
- 录像：Movie Maker 固定 30 fps；初版时间线受慢放影响被拉长到 14.6 s，改为未缩放时间推进后 10.4 s；`tools/build_media.sh` 生成 MP4/GIF。
- 性能采样：测量期间机器 load average 9–23（另有 worker 在跑 3D 工程），**最小基准 3D 场景也只有 ~20 FPS 并出现 2 s 卡顿**；绝对 FPS 不具代表性，最终报告同时给出 baseline 与预算/清理证据（见 TECH §7）。在安静环境下复测的命令已写入 README。

## R7 · 性能收敛：ribbon → 平面拖尾 + 资源缓存（23:50–00:40）

- **停顿定位**：同进程最小基准 1280×720 稳定 ~58 FPS；demo 空闲 ~45 FPS；只要发射/命中就出现 0.3–2 s 同步停顿。关掉拖尾后压力连发从 ~4 FPS 升到 ~41 FPS，确认 **每帧重建 ImmediateMesh ribbon** 是主因之一。
- **替换**：`TrailRibbon`（64 点历史三角带，逐帧 clear/rebuild）→ `TrailQuad`（1×1 缓存四边形，按后向/世界上构造基，UV 滚动）；材质与网格按 spell 缓存，节点池化复用。视觉上变成教程原意的“平面 scrolling sheet”，仍保留头部钩形网格 + 火花/火团。
- **资源缓存**：头部 ArrayMesh + ShaderMaterial 按 spell 缓存；粒子 QuadMesh + StandardMaterial + GradientTexture1D + CurveTexture 由 `main.particle_mesh / ramp / curve` 缓存；命中仍保留 Burst / FireCore / ImpactSparks / Embers / 冰刺 / 寒雾，移除命中 Smoke（遮主体 + overdraw）。
- **预算下调**：弹体火星 56→40、火团 24→16、命中火焰 30→22、命中火星 52→36、余烬 20→14、尘埃 110→80、聚能 64→48、枪口 26→18；峰值实测 284/2400。
- **实测（load 8–22，含同进程基准）**：
  - 720p：baseline 58.2；空闲 44.6；NORMAL(2.2 s/发) 10.4；STRESS(0.85 s/发) 20.3。
  - 1080p 离屏：baseline 57.1；空闲 24.6；NORMAL 18.8；STRESS 15.8。
  - 结论：空闲达标，**战斗中 30 FPS 未达成**；停顿与粒子数不成比例，怀疑 GL Compatibility 下运行时创建/重启 GPUParticles3D 管线。
- **handoff**（未完成项）：per-spell impact rig 池化或命中粒子改 CPUParticles3D；1080p 可将 3D 内部降到 960×540；在 load < 3 的干净机器复测。详见 TECH §7.2 / README 性能现状。
- 自测保持 **MAGIC_VFX_SMOKE_OK**；截图/视频已按最终平面拖尾与粒子预算重拍（10 张 1920×1080 + 10.9 s MP4/GIF）。
