## 2. 关键迭代

### 迭代 A · 第一张全黑图

首次 GPU 截图只有字幕，世界全黑。

原因：主场景的 `WorldDisplay` 是一个 `TextureRect`，但没有在 `main.gd` 里绑定 `WorldViewport.get_texture()`。

修复：`_ready()` 中设置 `display.texture = $WorldViewport.get_texture()`，并把过滤设为最近邻。之后全景正常。

### 迭代 B · 桥把河切成了两个水体

第一版 BFS 得到 **4 个水体**：海、河上游、河下游、湖。

原因：mask 生成时桥面格被同时从“水体”通道挖掉，BFS 看到桥面是陆地。

修复：

- mask 增加 **A 通道 = 桥下水体**（不受桥裁切影响）。
- 管线用 A 通道标记“桥下连接格”；BFS 与水深使用 `hard ∪ under_bridge_water`，绘制仍用 R（挖空）。
- 这样水体数回到 **3**，且桥面仍不画水，前景桥负责遮挡。

验证：水体数 3；桥中心格 `is_bridge_cell` 且 `is_under_bridge_water`；类别仍是河流；`13_debug_bridge_cutout.png` 中蓝色桥格两侧水体连续。

### 迭代 C · 近景相机越界黑边

海 / 河 / 湖聚焦机位推近后，画面边缘出现黑边（相机可视区域超出 1280×720 世界）。

Godot Camera2D 的 limit 在当前嵌套 SubViewport 组合下没有按预期夹住手动设置的机位，因此在 `main.gd` 增加显式夹取：

```text
half = world / (2 * zoom)
camera.position = clamp(pos, half, world - half)
```

修复后 03 / 04 / 05 / 06 等 14 张截图无黑边。

## 5. 已知问题 / 后续可做

1. 场景生成空载约 2–4s、并行负载下 5–8s，主要是逐像素 GDScript 绘制；可以缓存 PNG 或降低地面生成分辨率，但本任务不要求启动速度。
2. 水体分类是启发式；当前 `avg_width<9.5` 对本图有效，换图需重新调阈值或引入 neck/bottleneck 分析。
3. 双波前在礁石/岛周围非常清晰，在主沙滩上因与岸线白沫/浅水高光叠加，第二道更柔；可进一步按岸段噪声增强/减弱。
4. 积水为即时水膜（无体积积累/排干），这是任务允许的简化；后续可复用低洼场做逐格水量。
5. 中文 UI 依赖系统 CJK 字体；不同平台可能需要调整 `font_names`。
6. 13MB 的 GIF 较大；MP4 为 7.5MB。需要更小 GIF 时可减色或降到 720 宽。

### 7.7 仍不足 / handoff

1. **16px 岸线阶梯**：湿沙/泡沫遮大部分；仍未降 8px 栅格（数据×4，另评估）。

3. **地表仍是程序化**：大色块/花簇/石墙/阴影已加，但密度仍低于手绘参考。
