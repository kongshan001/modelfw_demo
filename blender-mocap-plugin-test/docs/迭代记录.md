## 10:00–10:55 T-012 follow-up：修可见穿模（手臂/披风/脚）

用户反馈 T-004 的 Godot 走路预览“这个穿模比较厉害”。逐帧看：护腕/拳头/前臂穿进躯干/腰带/披风，脚 boot 埋进地面。本任务只修可见穿模，不改源视频/源骨架/时间轴/根运动。

### 1) 诊断口径先修正

- 第一版诊断用 `find_nearest` 的 signed distance 判内外，body mesh 在 neck/armhole 有小开口 → 大量假阳性（深度 200+ mm、-174 mm 脚）。改为 **3-ray 多数投票**（±X/Y/Z，多数内部才算内），最近面距离为深度。
- 旧“脚底 -0.84 cm”是 **foot 骨 head** 口径；实测 evaluated leg mesh 最低 **-174.36 mm**，两脚分别 148/145 帧 <0。脚的问题比原报告严重得多。
- 可见手区 = `hand.*` + 距腕 0.16 m 内 `lowerarm.*` 顶点；上臂近肩的 mesh 在躯干内是 KayKit 设计（自带 Walking_A 同样如此），不计入可见穿模。
- 体积代理 = Σ(顶点面积×深度)，**不是 boolean volume**；只用于相对比较。
- 8 采样帧：1/19/37/56/74/92/111/130；全 148 帧汇总。

### 2) 手臂：corridor + 2-bone IK，而不是逐帧硬推

- 测量角色自带 `Walking_A_Rig`：腕 **|x|≈0.513 m**、手 ≈0.55 m；raw retarget 腕 x **0.0–0.33 m**，而 body 腰带/裙摆 x 约 **±0.48 m**。这是 chibi 比例 + 角色宽体，不是手腕旋转单点错。
- 第一版逐帧 mesh push 到 x≈0.48：手出来了，但手臂几乎伸直、逐帧容易抖。
- 最终：保留源腕 y/z（前后/上下摆动），只把 **|wrist.x| clamp 到 0.55**；解析 2-bone IK 解 upperarm/lowerarm，肘极向 `(0.35·side,-0.9,+0.15)`；每帧 LINEAR key。残余 mesh push 只在 >12 mm 时触发（本次没有触发）。
- 结果：最大手/前臂深度 **L 253.3 / R 291.7 mm → L 11.8 / R 11.8 mm**；>4 mm 帧 L 36 / R 34，每帧最多 6 个顶点；骨净距最小 **-146.7 → +123.3 mm**；体积代理均值 L 11,624 → 5.3 cm³、R 9,682 → 6.7 cm³。视觉与角色自带 Walking_A（29.6/30.4 mm）同量级或更好。
- 代价：手臂比 raw 更“张”；这是宽体 chibi 的固有姿态，未改骨架/手指。

### 3) 脚：pitch cap + hips 残留 lift

- raw foot pitch **50–74° toe-down**；只旋转 foot 到 45° 仍无法清除（heel 会掉下去），因为 boot 几何太长。
- 方案：foot/toes 向下 pitch cap **20°**，再评估 leg mesh min z，把残留穿地加到 hips location.z（1 帧膨胀 + 3 帧均值，且不低于 raw 需求）。lift **max 65.5 mm / mean 23.8 mm**；追加 contact clamp 下压 hips，使最低 boot mesh 距地约 1 mm（本次下压 0–26.1 mm），避免膨胀/平滑造成悬空。
- 结果：mesh 最低 **-174.36 → +1.0 mm**，0 帧穿地；接触帧 L64/R96、最长 17/29；髋起伏 5.01 → **6.35 cm**；root XZ 1.7 mm 不变；支撑滑 0.2315 → **0.1696 m**（HUD 40 采样 0.213 m；未做脚锁，仍存在）。
- 注意：Godot HUD 的 `foot bone min` 修复后约 +9.3 cm，因为测的是骨 head；真实 mesh 最低 +0.1 cm，HUD 文案已标注。

### 4) 披风：再导出 90° 错位 → skinned chest

- 第一次重新导出后，披风从背后旋转 ~90°、世界位置偏 **1.388 m**（`FIX_CAPE_REBIND error_mm=1388.373`），渲染里变成“盖在腿上的大蓝布”。原因：源 cape 是 bone-parent 到 chest 的刚性 mesh + object action；Blender glTF 再导出不往返 `matrix_parent_inverse`。
- 修复：取帧 1 evaluated cape 世界顶点，按 `P_pose·P_rest⁻¹` 逆变换写回 rest 空间，权重 1.0 到 chest，加 Armature modifier，删除原 action/bone parent。帧 1 误差 **0.000 mm**；之后跟随 chest（含 hips lift）。丢掉原约 1 cm 独立摆动。
- 披风-头内部重叠 25.69 mm（领口/头发内部）仍在，渲染不可见；未改披风几何。

### 5) 武器：handslot 语义 → 从 locomotion 版移除

- 5 件道具（Knife/Offhand Knife、1H/2H Crossbow、Throwable）在源 GLB 是 `BoneAttachment3D → handslot.l/r`；走路时跟手进躯干，实测 127–148 帧、215–288 mm。
- 任务允许隐藏；clean locomotion GLB/FBX 移除 5 件道具（12→7 mesh）。raw 完整 GLB 保留。Godot 预览原本就隐藏它们。

### 6) Godot 预览/录制坑

- `_measure()` 会 scrub 全片，静止截图传 `--phase` 后又被 scrub 到片尾 → 在 `_measure()` 后重新 `ap.seek(boot_phase)`（预览已修）。
- raw 与 fixed 的披风/阴影不同，同机位录制 raw 明显更暗；增加 `--flat`（关 key 阴影 + ambient 2.0）用于前后对比证据，正常预览仍保留阴影。
- `--write-movie` 相对路径会写到 Godot 项目目录/不明确；用绝对路径，避免文件丢失。
- fixed 版 Godot：41 骨/7 mesh/4.9333 s/24 轨；`SMOKE_FOOT fixed min_foot_y=0.0840 longest=12 stance_slide=0.1696 hip_y_range=0.0635 scale_dev=0 loop_seam=0`；`MOCAP_SMOKE_OK`；Movie Maker 5 s（150 帧）约 6–9 s 录制。
