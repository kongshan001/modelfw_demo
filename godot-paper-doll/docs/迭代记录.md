### 已知风险 / 限制

1. **动画帧率**：试衣镜以 24 Hz 重绘，渲染循环可到 35–55 FPS；这是刻意的定格木偶质感。
   若追求 60 FPS 动画，可继续把 17 层拆成预制部件贴图，或把红绘频率降到 12 Hz。
2. **描边 AA**：GLES3 不支持 2D MSAA；三角形批次边缘为硬边，放大后可见锯齿。
3. **FPS 波动**：真机采样受系统负载影响，建议以 `tools/perf_paperdoll.gd` 的 min 为准；
   verify 在极重负载下可能偶发低于 30。
4. **随机阵容的开销**：16 张卡在同一帧重新烘焙，点击“随机阵容”约有短暂卡顿；
   单张重抽与随机当前纸偶不会触发整队重烘焙（签名缓存）。
5. **UI**：代码构建、中文界面；未做多语言、手柄导航或移动端触控布局。
6. **存档**：默认写 `user://paperdoll_outfit.json`，没有版本迁移与多存档位。
7. **无音频**：Movie Maker 生成的 AVI 带静音 AAC 轨，转码后 MP4 仍有静音音轨，不影响播放。

### 下一步（如需继续）

- 将阵容面板改为单 CanvasItem 绘制，进一步降低 16 张卡的静态合成开销；
- 为工作室增加“导出 PNG / 角色卡”；
- 增加移动端虚拟摇杆与触控槽位；
- 若允许外部资源，可把高频动作预烘焙为精灵表以换取 60 FPS 动画。

## 2026-11-21 · T-20261121-001（Game Artist walk 脚姿/滑步修复）

### 问题与根因

- 用户反馈：“走路的脚的那个姿势特别奇怪。”
- QA BUG-03 / 复评 R2-P0-2：walk 支撑脚水平漂移 **dir6 = 45.26px、dir0 = 5.42px**（阈值 2px @2.1×）；
  侧向走像原地蹬腿。
- 根因：
  1. 旧版 walk 只在 `hip/knee` 上直接叠加 sin 角度，没有脚目标/锁脚/根位移，支撑相的脚必然随步幅横扫；
  2. `foot_angle = −shin × 0.35 + foot_roll` 让脚掌姿态跟着小腿角度走，脚踝会随摆动前后翻；
  3. `shin = thigh + max(0, gait) × 0.78` 在腿前摆时把小腿继续向前推，膝盖呈反关节/过伸。

### 改法（只改 walk，不动玩法/数据）

文件：`scripts/doll/doll_pose.gd`（walk 分支 + 2 个 helper；其余动作路径未改）

| 参数 | 值 |
| --- | --- |
| 周期 / keys | 0.82s / 8 keys（保留） |
| 支撑相 | p 0–0.58，脚目标 x = plant，锁定不随髋摆动 |
| 摆动相 | p 0.58–1.0，抬起 12 local（正/背面 5.5）+ 前探 7 local（正/背面 2） |
| 髋部 | bob 2.6±0.9 local；hip sway ±0.9 local |
| 手臂 | ±0.52 rad，与向前摆的腿反相 |
| 脚掌 | −15° 脚跟 → 0° 全掌（p 0.10–0.36）→ +22° 脚尖（p 0.58）→ 摆动回 −15° |
| 踝点滚动补偿 | `WALK_SOLE_DROP 5.4`、`WALK_FOOT_PIVOT 8.5`，鞋底最低点保持在同高 |
| 披风 / 发 | `secondary` 3.4 local，滞后 2 帧 @30fps（0.51 rad；披风 sway ≈ ±4.8 local） |
| 膝向 | 正/背面左右膝向外对称让位；3/4 与侧面两膝朝前，避免反关节 |

实现要点：

- 双腿用 2 骨 IK（THIGH 25 / SHIN 22）反解膝/踝；`bend_sign` 保证膝不过伸、左右曲线一致；
- 锁脚目标不使用带 sway 的 `hip.x`，髋部只做 bob/sway，支撑脚 x 严格固定；
- 脚掌只做矢状面俯仰，不叠加 shin 角，脚踝不内外翻；
- 选“原地踏步 gait”（评审 brief 允许的二选一），不引入 root 位移/背景滚动；展示物料不改玩法。
