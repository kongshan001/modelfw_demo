# 章鱼程序化动画：从 Verlet 触手到缠绕与变色

> 参考视频：《章鱼 | 程序化动画 | 运动学模拟》（B 站，Unity，像素风）。
> 本项目实现：`scripts/garden_octopus.gd` + `shaders/octopus.gdshader` + `shaders/octopus_arm.gdshader`；集成在花园水池边的石像旁。
> 逐轮对比：`docs/迭代记录.md` 轮次 4；技术方案：`docs/2026-10-29-废墟花园技术方案.md` §13.8。

## 0. 先说结论

参考片真正值得学的不是“章鱼模型”，而是四件事：

| 技术线 | 参考片 | 本项目 |
|---|---|---|
| 触手形变 | Verlet 布料 + 约束迭代 + 气动阻力/弹簧负重 | 8 条 Verlet 链 + 距离约束 + 目标弹簧 |
| 缠绕 | 柱面展开映射 + 螺旋路径 + 落点预测 | 石像近似圆柱 + 螺旋目标 + 碰撞投影 |
| 移动 | 地形采样落点 + 牵引式步态 + 碰撞投影 | 石像旁 idle/wrap/sleep；地形步态未实现 |
| 变色 | 色素细胞模型 + 分层体色 + 调色板量化 | 夜间/睡眠 shader 色移 + 12 级量化 |

**一句话配方**：

> 每个触手 = 一条 Verlet 链；每帧用“重力/阻尼 + 目标弹簧 + 距离约束 + 碰撞投影”把点拉成触手；渲染时把 12 个点传给顶点着色器，用 Catmull-Rom 重建平滑管；缠绕 = 把点目标换成绕柱螺旋；变色 = 灯光/睡眠状态驱动 shader 调色。

## 1. 原理：Verlet 链

### 1.1 为什么不直接算弹簧力

质点-弹簧模型需要速度、刚度、阻尼、积分器，容易爆炸。Verlet 用“当前位置 + 上一帧位置”隐式表示速度：

```text
velocity ≈ (pos - prev_pos) / dt
pos_next = pos + (pos - prev_pos) * damping + accel * dt²
prev_pos = pos
```

优点：

- 稳定、简单、无需显式速度。
- 约束可以直接改位置（Position Based Dynamics），不用算力。

### 1.2 距离约束

触手每两个相邻点之间有一条“不可拉伸的绳”：

```text
target_len = arm_length / (segments - 1)
for iteration in 4:
    for each adjacent pair (a, b):
        d = length(b - a)
        correction = (b - a) * (1 - target_len / d) * 0.5
        a += correction
        b -= correction
```

- 第一个点是**基点**，必须钉在身体上；对 j==1 的约束只移动 b，避免把身体拉走。
- 迭代次数越多越硬；3–5 次通常够。我们的 12 点 × 4 次。
- 约束后再做碰撞投影（地面/石柱），然后重新钉基点。

### 1.3 目标弹簧：让触手“想”去哪里

只有重力 + 约束，触手会软塌塌地垂到地上。要让触手抬起/摆动/缠绕，需要给每个点一个目标位置：

```text
pos += (target - pos) * min(1, spring * dt)
```

- `spring` 小 → 触手更自由、滞后；大 → 更贴目标。
- idle 目标：向外伸展 + 正弦起伏 + 沿 Y 轴缓慢旋转（S 形）。
- wrap 目标：绕石柱的螺旋。
- sleep 目标：向身体收拢。

### 1.4 碰撞投影

- **地面**：`if p.y < ground: p.y = ground`；可再把 `prev.y = p.y` 消掉垂直反弹。
- **圆柱/石柱**：把 xz 到柱心的距离压到 `radius + tube_radius` 外；高度范围内才处理。
- 参考片的“落点预测/地形采样”本质是更聪明的碰撞+目标选择；我们这版只做了地面/单圆柱。

### 1.5 螺旋缠绕

给定柱心 `C`、半径 `r`、起始角 `a0`、圈数 `turns`、高度 `y0..y1`：

```text
for j in 0..N-1:
    t = j/(N-1)
    angle = a0 + t * turns * TAU
    target = C + (cos(angle)*r, lerp(y0,y1,t), sin(angle)*r)
```

- 把触手各点的目标从“向外伸展”切换为这条螺旋，弹簧会把链拉上柱子。
- 碰撞投影让点贴在柱面，不会穿进去。
- 参考片还做了“柱面展开/落点预测”：先预测触手能绕几圈、落点在哪，再生成路径；我们简化为固定 0.65 圈。

## 2. Godot 实现

### 2.1 数据结构

```gdscript
const ARM_COUNT := 8
const SEGMENTS := 12
var _arm_points: Array = []   # Array[Array[Vector3]]
var _arm_prev: Array = []     # 上一帧位置
var _arm_base_offset: Array[Vector3] = []
var _arm_dir: Array[Vector3] = []
var _arm_length: Array[float] = []
```

- 点用 `Array[Vector3]`（可变），不要用 `PackedVector3Array` 做逐点修改再忘记写回。
- 基点 = `body_node.position + offset.rotated(UP, body_rotation)`；身体转动时触手跟着转。

### 2.2 每帧顺序

```text
1. 更新状态机（idle/wrap/sleep）与身体位置/倾斜
2. 对每条触手：
   a. 计算每个点的目标（idle/wrap/sleep）
   b. Verlet 积分 + 目标弹簧
   c. 4 次距离约束
   d. 钉基点 + 地面/石柱碰撞
3. 把 12 个点传给触手材质 uniform
4. 身体 shader 的 u_night/u_sleep
5. 眨眼/眼睛缩放
```

### 2.3 触手渲染：静态管 + 顶点变形

这是本轮最重要的性能取舍。

**方案 A：每帧重建 ImmediateMesh 管** → 42 FPS。GDScript 逐顶点 `surface_add_vertex` 太贵。

**方案 B：MultiMesh 圆柱段** → 60 FPS，但圆柱段之间有缺口/条纹，视觉不可接受。

**方案 C（最终）：静态管网格 + 顶点着色器 uniform 数组** → 80–83 FPS：

- 每条触手一个 MeshInstance/材质；共享同一个静态网格（36 环 × 8 边）。
- 网格的 UV 存 `(绕圈角度, 沿触手 0..1)`；顶点位置是占位，真正的曲线在 shader 里算。
- 每帧只设置 `arm_points[12]`（12 个 vec3）+ `u_night/u_sleep`；8 条触手 = 8 次 uniform 设置、8 个 draw call。
- 顶点着色器用 Catmull-Rom 在 12 个点之间采样，构建切线和环，输出平滑管；片元做色斑/吸盘/夜间色移/量化。
- 静态网格的 AABB 需要放大（`custom_aabb`），否则可能被视锥裁剪掉。

**触手 shader 的关键代码**

```glsl
uniform vec3 arm_points[12];

void vertex() {
    float along = UV.y;
    float angle = UV.x * TAU;
    float scaled = along * 11.0;
    int i = clamp(int(floor(scaled)), 0, 10);
    float f = fract(scaled);
    vec3 center = catmull(arm_points[i-1], arm_points[i], arm_points[i+1], arm_points[i+2], f);
    vec3 tangent = catmull_tangent(...);
    vec3 up = abs(tangent.y) > 0.95 ? vec3(1,0,0) : vec3(0,1,0);
    vec3 side = normalize(cross(tangent, up));
    vec3 up2 = normalize(cross(side, tangent));
    float radius = mix(base_radius, tip_radius, along);
    VERTEX = center + side*cos(angle)*radius + up2*sin(angle)*radius;
    NORMAL = normalize(side*cos(angle) + up2*sin(angle));
}
```

**再快一点**：

- 8 条触手可以共享一个材质，用**实例 uniform** 或纹理/SSBO 传点；Godot 的 `instance uniform vec3 arm_points[12]` 可尝试；当前 8 个材质足够。
- 如果触手更多（16+），把点写进 `ImageTexture`/`Image` 的浮点纹理，shader 采样，而不是 uniform 数组；这是 GPU 蒙皮的思路。
- 更新频率：触手物理 60Hz、顶点 uniform 每帧；不需要每帧重建网格。

### 2.4 吸盘

- 静态网格 UV：`u = 绕圈角度 / 8`，`v = 沿触手 0..1`。
- shader 在腹面（`u≈0.7/0.8`）画两排白色小点：

```glsl
float row = max(smoothstep(0.055,0.0,abs(UV.x-0.7)),
                smoothstep(0.055,0.0,abs(UV.x-0.8)));
float dots = step(0.5, sin(UV.y*78.0 + UV.x*9.0));
col = mix(col, vec3(0.95,0.76,0.56), row*dots*0.72);
```

- 吸盘让触手一眼读成“章鱼”而不是“红管子”。

### 2.5 变色 / 睡眠

- shader uniforms：`u_night`、`u_sleep`。
- 夜间：整体偏冷、压暗、去饱和；睡眠：进一步去饱和 + 收拢。
- 12 级量化：`floor(col*12)/12`，配合 640×360 的像素化，读作像素色块。
- 眼睛用 unshaded 黄色 + 黑瞳，夜里仍然可读；睡眠时眼睛 Y 缩放/闭眼。

## 3. 与参考片的差距

| 参考片技术 | 本项目 | 差距 |
|---|---|---|
| Verlet 布料、约束迭代、气动阻力、弹簧负重 | 有 | 参数更简化 |
| 多布料实时解算、程序化节拍 | 有（8 条独立链） | 没有“布料片”宽面，只有管 |
| 柱面展开、螺旋路径、落点预测 | 有螺旋目标/碰撞 | 没有落点预测/自动圈数 |
| 地形采样落点、牵引式步态 | **未实现** | 章鱼在石像旁静止 |
| 单杠摆荡、阻尼单摆 | **未实现** | 没有悬挂/摆荡 |
| 色素细胞、分层体色、调色板量化 | shader 色移 + 量化 | 没有多层色素细胞动画 |
| 像素风/低分辨率 | 640×360 + NEAREST | 一致 |

下一步优先级：

1. **地形采样 + 落脚点 + 牵引步态**：把章鱼的几条触手当腿，采样地面高度，交替选择落脚点，身体被拉向前。
2. **单杠摆荡**：在横杆上选 3 个缠绕点，身体质量做阻尼单摆。
3. **落点预测**：根据触手长度/柱半径计算可绕圈数，再生成螺旋。
4. **交互**：点击章鱼切换 idle/wrap/sleep，或让它从水池爬到石像。

## 4. 跨引擎复刻

### 4.1 Unity

- **物理**：C# 里做 Verlet；触手多/点多用 Job System + Burst（`NativeArray<float3>`）。
- **渲染**：
  - 原型：`LineRenderer`/`TubeRenderer`（Asset Store 有 TubeRenderer）或 `SkinnedMeshRenderer`。
  - 正式：静态管 Mesh + `ComputeBuffer`/`GraphicsBuffer` 传点数组，HLSL `StructuredBuffer<float3> _ArmPoints;` 在顶点着色器采样 Catmull-Rom。
  - 材质：Shader Graph 不方便做结构化 buffer，手写 HLSL 更合适。
- **碰撞**：`Physics.SphereCast`/`Raycast` 或自定义圆柱投影；不要给每个点加 Collider。
- **注意**：Unity 的光照单位/色彩空间；URP 的 shader 变量/Instancing。

### 4.2 Unreal Engine 5

- **物理**：C++ Tick 或 Blueprint（点数多建议 C++）；`TArray<FVector>` 做 Verlet。
- **渲染**：
  - 原型：每条触手一组 `USplineMeshComponent`（按点分段），或 `UProceduralMeshComponent` 每帧更新。
  - 正式：**Skeletal Mesh + 12 根骨骼/触手**，用物理/动画蓝图驱动骨骼；或 ProceduralMesh + Material 的 `Custom Primitive Data`/MPC 传点（数组支持有限，常用纹理/曲线图集）。
  - 顶点动画可用 `World Position Offset` + 采样曲线纹理；复杂逻辑放 C++/Compute Shader。
- **碰撞**：`LineTrace`/`SphereTrace` 或自定义圆柱投影。
- **注意**：Auto Exposure/Lumen 会改变观感；像素化可用 SceneCapture2D + Nearest RT。

### 4.3 Three.js / WebGL

- **物理**：JS 里 Verlet（8×12 点很便宜）；点更多可用 Web Worker。
- **渲染**：静态 `BufferGeometry`（UV 存 along/angle）+ `ShaderMaterial`：
  - `uniform vec3 armPoints[12]`（每条触手一个材质/网格）或 `DataTexture`/`InstancedBufferAttribute`。
  - 顶点着色器 Catmull-Rom + 环；片元色斑/吸盘/量化。
- **碰撞**：简单平面/圆柱数学，或 `Raycaster` 对地形网格；不要在 JS 里给每个点做物理引擎刚体。
- **注意**：`renderer.outputColorSpace`、`toneMapping`、透明排序；ShaderMaterial 的 uniform 数组上限。

### 4.4 通用迁移清单

- [ ] 每个触手是独立链，基点在身体上。
- [ ] Verlet + 距离约束迭代；约束后再碰撞，最后钉基点。
- [ ] 目标弹簧：idle/wrap/sleep 三种目标。
- [ ] 缠绕用螺旋目标 + 柱面碰撞；不是直接把点吸到柱心。
- [ ] 渲染用静态网格 + 顶点变形，避免每帧 CPU 重建。
- [ ] 吸盘 UV/色斑，夜间/睡眠色移。
- [ ] 性能：先测 CPU（模拟）与 GPU（网格/材质）成本，再决定更新频率。

## 5. 练习

1. **一条触手**：8 个点，重力 + 距离约束 + 地面碰撞；能自然垂下。
2. **目标弹簧**：让触手尖端追一个移动目标；调 spring/damping。
3. **八条触手**：围绕身体排布；每条不同相位。
4. **柱面碰撞**：把触手推向一个圆柱，确保不穿模。
5. **螺旋缠绕**：给 3 条触手螺旋目标，绕柱 0.5–1 圈。
6. **GPU 管**：静态管 + uniform 数组 + Catmull-Rom；对比 CPU 重建 FPS。
7. **变色**：夜间偏冷、睡眠收拢；加吸盘 UV。
8. **迁移**：在 Unity/Unreal/Three.js 里复刻 1、3、5。

## 6. 常见坑

- **每帧 CPU 重建网格**：GDScript/蓝图逐顶点调用非常贵；用静态网格 + shader。
- **MultiMesh 段拼接**：圆柱段太短/太少会露出缺口；不如管网格。
- **距离约束后忘记钉基点**：身体会被触手拉走。
- **约束与碰撞顺序**：先约束再碰撞再钉基点；否则会穿地/穿柱。
- **螺旋目标太贪心**：圈数超过触手长度会拉成直线/抖动；先按长度限制圈数。
- **shader uniform 数组越界**：`arm_points[12]` 固定大小，点数变化要同步改。
- **AABB 裁剪**：顶点变形后几何超出原 AABB；设 `custom_aabb`/`extra_cull_margin`。
- **光照/色彩空间**：迁移到 Unity/Unreal 后红/橙色会变；先做三灯校准。
