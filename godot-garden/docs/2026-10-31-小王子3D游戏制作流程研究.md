# 《小王子》3D 游戏制作流程研究 & 对废墟花园的可迁移优化

> 来源：B 站视频《教程：《小王子》3D 游戏作者公开了制作流程》BV1EjJ262Ek9（UP：i陆三金），2026-10-31 抓取简介。
> 说明：本环境无法抓取 B 站视频画面/字幕，以下流程来自作者公开简介，不臆测视频内未写出的参数。

## 1. 作者公开的流程（原文要点）

**场景**
1. `image2.5` 生图（场景概念图）。
2. 让 AI 从概念图里**找出需要单独制作的资产**。
3. **Tripo** 生成这些资产（3D）。
4. 拿着场景图，让 **Opus 5.5 组装资产**；**分配子 agent 做对抗审查**。

**人物**
1. `image2.5` 生图（角色概念）。
2. **Tripo** 生成人物模型。
3. **Auto-Rig Pro** 插件绑骨骼与蒙皮。
4. 动作来自 **Mixamo**（没有合适的就找近似动作，再让 **Claude 调整**）。

核心不是某个软件，而是：**参考图 → 资产拆解 → AI 生成 → AI 组装 → 对抗审查 → 动作适配** 这条“人机协作流水线”。

## 2. 我们现在的管线 vs 作者管线

| 环节 | 作者 | 废墟花园现状 | 差距 |
|---|---|---|---|
| 概念图 | image2.5 | 无（参考片 + 截图） | 缺“统一参考图” |
| 资产拆解 | AI 从概念图列资产 | 手工/agent 评审 | 可模板化 |
| 3D 资产 | Tripo 生成 | 程序化 + CC0（KayKit/glTF Fox） | 缺“独特资产” |
| 组装 | Opus 5.5 + 子 agent | 程序代码 + 美术/QA agent | 已有对抗审查雏形 |
| 角色 | Tripo + Auto-Rig Pro + Mixamo | CC0 预绑定模型 | 缺“自定义主角” |
| 动作 | Mixamo + Claude 调整 | KayKit 内置动画 | 够用，缺微调 |

## 3. 可迁移的优化（按投入产出）

### P0：现在就能做

1. **把“对抗审查”制度化**：新增 `game-red-team` agent，在美术/QA 签字后独立攻击版本（视觉一致性、证据造假、性能口径、逻辑回归），输出可复现问题清单。作者用子 agent 对抗审查，我们目前只有美术/QA 两个“建设性”角色，缺一个“找茬”角色。
2. **建立资产清单模板**：每轮先写“参考图 → 需要单独搓的资产 → 来源（程序化/CC0/AI 生成）→ 许可”，避免边做边找资产导致风格漂移。
3. **参考图驱动构图**：即使没有 image2.5，也可以用固定截图作为“参考图”，让美术 agent 做“概念图 vs 实机”差异表；有图像账号后再换成 AI 概念图。

### P1：需要账号/预算

4. **Tripo 自定义资产**：Tripo 免费档 200 credits/月（约 13 个 HD 模型），但免费档模型**公开、需署名、导出受限**，商用需付费（Starter $5/月起）。适合先做 1–2 个独特道具/主角原型评估，不宜直接进商用包。
5. **自定义主角管线**：image2.5（或 Seedream）→ Tripo → Blender Auto-Rig Pro（付费插件）→ Mixamo 动作 → Claude 调整。相比继续用 KayKit，能得到唯一角色，但链路长、需要 Blender/插件/账号。
6. **参考图一致性**：用同一张概念图约束所有生成资产的比例、材质、色温；我们现在靠“同一骨架/图集”统一，作者靠“同一参考图”统一，两者可以叠加。

### P2：暂不建议

- 直接拿 Tripo 免费档资产进商用包：许可（公开/署名/平台 IP）与风格稳定性都有风险。
- 为当前场景购买 Auto-Rig Pro：现有 KayKit 动画够用，除非确定要做自定义主角。
- 盲目复刻“AI 生成全部资产”：我们的程序化世界/章鱼是差异点，不应被替换。

## 6. 建议的下一步

1. **立即**：启用 `game-red-team` agent，对当前构建做一轮对抗审查（不依赖任何外部账号）。
2. **账号恢复后**：用 Seedream 出 1 张花园概念图 → 按作者流程列资产清单 → Tripo 免费额度试做 1 个独特道具，评估风格与许可。
3. **决定是否做自定义主角**：这是唯一需要 Blender + Auto-Rig Pro + Mixamo 的长链路；若不做，继续用 KayKit 统一管线。
