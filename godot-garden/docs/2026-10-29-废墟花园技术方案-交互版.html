为什么不用“高分辨率 + 全屏像素化 shader”

那样每个像素都要先按 1920×1080 算一遍，再降采样；更贵，而且相机动起来会有采样闪烁。低分辨率直接渲染从源头就没有这些像素。

为什么 UI 不放进小画布

UI 一旦进入 640×360，文字会被 NEAREST 放大成马赛克。UI 放在外层 CanvasLayer，按 1920×1080 绘制，和后处理完全隔离。

像素稳定性：相机吸附

低分辨率 + 缓慢环绕时，相机位置的微小变化会让像素在屏幕上“爬”。把相机世界坐标吸附到 0.04 的网格：

pos = (pos / 0.04).round() * 0.04
_camera.global_position = pos
_camera.look_at(Vector3(0, 1.0, 0))

吸附太粗会“跳格”，太细没有效果；0.04 是稳定与顺滑的折中。MSAA、屏幕空间 AA、TAA 全部关闭。

§02

渲染器：为什么最后选了 Mobile

一个真实踩坑

同一个场景，GL Compatibility、Forward+、Mobile 的结果完全不同。这个结论只对本机 + Godot 4.6成立，但排查方法可以复用。

GL Compatibility

环境光、自发光、Unshaded 正常；方向光/点光几乎不照亮材质。最小复现（球 + 地板 + 两盏灯）仍然只有环境光。

本机不可用 → 放弃

Forward+

在 MoltenVK 上 fragment shader 编译失败：VK_ERROR_INVALID_SHADER_NV，大量 pipeline 创建失败。

本机不可用 → 放弃

Mobile / Vulkan

方向光、点光、阴影、自发光全部正常；1280×720 约 88–90 FPS。

最终选择
[rendering]
renderer/rendering_method="mobile"
renderer/rendering_method.mobile="mobile"
注意：换渲染器后光照单位/环境响应会变，不能沿用旧能量。切到 Mobile 后我重新调了太阳、环境、曝光，并把“黄昏提亮”从全局常量改成 dusk_glow 曲线，否则正午会过曝。

排查流程（可复用）

  1. 先做最小场景：一个球、一块地板、一个方向光、一个点光、一个 WorldEnvironment。
  2. 打印 rendering/limits/opengl/max_lights_per_object（本机 8）和 max_renderable_lights（32），排除灯数量限制。
  3. 检查灯光 light_cull_mask 与材质 layer。
  4. 依次切 Forward+ / Mobile，看是否恢复。
  5. 如果换了渲染器，重新校准曝光/能量，再做视觉验收。

640×360 的取舍

640×360 在 1920×1080 下是 3× 放大，像素块明显；480×270 太糊，960×540 像素感太弱。内部 640×360 + NEAREST 是“像素感/可读性”的折中。

§03

世界怎么搭：程序化几何的六个部件

无外部模型/贴图

所有东西都是 Godot 原语 + 自定义 shader。关键不是“模型多精细”，而是轮廓、配色、光照和重复密度在 640×360 下读起来像一座花园。

GROUND

地面

60×60 的 PlaneMesh + value noise 混三种草/土色。真正的“草”由 3.9k 草叶覆盖，地面只负责底色和颜色变化。

PATH

石径

10 个控制点的闭合 Curve3D。路面是 2.0m 宽的三角带，石板上按 0.62–0.94m 间隔随机放置，三套石材质 + 18% 苔藓。

var side = Vector3(tangent.z, 0, -tangent.x)
var yaw = atan2(tangent.x, tangent.z)
POND

水池

48 段不规则岸线（正弦 + 噪声），三角扇水面 + 亮色岸线 + 26 块岸边石 + 3 块水中石。夜间再加两块暖色反射光斑。

RUINS

废墟

拱门 = 两根柱子 + 半圆上 13 段 Box；每段绕 Z 旋转 a + 90° 贴合圆弧，随机跳过 2–4 段形成断顶。另有断柱、断墙、石圈、雕像、碎石和垂藤。

TREES

树

树干 + 两根斜枝；树冠由 8 个低多边形球 + 底部暗层 + 顶部球组成，三套绿色材质交替，整体缩放 0.85–1.25。

GIRL

小女孩

低多边形红上衣/白裙/金发模型，挂在 PathFollow3D 上循环行走；手脚摆动 + 身体起伏；脚下软阴影 + 一盏很小的暖光。

草：一个 MultiMesh 解决 3.9k 株

草叶是两片交叉的竖直四边形（宽 0.16m、高 0.5m），每个实例随机旋转/缩放；一个 MultiMesh 一次 draw call。排布排除水池、石径和石圈。

// 草叶 shader 的核心：UV 刀片 + 风摆
float h = UV.y;
float phase = INSTANCE_CUSTOM.x * 6.2831;
float sway = sin(TIME*1.6 + phase + MODEL_MATRIX[3].x*0.7) * 0.09 * h*h;
VERTEX.x += sway;
VERTEX.z += sway * 0.35;

float half_width = mix(0.5, 0.035, UV.y);
if (abs(UV.x - 0.5) > half_width) discard;
ALBEDO = mix(root_color, tip_color, UV.y) * (0.78 + INSTANCE_CUSTOM.y*0.38);

INSTANCE_CUSTOM.x 是每株草的风相位，.y 是颜色变化；没有逐节点逻辑，也没有 3.9k 个 Node。

水池：噪声 + Fresnel + 反射

水面不透明，靠两层 value noise 做波纹，Fresnel 让边缘更亮，太阳高光用 reflect 的 70 次幂，夜间再加暖色波纹和压暗。岸线用 0.965–1.07 倍半径的亮色环，读作泡沫/浅滩。

拱门：圆弧上的 Box 段

for i in 13:
    var a = PI * i / 12.0
    var p = Vector3(cos(a)*r, pillar_h + sin(a)*r, 0)
    var seg = _add_box(root, p, Vector3(0.46,0.34,0.56), stone)
    seg.rotation.z = a + PI*0.5   # 长边沿圆弧切线
    if i in [8,9]: continue       # 断顶

太阳高度：不是 6→18 的正弦

参考片面板显示：18:00 太阳仍有 +28°。如果按“6 点日出、18 点日落”的简单正弦，18 点刚好 0°，黄昏会瞬间变黑。所以实际用的是：

sun_alt = sin((hours - 4.9) / 14.2 * PI)
# 4.9 点日出，19.1 点日落，12 点最高

五条曲线各自解决什么

变量含义关键区间解决的问题
day太阳高度 0–1日出–日落主光/长阴影
night月夜强度日落后–日出前冷色轮廓/夜景

DUSK_GLOW

只在“太阳还在地平线上方但很低”时抬高环境光、补光和曝光；正午/深夜都不受影响。它是从参考片亮度反推的经验曲线，不是物理量。

路灯：光晕 + 点光 + 自发光

灯柱本身是铁艺几何；真正让它“亮”的是三件套：灯罩自发光、Sprite3D 径向光晕、OmniLight3D。能量带轻微闪烁：

energy = 2.15 * level * (0.94 + 0.04*sin(7t+phase) + 0.02*sin(21t+2phase))
_glass.emission_energy_multiplier = 3.2 * level

萤火：粒子 + 加法 billboard

220 个粒子，box 范围 15×1.6×15；颜色黄绿、径向渐变、加法混合。粒子颜色渐变负责“忽明忽暗”，时间曲线负责“白天不出现”。

process.emission_shape = EMISSION_SHAPE_BOX
process.emission_box_extents = Vector3(15, 1.6, 15)
fireflies.lifetime = 7.0
fireflies.amount_ratio = clamp(level, 0.06, 1.0)

水面：三层视觉信息

  • 底色：深青，按 Fresnel 向浅青过渡；
  • 波纹：两层 value noise 反向滚动；
  • 高光：太阳镜面 + 夜间路灯暖色波纹 + 两块静态反射光斑。

光束：面片近似，不是体积光

每道光束是一个大 Quad。局部 Y 对齐光线方向，Z 对齐相机，shader 做边缘柔化 + 两端淡出。没有真实体积散射，但在低分辨率下足够读作“丁达尔光”。

right  = dir.cross(to_cam).normalized()
normal = right.cross(dir).normalized()
mesh.global_transform = Transform3D(Basis(right, dir, normal), anchor + dir*length*0.5)
注意：光柱面片很容易“抢戏”。最终只保留 2 道背景夕阳束 + 1 道月光束，alpha 0.09–0.12；大面积、正对镜头、高 alpha 会让画面变成斜条纹。

云影 / 池面雾

云影是花园上方 4.2m 的透明 Plane，滚动 value noise，强度 0.02–0.06；池面雾是 0.45m 高的 Plane，噪声 + UV 径向淡出，避免矩形边。

§06

后处理：让低分辨率看起来“像像素画”

CanvasItem shader

后处理只挂在 PixelDisplay 上，不碰 UI。四步：柔光 → 冷暖分级 → 抖动/量化 → 暗角。

// 8 邻域亮部柔光（低分辨率下很便宜）
base += bloom * u_bloom * 0.7;

// 黄昏偏暖 / 深夜偏冷
base = mix(base, base*vec3(1.06,0.97,0.86)+vec3(0.012,0.006,0.0), u_warm*0.4);
base = mix(base, base*vec3(0.82,0.92,1.08)+vec3(0.0,0.004,0.012), u_night*0.42);

// 2×2 抖动 + 6bit 量化
float d = dither2(FRAGCOORD.xy);
base = floor(base*63.0 + d) / 63.0;

// 暗角
base *= mix(1.0 - u_vignette, 1.0, smoothstep(0.82, 0.22, length(UV-0.5)));

为什么要抖动

低分辨率 + 大面积渐变容易出现色带；2×2 抖动把量化误差打散，色带变成细密噪点，像像素画的颗粒。

为什么量化到 6bit

每通道 64 级，足够保留渐变，又能让颜色“收”一点；配合 NEAREST 放大，像素感更明确。

不要把 UI 放进后处理：后处理会量化文字边缘、产生抖动噪点；UI 必须保持在低分辨率世界之外。
§07

性能账本：90 FPS 是怎么来的

Intel Iris 6000

这个场景的预算很明确：低分辨率省片元，MultiMesh 省 draw call，灯/阴影省光源开销。

项数值为什么这样选
内部渲染640×36023 万像素，约为 1920×1080 的 1/9
草~3.9k 实例一个 MultiMesh，一次 draw call
萤火220 粒子GPU 粒子，fixed 30fps，不占 CPU
灯8 Omni + 3 Directional只有太阳投影；路灯不投影
阴影4 split / 55m近处精度够，远处不浪费
后处理8 tap + 量化在 640×360 上做，成本很低
实测88–90 FPS1280×720 输出，Intel Iris 6000
省性能的三个关键：① 低分辨率直接渲染，而不是高分辨率 + 全屏像素化；② 草用 MultiMesh，不逐节点；③ 不启用 SSAO/SSR/体积雾，用噪声/面片近似。
§08

踩坑与修复：六个真实问题

症状 → 原因 → 修复

这些坑都实际发生过；照着“症状”排查，比从头读代码快。

PIT 01

GL Compatibility 灯不亮

症状：环境光/自发光正常，方向光/点光几乎不亮；最小场景也一样。

修复：切 Mobile/Vulkan；Forward+ 在本机 MoltenVK 上 shader 编译失败，不采用。

PIT 02

uniform 初始值不是常量

症状：shader 报 Expected constant expression。

修复：vec2(1.0/640.0, 1.0/360.0) 改成字面量 vec2(0.0015625, 0.0027777778)，或从脚本传 uniform。

PIT 03

look_at 时节点还没进树

症状：Node not inside tree. Use look_at_from_position() instead.

修复：先 add_child，再设 global_position / look_at。

PIT 04

换渲染器后整体过曝

症状：草地荧光绿、石板纯白。

修复：重新校准太阳/环境/曝光；把黄昏提亮改成 dusk_glow 曲线，只在黄昏抬 0.3 档曝光。

PIT 05

光柱变成斜条纹

症状：大面积半透明 Quad 盖住画面。

修复：减少数量/宽度/长度，alpha 降到 0.09–0.12，移到背景树冠；月光束单独保留。

PIT 06

雾/云影露出矩形边

症状：Plane 的四个角/边明显。

修复：在雾 shader 里加 radial = smoothstep(0.55,0.12,length(UV-0.5))；云影强度压到 0.02–0.06。

PIT 07

萤火在白天还亮着

症状：切到白天后旧粒子还在飞。

修复：初始化 emitting=false、amount_ratio=0；只在时间曲线的夜间窗口开启。

PIT 08

云影把画面压脏

症状：整张图像蒙了一层灰。

修复：云影强度从 0.1+ 降到 0.02–0.06；夜间进一步减弱。

PIT 09

相机吸附太粗会跳格

症状：缓慢环绕时相机一格一格跳。

修复：吸附保持 0.04 世界单位；如果相机完全静止可以不做吸附。
