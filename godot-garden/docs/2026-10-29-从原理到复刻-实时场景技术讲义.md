## 1. 实时渲染的最小模型

### 1.1 原理：一帧里发生了什么

实时渲染每帧大致经历：

```text
游戏逻辑更新
  → 可见性裁剪（视锥/遮挡）
  → 提交 Draw Call（CPU 告诉 GPU 画什么）
  → 顶点着色器（每个顶点）
  → 图元装配 + 光栅化（三角形 → 像素）
  → 片元着色器（每个像素）
  → 深度/模板/混合测试
  → 写入帧缓冲
  → 后处理（可选）
  → 显示到屏幕
```

关键结论：

- **像素越少，片元着色器执行次数越少**。640×360 的片元数约是 1920×1080 的 1/9。
- **Draw Call 是 CPU 开销**。同样的草，拆成 4000 个节点提交和用一个实例化网格提交，GPU 工作量接近，CPU 差距巨大。
- **顶点着色器按顶点跑，片元着色器按像素跑**。草的风摆放在顶点着色器，水/花的细节放在片元着色器。
- **后处理是另一轮全屏渲染**：把场景画到一张纹理（Render Target），再用一个全屏三角形/四边形对它采样。

### 1.2 Render Target：离屏渲染

Render Target（渲染目标 / 渲染纹理）是一张 GPU 纹理，场景先画到它上面，而不是直接画到窗口。

用途：

- 低分辨率渲染后再放大（像素化）。
- 后处理（Bloom、调色、暗角）。
- 小地图、镜面反射、监控摄像头、UI 背景模糊。

在 Godot 里：

```gdscript
var viewport := SubViewport.new()
viewport.size = Vector2i(640, 360)
viewport.render_target_update_mode = SubViewport.UPDATE_ALWAYS
viewport.own_world_3d = true
add_child(viewport)

var camera := Camera3D.new()
viewport.add_child(camera)
# 3D 世界节点都加到 viewport 下

var display := TextureRect.new()
display.texture = viewport.get_texture()
display.texture_filter = CanvasItem.TEXTURE_FILTER_NEAREST
display.set_anchors_and_offsets_preset(Control.PRESET_FULL_RECT)
add_child(display)
```

要点：

- `SubViewport` 自己有一个 World3D；`own_world_3d = true` 让它拥有独立的 3D 世界，不干扰主场景。
- `UPDATE_ALWAYS` 表示每帧更新；也可以按需更新（小地图）。
- `TextureRect` 的 `NEAREST` 决定放大时不插值。

其他引擎：

| 概念 | Godot | Unity | Unreal | Three.js |
|---|---|---|---|---|
| 离屏渲染 | `SubViewport` | `RenderTexture` + `Camera.targetTexture` | `SceneCapture2D` + `TextureRenderTarget2D` | `WebGLRenderTarget` |
| 显示到 UI | `TextureRect` | `RawImage` | UMG `Image` | 全屏 Quad + `ShaderMaterial`，或 CSS/Canvas 覆盖 |
| 最近邻过滤 | `TEXTURE_FILTER_NEAREST` | `FilterMode.Point` | `TextureFilter = TF_Nearest` | `minFilter/magFilter = NearestFilter` |

### 1.3 Draw Call 与实例化

一个 Draw Call 是 CPU 向 GPU 提交一批网格+材质+状态的命令。数量太多会被 CPU 提交拖慢。

实例化（Instancing）把同一个网格的多个副本合成一次提交，每个副本只传一个变换矩阵（和可选的自定义数据）。

| 概念 | Godot | Unity | Unreal | Three.js |
|---|---|---|---|---|
| 实例化 | `MultiMesh` / `MultiMeshInstance3D` | `Graphics.DrawMeshInstanced` / GPU Instancing | `InstancedStaticMesh` / `HierarchicalISM` / Foliage | `InstancedMesh` |
| 每实例数据 | `INSTANCE_CUSTOM` | `MaterialPropertyBlock` / instancing buffer | `PerInstanceCustomData` | `InstancedBufferAttribute` |
| 草地常用 | MultiMesh 十字面片 | GPU Instancer / 手写 instancing | Foliage / HISM | InstancedMesh + 自定义 shader |

### 1.4 着色器阶段与渲染状态

一个空间（3D）着色器至少有：

```text
vertex()   → 改顶点位置/法线/UV，传 varying 给片元
fragment() → 算颜色/粗糙度/金属度/自发光，或 discard 丢弃像素
```

常见渲染状态：

- `cull_back` / `cull_front` / `cull_disabled`：背面剔除。草叶/花是双面，需要 `cull_disabled`。
- `depth_draw_opaque` / `depth_draw_never` / `depth_prepass_alpha`：是否写深度。
- `blend_mix` / `blend_add` / `blend_mul`：混合方式。萤火/光柱用加法，云影用乘法/透明叠加。
- `unshaded`：不受光照，适合 UI 式光晕/纯色雾。
- `discard`：丢弃片元，适合草叶/花的形状遮罩。

### 1.5 颜色空间与 Tonemap

这是跨引擎最容易翻车的地方。

- **sRGB 纹理**：美术贴图通常是 sRGB 编码；引擎采样时会转到线性空间做光照计算。
- **线性光照**：光照/混合应在线性空间做，否则亮部/暗部会不对。
- **HDR**：Bloom 需要值大于 1 的亮部；渲染目标要支持 HDR。
- **Tonemap**：把 HDR 亮度压到 0–1；ACES/Filmic/Reinhard 曲线不同。
- **Gamma 输出**：最后转到 sRGB 显示。

如果颜色发灰/发黑/过曝，排查顺序：

1. 项目/渲染管线是否在 Linear 色彩空间？
2. 贴图是否标记为 sRGB？
3. 是否重复做了 gamma 校正？
4. Tonemap 与曝光是否叠加过多？
5. 后处理是否在 sRGB 纹理上做线性运算？

Godot：`Environment.tonemap_mode`、`tonemap_exposure`、`glow_hdr_threshold`。
Unity URP：Volume 的 `Tonemapping`、`Color Adjustments`；Project Settings → Player → Color Space = Linear。
Unreal：Post Process Volume 的 `Film/ACES`、`Exposure`；默认 Linear。
Three.js：`renderer.toneMapping = ACESFilmicToneMapping`；`renderer.outputColorSpace = SRGBColorSpace`。

### 1.6 练习

1. 在你的引擎里创建一张 640×360 的 Render Target，用 Point/Nearest 显示到 UI。
2. 用 Profiler/Frame Debugger 找到当前场景的 Draw Call 数，指出最大的三个来源。
3. 把同一张 sRGB 贴图分别在线性/伽马空间下采样，观察亮度差异。

## 2. 像素化管线：低分辨率 + 最近邻 + UI 分离

### 2.1 原理

“像素风”不是把画面模糊后再加马赛克；正确做法是 **用低分辨率渲染**：

```text
3D 世界 → 640×360 渲染目标 → NEAREST 放大到 1920×1080 → 显示
UI     → 1920×1080 独立层（不经过低分辨率）
```

好处：

- 像素块大小由内部分辨率决定，不随窗口大小变化。
- 片元着色器只跑 640×360 次，性能好。
- UI 文字/图标保持高清，不会变成马赛克。

放大方式：

- `NEAREST`：硬边像素，适合像素风。
- `LINEAR`：平滑放大，适合“低分辨率但柔和”的风格。
- 整数倍放大（3×）最稳定；非整数倍会导致像素大小不一致（3px/4px 混合）。

### 2.2 相机吸附（Pixel Snapping）

即使分辨率固定，相机缓慢移动时，场景在像素网格上的覆盖会不断变化，产生“爬行/闪烁”。解决：

```text
world_per_pixel ≈ view_height / render_height
camera_position = round(camera_position / snap) * snap
snap ≈ world_per_pixel × k（k=0.5~1）
```

我们的参数：视野高度约 15.7m，内部 360px → 每像素约 0.0436m；相机吸附 0.04 世界单位，接近 1 像素。

注意：

- 吸附太粗会“跳格”。
- 吸附只在低分辨率/像素风需要；高分辨率写实场景不需要。
- 相机旋转/缩放也会改变像素覆盖；如果做像素风，尽量固定 FOV/距离，只做轻微位移。

### 2.3 后处理与源像素对齐

如果后处理在 1920×1080 的放大图上跑，`FRAGCOORD`/`gl_FragCoord` 是屏幕像素；而底图是 3×3 的源像素块。这时做 1px 的抖动/描边，会在每个 3×3 块里出现 1px 噪点，既不是像素风也不干净。

两种正确做法：

1. 后处理放在 640×360 的渲染目标内（推荐）；最后只做 NEAREST 放大。
2. 后处理在放大图上跑时，把采样 UV 对齐到源像素中心：

```glsl
vec2 cell = floor(UV * vec2(640.0, 360.0));
vec2 uv = (cell + 0.5) / vec2(640.0, 360.0);
vec3 base = texture(TEXTURE, uv).rgb;
```

我们的最终实现用了第 2 种（Display 上挂 CanvasItem shader），所以 UI 仍在外层保持高清。

### 2.4 Godot 实现

- 世界：`SubViewport` 640×360，`own_world_3d=true`，MSAA/SSAA/TAA 关闭。
- 显示：`TextureRect`，`texture_filter=NEAREST`，`stretch_mode=STRETCH_SCALE`。
- UI：同级的 `CanvasLayer`，不进入 SubViewport。
- 相机：`_camera_position()` 里按 0.04 吸附；环绕幅度 ±0.025 rad。
- 后处理：Display 的 `ShaderMaterial`；采样源像素中心；不做全屏 dither/量化（会与 3× 网格冲突）。

### 2.5 跨引擎等价

**Unity URP（C#）**

```csharp
var rt = new RenderTexture(640, 360, 24, RenderTextureFormat.DefaultHDR);
rt.filterMode = FilterMode.Point;
rt.Create();
var cam = worldCamera;           // 只渲染 3D 的相机
cam.targetTexture = rt;
var raw = uiImage;               // Canvas 里的 RawImage
raw.texture = rt;

// 每帧或 LateUpdate 吸附相机位置
float snap = 0.04f;
var p = cam.transform.position;
p.x = Mathf.Round(p.x / snap) * snap;
p.z = Mathf.Round(p.z / snap) * snap;
cam.transform.position = p;
```

- UI Canvas 设置为 Screen Space - Overlay 或独立的 Screen Space - Camera，不要进入 RT。
- URP 后处理：Volume + `Tonemapping`/`Bloom`/`Color Adjustments`/`Vignette`；自定义后处理用 URP Renderer Feature（Full Screen Pass）。
- 注意：RenderTexture 的 `filterMode` 是纹理级；在 Canvas 上还要确保 RawImage 的材质/纹理采样不过滤。

**Unreal Engine 5（蓝图/材质）**

- 用一个 `SceneCaptureComponent2D` 捕获 3D 场景到 `TextureRenderTarget2D`（640×360）。
- Render Target 的 `TextureFilter` 设为 `Nearest`。
- UMG `Image` 显示 Render Target；UI 在 UMG 里，天然高清。
- 相机吸附：在 Tick 里把相机位置按 snap 取整（注意 Unreal 单位是厘米，0.04m = 4cm）。
- 后处理：Post Process Volume + Post Process Material（Blendable）；或直接对 SceneCapture 的 Render Target 做材质后处理。
- 注意：SceneCapture 每帧捕获成本高；小场景可接受；大场景优先用 `r.ScreenPercentage` 或自定义渲染管线。

**Three.js（JS）**

```js
const rt = new THREE.WebGLRenderTarget(640, 360, {
  minFilter: THREE.NearestFilter,
  magFilter: THREE.NearestFilter,
  depthBuffer: true
});
renderer.setRenderTarget(rt);
renderer.render(scene, camera);
renderer.setRenderTarget(null);

// 全屏 quad（正交相机）显示 rt.texture
const quadScene = new THREE.Scene();
const quadCam = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);
const quad = new THREE.Mesh(
  new THREE.PlaneGeometry(2, 2),
  new THREE.ShaderMaterial({
    uniforms: { tDiffuse: { value: rt.texture } },
    vertexShader: `varying vec2 vUv; void main(){ vUv=uv; gl_Position=vec4(position.xy,0.,1.); }`,
    fragmentShader: `uniform sampler2D tDiffuse; varying vec2 vUv;
      void main(){ gl_FragColor = texture2D(tDiffuse, vUv); }`
  })
);
quadScene.add(quad);
renderer.render(quadScene, quadCam);
```

- UI 用 DOM/CSS 覆盖在 canvas 上，或单独的高分辨率 Canvas。
- `renderer.outputColorSpace = THREE.SRGBColorSpace`，`toneMapping = ACESFilmicToneMapping`。
- 相机吸附：`camera.position.x = Math.round(x / snap) * snap`。

### 2.6 常见坑

- UI 放进了低分辨率 RT → 文字糊。
- 纹理过滤是 `Bilinear`，不是 `Point/Nearest`。
- 渲染目标带 MSAA/TAA → 像素边缘变软。
- 后处理 dither 用了屏幕像素，而不是源像素格。
- 非整数倍放大 → 像素块大小不一致。
- 相机吸附太粗 → 跳格；太细 → 闪烁。

### 2.7 练习

1. 在任意引擎里做 480×270 / 640×360 / 960×540 三档，NEAREST 放大到 1920×1080，截图对比。
2. 把 UI 放在 RT 外，确认文字清晰。
3. 把相机吸附从 0.04 改成 0.2，观察跳格；改成 0.005，观察闪烁。

## 3. 光照与颜色：三盏方向光 + 环境

### 3.1 原理

实时渲染的常见光类型：

- **Directional Light**：平行光，模拟太阳/月亮；只有方向，没有位置。
- **Point Light**：点光，从一点向四周；有位置、范围、衰减。
- **Spot Light**：聚光，有方向、内外锥角；路灯/手电。
- **Ambient / Sky Light**：环境光，均匀照亮暗部；不产生方向/阴影。

直接光的基本漫反射：

```text
diffuse = albedo × max(N · L, 0) × lightColor × intensity
```

- `N` 是法线，`L` 是指向光源的单位向量。
- 点光还要乘距离衰减（不同引擎公式不同）。

高光（简化 Blinn-Phong / GGX）：

```text
specular ≈ pow(max(N · H, 0), shininess) × specularColor
H = normalize(L + V)
```

风格化光照常用：

- **Wrap diffuse**：`(N·L × 0.5 + 0.5)`，让暗部不死黑。
- **Backlight/透光**：给叶/草一点背光颜色，模拟透光。
- **Rim light**：`pow(1 - N·V, p)`，勾轮廓。

阴影：

- 从光源视角渲染深度图；相机视角比较深度。
- 需要 bias 防止自阴影（shadow acne）；bias 太大会“影子脱离物体”（peter-panning）。
- 方向光常用级联阴影（CSM/splits）：近处精度高，远处精度低。

Tonemap/曝光：

- 现实亮度范围很大；渲染到 HDR，再压到屏幕。
- 曝光决定整体亮度；Tonemap 曲线决定高光滚降。
- 不同引擎的光照单位不同：Unity/Unreal 用物理单位（lux/lumen/candela），Godot/Three.js 更偏任意 intensity。

### 3.2 我们的实现

- **Sun**：暖橙→暖白；能量 `pow(day,0.5) × (2.2 + dusk_glow×1.4)`；4 split 阴影；正午约 70°（不是 90°），黄昏约 25°。
- **Moon**：冷蓝；能量 `pow(night,0.8)×0.48`；阴影关闭（性能）。
- **SkyFill**：冷蓝补光；能量 `0.08 + dusk_glow×0.45 + night×0.15 + twilight×0.15`；不投影。
- **环境光**：能量 `0.32 + day×0.3 + dusk_glow×0.8 + twilight×0.35`；黄昏环境色偏冷，暖色交给太阳和路灯。
- **曝光**：`1.0 + dusk_glow×0.45`。
- **路灯**：8 个 OmniLight3D，range 7，energy `2.15×level×flicker`；玻璃自发光 + Sprite3D 光晕。
- **Tonemap**：ACES；glow 阈值 1.15。

### 3.3 跨引擎等价

| 概念 | Godot | Unity URP | Unreal | Three.js |
|---|---|---|---|---|
| 方向光 | `DirectionalLight3D` | `Light.type=Directional` | `DirectionalLight` | `DirectionalLight` |
| 点光 | `OmniLight3D` | `Light.type=Point` | `PointLight` | `PointLight` |
| 环境光 | `Environment.ambient_light_*` | `RenderSettings.ambient*` / Volume | `SkyLight` / Post Process | `AmbientLight` / `HemisphereLight` |
| 阴影 | `shadow_enabled` + splits | `shadowDistance`、URP shadows | `Cast Shadows`、CSM | `castShadow` + `shadow.mapSize` |
| Tonemap | `Environment.tonemap_*` | Volume `Tonemapping` | Post Process `Film/ACES` | `renderer.toneMapping` |
| 曝光 | `tonemap_exposure` | `Color Adjustments`/Exposure | `Exposure Compensation`/Auto Exposure | `toneMappingExposure` |
| Bloom | `Environment.glow_*` | Volume `Bloom` | Post Process `Bloom` | `UnrealBloomPass` |

**Unity URP 光照/后处理（示意）**

```csharp
// 3 盏方向光：Sun / Moon / Fill
sun.type = LightType.Directional;
sun.color = new Color(1f, 0.64f, 0.34f);
sun.intensity = sunEnergy;              // 注意 URP 方向光单位是 lux
sun.shadows = LightShadows.Soft;

// Volume：Tonemapping + Bloom + Color Adjustments + Vignette
var volume = gameObject.AddComponent<Volume>();
volume.profile = ScriptableObject.CreateInstance<VolumeProfile>();
volume.profile.Add<Tonemapping>(t => t.mode.value = TonemappingMode.ACES);
volume.profile.Add<Bloom>(b => b.intensity.value = bloom);
volume.profile.Add<Vignette>(v => v.intensity.value = vignette);
```

**Unreal（蓝图/材质思路）**

- 3 个 Directional Light：Sun（Movable/Stationary，开 CSM）、Moon（低强度、冷色）、Fill（无阴影）。
- SkyLight 提供环境光；Post Process Volume 控制 Exposure Compensation、Bloom、Color Grading。
- 关闭 Auto Exposure（或用固定曝光），否则时间变化会被自动曝光抵消。
- 光柱/体积光可用 Volumetric Fog + Light Shaft 相关设置（比 Godot Mobile 容易）。

**Three.js**

```js
const sun = new THREE.DirectionalLight(0xffa060, sunEnergy);
sun.castShadow = true;
sun.shadow.mapSize.set(2048, 2048);
sun.shadow.camera.left = -20; sun.shadow.camera.right = 20;
sun.shadow.camera.top = 20; sun.shadow.camera.bottom = -20;

const moon = new THREE.DirectionalLight(0x88aaff, moonEnergy);
const fill = new THREE.DirectionalLight(0x88aaff, fillEnergy);
const ambient = new THREE.AmbientLight(0x445566, ambientEnergy);

renderer.toneMapping = THREE.ACESFilmicToneMapping;
renderer.toneMappingExposure = exposure;
```

### 3.4 常见坑

- **光照单位不同**：Unity/Unreal 的 lux/lumen 不能直接套 Godot/Three.js 的数字。
- **Auto Exposure**：Unreal 默认自动曝光，会把你的时间曲线抹平；先关掉。
- **Gamma/Linear**：项目色彩空间不对，亮部/暗部会整体偏。
- **环境光太亮**：所有阴影被填平，物体没有体积；宁可冷色补光，也不要用高亮暖色环境光。
- **Shadow bias**：太小有 acne，太大影子脱离；先调 normal bias，再调 bias。
- **阴影级联**：4 split 比 1 split 贵；移动端/低端机用 2 split 或不投影。

### 3.5 练习

1. 用 Sun/Moon/Fill + 环境光搭一个黄昏，要求亮部暖、暗部冷。
2. 把环境光从暖色改成冷色，观察暗部颜色变化。
3. 在 4 split / 2 split / 关闭阴影之间对比 FPS 和画面。

## 4. 时间系统：太阳高度与五条曲线

### 4.1 原理

不要用一组“预设”（早晨/中午/夜晚）做离散切换；用 **连续函数** 把 `hours` 映射到每个参数：

```text
hours (0–24)
  → sun_alt = sin((hours - sunrise) / daylight * PI)
  → day = clamp(sun_alt, 0, 1)
  → night = clamp(-sun_alt, 0, 1)
  → 各效果用 smoothstep 窗口
```

好处：

- 任意拖动时间都能得到一致结果。
- 可以自动播放（×600 速度）。
- 每个效果独立调窗口，不会互相打架。

`smoothstep(a, b, x)`：

```text
t = clamp((x-a)/(b-a), 0, 1)
result = t*t*(3-2t)
```

它比线性 `lerp` 更自然：两端平缓，中间过渡。

### 4.2 我们的曲线

```gdscript
sun_alt = sin((hours - 4.9) / 14.2 * PI)
day = clamp(sun_alt, 0, 1)
night = clamp(-sun_alt, 0, 1)
low_sun = clamp(1 - abs(sun_alt)/0.55, 0, 1) * (1 - night)
dusk_glow = smoothstep(0.05, 0.18, day) * (1 - smoothstep(0.45, 0.8, day))
twilight = smoothstep(18.6, 19.2, hours) * (1 - smoothstep(20.4, 21.6, hours))
```

- 4.9 点日出、19.1 点日落、12 点最高。
- `dusk_glow`：太阳还在地平线上但很低时，补环境光/曝光，避免黄昏过暗。
- `twilight`：太阳落山后补冷蓝环境光，避免直接死黑。
- 路灯窗口：17:24 开始，19:24 全亮，05:12–06:48 渐灭。
- 萤火窗口：19:12 开始，21:00 全亮，05:12–06:48 渐灭。
- 光束窗口：夕阳 16:12–19:48；晨光 05:00–08:48。

### 4.3 更新顺序

每帧：

```text
1. hours += delta * speed
2. 计算 day/night/low_sun/dusk_glow/twilight
3. 更新太阳/月亮/补光的方向/颜色/能量
4. 更新环境光/雾/曝光/glow
5. 更新路灯/萤火/水面/光柱/云影
6. 更新后处理 uniform
7. 更新 UI 时钟/滑杆
```

顺序很重要：后处理依赖光照结果；UI 只依赖 hours。

### 4.4 跨引擎等价

**Unity C#**

```csharp
float sunAlt = Mathf.Sin((hours - 4.9f) / 14.2f * Mathf.PI);
float day = Mathf.Clamp01(sunAlt);
float night = Mathf.Clamp01(-sunAlt);
float duskGlow = Mathf.SmoothStep(0f, 1f, Mathf.InverseLerp(0.05f, 0.18f, day))
               * (1f - Mathf.SmoothStep(0f, 1f, Mathf.InverseLerp(0.45f, 0.8f, day)));
```

- 用 `Mathf.Deg2Rad`/`Rad2Deg` 转换角度。
- 用 `AnimationCurve`/Timeline 也可以，但连续函数更容易拖动。

**Unreal（蓝图/材质）**

- 蓝图：`Sin`、`Clamp`、`SmoothStep`、`Lerp` 节点；用 `Timeline` 或 Tick 更新 hours。
- 材质：`Time` 节点 + `Material Parameter Collection` 传 `hours`；或用 `Curve Atlas`。
- 后处理参数可通过 Blueprint 设置 Post Process Volume 的 `Settings`。

**Three.js**

```js
const sunAlt = Math.sin((hours - 4.9) / 14.2 * Math.PI);
const day = THREE.MathUtils.clamp(sunAlt, 0, 1);
const night = THREE.MathUtils.clamp(-sunAlt, 0, 1);
const smoothstep = (a, b, x) => {
  const t = THREE.MathUtils.clamp((x - a) / (b - a), 0, 1);
  return t * t * (3 - 2 * t);
};
```

### 4.5 常见坑

- 角度/弧度混用。
- `lerp` 用上一帧状态做插值，拖动时间时会“追不上”；用绝对函数。
- 时间曲线和动画/粒子时间混在一起，导致回放不一致。
- 自动播放速度与 `delta` 绑定；暂停时要停止累加。
- UI 滑杆回写时间时触发“用户改变”信号，导致自动播放暂停/循环；用 `updating` 标志防回环。

### 4.6 练习

1. 实现 24h 太阳/月亮，要求 18:00 还有 20–30° 低太阳。
2. 给路灯/萤火各写一条 smoothstep 窗口，时间滑杆拖动时验证顺序。
3. 加一个“蓝调时刻”冷色环境光，避免日落后直接黑屏。

## 5. 程序化几何：曲线、条带、拱门、石板

### 5.1 原理

一个网格至少包含：

- 顶点位置（object space）
- 索引（三角形如何连接）
- 法线（光照）
- UV（贴图/遮罩）
- 可选：顶点色、切线、骨骼权重、实例数据

生成网格的通用步骤：

```text
生成顶点/UV/法线
  → 生成索引（注意三角形绕序/正面）
  → 写入 Mesh/ArrayMesh/BufferGeometry
  → 交给 MeshRenderer/MeshInstance
```

绕序（winding）：

- 多数引擎默认逆时针为正面（从外部看）。
- 绕序反了会看到背面/全黑；可用 `cull_disabled` 排查，但最好修正。

法线：

- 平面/盒子用面法线；曲面用平均/平滑法线。
- 非均匀缩放会扭曲法线，需要逆转置矩阵；引擎通常自动处理，但自定义 shader 要小心。

### 5.2 我们的实现

**石径条带（SurfaceTool）**

```gdscript
# 对曲线采样，沿切线生成左右两条边，拼三角形
var side = Vector3(tangent.z, 0, -tangent.x).normalized()
var a = p0 + side0 * width * 0.5
var b = p0 - side0 * width * 0.5
...
```

- `Curve3D` 采样位置；`sample_baked(s)` 取点。
- 切线 = 前后采样点之差；侧向 = 切线在水平面的垂线。
- 条带适合路、河、轨道、丝带。

**拱门（半圆上的 Box 段）**

```gdscript
for i in 13:
    var a = PI * i / 12.0
    var p = Vector3(cos(a) * r, pillar_height + sin(a) * r, 0)
    var seg = add_box(p, Vector3(0.46, 0.34, 0.56))
    seg.rotation.z = a + PI * 0.5   # 长边沿圆弧切线
```

- 每段 Box 的局部 X 轴沿圆弧切线；绕 Z 旋转 `a + 90°`。
- 跳过 2–4 段 → 断顶。

**不规则石板**

- 用 6–8 边 CylinderMesh（top_radius < bottom_radius），再在 X/Z 上非均匀缩放。
- 顶部小、底部大 → 倒角；随机旋转/缩放 → 不规则。
- 比 BoxMesh 更像被踩过的石板。

### 5.3 跨引擎等价

| 概念 | Godot | Unity | Unreal | Three.js |
|---|---|---|---|---|
| 曲线 | `Curve3D` | `Spline`/`AnimationCurve` | `USplineComponent` | `CatmullRomCurve3` |
| 手工网格 | `SurfaceTool`/`ArrayMesh` | `Mesh`/`MeshFilter` | `ProceduralMeshComponent`/Geometry Script | `BufferGeometry` |
| 盒子/圆柱 | `BoxMesh`/`CylinderMesh` | `GameObject.CreatePrimitive` | `UStaticMesh`/`UProceduralMeshComponent` | `BoxGeometry`/`CylinderGeometry` |
| 条带 | 手写三角带 | 手写 Mesh | Spline Mesh | `TubeGeometry`/手写 BufferGeometry |
| 拱门 | 半圆 Box 段 | 半圆 Box 段 | 半圆 StaticMesh 段 | 半圆 Box 段 |

**Unity 生成条带（示意）**

```csharp
var mesh = new Mesh();
var verts = new List<Vector3>();
var tris = new List<int>();
for (int i = 0; i <= steps; i++) {
    Vector3 p = curve.GetPoint(i / (float)steps);
    Vector3 t = curve.GetTangent(i / (float)steps);
    Vector3 side = Vector3.Cross(Vector3.up, t).normalized;
    verts.Add(p + side * width * 0.5f);
    verts.Add(p - side * width * 0.5f);
    if (i < steps) {
        int k = i * 2;
        tris.AddRange(new[] { k, k+1, k+2, k+1, k+3, k+2 });
    }
}
mesh.SetVertices(verts);
mesh.SetTriangles(tris, 0);
mesh.RecalculateNormals();
```

**Three.js 生成条带（示意）**

```js
const positions = [];
const indices = [];
for (let i = 0; i <= steps; i++) {
  const t = i / steps;
  const p = curve.getPoint(t);
  const tan = curve.getTangent(t);
  const side = new THREE.Vector3().crossVectors(new THREE.Vector3(0,1,0), tan).normalize();
  positions.push(p.clone().addScaledVector(side, width/2).toArray());
  positions.push(p.clone().addScaledVector(side, -width/2).toArray());
  if (i < steps) {
    const k = i*2;
    indices.push(k,k+1,k+2, k+1,k+3,k+2);
  }
}
const geo = new THREE.BufferGeometry();
geo.setAttribute('position', new THREE.Float32BufferAttribute(positions, 3));
geo.setIndex(indices);
geo.computeVertexNormals();
```

### 5.4 常见坑

- 绕序反了 → 看不见/背面黑。
- 没有法线 → 光照全黑/奇怪。
- UV 没设 → 贴图/遮罩错。
- 非均匀缩放后法线错 → 自定义 shader 用逆转置。
- 每个石板一个 Mesh → Draw Call 爆炸；后续用 MultiMesh/InstancedMesh 合并。
- 曲线采样间距太大 → 条带折线感；0.2–0.5m 较合适。

3. 把石板从 BoxMesh 改成 6–8 边倒角圆柱，观察轮廓差异。

## 6. 实例化与植被：MultiMesh、顶点风、UV 遮罩

### 6.1 原理

草/花/落叶的共同点：

- 数量大（几千到几万）
- 形状简单（面片/小几何）
- 每株只有位置/旋转/缩放/颜色变化

正确做法：

```text
一个网格 + 一个材质 + N 个实例变换/自定义数据
→ 1 次 Draw Call
```

顶点风：

```glsl
float h = UV.y; // 0 根，1 尖
float sway = sin(TIME * speed + phase + worldPos.x) * wind * h * h;
VERTEX.x += sway;
```

- 只让顶部摆动（`h*h`），根部固定。
- 每株相位不同（实例自定义数据/世界位置），避免整片草地同频。
- 风摆放在顶点着色器，不增加片元成本。

UV 遮罩：

- 草叶：`UV.y` 从根到尖；`UV.x` 控制宽度；`discard` 掉三角形外的像素。
- 花：下段是茎，上段用极坐标 `cos(5θ)` 切五瓣。
- 不需要贴图，省内存；但边缘会有硬像素（适合像素风）。

### 6.2 我们的实现

- 3 种草型：中草 2800、短草 1600、高草 700；3 个 MultiMesh。
- 每个 MultiMesh 一个十字面片 mesh（两片交叉的四边形），`use_custom_data=true`。
- `INSTANCE_CUSTOM.x` 是风相位，`.y` 是颜色变化。
- 草不投影（`cast_shadow=OFF`），只接收光照。
- 花：`flower.gdshader` + 十字面片；白 380、蓝紫 160；MultiMesh。
- 树叶/落叶：小 Box/球，数量少，单独节点可接受；数量大也应实例化。

### 6.3 跨引擎等价

**Unity（GPU Instancing）**

```csharp
var matrices = new Matrix4x4[count];
var colors = new Vector4[count];
for (int i = 0; i < count; i++) {
    matrices[i] = Matrix4x4.TRS(pos[i], Quaternion.Euler(0, rot[i], 0), Vector3.one * scale[i]);
    colors[i] = new Vector4(phase[i], variation[i], 0, 0);
}
var block = new MaterialPropertyBlock();
block.SetVectorArray("_CustomData", colors);
Graphics.DrawMeshInstanced(mesh, 0, material, matrices, count, block, ShadowCastingMode.Off);
```

- Shader 里用 `UNITY_INSTANCING_BUFFER` / `UNITY_SETUP_INSTANCE_ID` 或 `_CustomData`。
- URP 的 Shader Graph 有 `Instance` 节点；手写 HLSL 更灵活。
- 草不投影，`ShadowCastingMode.Off`。

**Unreal（HISM/Foliage）**

- 用 `HierarchicalInstancedStaticMeshComponent` 或 Foliage 工具刷草。
- 材质里用 `World Position Offset` 做风摆：`sin(Time*Speed + WorldPosition.x*0.5) * Wind * VertexNormal?` 用 `VertexInterpolator`/`Custom` 控制根部固定（可以用 UV/顶点色）。
- `PerInstanceCustomData` 传相位/颜色变化；材质节点 `PerInstanceCustomData`。
- 草的阴影关闭：`Cast Shadow` off；或使用低分辨率阴影。

**Three.js**

```js
const inst = new THREE.InstancedMesh(grassGeo, grassMat, count);
const dummy = new THREE.Object3D();
for (let i = 0; i < count; i++) {
  dummy.position.set(x[i], 0, z[i]);
  dummy.rotation.y = rot[i];
  dummy.scale.setScalar(scale[i]);
  dummy.updateMatrix();
  inst.setMatrixAt(i, dummy.matrix);
}
inst.instanceMatrix.needsUpdate = true;
scene.add(inst);
```

- 自定义 `ShaderMaterial` 里用 `instanceMatrix`；`attribute float aPhase` 可以用 `InstancedBufferAttribute` 加到 geometry 上。
- 草不投影：`inst.castShadow = false`。

### 6.4 常见坑

- 每株一个 GameObject/Node → CPU/Draw Call 爆炸。
- 风相位用同一个时间 → 整片草同频摆动。
- 草投影 → 阴影 pass 成本翻倍；低端机直接关。
- UV 遮罩没有 `discard` → 面片是方片，不像草。
- 双面材质忘了 `cull_disabled` → 从某些角度看不见。
- 实例数据更新每帧忘记 `needsUpdate`。

### 6.5 练习

1. 用 MultiMesh/InstancedMesh 画 2000 株草，要求 1 个 Draw Call、不投影。
2. 给每株不同的风相位和颜色变化。
3. 把草叶从矩形改成三角形遮罩，观察像素风效果。

## 7. 水面：噪声、Fresnel、高光、假反射

### 7.1 原理

水面在实时渲染里通常是一个平面/网格 + 一套 shader，不是真的流体模拟。核心视觉信息：

- **颜色**：深水/浅水/浑浊。
- **波纹**：法线扰动（真实）或颜色扰动（廉价）。
- **反射**：天空/树/灯光；可用平面反射、屏幕空间反射、或假反射。
- **高光**：太阳/月亮的镜面反射。
- **岸边**：泡沫、湿石、浅水过渡。

Fresnel：

```text
F = pow(1 - max(dot(N, V), 0), p)
```

- 视线越平（掠射），反射越强；垂直看下去，水更透明/深色。
- `V` 是视线方向，`N` 是水面法线。

高光：

```text
R = reflect(-L, N)
spec = pow(max(dot(R, V), 0), shininess)
```

假反射：

- 用一个环境色/渐变，按 Fresnel 混合。
- 或者在岸边放加法光斑，模拟路灯倒影。
- 真正的平面反射需要额外相机/渲染目标，成本高。

### 7.2 我们的实现

- 48 段不规则岸线，三角扇水面；两层 value noise 波纹；Fresnel 混深浅色；太阳高光 `pow(...,70)`；夜间暖色波纹 + 压暗；岸边 4 片睡莲 + 6 根芦苇 + 噪声打断的泡沫环。
- 水面不透明；岸线用 alpha 混合的浅色环；灯光反射用两个加法 Quad。

**关键 shader 片段**

```glsl
float fresnel = pow(1.0 - max(dot(normal, view), 0.0), 2.2);
vec3 col = mix(deep_color, shallow_color, 0.22 + fresnel*0.4 + ripple*0.1);
col += glint_color * pow(max(dot(reflect(-sun_dir, normal), view),0.0), 70.0);
col = mix(col, deep_color, depth*0.35);
```

### 7.3 跨引擎等价

| 概念 | Godot | Unity URP | Unreal | Three.js |
|---|---|---|---|---|
| 水面 shader | ShaderMaterial | Shader Graph/HLSL | Material/HLSL | ShaderMaterial |
| 噪声 | 手写 value noise | Shader Graph Noise/HLSL | Material Noise/HLSL | GLSL noise |
| 反射 | 假反射/环境色 | Planar Reflection/SSR/假反射 | Planar Reflection/SSR/假反射 | Reflector/假反射 |
| 泡沫 | 噪声 alpha 环 | 贴图/噪声 | 贴图/噪声 | 贴图/噪声 |

**Unity Shader Graph 思路**

- UV + Time → Noise → Normal From Height → 混入水面法线。
- Fresnel 节点 → 混深浅色；Specular 节点/手写高光。
- Scene Color/Reflection Probe 采样做反射；或用手绘环境色。

**Unreal 材质思路**

- `Water` 插件（单层水/海洋）可直接用；自定义材质用 `Panner` + `Noise` + `Fresnel` + `Reflection Vector`。
- 平面反射 Actor / Lumen 反射；移动端用假反射。

### 7.4 常见坑

- 透明水面排序错误；不透明水面更稳。
- 没有法线扰动 → 像塑料板。
- Fresnel 用反了 → 垂直看很亮，远处很暗。
- 反射采样用屏幕 UV 不对 → 反射错位。
- 泡沫整圈均匀 → 霓虹环；用噪声打断。

### 7.5 练习

1. 写一个水面 shader：两层噪声 + Fresnel + 高光。
2. 加一个噪声打断的泡沫环。
3. 比较“假反射（环境色）”和“真平面反射”的成本/效果。

## 8. 粒子与萤火：GPU 粒子、Billboard、加法混合

### 8.1 原理

粒子系统 = 发射器 + 每个粒子的生命周期：

```text
出生位置/速度 → 生命周期 → 颜色/大小/透明度曲线 → 死亡
```

关键参数：

- 发射形状：点/球/盒/圆锥。
- 初速度/方向/扩散。
- 重力/阻力/湍流。
- 生命周期/预 warm。
- 颜色渐变（color ramp）。
- 大小/旋转。
- 渲染模式：Billboard（永远面向相机）、Stretched Billboard、Mesh。
- 混合：Alpha（半透明）vs Additive（加法，发光）。
- 排序/深度：加法粒子通常不写深度。

萤火的特点：

- 小、亮、黄绿、忽明忽暗。
- 数量几十到几百。
- 加法混合 + 径向渐变 alpha。
- 夜间出现，白天隐藏。

### 8.2 我们的实现

- `GPUParticles3D`，220 个，box 15×1.6×15，lifetime 7s，preprocess 4s，fixed_fps 30。
- 材质：径向渐变贴图 + Billboard + Unshaded + Alpha + Additive + emission。
- 颜色渐变：0 透明 → 中间黄绿 → 1 透明。
- 时间控制：`emitting = level > 0.02`，`amount_ratio = clamp(level, 0.06, 1.0)`。

### 8.3 跨引擎等价

| 概念 | Godot | Unity | Unreal | Three.js |
|---|---|---|---|---|
| 粒子系统 | `GPUParticles3D` | Particle System/VFX Graph | Niagara | `Points`/`InstancedMesh` + shader |
| 材质 | `ParticleProcessMaterial` | Particle System modules | Niagara modules | 自定义 ShaderMaterial |
| Billboard | `BILLBOARD_ENABLED` | Render Mode Billboard | Sprite Renderer | 顶点朝相机 |
| 加法混合 | `BLEND_MODE_ADD` | Additive | Additive | `AdditiveBlending` |

**Unity VFX Graph**

- Spawn（Box）→ Initialize（位置/速度/寿命）→ Update（重力/湍流）→ Output（Billboard + Additive）。
- Color over Life 用 Gradient；Size over Life 用 Curve。
- 用 `VFX Property Binder` 把时间/强度绑到脚本。

**Unreal Niagara**

- Emitter：Box Location、Initial Velocity、Gravity、Color Curve、Sprite Renderer（Additive）。
- 用 Niagara Parameter Collection 传夜间强度。
- 预 warm：`Warmup Time`。

**Three.js**

```js
const geo = new THREE.BufferGeometry();
geo.setAttribute('position', new THREE.Float32BufferAttribute(positions, 3));
geo.setAttribute('aPhase', new THREE.Float32BufferAttribute(phases, 1));
const mat = new THREE.ShaderMaterial({
  transparent: true,
  blending: THREE.AdditiveBlending,
  depthWrite: false,
  uniforms: { uTime: { value: 0 }, uTex: { value: radialTexture } },
  vertexShader: `...`,
  fragmentShader: `...`
});
const points = new THREE.Points(geo, mat);
```

- 或在 `InstancedMesh` 里每帧更新矩阵；性能不如 Points/GPU 粒子。

### 8.4 常见坑

- 加法粒子写了深度 → 遮挡奇怪；通常 `depthWrite=false`。
- 白天没关发射 → 粒子残留；需要 emitting/amount 控制。
- 粒子数量太多 → overdraw/填充率爆炸；小粒子可接受。
- 没有预 warm → 进入夜晚时萤火要等几秒才出现。
- 粒子在低分辨率下变成方块 → 用径向渐变 alpha/柔和贴图。

### 8.5 练习

1. 做 100 只萤火，黄绿、加法、径向渐变，夜里出现白天消失。
2. 用 color ramp 做忽明忽暗。
3. 对比 Points/GPU 粒子和实例化 Mesh 的性能。

## 9. 体积光与大气：真体积 vs 假光柱

### 9.1 原理

体积光/丁达尔效应 = 光在空气中被微粒散射，形成可见光柱。真实做法：

- 体积雾（Volumetric Fog）+ 光源散射。
- 屏幕空间光轴（God Rays）：遮挡图 + 径向模糊。
- 光线步进（Raymarching）：在相机射线上采样密度/光照。

代价高，移动端/低端机通常用 **假光柱**：

- 一个半透明面片/锥体，沿光线方向摆放。
- 面向相机（billboard）或用一个固定方向的 Quad。
- Additive 混合，边缘/两端淡出，避免硬边。
- 可以叠加噪声/尘点。

### 9.2 我们的实现

- 4 条夕阳束 + 1 条月光束；每条是一个 Quad。
- 局部 Y 对齐光线方向，局部 Z 对齐相机：

```gdscript
right = dir.cross(to_cam).normalized()
normal = right.cross(dir).normalized()
basis = Basis(right, dir, normal)
mesh.global_transform = Transform3D(basis, anchor + dir*length*0.5)
```

- Shader：`unshaded` + `blend_add` + `depth_draw_never`；UV.x 边缘柔化，UV.y 两端淡出，轻微闪烁。

### 9.3 跨引擎等价

| 概念 | Godot | Unity URP | Unreal | Three.js |
|---|---|---|---|---|
| 真体积光 | Forward+ Volumetric Fog | HDRP Volumetric Fog / 自定义 | Volumetric Fog + Light Shaft | 自定义 raymarch |
| 假光柱 | 半透明 Quad | 半透明 Quad/Shader | 半透明 Mesh/材质 | 半透明 Plane/Shader |
| 上帝光 | 屏幕空间 God Rays | 自定义 Renderer Feature | Light Shaft Bloom | GodRaysPass |

**Unity/Unreal 注意**

- URP 没有内置体积雾（HDRP 有）；可以用自定义 Renderer Feature 或假面片。
- Unreal 的 Volumetric Fog + Directional Light 的 Light Shaft 很适合做丁达尔；但移动端要评估成本。
- 真体积光通常需要深度/阴影采样，半透明面片更便宜。

### 9.4 常见坑

- 面片太大/太正对镜头 → 变成斜条纹；减少数量/宽度/alpha，移到背景。
- 没有深度测试 → 光柱穿过树/角色；需要 `depth_draw_never` + 正常深度测试。
- Additive 叠加太多 → 画面发白。
- 雾密度/颜色不跟随时间 → 黄昏/夜晚不一致。

### 9.5 练习

1. 用 4 个面向相机的半透明 Quad 做夕阳束，要求两端淡出。
2. 加一个月光束，夜间出现。
3. 在 Unreal 里用 Volumetric Fog + Light Shaft 做同样效果，比较成本。

## 10. 后处理：Bloom、调色、暗角、抖动

### 10.1 原理

后处理链：

```text
场景 → RT → 亮部提取 → 模糊 → 与原图合成（Bloom）
     → Tonemap → 调色（lift/gamma/gain/LUT）
     → 暗角 → 抖动/量化 → 输出
```

- Bloom：阈值提取亮部，模糊，加法叠加；让灯光/萤火“晕开”。
- Tonemap：HDR → LDR；ACES/Filmic。
- 调色：阴影/中间调/高光分别染色；LUT 可以固化风格。
- 暗角：边缘压暗，聚焦中心。
- 抖动/量化：低分辨率/像素风用；注意在源像素格上做，不要在全屏放大图上做。

### 10.2 我们的实现

- Display 的 CanvasItem shader：8 tap 亮部柔光、暖/冷分级、饱和度、暗角。
- 采样锁定到 640×360 源像素中心；不做全屏 dither/量化（会与 3× 网格冲突）。
- Environment glow 负责灯光核心；post bloom 只做很轻的补充。

### 10.3 跨引擎等价

| 概念 | Godot | Unity URP | Unreal | Three.js |
|---|---|---|---|---|
| 后处理 | Environment + CanvasItem shader | Volume + Renderer Feature | Post Process Volume/Material | EffectComposer |
| Bloom | `glow_*` | `Bloom` | `Bloom` | `UnrealBloomPass` |
| Tonemap | `tonemap_*` | `Tonemapping` | `Film/ACES` | `renderer.toneMapping` |
| 调色 | `adjustment_*`/shader | `Color Adjustments`/LUT | `Color Grading`/LUT | `ShaderPass`/LUT |
| 暗角 | shader | `Vignette` | `Vignette` | `ShaderPass` |
| 自定义全屏 | CanvasItem shader | Full Screen Pass Renderer Feature | Post Process Material | `ShaderPass` |

**Unity URP 自定义后处理**

- 创建 `ScriptableRendererFeature` + `ScriptableRenderPass`。
- 在 `Blit` 时用 `Blitter.BlitCameraTexture`/`CommandBuffer.Blit` + 材质。
- 或 URP 14+ 的 Full Screen Pass Renderer Feature + Shader Graph。
- 注意 URP 的 render target 可能是 HDR/MSAA，需要 `ConfigureInput`/`renderPassEvent`。

**Unreal 后处理材质**

- 创建一个 `Post Process Material`，Domain = Post Process。
- `SceneTexture:PostProcessInput0` 采样场景；做 Bloom/调色/暗角，输出 Emissive Color。
- 加到 Post Process Volume 的 `Post Process Materials`（Blendable）。
- 注意 exposure/tonemap 顺序：通常 Tonemap 在后处理之后；自定义材质在 Tonemap 前后的位置会影响结果。

### 10.4 常见坑

- 后处理把 UI 也处理了 → 文字糊/量化；UI 单独一层。
- Bloom 阈值太低 → 石头/路面都发光；太高 → 灯光不晕。
- 在 sRGB 空间做线性运算 → 颜色不对；用线性 RT/HDR。
- dither 坐标在全屏像素 → 1px 噪点；对齐源像素。
- 多重后处理叠加（Environment glow + post bloom + sprite halo）→ 灯光过曝；三选一/收敛。

### 10.5 练习

1. 加 Bloom + Vignette + 调色，观察顺序变化。
2. 在低分辨率 RT 内做 dither，再 NEAREST 放大；对比在全屏做。
3. 用 LUT 把黄昏调成暖色、夜晚调成冷色。

## 11. 性能：填充率、Draw Call、阴影

### 11.1 原理

常见瓶颈：

- **CPU/Draw Call**：太多独立 Mesh/材质/状态切换。
- **GPU 填充率**：全屏后处理、透明/加法粒子、草叶 overdraw。
- **顶点**：高模/大量实例；通常不是瓶颈。
- **阴影**：额外的深度 pass；每个投影光源/级联。
- **Shader 复杂度**：噪声/采样/分支多的片元。
- **带宽**：高分辨率 RT、多次全屏采样。

优化顺序：

1. 降低渲染分辨率（640×360 vs 1920×1080，片元 1/9）。
2. 合批/实例化（草/花/石/树）。
3. 关闭不必要的阴影/投影。
4. 降低透明/加法 overdraw。
5. 简化 shader（少噪声/采样）。
6. 降低后处理分辨率/采样数。
7. 用 Profiler 确认 CPU/GPU 瓶颈，不要盲猜。

### 11.2 我们的数据

| 项 | 数值 |
|---|---|
| 内部渲染 | 640×360 |
| 草 | 2800+1600+700 = 5100 株，3 个 MultiMesh |
| 花 | 540 朵，2 个 MultiMesh |
| 萤火 | 220 粒子 |
| 灯 | 8 Omni + Sun/Moon/Fill |
| 阴影 | Sun 4 split；Moon 关闭 |
| FPS | 87 @1280×720（Intel Iris 6000） |

### 11.3 跨引擎工具

| 引擎 | CPU | GPU | Draw Call |
|---|---|---|---|
| Godot | Profiler/Monitors | Visual Profiler | `RenderingServer`/Monitor |
| Unity | Profiler | Frame Debugger/GPU Profiler | Frame Debugger |
| Unreal | Unreal Insights | GPU Visualizer/`stat gpu` | `stat scenerendering`/`stat rhi` |
| Three.js | Chrome Performance | Spector.js/WebGL Inspector | `renderer.info.render.calls` |

### 11.4 常见坑

- V-Sync 把 FPS 限制在 60；测性能先关 V-Sync 或看 mspf。
- 一次测量不可靠；看多帧/多场景。
- 只测 GPU 忽略 CPU；草/石板的 Draw Call 可能先爆。
- 阴影/后处理在低分辨率下看起来便宜，但仍是额外 pass。
- 在笔记本/集显上测；目标设备为准。

### 11.5 练习

1. 用 Profiler 找出场景的 CPU/GPU 瓶颈。
2. 把草从 5100 改到 1000，看 FPS 变化。
3. 关闭太阳阴影，看 FPS 变化；判断阴影成本。

## 12. 跨引擎迁移 10 步

### 12.1 步骤

```text
1. 低分辨率 RT + Point/Nearest 放大
2. UI 独立层（不进入 RT）
3. 相机吸附 + 关闭 AA/TAA
4. 色彩空间/Tonemap/曝光对齐
5. 3 盏方向光 + 环境光 + 阴影
6. 时间曲线（hours → 光照/雾/粒子/后处理）
7. 程序化几何（路/池/拱门/石板）或替换为资产
8. 实例化植被 + 顶点风 + UV 遮罩
9. 水/粒子/光柱/云影/后处理
10. Profiler 校准 + 单位/坐标/平台差异
```

### 12.2 坐标与单位差异

| 项 | Godot | Unity | Unreal | Three.js |
|---|---|---|---|---|
| 上方向 | +Y | +Y | +Z | +Y |
| 前方向 | -Z | +Z | +X | -Z |
| 单位 | 米 | 米 | 厘米 | 任意（常用米） |
| 方向光单位 | 任意 energy | lux | lux | 任意 intensity |
| 点光单位 | 任意 energy | lumen | lumen/candela | 任意 intensity |
| 角度 | 弧度（数学）/度（节点） | 度 | 度 | 弧度（数学） |

迁移时：

- 把 Godot 的 `Vector3(x,y,z)` 映射到目标引擎时，注意 Y/Z 交换和正负。
- 相机 pitch/yaw：Godot 的 `-Z` 前向，Unity `+Z`，Unreal `+X`；用 `look_at`/`FindLookAtRotation` 而不是抄欧拉角。
- 光照能量：先归一化到 0–1 的相对强度，再按目标引擎单位重调；不要直接复制 2.15。
- 时间：所有引擎都用“秒”作为 delta；`hours += delta * speed` 通用。

### 12.3 渲染管线差异

- Unity：Built-in vs URP vs HDRP，后处理/Shader API 不同；先确定管线。
- Unreal：Deferred/Forward、Lumen/Nanite、Auto Exposure；移动端要用 Mobile 渲染器/简化材质。
- Three.js：WebGL/WebGPU；后处理用 EffectComposer；颜色空间/tonemap 要显式设置。
- Godot：Mobile/Forward+；本项目因本机 GL Compatibility 灯光问题固定 Mobile；Forward+ 支持体积雾。

### 12.4 迁移检查清单

- [ ] RT 是 640×360（或目标分辨率），过滤是 Point/Nearest。
- [ ] UI 在 RT 外，文字清晰。
- [ ] 相机吸附；AA/TAA 关闭或评估。
- [ ] 线性色彩空间；Tonemap/曝光正确。
- [ ] 3 盏方向光 + 环境光；单位重调。
- [ ] 时间曲线连续；滑杆可拖动。
- [ ] 程序化几何的绕序/法线/UV 正确。
- [ ] 植被实例化；每实例相位/颜色；不投影。
- [ ] 水/粒子/光柱/后处理顺序正确。
- [ ] Profiler 确认瓶颈；目标设备帧率达标。

## 13. 综合练习与自检

### 13.1 练习（按难度）

1. **像素管线**：任意引擎 640×360 RT + NEAREST + UI 外置；截图证明 UI 清晰。
2. **光照**：Sun/Moon/Fill + 环境光；黄昏亮部暖、暗部冷。

10. **光柱**：4 条夕阳束 + 1 条月光束，边缘柔化。
11. **后处理**：Bloom + 调色 + 暗角 + 源像素 dither。

### 13.2 自检问题

- 草/花的 UV 遮罩怎么工作？
- Fresnel 为什么让水面边缘更亮？

| Tonemap | 把 HDR 亮度压到屏幕范围 |
| Exposure | 曝光，整体亮度 |

| Billboard | 永远面向相机的面片 |
