## 与参考片的核心差距 Top 5

### 1. 镜头与构图：现在是“全园地图”，参考片是“跟着女孩走的场景”

- **参考片做了什么**：`frame_10` 的视野高度 11.3m、`frame_340` 只有 9.0m；镜头离地面更近，少女明显更大，S 形石径从画面下方进入，经过水池边，再被右上树冠和左侧水面夹住。画面有明显的 Foreground（水池/树冠）、Midground（少女/石径）、Background（密林）。
- **我们现在是什么**：默认相机 `(14,30,16)`、FOV 32、`_zoom=0.9`，视野高度约 19m；整个花园像一张俯视棋盘。环形路径把画面四周框住，中间是空地，少女在左下边缘，主拱门在中右但不抢眼。8 盏灯按 0.04–0.91 等分排布，26 块岸石等角排布，读起来是程序布局，不是场景。
- **为什么有差距**：构图没有主次。当前把“所有东西都看得见”当成目标，结果每样东西都不重要；参考片只让你看少女、路径和一小片水，剩下的用树冠遮掉。镜头拉近还会同时提升角色尺寸、像素密度和材质可读性，是成本最低、收益最大的一刀。

### 2. 光影与氛围：现在是“换颜色”，不是“打光”

- **参考片做了什么**：`frame_10` 有强烈的斜向阳光、树冠斑驳影和草地的亮暗分层；`frame_80` 树冠边缘有暖色轮廓光、地面长影；`frame_280` 晨光把长影和光束一起打进画面；`frame_220` 夜景是蓝绿环境光 + 小面积暖灯池，暗部仍然可读。
- **我们现在是什么**：正午太阳几乎顶光（`rotation.x = -(8 + day*82)`，day=1 时接近 -90°），没有参考片那种侧向长影；黄昏/黎明的环境光被 `dusk_glow * 1.7` 推到约 2.1，`_fill` 到 0.9，再叠加 post 的 `u_warm`，所有阴影都被暖光填平；夜里月亮没有阴影、能量 0.35，水池岸线反而比地面亮。光束锚点在 `(-12,5,-8)` 附近，默认镜头基本看不到。
- **为什么有差距**：光影是场景造型的第一语言。当前主要靠环境光和后处理 tint 表达时间，直射光和阴影没有承担造型任务；于是石头、树、角色都没有体积，画面像“贴了颜色的平面”。

### 3. 材质与细节密度：信息量不够，不是“再摆几个石头”能补的

- **参考片做了什么**：`frame_340` 的水池边有湿石、干石、苔藓、碎石、草从石缝里长出来；路面石板大小/角度/高度都不同，石缝是暗绿/泥色而不是纯黑；树冠是多个叶簇的叠加，底部暗、顶部亮；地面有草叶、白花、蓝花、落叶、泥土斑块等多个尺度。
- **我们现在是什么**：石板是统一长方体，下面是 `_dirt` 深色带，远看像黑色沥青；树冠是 8–10 个光滑球体，没有叶簇层次；岸边 26 块石头等距排列，水面是一整块三角扇；大部分材质是 `StandardMaterial3D` 纯色，没有 AO、没有粗糙度变化、没有纹理；草是单一种类的十字面片，花是 0.035m 的小球，在 19px/m 下小于 1 像素。
- **为什么有差距**：当前是“几何 blockout + 纯色材质”，参考片是“低多边形 + 多尺度表面细节”。低多边形不等于低信息量；参考片靠颜色变化、AO、苔藓、碎石和不规则边缘把信息补回来了。你现在缺的不是模型数量，是表面语言。

### 4. 色彩与调色：参考片是“光变色”，我们是“整张图刷滤镜”

- **参考片做了什么**：正午是明亮的黄绿高光 + 深绿/蓝绿阴影；黄昏是暖色高光 + 冷色阴影；夜晚是深蓝绿环境 + 橙色灯池；水面始终是深青绿，岸线是灰绿/暖灰，不会变成霓虹。整体饱和度受控，石头是中性灰褐，不抢少女的红色。
- **我们现在是什么**：正午草偏黄绿、饱和度偏高；黄昏/黎明全局橙色；06:24 水池变成灰白；夜里岸线是青绿色高亮环；路面石板是奶黄色，经常比少女更亮。post 的 `u_warm`/`u_night` 直接乘整张图，和灯光颜色叠加，双重分级。
- **为什么有差距**：全屏 tint 会把阴影一起染暖，破坏“暖光 + 冷影”的自然关系；参考片的阴影由天空光照亮，所以偏蓝绿。另外，没有明确的 palette，所有颜色都接近“程序默认值”，缺少主色/辅色/点缀色的层级。

### 5. 视觉主次与叙事：所有东西一样重，等于没有重点

- **参考片做了什么**：`frame_10` 的少女红上衣是唯一高饱和色，石径引导视线，水池在左侧提供暗部，树冠在上方压住画面；`frame_220` 的主拱门、灯柱、水池形成三角关系，萤火聚集在水边和拱门附近；场景里有长椅、墓碑/石柱、残墙，暗示“有人来过”。
- **我们现在是什么**：少女、8 盏灯、2 个拱门、5 根柱子、石圈、水池、树，全部均匀分布；灯距相同、岸石角度相同、石圈 14 块等分；中右空地没有遮挡，没有前景，没有“必须看这里”的视觉钩子。少女沿闭环匀速走，没有停顿、没有目的地。
- **为什么有差距**：程序化布局追求均匀，场景美术追求不均衡。参考片的“破败花园”是靠不对称、遮挡、聚集和叙事道具建立的；当前更像一个功能完整的关卡白盒。

## 具体 Godot 落地建议

### 1. 镜头与构图参数

- 当前视野高度约 **19m**（相机距离约 36.8m、FOV 32、zoom 0.9），参考片英雄镜头是 **9–14.4m**，夜间全景才是 25.8m。建议把默认镜头改成“英雄机位”，全景只作为可切换视图。
- 可先试：目标点 `(-1.5, 0.8, 4.5)`（石径靠水池的弯道），距离 24m，俯角 48°，FOV 32，zoom 0.85。这样视野高度约 11.7m，少女和路面会立刻大一圈。
- 把 `_zoom` 的 clamp 从 `0.82–1.25` 改成 `0.55–1.8`；默认值不再是 0.9，而是约 0.62–0.85（取决于最终机位）。保留滚轮，但加一个 `V` 键或 UI 按钮在“英雄/全景”之间切换，截图时用英雄机位。
- 相机漂移当前是 `sin(_elapsed * 0.025) * 0.045`（约 ±2.6°），可以保留，但不要再加大；参考片的镜头运动很克制。
- 构图层面：把闭环路径至少藏掉一段（用树冠/断墙/灌木），让它在画面里读成 S 形或一条有去处的路，而不是围住画面的跑道。把主拱门从 `(4.5,-3)` 移到画面偏上位置并放大；前景放一棵树冠或半截断柱，制造遮挡和深度。

### 2. 光照与大气

**先修代码里的三个硬伤：**

1. **黄昏/黎明的环境光尖峰**：`_env.ambient_light_energy = 0.35 + day*0.25 + dusk_glow*1.7 + twilight*0.4`，在 17:48/06:24 时 `dusk_glow=1`，环境光约 **2.1**；`_fill.light_energy` 同时到 **0.9**。这是“橙色滤镜感”的主因，比 post 的 tint 更大。把 ambient 上限压到 **0.45–0.55**、`_fill` 上限压到 **0.2–0.25**，让阴影由冷色天光而不是暖色补光填充。
2. **太阳高度曲线**：当前 `rotation.x = -(8 + day*82)` 在正午把太阳打到接近 -90°（顶光），所以 `garden_noon.png` 几乎没有参考片那种斜向长影；黎明又到 -35°，比参考 07:00 的 +11.4° 高很多。建议用一条 24h 的 `Curve` 直接给太阳/月亮高度，不要从 `day` 线性推：
   - 07:00 太阳约 +11°
   - 14:30 太阳约 +68°
   - 17:36 太阳约 +32.5°
   - 18:00 太阳约 +28°
   - 00:00 月亮约 +21°（参考片 UI 值）
3. **月亮阴影**：现在 `_moon.shadow_enabled = false`、`rotation.x = -(10 + night*70)` 夜里接近 -80°，几乎顶光。把月亮降到 +20–25° 并开阴影，夜景会有长而柔的冷色影子和可读的剪影；这比继续加萤火有效。

**时间/光照起点值**（按画面再微调）：

| 时刻 | 太阳/月亮 | 高度 | 环境光 | 雾 | 备注 |

| 06:24 | 太阳 `Color(1.0,0.79,0.55)`，1.2–1.4 | +8–12° | 冷蓝紫 `Color(0.30,0.36,0.45)`，0.3–0.4 | 暖灰 `Color(0.55,0.48,0.40)`，0.012 | 长影，阴影保持冷色 |

- `light_angular_distance` 可在 1.0–2.0 之间试，配合 directional shadow 的 blur 做软影；当前 `shadow_normal_bias=0.8` 偏大，容易让影子脱离物体，建议在 0.2–0.4 之间实测。
- 给树、灯、岩石加“接触阴影”贴地 Quad：unshaded、alpha 径向纹理、乘性混合，alpha 0.35–0.5，尺寸 1.5–3 倍物体。当前只有少女有，地面会立刻“坐实”。
- 雾：当前黄昏密度 0.009、夜里 0.017；把黄昏/黎明提到 0.012–0.016，并让 `fog_light_color` 跟天空/地平线色走，而不是固定绿灰。雾是拉开前后景最便宜的工具。
- Glow：Environment glow 强度 0.3–0.5、阈值 1.1–1.3、bloom 0.02–0.05；post 的 8 tap bloom 建议关掉或降到 0.1。当前灯球是“Environment glow + post bloom + 2.15m halo”三重叠加，必须一起收。

### 3. 材质与 shader

- **Stone shader（石板/废墟/岩石共用）**：世界坐标噪声三色 ramp（冷灰阴影 → 中性灰 → 暖灰高光）；`moss = smoothstep(0.55,0.85,NORMAL.y) * step(noise, 0.55)` 只长在朝上的面；靠近水池的世界距离 < `POND_RADIUS+1.5` 时压暗、降 roughness 做湿石；用顶点色/世界高度做底部 AO。这样不用贴图也能把“纯色块”变成石头。
- **Foliage shader**：用 wrap diffuse（`NdotL*0.5+0.5`）而不是硬 Lambert，避免树冠底部死黑；`BACKLIGHT` 给一点黄绿透光；用世界位置噪声做每簇色相变化；顶点按高度轻微摇摆。树冠从 8–10 个大球改成 20–30 个小叶簇（icosphere 8–12 段），底部加一层更暗/更蓝的簇。
- **Ground shader**：现在已有 3 色 + 两个噪声尺度，方向对但太均匀。加三样东西：大尺度泥土/苔藓斑块、高频落叶/碎石点、以及**云影/斑驳影**（世界 XZ 噪声乘 0.82–1.0，缓慢移动）。在“云影”开关打开时生效，比现在的 y=4.2 半透明大平面正确得多。
- **Path**：删掉或大幅弱化 `_build_path_ribbon()` 的深色底带；改成窄一点、带噪声边缘的泥土/苔藓条，颜色压到 `(0.16,0.17,0.11)` 附近。石板改成 6–8 边不规则棱柱 + 顶面小倒角，尺寸 0.6–1.1m、缝 3–8cm、yaw ±10°、pitch/roll ±2°、高度 ±2cm；缝里填苔藓/泥土而不是黑色。倒角会立刻让石板有“被阳光打到”的厚度。
- **Grass**：3 种草型（短簇/高叶/带花），每种一个 MultiMesh；叶片宽度 0.22–0.3m、高度 0.35–0.7m，避免 1px 细线；数量可到 6–9k。实例 custom data 做色相/高度变化；风加一个低频 gust。当前 0.16m 宽的草在 19px/m 下约 3px，勉强；拉近后没问题，但草型太单一。
- **Flowers**：从 0.035m 小球改成 0.08–0.15m 的 billboard/十字面片，白/米白为主，少量蓝紫；400–600 朵，靠噪声成片分布，不要均匀撒。参考片的白色小花是画面“闪光点”，现在太稀。
- **Water**：删掉 `EMISSION`（当前 `vec3(0.01,0.035,0.04)` 会让夜水发光）；深水色压到 `(0.02,0.07,0.075)`，浅水色 `(0.06,0.20,0.18)`；两层滚动噪声做 normal，菲涅尔混一个随时间变化的反射色（白天树绿/天空灰，黄昏暖橙，夜里深蓝）；低太阳时给一条窄高光，不要整面亮；岸边用噪声 + 深度/边缘遮罩做不规则泡沫。睡莲/芦苇/半沉石头能极大提升“水池”的可信度。
- **Foam**：当前是 `unshaded` 恒定 `foam_color` × `u_intensity`，夜里 0.48，所以变成一个青绿色霓虹环。改成噪声 + 时间 + 边缘遮罩，alpha 白天 0.10–0.16、夜里 0.04–0.08，颜色偏暖灰/灰绿；不要把整个岸线一圈都点亮，只留几段。
- **Cloud shadow**：`_build_clouds()` 的 48×48 半透明平面在 y=4.2，是从上方盖一层黑纱，不是投影；树冠高于 4.2m 的部分还会漏掉。建议删掉，改成 ground/grass shader 中的世界噪声，或贴地 Quad + 乘性混合。
- **像素尺度的细节预算**：在 640×360、约 19px/m 下，1 个像素约 5.3cm。小于 2–3 像素的东西（0.035m 花、0.025m 灯框、0.018m 眼睛、0.05m 藤蔓）不会成为细节，只会成为噪点/闪烁。要么把镜头拉近/提高内部分辨率，要么把这些尺寸整体放大到 0.1m 级别。

### 4. 后处理

- **先修 dither 的坐标空间**：`post_process.gdshader` 作为 `TextureRect` 的 canvas_item 跑在 1920×1080，`FRAGCOORD.xy` 是屏幕像素；2×2 dither 每个屏幕像素都不同，而底图是 3×3 源像素块。结果是在每个 3×3 块里出现 1px 彩色噪点，既不是像素风，也不是干净画面。两个改法：
  1. 把 post 移进 640×360 的 SubViewport（推荐），让 bloom/dither/量化都在源像素上做，外层只做 NEAREST 放大；
  2. 或者用 `vec2 cell = floor(UV * vec2(640.0,360.0))` 作为 dither 单元，并在源像素中心采样。
- **6bit 量化**：当前 `floor(base*63+d)/63` 在 640×360 上会产生明显色阶，再叠加全分辨率 dither，画面会脏。参考片是平滑渐变；建议先去掉量化，或只在低分辨率 post 内用 5–6bit + 蓝噪声，且不要和全屏 tint 叠加。
- **分级**：把 `u_warm`/`u_night` 的整图乘法降下来，改成 lift/gamma/gain：阴影 lift 到 `#12202a`（青蓝），中间调保持中性，高光 gain 轻微暖；强度控制在 0.1–0.2。这样黄昏/黎明的阴影仍然是冷的，不会变鲑鱼色。
- **Bloom**：保留 Environment glow 做灯光核心，关掉或大幅降低 post 的 8 tap bloom；当前阈值 0.62 会把奶黄色石板也纳入 bloom，削弱对比。灯的外形交给 Sprite3D 的径向渐变控制，比全屏 bloom 更可控。
- **暗角**：夜里 `u_vignette=0.44` 偏重，加上暗部已经很黑，边缘会丢信息；降到 0.25–0.3。参考片的暗角是柔和的，不是黑框。

### 5. 动态、粒子与特效

- **光柱**：当前只有 2 条太阳 + 1 条月亮，锚点在 `(-12,5,-8)`/`(-6,5.4,-12)`，默认镜头基本在画面外或被树挡住。做法：把 6–10 条 camera-facing 的 additive 面片放进默认视锥，沿太阳方向倾斜，alpha 0.05–0.12，UV 上做噪声和两端淡出；再在光束里加少量尘点（GPUParticles3D 小 billboard）。参考 `frame_80`/`frame_280` 的光束是画面的主要气氛来源之一。
- **萤火**：当前是 15×15 的均匀 box emitter，220 个，0.13m quad + 加色 halo；夜里读成绿色小方块。改成 3–4 个分区 emitter（水池、拱门、路弯），总数 80–150 就够；sprite 用 fragment 里的 `length(UV-0.5)` 程序化径向衰减，不要依赖 64px 纹理的 NEAREST 放大；颜色以黄绿为主，少量琥珀。靠近少女放几只，作为视觉引导。
- **路灯**：灯芯保持 emissive，但 halo 改成两层：核心 0.5–0.7m、alpha 0.5；外圈 1.2–1.6m、alpha 0.10–0.15；地面加 2.5–3.5m 的暖色光池 Quad（additive 或乘性），alpha 0.12–0.22。真实 OmniLight 可以只保留靠近镜头的 2–3 盏，其余用假光池，省移动端光源开销，美术控制也更强。
- **树/草风**：草已经有 `wind`，但只有 0.09 且单一正弦；加一个低频 gust（`sin(TIME*0.13 + world_x*0.07)`）调制振幅，避免整片草地同频。树冠也加顶点摇摆，幅度 0.02–0.05m，别太大。
- **水**：加岸边涟漪环（石头周围）、灯光反射条（当前有 2 条，但太弱）、偶尔的落叶/花瓣漂浮；这些比单纯提高水面亮度更能说明“这是水”。
- **角色**：走路摆臂已经有了；增加“在池边停 2 秒”“抬头看拱门”的路径节拍，或者走到拱门下停一下。夜晚给她一个暖色小灯笼（点光 + 小 emissive），她就会成为夜景的视觉锚点，而不是一个红点。

### 6. 资产管线与性能

| 资产/改动 | 成本 | 收益 | 建议 |
|---|---|---|---|
| 128px tileable 石/草/土贴图 3–4 张（手绘或 Seedream 生成后统一调色板） | 2–4 小时/张，AI 成本约几元 | 高：石板/地面立刻有表面信息 | 做，优先级最高 |
| 3–5 张透明 decal（苔藓、裂纹、水渍、落叶） | 0.5–1 人日 | 中高：补局部细节，成本低 | 做，贴在石头/路面/墙根 |
| 256px normal map | 1–2 人日 | 低：640×360 下基本看不到 | 暂不做；改 960×540 后再考虑 |
| 3D 角色重制/绑定/动画 | 1–2 周 | 低：当前镜头下角色只有几十像素 | 先不做；先改镜头 |
| 2D sprite 角色/植被 | 1–2 周 | 与现有 3D 风格冲突 | 不做 |
| MultiMesh 合并石板/岩石/叶簇 | 1–2 人日 | 高：draw call 下降，可换取更多草花/更高内部分辨率 | 做；先 profiler 确认瓶颈 |
| 重建废墟为按材质合并的单一网格 | 1 人日 | 中：draw call 与光影一致性 | 有余力再做 |

- 当前估计有 600+ 个独立 MeshInstance（石径约 90 块、树 10×13、灯 8×15，另有废墟/岩石/树叶）。在 640×360 下 88–90 FPS 偏低，瓶颈很可能是 draw call/CPU，而不是填充率；用 profiler 确认后，优先把石板、岩石、树冠叶簇改成 MultiMesh（transform + custom data 颜色）。
- 如果决定走“接近参考片”的路线，建议测 **960×540** 内部分辨率（2× 到 1080p）作为高质量档，640×360 作为低端档；两者用同一套美术资产，靠 UI 或设置切换。960×540 的像素量是 2.25×，在 Mobile 上仍有希望保持 60+ FPS，但必须配合 MultiMesh 和灯光池。
- 若坚持纯像素路线，内部分辨率保持 640×360，但默认镜头要拉近到 9–12m；否则细节密度永远不够。像素风不是“低分辨率 + 平滑着色”的混合体，必须有调色板和像素网格纪律。

### 7. UI

- 副标题 `_label("黄昏 · 实时像素渲染", ...)` 是硬编码，12:00/06:24/00:00 都显示“黄昏”；`project.godot` 的 `config/name` 也固定“废墟花园 · 黄昏”。改成按 `hours` 映射“清晨/正午/黄昏/深夜”，窗口标题同步。
- 面板 `bg_color` 从 `(0.012,0.022,0.026,0.8)` 降到 0.55–0.65，标题 23→19–20，圆角 9→3–4；参考片的调试面板更小、更透明、更不抢画面。
- 右下角 “GODOT 4.6 · 640×360 → 1920×1080” 是技术演示水印，放进游戏会破坏沉浸；移到 F1 debug 或删除。
- 如果走像素路线：UI 也应进入低分辨率网格，用 12px 中文像素字体（如 Fusion Pixel）并整数倍放大；如果走绘画低多边形，UI 保持全分辨率清晰，反而能形成“世界是画、UI 是纸”的对比。现在两者都不彻底。

### 8. 不确定项（明确标注）

- Godot 4.6 Mobile 渲染器下 **SSAO / Decal / depth texture** 的具体支持情况我没有在本机验证；上面的建议默认走**顶点 AO + 贴地 Quad + 世界噪声**，这些不依赖上述特性。若 depth texture 可用，水体岸边融合会更自然。
- 88–90 FPS 的瓶颈是否在 draw call/CPU，需要 profiler 确认；我基于“640×360 低填充率 + 数百个独立 MeshInstance”判断可能性较大，但这不是实测结论。
- 参考片的相机 FOV、后处理强度、是否使用 TAA/景深无法从画面反推，我只能根据 UI 的“视野高度”和画面透视估算。
- 参考片的水面/树冠是否用了平滑法线或后处理模糊无法确定；视觉上它是“低多边形 + 柔化”，不是硬像素风。

## “不要做”的 3 件事

1. **不要再用全屏 tint 作为昼夜的主手段。** 当前 `u_warm`/`u_night` + 暖色 ambient/fill 已经把黄昏/黎明变成滤镜；继续加滤镜只会让颜色更脏。时间变化应该由太阳/月亮/天光/雾/灯光池驱动，后处理只做轻微分级。
2. **不要在 640×360 上继续堆亚像素细节和更多粒子来救画面。** 3.5cm 的花、2.5cm 的灯框、1.8cm 的眼睛在 19px/m 下等于不存在；220 只萤火、3 条画面外光束也补不回构图和光照。先拉近镜头、打对光、统一材质，再谈数量和特效。
3. **不要同时追两种风格。** 640×360 NEAREST + 平滑 PBR + 全分辨率 UI + 全分辨率 dither 是混合体，既不像干净像素画，也不像参考片的绘画低多边形。也不要靠描边、CRT 扫描线、色差来“伪装”像素风；那只会加重噪点。先选一条路线，再在一条路线上做深。

---

## 如果只做一件事

**把默认镜头从约 19m 视野高度拉到约 12m，目标点从 `(0,1,0)` 移到石径弯道/水池边，让少女落在画面下三分之一、主拱门落在上三分之一。**

这一件事会同时放大角色、提高像素信息密度、暴露材质问题、迫使构图出现主次；成本约半天，是所有改动里性价比最高的一刀。做完再决定是否继续走像素风或绘画低多边形，后面的光照和材质投入才不会白费。
