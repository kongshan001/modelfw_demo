## 2. 问题清单（按严重度）

### P0-1 “阶段门槛达成”与硬门证据矛盾；用宽光晕替代手持灯指标

**证据**

1. 同目录三份报告互相矛盾：
   - `03-art-final.md:125,136`：**“未达标（硬门失败）”**；并明确 `_lantern_halo_wide` 未实例化、145×165 不可复现。
   - `04-qa-final.md:11-15,71`：结论是**“条件放行”**；`HALO wide=NULL`，列为 P2 条件项。
   - `05-cycle-report.md:5,25` 与 `scorecard.md:39`：结论变成**“阶段门槛达成”**，硬门写成“宽光晕 **143×162 px ≥70**”。
2. 当前代码确实补了宽光晕：`scripts/garden_patrol.gd:494-495` 创建 1.4 m 层；探针实测 `wide alpha=0.354`。但代码 mtime 是 **17:53:16**，晚于 03/04 报告（17:4x）；03/04 的结论和 05 的“143×162”之间没有任何一份针对最终代码的 QA 报告。
3. 对最新 `cycle1_wide_night.png`（17:53:33，晚于代码）按 03 的硬门阈值 `R>150, G>90, R−B>40` 实测：
   - 手持灯连通域 **11×25 px**（bbox `(1084,656)-(1094,680)`，area 142）；要求 ≥70×70。
   - 灯区 **无** `R>200,G>150` 亮芯（区域内 Rmax=196）；要求芯 ≥30×30。
   - 灯 Rmax 196，最近街灯（`(928,583)-(991,642)`，64×60）Rmax 255，亮度比 **77%**；要求 ≥80%。
   - 灯心与街灯心约 140.9 px；按 03 自己使用的 68.5 px/m 换算约 **2.06 m**；要求 ≥3 m。
4. “143×162”不可用硬门阈值复现：最松阈值（`R>90,G>60,R−B>20`）在灯附近得到 **118×133** 的连通域（`(1009,631)-(1126,763)`），已包含头/手/地面；整片 ROI 裁剪后的松阈值 bbox 为 233×294。03 已解释过 145×165 更像 2.2 m/4.5 m halo 的投影，不是灯芯。

**期望 vs 实际**

- 期望：阶段门结论只在“默认广角手持灯”硬子门实测达标后成立（≥70×70、芯 ≥30、亮度 ≥80%、离街灯 ≥3 m、不被遮挡）。
- 实际：灯仍是 11×25、无亮芯、77% 亮度、约 2.06 m；宽光晕变大不等于提灯可读。

**影响**

Cycle 3 的核心交付被虚报；scorecard、README 与后续循环会以此为前提，外部“7.0 阶段门达成”的说法站不住。

**最小修复建议**

1. 把 `05-cycle-report.md` 与 `scorecard.md` 的结论回退为“条件通过 / 阶段门未达成”，直到硬门真的通过。
2. 明确“143×162”的测量对象、ROI、阈值，并用同一脚本重测；如果是宽光晕而非灯，就不能记入该硬门。
3. 要让硬门过：把提灯人 waypoint 移离最近街灯 ≥3 m，保证灯在镜头侧不被身体夹住；同时提高灯玻璃/灯框在广角下的可读尺寸（或按 03 的距离分级方案）。不要只加大 halo。

**证据**

- `01-art-final.md:6`：去灯玻璃皮肤 p95 黄昏 213 / 夜 234。
- `03-art-final.md:41`：黄昏 234（宽 ROI）/243（紧 ROI）；夜 **255**（紧 ROI，≥250 占 11.7%）。
- `05-cycle-report.md:26,41` 与 `scorecard.md:31,40`：夜 **244**（阈值 240，差 4）、黄昏 **211**。

**期望 vs 实际**

- 期望：固定 ROI、固定通道、固定百分位/阈值，所有报告引用同一组机器可复现数字。
- 实际：同一张图至少出现 234/239/243/244/255 五组数字；“差 4”实际是超阈 15。

**最小修复建议**

写一个固定 ROI 的像素统计工具（输出 ROI 坐标、p95、≥250 占比），所有报告只引用它的输出；按实测 255 重新评分，并继续压灯 omni/宽晕近景强度。
