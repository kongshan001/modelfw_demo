## 0. 先看结论

这个 demo 不是“做了一个黄昏场景”，而是把参考视频拆成四条可复用的技术线：

| 技术线 | 参考片的做法 | 我们的做法 | 差距 |
|---|---|---|---|
| 像素化 | 低分辨率渲染 + 像素偏移补偿 | 640×360 `SubViewport` + `NEAREST` + 相机网格吸附 | 接近；没有自研像素偏移 shader |
| 草地 | 风格化草叶渲染 | `MultiMesh` 十字草叶 + UV 刀片遮罩 + 风摆 shader | 密度/细节较低 |
| 体积光 | 真正的体积光 / 丁达尔效应 | 半透明面片近似 + 边缘/长度衰减 | 近似，不是体积雾 |
| 昼夜 | 参数化时间 + 路灯/萤火曲线 | 连续函数驱动光/雾/水/粒子/后处理 | 曲线是自调的，未逐项复刻原片 |

**一句话配方**：

> 低分辨率 3D 世界 → 连续时间曲线驱动光照/雾/粒子 → 自定义 shader 做水面/草/光柱/云影 → `NEAREST` 放大 → 全分辨率 UI + 轻量后处理。

成品指标：

- 内部渲染 640×360，窗口 1920×1080，3× 像素放大。
- 测试机 Intel Iris 6000 / macOS，1280×720 输出约 **88–90 FPS**。
- 8 盏路灯、220 只萤火、约 3.9k 草叶、3 盏方向光（太阳/月亮/天空补光）。
- 独立 Godot 4.6 工程，无外部美术、无第三方运行时依赖。

## 1. 渲染管线总图

### 1.1 场景树

```text
Garden (Node3D, garden_scene.gd)
├── WorldViewport (SubViewport 640×360, own_world_3d=true)
│   ├── WorldEnvironment
│   ├── Sun / Moon / SkyFill (DirectionalLight3D)
│   ├── Camera3D
│   └── GardenWorld (garden_world.gd)
│       ├── Ground / Path / Pond / Ruins / Trees
│       ├── Grass (MultiMeshInstance3D) / Flowers / Bushes / Leaves
│       ├── Lamps × 8
│       ├── Fireflies (GPUParticles3D)
│       ├── Beams / CloudShadow / PondMist
│       └── GirlPath (Path3D) → PathFollow3D → GardenGirl
└── Screen (CanvasLayer, 全分辨率)
    ├── PixelDisplay (TextureRect, texture_filter=NEAREST, post_process shader)
    └── UI (GardenUI)
```

### 1.2 数据流

```text
_  process(delta)
   └─ hours += delta × 600/3600
      └─ _apply_time()
         ├─ 太阳/月亮/补光 → 方向、颜色、能量
         ├─ Environment → 环境色、雾、曝光、glow
         ├─ GardenWorld → 路灯/萤火/水面/光束/云影/雾
         ├─ post shader → u_night / u_warm / 暗角 / 柔光
         └─ UI → 时钟、滑杆
```

### 1.3 为什么把世界放进 SubViewport

- **像素化**：3D 世界渲染到 640×360，再用 `TextureRect` 以 `NEAREST` 放大。像素大小由内部分辨率决定，不依赖窗口尺寸。
- **UI 清晰**：UI 放在 `SubViewport` 外层的 `CanvasLayer`，始终按 1920×1080 绘制，不会被像素化。
- **后处理只作用于世界**：后处理 shader 挂在 `PixelDisplay` 的 `TextureRect` 上，UI 不受影响。
- **性能**：640×360 约 23 万像素，1920×1080 约 207 万像素；片元开销约为 1/9。

## 2. 为什么是 Mobile 渲染器 + 640×360

### 2.1 一次真实的踩坑

最初用 GL Compatibility（与仓库里的 2D 战斗项目一致）。结果：

- 环境光、背景色、自发光、Unshaded 材质正常；
- **DirectionalLight3D / OmniLight3D 对 StandardMaterial3D 和 ShaderMaterial 几乎不产生照明**；
- 最小复现：一个球、一块地板、一个方向光、一个点光、一个 WorldEnvironment，仍然只有环境光。

排查：

1. `rendering/limits/opengl/max_lights_per_object = 8`，`max_renderable_lights = 32`，不是灯数量限制。
2. 灯光 `light_cull_mask` 默认全开，材质 layer 默认 1。
3. 换 Forward+：本机 Intel Iris 6000 + MoltenVK 出现 fragment shader 编译错误（`VK_ERROR_INVALID_SHADER_NV`），不能作为稳定方案。
4. 换 **Mobile / Vulkan**：方向光、点光、阴影全部正常。

最终 `project.godot` 固定：

```ini
[rendering]
renderer/rendering_method="mobile"
renderer/rendering_method.mobile="mobile"
```

> 这是本机/本版本的环境问题，不代表 GL Compatibility 在所有机器上都坏。
> 如果你的机器上 GL Compatibility 灯光正常，可以切回去；切回后必须重新调曝光/能量。

### 2.2 640×360 的选择

- 1920/640 = 3×，像素块明显；接近参考片的颗粒度。
- 再低（480×270）会让灯柱、女孩、UI 世界内细节糊成块。
- 再高（960×540）像素感变弱。
- 内部 640×360 + 3× 放大，在 1920×1080 下每个“像素”是 3×3 屏幕像素。

### 2.3 像素稳定性

- `msaa_3d = DISABLED`、`screen_space_aa = DISABLED`、`use_taa = false`。
- 相机位置做网格吸附：`pos = round(pos / 0.04) * 0.04`，减少低分辨率下的爬行/闪烁。
- 相机缓慢环绕（`sin(elapsed × 0.025) × 0.045` 弧度），吸附网格不能太大，否则会“跳格”。0.04 是稳定与顺滑的折中。

## 3. 世界怎么搭

世界全部是程序化几何 + 自定义 shader，没有外部模型/贴图。

### 3.1 布局

- 相机：默认距离 = `(14,30,16).length() × 0.9`，FOV 32°，看向 `(0,1,0)`。
- 石径：10 个控制点的闭合曲线，绕水池与废墟一圈。
- 水池：中心 `(-5,0,3)`，半径约 4.2，48 段不规则岸线。
- 石圈：中心 `(8,0,5)`，半径 2.3。
- 树：10 棵，分布在花园外圈；灯柱 8 盏沿石径外侧。

### 3.2 地面

- `PlaneMesh 60×60` + `ground.gdshader`。
- 用世界坐标做 value noise，混合三种草/土色，避免纯色平板。
- 草地本身由 3.9k 草叶覆盖，地面主要作为底色。

### 3.3 石径

1. 用 `Curve3D` 采样闭合路径，每 0.2m 取一个点。
2. 路面：沿切线方向生成一条宽 2.0m 的三角带（`SurfaceTool`），深棕土色。
3. 石板：每 0.62–0.94m 放一块 BoxMesh，尺寸/旋转/横向偏移随机；三套石材质轮换。
4. 18% 石板加一层薄苔藓；路边撒碎石。

关键数学：

```gdscript
var tangent = (path_curve.sample_baked(s + 0.2) - path_curve.sample_baked(s - 0.2)).normalized()
var side = Vector3(tangent.z, 0, -tangent.x).normalized()   # 切线在水平面的垂线
var yaw = atan2(tangent.x, tangent.z)                        # 让石板的长边顺着路径
```

### 3.4 水池

- 48 段岸线：`r = 4.2 + sin(angle*3 + 1.2)*0.35 + noise`，避免完美圆。
- 水面：中心点 + 岸线的三角扇，放在 `y = 0.055`。
- 岸线：一圈 0.965–1.07 倍半径的亮色环，`foam.gdshader`（Unshaded + Alpha）。
- 石头：26 块岸边石 + 3 块水中石，低多边形球体随机缩放。
- 灯光反射：两块水平 Quad + 加法混合的径向光斑，随路灯强度渐亮。

水面 shader 的近似：

```glsl
// 两层 value noise 做波纹
float ripple = vnoise(p*1.3 + t) * 0.62 + vnoise(p*2.7 - t*0.8) * 0.38;
// Fresnel：视线越平，反射越强
float fresnel = pow(1.0 - max(dot(normal, view), 0.0), 2.2);
vec3 col = mix(deep_color, shallow_color, 0.26 + fresnel*0.45 + ripple*0.1);
// 太阳高光
col += glint_color * pow(max(dot(reflect(-sun_dir, normal), view), 0.0), 70.0);
// 夜间路灯暖色波纹 + 压暗
col += vec3(1.0,0.62,0.28) * pow(ripple,4.0) * u_lamp * 0.12;
col *= mix(1.0, 0.58, u_night);
```

### 3.5 废墟

- **拱门**：两根柱子 + 半圆上的 13 段 BoxMesh。
  - 每段位置：`(cos(a)*r, pillar_h + sin(a)*r, 0)`。
  - 绕 Z 旋转 `a + 90°`，让 Box 的长边沿圆弧切线。
  - 跳过 2–4 段，形成“断顶”。
- **断柱**：圆柱 + 柱础/柱头；断柱顶部加一块歪斜的碎石。
- **断墙**：按 1.4m 一段拼接，随机缺段、随机高度、顶部苔藓。
- **石圈**：14 块切向石板 + 中央暗色圆盘 + 一块祭坛石。
- **雕像/碎石/垂藤**：低多边形球/柱/细 Box，补细节。

### 3.6 树

- 树干：CylinderMesh；两根斜枝。
- 树冠：8 个低多边形球 + 1 个底部暗层 + 1 个顶部球，三套绿色材质交替。
- 每棵树整体缩放 0.85–1.25，树冠球做非均匀缩放（1.2, 0.55, 1.2 等），避免“圆球树”。

### 3.7 草

核心是 **MultiMesh + 一个十字草叶 mesh + 一个 shader**：

- 草叶 mesh：两片交叉的竖直四边形，宽 0.16m、高 0.5m。
- 每个实例随机旋转/缩放；`MultiMesh` 一次 draw call。
- 排布排除：水池半径 +1m、石径 1.9m 内、石圈 3m 内。
- 草叶 shader：

```glsl
void vertex() {
  float h = UV.y;                       // 0=根，1=尖
  float phase = INSTANCE_CUSTOM.x * 6.2831;
  float sway = sin(TIME*1.6 + phase + MODEL_MATRIX[3].x*0.7) * 0.09 * h*h;
  VERTEX.x += sway;
  VERTEX.z += sway * 0.35;
}
void fragment() {
  float half_width = mix(0.5, 0.035, UV.y);  // 三角刀片
  if (abs(UV.x - 0.5) > half_width) discard;
  ALBEDO = mix(root_color, tip_color, UV.y) * (0.78 + INSTANCE_CUSTOM.y*0.38);
}
```

- 草不投影（`cast_shadow = OFF`），只接收光照，省性能。
- 花：两颗小 MultiMesh 球体（白/蓝），点缀在草里。
- 灌木/落叶：低多边形球 + 小 Box，给废墟边缘增加层次。

### 3.8 灯柱

- 8 盏，按石径比例 `[0.04, 0.16, 0.29, 0.41, 0.54, 0.67, 0.79, 0.91]` 放置，左右交替偏移 1.75m。
- 几何：底座 + 灯杆 + 四角框 + 玻璃罩 + 四棱锥顶 + 顶珠。
- 发光：
  - 玻璃材质共享一个 `StandardMaterial3D`，`emission_energy_multiplier = 3.2 × lamp_level`。
  - `Sprite3D` 径向渐变光晕（加法混合），透明度随 `lamp_level`。
  - `OmniLight3D`：range 7，energy `2.15 × lamp_level × flicker`。
  - 轻微闪烁：`0.94 + 0.04*sin(7t+phase) + 0.02*sin(21t+2phase)`。

### 3.9 小女孩

- 低多边形：红上衣、白裙、金发、黑腿、白袖；头/身体/手脚分开。
- `Path3D` + `PathFollow3D`：
  - `loop = true`，`rotation_mode = ROTATION_Y`，`cubic_interp = true`。
  - 每帧 `progress += 0.72 × delta`。
- 走路动画：手脚枢轴绕 X 轴摆动，身体上下 1.6cm，头/裙摆微动。
- 脚下软阴影：水平 Quad + 径向黑色 alpha 贴图。
- 随身一盏很小的暖色 OmniLight（range 2.5，energy 0.32），避免深夜完全没入黑暗。

### 3.10 萤火

- `GPUParticles3D`：
  - amount 220，lifetime 7s，preprocess 4s，fixed_fps 30。
  - `EMISSION_SHAPE_BOX`，范围 `15 × 1.6 × 15`，覆盖整个花园。
  - 初速度很小、无重力，靠 lifetime + 颜色渐变形成“忽明忽暗”。
- 材质：
  - 径向渐变贴图 + `BILLBOARD_ENABLED` + `UNSHADED` + `TRANSPARENCY_ALPHA` + `BLEND_MODE_ADD`。
  - 颜色黄绿，`emission_energy_multiplier = 1.0 + level*2.6`。
  - `vertex_color_use_as_albedo = true`，让粒子颜色渐变生效。
- 时间控制：`emitting = level > 0.02`，`amount_ratio = clamp(level, 0.06, 1.0)`。

### 3.11 光束 / 云影 / 雾

- **光束**：不是真体积光，是半透明 Quad + 加法混合 shader。
  - Quad 的局部 Y 对齐光线方向，Z 对齐相机方向：
    ```gdscript
    right  = dir.cross(to_cam).normalized()
    normal = right.cross(dir).normalized()
    basis  = Basis(right, dir, normal)
    ```
  - shader 做边缘柔化 + 两端淡出 + 轻微闪烁。
  - 只保留 2 道背景夕阳束 + 1 道月光束，避免大面积平铺。
- **云影**：花园上方 4.2m 的透明 Plane，滚动 value noise，`ALPHA = cloud × strength`，强度 0.02–0.06，避免把画面压脏。
- **池面雾**：水池上方 0.45m 的 Plane，噪声 + UV 径向淡出（避免矩形边缘），只在夜间出现。

## 4. 时间与光照

### 4.1 太阳高度模型

参考视频里的角度（面板读数）：

- 14:30 太阳 +68°
- 17:36 太阳 +32.5°
- 18:00 太阳 +28°
- 00:00 太阳 -26.7°

我们用的是：

```gdscript
var sun_alt = sin((hours - 4.9) / 14.2 * PI)
```

- 4.9 点日出，19.1 点日落，12 点最高。
- 17.8 点 `sun_alt ≈ 0.28`，对应约 23° 的低角度——比“6 点日出、18 点日落”的正弦更接近参考片的黄昏长度。
- 这个模型不是天文精确的，目标是“17:30–18:30 仍然有足够亮的暖光”。

### 4.2 五条时间曲线

| 变量 | 作用 | 关键区间 |
|---|---|---|
| `day` | 太阳高度（0–1） | 白天 |
| `night` | 月夜强度 | 夜间 |
| `low_sun` | 低角度暖色/黄昏色 | 太阳接近地平线 |
| `dusk_glow` | 黄昏亮度补偿 | 太阳 0.05–0.45 高度 |
| `twilight` | 蓝调时刻 | 18:36–21:36 |

```gdscript
var low_sun    = clamp(1.0 - abs(sun_alt)/0.55, 0, 1) * (1.0 - night)
var dusk_glow  = smoothstep(0.05, 0.18, day) * (1.0 - smoothstep(0.45, 0.8, day))
var twilight   = smoothstep(18.6, 19.2, h) * (1.0 - smoothstep(20.4, 21.6, h))
```

为什么需要 `dusk_glow` 和 `twilight`：

- 只靠太阳高度，17:48 的太阳角度低、阴影长，画面会迅速变暗；
- `dusk_glow` 在“太阳还在地平线上方但很低”时补环境光/曝光/补光，让黄昏保持金色可读；
- `twilight` 在太阳落山后补一层冷蓝环境光，避免 19:12 直接掉进纯黑；
- 两者曲线不同，分别解决“黄昏太暗”和“入夜太黑”。

### 4.3 三盏方向光

| 灯 | 颜色 | 能量 | 阴影 | 作用 |
|---|---|---|---|---|
| Sun | 暖橙 → 暖白 | `pow(day,0.5) × (1.8 + dusk_glow×1.2)` | 4 split | 主光/长阴影 |
| Moon | 冷蓝 | `pow(night,0.8) × 0.35` | 无 | 夜间轮廓 |
| SkyFill | 冷蓝 | `0.1 + dusk_glow×0.8 + night×0.2 + twilight×0.2` | 无 | 补暗部，避免死黑 |

太阳旋转：

```gdscript
_sun.rotation_degrees = Vector3(
    -(8.0 + day * 82.0),          # 太阳越低，角度越斜
    105.0 + (h - 12.0) * 10.0,   # 方位随时间转
    0.0)
```

### 4.4 环境/雾/曝光

- 环境色：夜蓝 → 日间中性 → 黄昏暖 → 蓝调冷，逐层 lerp。
- 雾：`density = 0.005 + night×0.012 + dusk_glow×0.004`；雾色跟随背景色。
- 曝光：`1.0 + dusk_glow×0.3`，只在黄昏抬 0.3 档，避免正午过曝。
- 环境能量：`0.35 + day×0.25 + dusk_glow×1.7 + twilight×0.4`。
  - 黄昏的 1.7 倍补偿是“从参考片亮度反推”的经验值；
  - 这是本工程最敏感的参数：太高会洗白，太低会黑成剪影。

### 4.5 路灯/萤火/光束曲线

| 效果 | 开始 | 完全亮/出现 | 结束 |
|---|---|---|---|
| 路灯 | 17:24 | 19:24 | 05:12–06:48 渐灭 |
| 萤火 | 19:12 | 21:00 | 05:12–06:48 渐灭 |
| 夕阳束 | 16:12 | 17:24 | 19:00–19:48 渐隐 |
| 晨光束 | 05:00 | 06:12 | 07:00–08:48 渐隐 |
| 蓝调 | 18:36 | 19:12 | 20:24–21:36 渐隐 |

路灯先亮、萤火后出，光束只在太阳低角度出现——这是参考片“一点点亮起来”的节奏。

## 5. 后处理与像素味

`post_process.gdshader`（CanvasItem shader，挂在 `PixelDisplay` 上）：

1. **8 邻域亮部柔光**：采样 1.2–1.6 texel 的 8 个方向，减去阈值 0.62，叠加 `×0.7`，模拟路灯/萤火辉光。
2. **冷暖分级**：
   - 黄昏：`base × (1.06,0.97,0.86) + 微暖偏移`；
   - 深夜：`base × (0.82,0.92,1.08) + 微蓝偏移`。
3. **饱和度**：向亮度 lerp 1.07，轻微提鲜。
4. **2×2 抖动 + 6bit 量化**：
   ```glsl
   float d = dither2(FRAGCOORD.xy);
   base = floor(base * 63.0 + d) / 63.0;
   ```
   - 低分辨率下渐变容易出现色带；抖动把色带打散，量化强化“像素质感”。
5. **暗角**：`smoothstep(0.82, 0.22, length(UV-0.5))`，夜间暗角更强。

注意：后处理只作用于 `PixelDisplay` 的 TextureRect，**不作用于 UI**；所以 UI 文字仍然清晰。

## 6. 性能账本

| 项 | 数值 | 说明 |
|---|---|---|
| 内部渲染 | 640×360 | 23 万像素 |
| 外部输出 | 1920×1080 | 3× 放大 |
| 草 | ~3.9k 实例 | 1 个 MultiMesh draw call |
| 萤火 | 220 粒子 | GPU 粒子，fixed 30fps |
| 灯 | 8 Omni + 3 Directional | 只有太阳投影 |
| 阴影 | 4 split，最大距离 55m | Mobile/Vulkan |
| 后处理 | 8 tap + 量化 | 低分辨率下开销很小 |
| 实测 | 88–90 FPS | 1280×720 输出，Intel Iris 6000 |

省性能的关键选择：

- 低分辨率渲染，而不是高分辨率 + 全屏像素化后处理（后者更贵且更容易闪烁）。
- MultiMesh 草：一次 draw call，不逐节点。
- 草不投射阴影；灯不投射阴影；只有太阳投影。
- 不用 SSAO/SSR/体积雾；用噪声/半透明面片近似。
- 粒子 `preprocess` 让进入夜晚时立刻有萤火；`amount_ratio` 平滑控制数量。
- 所有材质/贴图共享，避免每帧创建节点/材质。

## 7. 踩坑与修复

### 7.1 GL Compatibility 3D 灯光不生效

- 症状：环境光/自发光正常，方向光/点光几乎不亮；最小复现仍然如此。
- 原因：本机 Godot 4.6 + GL Compatibility 的环境问题（不是灯数量/层掩码）。
- 修复：切 Mobile/Vulkan；Forward+ 在本机 MoltenVK 上 shader 编译失败，不采用。
- 教训：换渲染器后所有能量/曝光都要重调，不能沿用旧值。

### 7.2 Shader uniform 初始值必须是常量

```glsl
// 错
uniform vec2 u_texel = vec2(1.0 / 640.0, 1.0 / 360.0);
// 对
uniform vec2 u_texel = vec2(0.0015625, 0.0027777778);
```

### 7.3 `look_at` 时节点还没进树

- 相机先 `add_child`，再设置 `global_position` / `look_at`；或者用 `look_at_from_position`。
- 否则会报 `Node not inside tree`，相机朝向错误。

### 7.4 切到 Mobile 后整体过曝

- 直接原因：环境能量 1.7× + 曝光 1.38 + 太阳 2.8，叠加过量。
- 修复：把“黄昏补偿”从全局常量改成 `dusk_glow` 曲线，只在黄昏抬，不动正午/夜间；曝光只抬 0.3 档。

### 7.5 光柱面片抢戏

- 大面积半透明 Quad 在低分辨率下会变成“斜条纹”，盖住场景。
- 修复：减少数量/宽度/长度，把 alpha 降到 0.09–0.12，移到背景树冠处；月光束单独保留。
- 想要真正体积光：Forward+ + volumetric fog（本机不可用）。

### 7.6 雾面/云影出现矩形边

- 平面雾直接用噪声 alpha 会露出矩形。
- 修复：加 `radial = smoothstep(0.55, 0.12, length(UV-0.5))`，边缘淡出。

### 7.7 云影把画面压脏

- 云影强度一开始 0.1+，整个画面像蒙了一层灰。
- 修复：降到 0.02–0.06，并只在白天略强；夜间关闭/极弱。

### 7.8 萤火在白天还亮着

- 粒子系统默认 `emitting=true`，切到白天后旧粒子还在。
- 修复：初始化 `emitting=false`、`amount_ratio=0`；由时间曲线控制。

### 7.9 相机吸附太粗会“跳格”

- 吸附 0.04 世界单位是稳定/顺滑的折中；0.1 以上会明显一格一格跳。
- 如果相机完全静止，可以不做吸附；一旦有缓慢环绕，必须吸附。

## 9. 术语表

| 术语 | 大白话 |
|---|---|
| SubViewport | 在窗口里再开一块“小画布”，3D 先画到小画布上 |
| NEAREST | 放大时直接复制最近像素，不做模糊，所以是硬边像素 |
| 像素偏移补偿 | 相机移动时按像素网格吸附，避免画面抖动/爬行 |
| Fragment / 片元 | 每个像素上执行的一次着色计算 |
| Draw call | CPU 让 GPU 画一批东西的指令；越少越好 |
| MultiMesh | 一份网格 + 很多实例，一次画完（草） |
| INSTANCE_CUSTOM | 每个 MultiMesh 实例可以带的 4 个自定义数（草的风相位/颜色变化） |
| GPUParticles3D | 在 GPU 上跑的粒子系统（萤火） |
| ParticleProcessMaterial | 粒子出生位置、速度、颜色、寿命的配置 |
| Billboard | 永远面向相机的面片（光晕/萤火） |
| Additive blending | 加法混合，越叠越亮（灯光/萤火/光束） |
| DirectionalLight3D | 方向光，模拟太阳/月亮，光线平行 |
| OmniLight3D | 点光，从一点向四周照（路灯） |
| Ambient | 环境光，均匀照亮所有东西，不产生方向/阴影 |
| Fog | 雾，按距离把远处颜色混向雾色 |
| Shadow splits | 方向光阴影把视锥切成几段，近处更精细 |
| Tone mapping | 把高动态范围亮度压到屏幕可显示范围 |
| Glow / Bloom | 亮部溢出光晕 |
| Vignette | 暗角，边缘压暗 |
| Dithering | 用规则噪点打散色带 |
| Quantization | 把颜色数量压少（6bit/通道） |
| Fresnel | 视线越斜，反射越强（水面边缘更亮） |
| Value noise | 一种便宜、平滑的随机噪声（地面/水/雾） |
| Curve3D / SurfaceTool | 用曲线采样 + 手工拼三角面（石径/水池） |
| PathFollow3D | 让物体沿路径自动移动并朝向切线（小女孩） |
| Mobile renderer | Godot 的移动端 Vulkan 渲染器，兼容性好、功能少于 Forward+ |
| Forward+ | 桌面级渲染器，支持体积雾/SSAO/SSR 等 |
| GL Compatibility | 最老的 OpenGL 后端，兼容性最好但功能最少 |
| Emissive | 自发光，不受光照影响直接发亮（灯罩/萤火） |

## 13. 2026-10-29 P0 迭代记录

根据独立美术评审（`docs/2026-10-29-独立美术评审.md`）落地了 P0-1、P0-2、P0-4、P0-6 和部分 P0-3。以下是**当前代码**的参数，和本文前面的初版基线不同；每轮对比与决策记录见 `docs/迭代记录.md`。

### 13.1 镜头

```gdscript
const CAMERA_TARGET := Vector3(-1.5, 0.8, 4.5)
const CAMERA_DISTANCE := 27.5
const CAMERA_PITCH_DEG := 48.0
const CAMERA_AZIMUTH_DEG := 45.0
```

- 默认 `_zoom = 1.0`，滚轮范围 `0.65–1.7`；视野高度约 **15.7m**（初版约 19m）。
- 相机环绕幅度从 ±0.045 降到 **±0.025 rad**；相机位置仍按 0.04 世界网格吸附。
- 目标从 `(0,1,0)` 移到水池/石径弯道 `(-1.5,0.8,4.5)`；少女从画面边缘移到下三分之一。

### 13.2 光照

- 太阳高度（旋转 x）：`-(8 + day*62)`，正午约 70°（不是 90° 顶光），黄昏约 25°。
- 太阳方位（旋转 y）：`105 + (h-12)*0.8`，从初版的每小时 10° 改为 0.8°，让黄昏侧光而不是背光。
- 太阳能量：`pow(day,0.5) × (2.2 + dusk_glow×1.4)`。
- 月亮能量：`pow(night,0.8) × 0.48`；**月亮阴影关闭**（开启会从 89–90 FPS 掉到 68–79 FPS）。
- 冷色补光：`0.08 + dusk_glow×0.45 + night×0.15 + twilight×0.15`。
- 环境光：能量 `0.32 + day×0.3 + dusk_glow×0.8 + twilight×0.35`；黄昏环境色改为中性偏冷 `(0.36,0.36,0.38)`，暖色交给太阳与路灯。
- 曝光：`1.0 + dusk_glow×0.45`；雾密度 `0.006 + night×0.012 + dusk_glow×0.008`。

### 13.3 后处理

- `post_process.gdshader` 的采样锁定到 640×360 源像素中心：
  `uv = (floor(UV * 640×360) + 0.5) / (640×360)`。
- **移除**全屏 2×2 dither 和 6bit 量化（原实现与 3×3 放大网格冲突，会出 1px 噪点）。
- 柔光强度降到 `0.06 + lamp×0.1 + night×0.04`；暗角 `0.2 + night×0.1`；暖/冷分级系数从 0.4/0.42 降到 0.16/0.3。
- Environment glow：强度 `0.35 + lamp×0.45 + night×0.2`，bloom 0.03，阈值 1.15。

### 13.4 水面 / 岸线 / 路径 / UI

- 水面：降低天空反射与自发光；按局部半径加深中心；增加波纹对比；保留 2 条路灯反射光斑。
- 岸线：`foam.gdshader` 用世界噪声打断整圈，alpha 降低；不再是恒定霓虹环。
- 水池新增 4 片睡莲叶 + 6 根岸边芦苇；石径从 2.0m 收窄到 1.8m，石板加宽 1.0–1.45m。
- 少女缩放从 1.45 降到 0.95（近景镜头下保持比例）。
- UI：副标题随 `hours` 变为「清晨/正午/黄昏/深夜」；移除右下角技术水印；面板 alpha 0.8→0.7，标题 23→21，圆角 9→7。

### 13.5 P0-4 材质

- 新增 `stone.gdshader`：世界噪声三色 ramp、朝上苔藓、靠水池 1.8m 内湿石（压暗 + 降 roughness）、按法线朝上/侧面的假 AO；石板/废墟/岩石共用三套 `ShaderMaterial`。
- 新增 `foliage.gdshader`：世界噪声让同材质叶簇有明暗/色相变化，backlight 透光，顶点轻微风摆；树冠每棵增加 5 个小叶簇（8 大簇 + 底部暗层 + 顶簇 + 5 边簇）。
- 石径石板从 BoxMesh 改为 6–8 边 CylinderMesh（top_radius 0.46 / bottom_radius 0.56），非均匀缩放成不规则倒角石板；间距 0.55–0.78m，路径几乎被石板覆盖，只剩窄泥土缝。
- 性能仍为 **89–91 FPS** @1280×720；石头 shader 的世界噪声在 640×360 下成本可接受。

### 13.8 P1-9 程序化章鱼

- **模拟**：8 条触手 × 12 个 Verlet 点；重力/阻尼；每点目标弹簧；4 次距离约束迭代；基点跟随身体；地面 `y>=0.045` 与石像圆柱（半径 0.6、高 2.2）碰撞投影。
- **行为**：9s idle → 7s wrap → 循环；wrap 时 3 条触手沿石像生成半径 0.66、0.65 圈的螺旋目标，身体向石像倾斜；夜间 `sleep` 收拢触手/闭眼/变色。
- **渲染**：静态管网格（36 环 × 8 边）+ 顶点着色器 `arm_points[12]` + Catmull-Rom 重建；8 条触手 8 draw call；每帧只更新 uniform，不重建网格。触手 UV 画两排白色吸盘。
- **性能**：80–83 FPS @1280×720（P1-8 约 87）。中间版本：每帧重建 ImmediateMesh 42 FPS；MultiMesh 圆柱段 60 FPS 但视觉有缺口；最终方案兼顾平滑与性能。
- **对比图 / 文档**：`docs/media/octopus_before_after.jpg`；完整原理/跨引擎复刻见 `docs/2026-10-30-章鱼程序化动画-技术笔记.md`。

### 13.9 巡园游人（2026-10-30）

- **角色**：`scripts/garden_patrol.gd`，3 个程序化低多边形 NPC——提灯守夜人（斗笠 + 长袍 + 提灯）、扫园人（斗笠 + 扫帚）、小狐侍（狐耳 + 尾巴），每人约 20–25 个 `MeshInstance3D`，与小女孩同一套原语（圆柱/球/盒 + `StandardMaterial3D`）。
- **巡逻 FSM**：`WALK` → 到达路点 0.24m 内 → `PAUSE`（1.6–3.4s，按角色播放举灯 / 扫地 / 摇尾张望）→ 下一个路点（闭环）；朝向 `lerp_angle`，行走时手脚/身体按 `sin` 摆动。
- **路线**：`GardenWorld.PATROL_ROUTES` 手工配置，按水池（半径 4.2m）、石圈（环石 2.35m）、石像（2m 障碍）、拱柱（0.75m）的安全距离校验：
  - 提灯人：绕水池 8 点、半径约 7m；
  - 扫园人：绕石圈 5 点、半径 4.2m；
  - 小狐侍：拱门后方 5 点。
  不接 A*：NPC 是纯表现层，路线已保证可走；A* 返回 1m 网格中心会让步态出现折线，这里直接朝路点走更平滑。
- **灯笼**：玻璃盒 `emission` + billboard 光晕 + 1 盏无阴影 `OmniLight3D`（range 6、energy `glow×1.35`）；`glow = max(night, low_sun×0.55)`，所以黄昏是弱暖光、深夜最强。全场景只多这一盏动态灯。
- **相机**：
  - `focus_patrol(index)` 近景跟拍；提灯人用「锚点机位」——方位角由 `atan2(anchor - npc)` 实时求出（anchor = 水池中心），相机永远停在水面上方，绕池跟拍不会钻进池边树冠/灯柱；扫园人/小狐用固定方位角。
  - `set_film_camera(pos, target)` 提供定点机位，供序列拍摄（扫园人序列把机位固定在石圈中央，平地上没有遮挡）。
- **性能**（2026-10-30，1280×720，关垂直同步）：完整场景 60.2–60.7 FPS；隐藏巡逻 61.3 / 显示 60.2，**巡逻 3 人约 1.1 FPS**。README 历史里的 80–85 FPS 是主角 / 妖灵 / 任务层加入前的口径，当前完整场景约 60 FPS。
- **验收工具**：`tools/probe_patrol.gd`（位移、与水池/石圈/石像/拱柱的最小间距、FPS A/B、`5` 键开关）；`tools/screenshot_patrol.gd`（石圈有/无对比 + 提灯人黄昏/深夜 + 扫园人 + 小狐）；`tools/capture_patrol_sequence.gd`（90 帧 GIF 素材）。
- **已知不足**：NPC 是低多边形人偶，近看没有手指/关节；广角镜头里只有十几像素；不会避让玩家/妖灵，也没有点击互动。
