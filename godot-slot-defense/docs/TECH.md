# 技术拆解：Reelward 的老虎机自动战斗

> 机制研究自 Slotbound（转运军团）的公开演示：老虎机出单位、单位自动守线、
> 波次间用商店改变转轮。本工程为 Godot 4.6 净室实现，没有使用对方的代码、素材、
> UI 布局、文案或品牌。玩法细节与数值全部为本工程重新设计。

## 0. 一句话版本

一个 **约 4200 行的 GDScript 单场景**（`src/` 三个脚本，不含验收工具）：纯逻辑 `reel_slot.gd` 负责 seeded 转轮与 8 条
赔付线；`reel_game.gd` 用一个显式状态机（idle / wave / shop / win / lose）把
召唤、单线战斗、五波 + Boss、商店、经济、UI、VFX、音效串起来；`reel_art.gd` 在启动时用
`Image` 生成符号与全部静态美术层（视差背景、机台、卷轴底板、按钮、光晕、暗角）。
无头测试直接调用同一个状态机，不依赖渲染与真实帧率。

## 1. 文件与数据流

```
SlotLogic.spin()  ->  grid[row][col]  ->  SlotLogic.resolve_grid(grid)
                                        |-- triples: 召唤/升级
                                        |-- pairs: 金币
                                        v
ReelGame._apply_slot_result()  ->  units / gold / highlight lines
ReelGame._update_wave(dt)      ->  spawn_queue -> enemies -> attacks -> wave clear
ReelGame.open_shop()           ->  3 offers -> buy -> modifiers persist -> next wave
```

| 文件 | 职责 |
| --- | --- |
| `src/reel_slot.gd` | 纯函数/RefCounted：权重、seed、旋转、8 线判定、改权重/改符号 |
| `src/reel_game.gd` | 运行状态、战斗、波次表、商店、经济、背景/机台/UI 绘制、VFX、合成音效、调试钩子 |
| `src/reel_art.gd` | 6 个 32×32 符号、16×14 心形、金币、光晕/暗角；预烘焙的整屏天空、战场视差层、机台外壳、九宫格卷轴底板、按钮与角色影子 |
| `tools/smoke_slot.gd` | 无头验收：94 项断言 |
| `tools/playtest_slot.gd` | 8 个种子的自动对局，用于平衡回归 |
| `tools/screenshot_slot.gd` / `capture_slot_gif.gd` | SubViewport 抓图（7 张）/ 200 帧巡览 |
| `tools/perf_slot.gd` | 真实 GPU、关垂直同步的压力场景 FPS 探针 |
| `tools/art_sheet.gd` | 符号 + 背景调试图（开发辅助） |

`reel_slot.gd` 不 import 任何节点；smoke 可以直接 new 出来测试。`ReelGame` 的
`debug_*` 方法只做转发/时间步进，不绕过核心逻辑（例如 `debug_tick` 调用的就是
`_process` 本身）。

## 2. 转轮与连线

### 2.1 权重与 RNG

| 符号 | Blade | Bow | Shield | Steed | Orb | Crown |
| --- | --- | --- | --- | --- | --- | --- |
| 默认权重 | 24 | 22 | 18 | 16 | 14 | 6 |

合计 100。`RandomNumberGenerator.seed = seed_value`，每次旋转按 `randi_range(1, total)`
逐个格子抽取；相同 seed 的旋转序列完全一致。商店 RNG 使用 `seed * 31 + 17` 独立流，
不会打乱旋转序列。

### 2.2 网格

`grid[row][col]`，3 行 × 3 列。8 条线：3 行、3 列、2 对角线，定义为
`(col,row)` 的 `Vector2i` 数组。

### 2.3 结算规则

对每条线：

1. 数出非 Crown 符号计数与 Crown 数量。
2. 若 3 个 Crown → 三连，符号为 `crown`（游戏里解释为升级）。
3. 否则若某个非 Crown 符号的计数 + Crown 数量 ≥ 3 → 该符号三连（Crown 万能）。
4. 否则若某个非 Crown 符号计数 == 2 → 二连，+1 金币。
5. 一行三个不同符号、或“Crown + 两个不同符号”不产生二连（Crown 只参与三连）。

所有线独立结算，同一格可以同时属于行与列的两条中奖线；多条三连会依次召唤/升级。
二连只赔 1 金币，且不会与同线的三连重复。

### 2.4 召唤与升级

- 召唤优先放入**角色偏好格位**（见 3.1），已占用则顺延。
- 5 格全满：优先升级场上同类型单位（等级最低的一只）；没有同类型则升级全场等级最低者。
- 单位等级上限 5；每级生命 ×(1 + 0.35(L-1))，伤害 ×(1 + 0.45(L-1))，
  升级时回满血。
- 3 Crown 升级场上等级最低单位；如果场上没有单位，退化为 +2 金币。

## 3. 战斗

### 3.1 战线几何

- 战场区域 x 616–1256，地面前沿 y=560。
- 城门/扣心线 x=656；5 个格位 x = **840 / 910 / 980 / 1050 / 1120**。
- 敌人从 x=1238 出现向左走，接触最右侧单位（水平距离 ≤58）后停下攻击。
- 格位偏好：盾/马 → [4,3,2,1,0]（前排）；剑 → [3,2,1,4,0]（中前排）；
  弓/球 → [0,1,2,3,4]（后排）。这样后排在 840–980 的远程也能覆盖 1120 前排的接敌点。

### 3.2 单位

| 单位 | HP | 伤害 | 间隔(s) | 射程 | 备注 |
| --- | --- | --- | --- | --- | --- |
| Blade 剑 | 150 | 22 | 0.85 | 210 | 中前排近战 |
| Bow 弓 | 100 | 18 | 1.0 | 520 | 后排单体 |
| Shield 盾 | 460 | 9 | 1.3 | 120 | 高血量前排 |
| Steed 马 | 120 | 14 | 0.45 | 220 | 高攻速 |
| Orb 球 | 110 | 20 | 1.4 | 500 | 目标周围 78px 内 55% 溅射 |

仇恨：单位优先打**射程内最靠近城门**的敌人（x 最小）；敌人只攻击接触到的单位。
受击后单位/敌人有 0.12–0.15s 的闪白计时，升级与召唤有粒子和飘字。

### 3.3 敌人与波次

| 敌人 | HP | 速度 | 伤害 | 攻击间隔 | 击杀金币 |
| --- | --- | --- | --- | --- | --- |
| grunt 小兵 | 34 | 26 | 7 | 1.3 | 1 |
| runner 疾行者 | 24 | 46 | 5 | 0.9 | 1 |
| brute 蛮兵 | 115 | 17 | 16 | 1.6 | 3 |
| boss 齿轮暴君 | 900 | 12 | 26 | 1.4 | 12 |

- 每波血量 ×(1 + 0.12(W-1))，伤害 ×(1 + 0.06(W-1))。
- 波次表（绝对出现时间，秒）：
  - W1：6 grunt，2.0 + 1.3i。
  - W2：8 grunt（1.4 + 1.1i）+ 1 brute @10.2。
  - W3：6 grunt + 3 runner + 2 brute。
  - W4：10 grunt + 4 runner + 3 brute。
  - W5：12 grunt + 4 runner + 4 brute。
  - W6：Boss @2.0 + 6 grunt（8.0 + 4.5i，通常在被击杀前结束）。
- 全部 spawn 出完且场上无敌人 → 1.2s 后清波；普通波进商店，第 6 波进胜利。
- Boss 死亡立即清空后续 spawn 队列并进入 1.6s 胜利倒计时，不要求清光小兵。
- 漏怪：普通敌人扣 1 心，Boss 扣 3 心；心为 0 立即失败。

### 3.4 经济与商店

- 初始 8 金币、7 心、旋转 2 金币（“双账本”后最低 1）。
- 收入：二连每条线 1 金币；击杀 1/1/3/12；清波 +2。
- 每波之间（含第 5 波后）开 3 个商品，4 种池子按商店 RNG 洗牌取前 3，
  重摇 1 金币。

| 道具 | 类别 | 价格 | 效果 |
| --- | --- | --- | --- |
| 磁石·刃 Blade Magnet | 改概率 | 3 | Blade 权重 +10 |
| 冠冕换面 Crown Recast | 改符号 | 4 | Steed 全部权重并入 Crown（Steed 权重归零） |
| 双账本 Twin Ledger | 加经济 | 4 | 旋转 -1（最低 1），击杀金币 +1 |
| 淬火砂 Quench Sand | 加属性 | 4 | 全体伤害 +25%，生命 +20%，并立即重算已有单位 |

买下的修正都是 run 级变量（`weights` / `spin_cost` / `kill_bonus` / `dmg_mult` /
`hp_mult`），不随波次重置；未买商品在下一波商店重新洗牌。数值可以直接在
游戏机台底部的 **ODDS** 条里看到权重变化。

## 4. 渲染与音频

### 4.1 第 2 轮美术管线（暗色霓虹像素幻想）

- **1280×720**，GL Compatibility，项目级 nearest 过滤。
- **符号 32×32**：剑 / 弓 / 盾 / 马 / 球 / 冠在启动时逐像素绘制，自动加 1px 墨色描边，
  每个符号有受光面、阴影面、高光与稀有度色；在 116×116 的格子里以 96×96（3×）显示。
  心形 16×14、金币 16×16，HUD/商店复用。
- **预烘焙的静态美术**（启动时一次生成，之后每帧只画一张纹理）：
  - `build_page_sky()` 640×360：整屏渐变 + 星点 + 星云；
  - `build_backdrop()`：320×245 战场天空（月亮/星点/星云/极光）、两张云层、
    远山、神殿（窗光/门光/挂旗）、近景废墟、地砖、雾；在战场区域按 640 宽 2× 绘制，
    云/山/神殿/废墟以不同速度缓慢漂移形成视差；
  - `build_cabinet_shell()` 580×596：金属外框、黄铜倒角、四角包边、铆钉、跑马灯底座、
    玻璃与九宫格卷轴框、拉杆底板；
  - `build_reel_cells()` 416×408：9 个格子的内阴影底板与紫色氛围光；
  - `build_spin_button()` 两种状态、`build_shadow_texture()` 椭圆影子、
    `build_glow_texture()` 径向光晕、`build_vignette_texture()` 屏幕暗角。
- **机台与卷轴**：跑马灯与中奖线灯只在点亮时绘制；滚动时每列错峰，符号闪烁 +
  上下残影 + 竖向模糊条，停轮有回弹与闪光；中奖线两遍描边 + 行进光点；
  拉杆有弹簧摆动，SPIN 按钮有 hover / 按下 / 光泽扫描。
- **文字排版**：`SystemFont` 方案，显示字体 SF Mono/Menlo/Consolas，正文 Avenir Next，
  CJK 回退 PingFang SC/Noto Sans CJK；不打包字体文件。正文 1px 暗描边，
  标题/伤害数字 2–4px 描边（CJK 细笔画使用更细的描边，避免吞字）。
- **VFX**：命中火花（线段拖尾）、描边伤害数字、弓/球投射物拖尾、近战弧光、
  受击闪白与击退、死亡溶解剪影 + 余烬、屏震、红/白全屏闪光、金币喷射、胜利彩带；
  波次/ Boss 入场横幅、商店卡片错峰入场与 hover 抬升/扫光、胜负面板滑入与旋转光芒。
- **氛围分层**：`_atmo()` 按波次/商店/Boss/胜负改变天空、云、雾、地砖、灯光与 UI 强调色；
  Boss 波为红橙，商店为暖金，胜利为薄荷，失败为红。
- **性能策略**：静态机台/卷轴/整屏天空/底板全部烘焙成纹理，单帧绘制调用大幅减少；
  逐符号光晕只在中奖时绘制；环境粒子有上限；压力场景（14 敌人 + 满员 + 彩带）
  在 Intel HD 6000 上空闲时 **37–40 FPS**（1280×720，关垂直同步，`tools/perf_slot.gd`），
  正常对局更高；本机后台高负载时 5 次采样中位数 36.7 FPS（4/5 次 >30，1 次被外部进程挤到 19.7）。

### 4.2 音频与旧版说明

- 场景动态部分仍是 `Node2D._draw()`：单位/敌人分层拼块、血条、伤害数字、粒子、
  商店卡片与结算面板。
- 战斗手感：受击闪白、命中粒子、飘字、漏怪/击杀屏震（`shake_t/mag`，只作用于战场）、
  旋转时每列依次停下并播音。
- 音效：运行时合成 `AudioStreamWAV`（22050 Hz、单声道、16-bit），正弦扫频、
  方波、噪声和四音小旋律共 15 个短音效；无头模式通过
  `DisplayServer.get_name() == "headless"` 跳过音频节点，避免 CI 噪声。

## 5. 测试架构

`tools/smoke_slot.gd` 不等待真实帧，而是：

1. 直接测试 `reel_slot.gd` 的 seed 一致性、权重、改符号；
2. 用构造网格测 8 条线：单三连、二连、Crown 万能、3 Crown、行+列同时中奖；
3. 实例化主场景后 `set_process(false)`，用 `debug_tick(dt)` 手动步进状态机，
   覆盖扣费、召唤、满员升级、商店购买/售罄/效果、跨波保留、清波进店、
   Boss 胜利、漏怪失败、重开重置，以及 SPACE / F / 1-3 / R / 鼠标按钮的输入接线。
   成功打印 `SLOT_SMOKE_OK checks=94`，失败退出码 1。

`tools/playtest_slot.gd` 用固定策略（能转就转、每店有 14 金币就买一件）跑 8 个种子，
输出胜率与每波时间，作为平衡回归。本轮结果 8/8 胜利、68–76 秒。

真实 GPU 路径：`screenshot_slot.gd` / `capture_slot_gif.gd` 使用 1280×720
`SubViewport`（`UPDATE_ALWAYS`），`await RenderingServer.frame_post_draw` 后取图；
截图脚本输出 7 张（含胜利/失败），录像脚本 200 帧 / 20fps 覆盖
idle → spin → 战斗 → 商店 → Boss → 胜利；GIF/MP4 用 ffmpeg 转码。
`tools/perf_slot.gd` 在真实窗口关闭垂直同步，预热 40 帧后采样 360 帧，
报告平均 FPS 与最差帧，用于 Intel 集显回归。
`tools/verify.sh` 负责导入、600 帧启动无 ERROR、smoke、
必需文件与“src 不引用 assets 图片/音频”的结构检查。

## 6. 本轮踩坑

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 网格测试“一条三连”实际报 2 条 | 未注意 Crown 是万能，测试网格的另一行/对角线自己凑成了三连/二连 | 手工构造不含额外线的测试网格 |
| 某些 seed 的单波拖到 20–40 秒，甚至 240 秒都没结束 | 敌人停在最右侧单位处，其他 4 个单位的射程够不到接敌点（当时只有前排盾能输出），5 个单位实际只有 1 个在打 | 格位收紧到 840–1120；按角色放置单位（弓/球后排、盾/马前排）；弓/球射程提到 500+，剑/马 210/220 |
| 一局金币能刷到 1000+，旋转次数 200+ | 二连每条线赔 2、线数多，收入 > 旋转成本 | 二连改为每条线 1 金币；自动探针复查后金币回落到 100–400、68–76 秒通关 |
| 截图里商店打开时，机台 HUD 仍抢视线 | 商店只是普通面板 | 全屏 88% 暗色遮罩 + 顶部金币/标题重新排布 |
| 无头环境创建音频可能产生警告 | AudioServer 在 headless 下不必要 | `DisplayServer.get_name() == "headless"` 直接跳过音效构建 |
| 第一次 spin 后就进 wave，截图脚本重复 setup 导致阵容混乱 | `_apply_slot_result` 在 idle 时自动开第 1 波 | 截图/录像脚本在演示前 `start_run(seed)` 重置并显式召唤固定阵容 |
| 第 2 轮：中文字在标题上发灰、笔画消失 | 显示字体为细笔画 CJK，旧描边按字号 1/6–1/7 取值，24px 时 4px 描边盖住字形 | 描边改为按字号 1/12–1/14 并只对大字号启用；标题恢复亮度 |
| 第 2 轮：Boss 出场时半个身体在战场外 | 逻辑出生点 x=1238，齿轮半径 68+手臂 96，1280 宽右边界只有 1256 | Boss 绘制锚点左移 36px 并 clamp 到 1188；小兵血条仍跟随逻辑 x |
| 第 2 轮：拉杆拉下后旋钮飞到战场里 | 枢轴 x=554 + 臂长 146 + 旋钮半径 23 | 枢轴改 548、臂长 92、旋钮 17，行程限制在机台内 |
| 第 2 轮：全屏暗角把机台文字压暗 | 全屏 vignette 在 (310,110) 处 alpha≈0.47 | 暗角只绘制在战场矩形内，机台保持亮度 |
| 第 2 轮：美术升级后 Intel 集显只有 22fps | 机台/卷轴/整屏天空有 90+ 个逐帧 draw call，文本全部双遍描边 | 静态机台外壳/卷轴底板/整屏天空/按钮烘焙成纹理；逐符号光晕仅中奖时画；小字号取消描边；22→36fps |
| 第 2 轮：Boss/商店截图被入场横幅遮住 | 横幅时长 1.6–2.0s，截图等待 1.1–2.8s | 截图脚本等横幅结束再摆拍；横幅与 Boss 入场章错峰 |
