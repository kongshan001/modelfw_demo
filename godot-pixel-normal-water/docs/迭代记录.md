# 迭代记录 · 静水回廊

## 2026-11-25 · T-20261125-008

**目标**：在 Godot 4.6 复刻「2D 像素法线受光 + 零额外相机水面夜景反射 + round()
整格水波」，做一个可交互、可调参、可验收的原创夜景 demo。只借鉴数学/渲染思路，
不复制原视频的 Unity/C# 代码、视频素材或场景。

**参考确认**：用 `yt-dlp` 下载原视频元数据/低清帧到 `/tmp/bili_normal_water` 做
拆解（171s；2:52 短链对应完整视频），确认四条核心技术：法线正交拆解、暖色像素
保留的倒影、沿脚底锚点翻折、按屏幕格 `round()` 水波。参考文件只留 `/tmp`，没有
进入仓库。

---

### 迭代 1：世界与倒影骨架

- 建立 320×180 世界、一个 Camera2D（zoom=4）、无 SubViewport 的骨架。
- 用 1× 程序化像素画做出天空/远山/河岸/酒馆/杂货铺/枫树/松树/街灯/石头/码头。
- 把 6 个近岸物件的 albedo 打进 512×128 图集，生成 36 顶点单 Mesh，
  `reflection.gdshader` 做 mask 裁切与整行 `round()` 位移。
- 水面 overlay 用 additive 碎光/月影/灯影，水面底烘焙深水渐变。

**首轮截图问题**（未入库，只用于迭代判断）：

1. 建筑窗户 emission 太高，暖窗被冲成白色矩形，细节丢失。
2. 石岸画成连续横条，看起来像木栅栏，而非石块砌筑。
3. 枫树由大圆叠加，亮部也是一个完整圆盘，像粉色气泡/葡萄串。
4. 法线方向变化在平墙上几乎不可见，虽然 debug normal 图本身有细节。

### 迭代 2：美术与法线可读性

- 把暖窗 emission 从 1.05/0.90 降到 0.52/0.42；灯芯 2.4→1.15；窗玻璃改暗
  琥珀底 + 少量亮芯；灯罩加竖框/横框与 2×3 亮核。
- 石岸改成不规则鹅卵石 + 临水压顶石；建筑/树/街灯上移 8px，让石岸成为前景
  台阶而不是整面墙。整体删掉连续横向高光，增加暗缝、缺角与苔藓。
- 枫树改成 10 个大团 + 12 个边缘小团，亮部由 70 个小叶团组成而不是大亮圆；
  外轮廓描一圈暗梅色；叶簇高度场用低频噪声。
- **新增每像素大形 normal bias**：屋顶左右坡分别朝外、墙面轻微凸面、树冠从中心
  向外、石头圆顶。只在高度场做细部不够，方向光变化时大形 bias 才能让屋顶、
  树冠、石头明显换面。
- 对比截图 `02_tavern_normal_light.png`（光从右上）和
  `03_tavern_light_flip.png`（光从左上）：屋顶两坡、树冠受光面、梁柱阴影明显
  翻转。
- 降低水面 overlay 的波光密度和倒影暖色 alpha，避免满屏“电路板碎线”；把倒影
  冷色 alpha 从 0.30 提到 0.38，暗树影更可读。
- 调试光向量从左上移到顶部中央，避免展开 HUD 时被面板遮住；删除世界里的小字
  标签，信息集中到 HUD。

### 迭代 3：交互、单相机工具链与验收

- 增加 HUD：光方向/强度/光色、法线受光、波速/波幅/量化格、倒影/暖灯、时流、
  调试叠加、法线视图、暂停/重置；实时 FPS、draw calls、1 CAMERA、6 quads。
- 时间用 GDScript `time_value` 注入 shader，暂停/时流 0 可真正冻结；两个点光
  的 flicker 也基于同一时间。
- 调试叠加：光向量箭头、mask 岸线、6 个四边形线框、14 行 round() 水位刻度；
  法线视图通过 shader `u_debug_mode=1` 直接输出 world normal RGB。
- 截图不用 SubViewport：在 macOS 用 borderless 根窗口 + 屏幕外坐标获得真实
  1920×1080 root Viewport，仍只有一台 Camera2D。
- 视频改用 Movie Maker 录 300 帧 PNG，再 ffmpeg 合成；之前用
  `get_image()+save_png()` 逐帧保存，1920 下约 2.5s/帧，不可接受。
- 新增 smoke（160 checks）和 verify 脚本。

### 最终验证（2026-11-25）

- `NORMAL_WATER_SMOKE_OK checks=160`
- headless 600 帧、真实 GPU 600 帧：0 `SCRIPT ERROR` / `ERROR`
- 8 张原生 1920×1080 截图
- 10.0s 1920×1080 MP4（5.2MB）+ 960×540 GIF（15fps，9.8MB）
- 1280×720：世界 314.9 FPS / HUD 246.8 FPS
- 1920×1080：世界 119.0 FPS / HUD 109.7 FPS
- 世界 17 draw calls；含 HUD 81；倒影 1 Mesh / 1 surface / 6 quads

### 复盘

- **60 FPS 的关键不是减少物件数，而是避免抓屏/第二相机**：同一场景只渲染一遍，
  倒影以 36 顶点单片 Mesh 叠加，连水面 mask 都在 shader 里裁。
- **2D 法线贴图要“大形 bias + 细部高度场”两层**。只有高度场时，1px 窗框/梁柱
  的法线细节不足以让方向光改变整体明暗，看起来仍然平。
- **发光值要克制**；像素夜景的暖窗一旦把 RGB 推满，窗格、玻璃、室内剪影全部丢失。
- **像素水波必须按世界像素行量化**；一旦用平滑 UV，哪怕只差半像素，倒影看上去
  也会是一块被拉伸的塑料。
- Movie Maker 是录制像素 demo 的正确工具；逐帧 `get_image()` 的主线程/编码
  开销会毁掉时间线和开发效率。
