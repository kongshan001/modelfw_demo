# HTML → Godot 3D parity 表

- 基线：`web-html-tower-defense/`（T-20261126-022，单文件 HTML，640×360 Canvas 2D）
- 移植：`godot-emberhold-3d/`（T-20261126-029，Godot 4.6，3D）
- 原则：**玩法/AI 参数逐项一致；表现层按 3D 重做**。数值以 HTML `index.html` 为唯一来源。

### 无人值守 autotest（同 HTML `?autotest=1`：首波 prep 2.5s）

| 地图 | HTML | Godot | 差异 |
| --- | --- | --- | --- |
| 灰烬小径 | 胜 / 204 杀 / 20 命 / 559.67s / 72 决策 / 金币 1003 | 胜 / 204 / 20 / **559.67s** / **72** / 1003 | 无 |

两张图的最终 12 座塔的 type/level/cx/cy 与 HTML 的 `verification.json` **完全一致**。冻苔的 1.02s 差异属于浮点路径距离/弹道命中边界的亚秒级偏差，AI 决策数、击杀/生命/塔位均相同。

> **默认整局**的首波 prep 是 5.6s（不是 autotest 的 2.5s）。因此“默认整局”会在前 3.1s 产生不同的 AI 建塔时序，后半程可继续分化；本项目的整局胜利截图用时 09:54（594.07s），这是同一套规则下的正常整局，不是与 autotest 数值矛盾。

## 6. 表现/交互差异（有意）

| 维度 | HTML | Godot 3D |
| --- | --- | --- |
| 视角 | 2D 俯视 | 正交 3/4（yaw −11°，pitch −57°），跟随鼠标轻微视差 |
| 分辨率 | 640×360 内部，整数最近邻 | 1280×720 逻辑；3D 战场默认 928×672，1920 窗口自动 1.5×（1392×1008）；UI 矢量 |
| 塔/敌人/道具 | 程序化像素精灵 | 程序化 3D 低模，顶点色合并网格；血条为 Sprite3D（UI 例外） |
| 投射物 | 2D 精灵（火球有弧线高度） | 3D 网格 + 高度/抛物弧；火球溅射、冰冻、箭矢均有 3D VFX |
| 地图过渡 | 全画布抖动擦除 | 只对 3D 战场做抖动溶解；顶部/侧栏 HUD 保持可读 |
| 光照/阴影/雾 | 无真实光照，暗角烘焙 | DirectionalLight3D + 环境光 + 深度雾；单位/道具程序化接触阴影；实时方向光阴影可 `-- --shadows` 开启（默认关，保 Intel HD 30fps+） |
| HUD | 每帧 Canvas2D | 每帧 3D，HUD 10Hz 重绘（交互立即反馈）；新增 draw calls 显示 |
| 音效 | 无 | 无（保持范围） |
| 输入 | Canvas 像素点击 | 3D 正交射线落点到格 + HUD 命中矩形；键盘映射一致 |
