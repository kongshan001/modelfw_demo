## 2026-11-28 · T-20261127-018（本次续跑）

### 1. 启动修复（first light）

- 清点：9 个脚本齐全，`tools/` 与 `docs/` 空。
- `godot --headless` 首次失败：`Could not find type "LegionActor"` 连锁报错。
  - 根因 1：对未类型化 `game` 返回值做 `:=` 推断（`find_nearest_enemy` 等）。
  - 根因 2：`LegionWorld` 等全局类尚未注册，导致引用它的脚本全部 parse 失败。
  - 处理：给 Variant 来源的变量补显式类型；修正 `debug_box` 的 `Rect2` 类型；启动编辑器完成全局类注册。
- 修完 parse 后启动报：
  ```
  SCRIPT ERROR: Invalid assignment of property or key 'visible'
  ... on a base object of type 'MultiMesh' (legion_world.gd:954)
  ```
  - `var mm := embers.multimesh` 拿到的是 MultiMesh 而非节点；删除无效的 `mm.visible = true`。
- 此时 headless 启动 600 帧 0 错误；进入可验收阶段。

### 2. 验收工具与逻辑闭环

- 新增 `tools/smoke_legion_td.gd`：逐步覆盖启动、选择、框选、移动、攻击移动、招募/人口/金币、建塔/升级/出售、塔与玩家自动索敌、敌攻核心、波次、三选一、重掷、胜/负、重开、英雄技能/复活、强化效果、HUD 点击与建造快捷键。
- 初版 smoke 发现：
  - 由于敌人先被玩家单位拉住，测核心伤害的用例不成立 → 改为清场隔离后测试；这暴露测试假设问题，不是游戏 bug。
  - 击杀后死亡单位保留 1.15s，需要等待死亡淡出才进入三选一；测试改为模拟 1.4s。
  - **实际 bug：重开没有重置招募冷却**，导致 UI 招募点击在重开后仍被旧冷却阻挡；在 `start_run()` 中重置 `cooldowns`，并补 HUD 点击断言。
  - **实际 bug：`vigor` 强化只更新已存在单位，新招募单位不继承 HP 上限**；在 `LegionActor.setup()` 里按 `stats.unit_hp` 设置玩家单位最大生命。
  - **实际 bug：`暮霜附魔` 只影响暮霜图腾**，棱镜/熔渣不减速；在塔的命中和投射物参数里补 `tower_slow`。
- 新增 `tools/probe_legion_run.gd`：8 塔 Lv3 + 招募 + 自动三选一。结果：
  ```
  wave=1..5 state=upgrade, wave=6 state=win
  RUN_RESULT=WIN kills=131 core=100/100 time=129.8
  LEGION_TD_RUN_OK
  ```
  暴露的平衡问题（8 塔 Lv3 几乎无压力）记录为已知限制，不在本次加难度曲线。
