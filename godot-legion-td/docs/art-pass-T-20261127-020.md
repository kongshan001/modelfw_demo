## 一句话结果

**完成了 brief 要求的生产级美术第一遍：低模从“同一方块人 + 白蜡烛塔 + 程序员 HUD”改为按剪影/阵营色/明度分层设计的原创美术；draw calls 从 727 降到 292（基线），1080p 平均 41.1 FPS / P95 29.70ms，720p 平均 55.6 FPS / P95 22.05ms；但峰值压力场景（44 单位 + 20 敌人 + 8 塔 Lv3）仍为 639 dc / 25.2 FPS，需要 game-engineer 的 MultiMesh/全局血条/阴影批处理才能过硬预算。** 4 名玩家职业的纯黑剪影两两 IoU 最大 0.586（目标 ≤0.60），敌人 vs 地表 L* Δ22.4（目标 ≥18），英雄 Q 近白 0.011%（目标 ≤4%），HUD 面积 24.8%（目标 ≤25%）。

## 性能（真实 GPU，vsync off；`docs/perf_legion_td_after.json`）

| 场景 | 分辨率 | 平均 FPS | P95 ms | 最差 ms | DC 平均/最大 |
| --- | --- | ---: | ---: | ---: | ---: |
| 基线：8 塔 Lv3 + 第 4 波 + 小队 + Q | 1280×720 | **55.6** | 22.05 | 93.22 | 291 / 311 |
| 基线：同场景 | 1920×1080 | **41.1** | 29.70 | 164.96 | 291 / 311 |
| 峰值：44 玩家 + 20 生成敌人 + 8 塔 Lv3 + Q | 1280×720 | 32.0 | 45.59 | 105.77 | 639 / 666 |
| 峰值：同场景 | 1920×1080 | 25.2 | 49.96 | 185.86 | 639 / 666 |

**结论**：基线从 727 dc 降到 292（−60%），1080p 平均从 36.8→41.1 FPS，720p 41.2→55.6；但峰值仍超硬预算 550（639），且 1080p 峰值 <30fps。**T-020 的美术结构优化只能把“每单位 20+ draw”降到“每单位约 6 draw”；要达到 40 单位峰值，需要 engineer 的 MultiMesh/全局血条/全局阴影/UI 合批/LOD（brief P0-5 的工程部分）。** 本轮没有通过峰值验收，不把峰值标为通过。

## 未做 / 明确边界

1. **无外部 3D/贴图/字体/音频**：全部程序化/自写；没有使用 Tripo/GLB（本管线不需要，也没有伪造外部资产）；系统字体仅运行时引用，不随包分发。
2. **第 4 敌人未加**：执灯者需要 designer 签字，本轮未获签字；保持 3 型并加强剪影/骨甲/预警。
3. **无骨骼/mocap**：idle/walk/attack/death 仍为程序化/简单节点；LOD 未做。
4. **无原生 1920 UI 画布**：仍是 1280×720 设计 ×1.5；12–15px 的次要信息在 720 下低于 brief 严格字号线；需要在 UI/UX 专项里改成原生 1920 + 720 紧凑断点。
5. **无音频、手柄、本地化、商店 capsule、真实玩家盲测**；这些不在本轮范围。
6. **峰值性能未过**；见上，engineer 继续 P0-5。
7. **动画滑步**未量化；attack 前摇是视觉姿态，不延迟伤害（遵守“不改玩法”）。
8. 结算截图 `07/08` 的数字是用 debug API 设置的代表性整局值（真实渲染，不是 mockup）；已在 `docs/shots/after/README.md` 披露。
