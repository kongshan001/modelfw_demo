## 一句话结论

**加权 6.4 / 10（T-019 为 3.0；外放门槛 7.0）→ REJECT（不可外放）；内部 demo / 继续开发可以。**

美术升级是**真实且大幅的**：阵营色、角色/敌人剪影、三塔类型与等级、HUD 版式、环境氛围都已从“程序员低模 MVP”跨到“有明确 art direction 的可玩 demo”。但按 T-019 的 fail-closed 矩阵仍有 5 个红灯：**44 单位峰值 22.4 FPS / 642 dc / per-unit Node 仍在**、**47 处 12–15px 文字与 2 个 <32px 按钮**、**动画前摇/支撑脚/四态证据**、**传送门出生三段与屏幕外 beacon**、**96m 与 25% 可读性验收未闭环**。这些不是“再好看一点”，是可测的外放硬门槛。

**外放/商店页/媒体素材：禁止。** 内部 vertical slice、下一轮返工、独立复评：允许。

## 相对父任务 T-021 的新增（本报告独有的结论）

1. **独立 1080/720 性能重跑**：1080 基线 **41.1 FPS / P95 30.95ms / 294 dc**；720 基线 **53.1 / 23.77 / 292 dc**；1080 峰值 **22.4 / 57.42 / 642 dc**（44 单位 + 12 活敌人 + 8 塔）。结论：**美术没有破坏基线 30fps 卖点**（反而从 727→292 dc、36.8→41.1 FPS），但**峰值场景仍结构性不达标**，与 QA 自报（21.7/640）一致。
2. **独立剪影测量**：34m 玩家 84/85/97/95px，IoU max **0.523**；96m 玩家 **28/26/32/31px**（目标 33/32/32/41），巨像 **42px**（目标 55）。与 QA 一致，但这次是按 8-连通域独立复算。
3. **Q 证据失效**：`03_hero_skill_1920.png` 的 HUD 显示 **Q 冷却 20s**，画面里**没有** 9m 三环/18 余烬；150 帧视频逐帧扫描也没有 Q 环。也就是说 A3/A14 的“英雄 Q”证据不存在，该截图没有可辨的 9m 三环，QA 的“Q 近白 0.009%”读数**不能作为 Q 通过证据**（测的可能是战场其余区域）。Q VFX 本轮 **NOT ASSESSED**。
4. **石道/敌人明度重测**：石道中位 **L\*38.2**，敌人紫体 **L\*40.4**（体块核心 Δ≈2.2）；敌人靠骨白/紫高光在色相上可读，灰度/25% 只剩骨白斑点。**建议不要把石道提到 brief 的 L\*49**（会进一步压低敌人在车道上的明度差），改为加深敌人主体 + 加大骨白面积（见 P1-A）。
5. **传送门白环问题已修**：东门亮弧实测最大 **L\*55.8**（<L\*70），不再是纯白选中环；这是 P1-1 的真实修复。
6. **HUD 面积与过曝复核**：HUD **24.8%**（贴线）；全屏 >245 仅 **0.22–0.31%**（我测 02/09），Q 未测。
7. **默认构图无门**：`01_overview_1920.png` 三门全在画外；首屏只看到核心+小队+道路。这是 P1 构图缺口，不应靠“全景图 00”掩盖。
8. **加权分数**：**3.0 → 6.4**（不是 QA 的绿/红统计；按 9 维 rubric 重算）。6.4 = 强可玩 demo，距外放 7.0 还差 0.6，且 fail-closed 红灯优先于加权分。

### 4. 性能（本机独立重跑；Intel HD 6000，vsync off，load 3.56–4.44）

| 场景 | 分辨率 | 平均 FPS | P95 ms | 最差 ms | dc 平均 | 判定 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| 基线（8 塔 Lv3 + 第 4 波 + 小队） | 1920×1080 | **41.1** | 30.95 | 173.3 | **294** | ≥40 目标 PASS；P95 目标 28 未达、硬 33.3 PASS；worst 未过 |
| 基线（同场景） | 1280×720 | **53.1** | 23.77 | 94.5 | **292** | ≥50 目标 PASS；P95 目标 22 差 1.8；dc PASS |
| 峰值（44 玩家 + 12 活敌人 + 8 塔 + Q） | 1920×1080 | **22.4** | **57.42** | 237.0 | **642** | 硬线 <30 / P95 >33.3 / dc >550 → **FAIL** |
| per-unit Node | — | — | — | — | — | guard **13 nodes/8 mesh**；hero 15/9；crawler 11/7 → **FAIL（硬约束）** |

对照：QA 3 次中位 1080 基线 37.6 / 31.24 / 292；720 基线 43.5 / 30.15 / 294；峰值 1080 21.7 / 51.33 / 640。**基线在 37.6–41.1 之间随主机负载波动（两种都 >30fps），峰值 21.7–22.4 稳定失败。**

**结论**：
- “1080p/720p 30fps”作为**基线卖点没有被美术破坏**：draw calls 从 727 降到 292，FPS 反而提升；这是真实的工程/美术结构收益。
- 但“44 单位大战场”的**峰值场景只有 22.4 FPS**，且 **per-unit Node 树仍在**（13 Node/8 Mesh/单位），这不是“美术加多了”而是**渲染结构未按 brief P0-5 完成**。外放要展示“40 单位混战”，玩家会直接看到 20fps。

### P0-A · 44 单位峰值 22.4 FPS / 642 dc / per-unit Node 仍在（外放第一阻塞）

- **改法（参数）**：
  - 每职业 **1 个 MultiMesh**（或 1 个 SkinnedMeshInstance：单 surface、单材质、1 draw）；**禁止 per-unit Node 视觉树**。
  - 全局 3 个 MultiMesh：血条（≤40 条）、选中/悬停环、接触影；死亡余烬 1 个 MultiMesh；投射物按类型 1 个。

  - LOD：d>72 半更新、d>86 2 帧剪影、d>96 停更；阴影 1 方向光 2048，静态不投影。

## 风险

1. **主机负载敏感**：基线在 QA 是 37.6/43.5，我在 load 3.56–4.44 下是 41.1/53.1；draw calls 稳定（292–294）。峰值 21.7–22.4 不受争议，仍是红灯。正式门禁应在安静主机/固定优先级再测 3 次。
2. **峰值测试本身失真**：`PERF_SCENE enemies=12`（声称 20）；修成 20 后只会更差，必须先修测试再当门禁。
3. **25% 目标可能过严**：480×270 的整帧单位只有 5–8px 可辨像素；brief 的“14px”在全剪影下勉强，必须靠专门展示帧/盲测，否则会逼出“为缩略图放大模型”的错误优化。
4. **原生 1920 UI 重做会动输入热区**：必须同时跑 smoke 的 HUD 点击与 720 热区；否则点击错位。
5. **动画加 IK/前摇可能加 CPU**：在 Intel HD 6000 上要计入峰值预算；不要用每帧 `new`。
6. **风格漂移**：熔岩/橄榄色面积大，与 brief 的“charcoal world”不同；本轮视为“浮空余烬岛”的合理改写，但必须更新 art bible，不能两边都声称。
7. **石道 L\*49 的 brief 值与车道可读性冲突**：本报告明确选择“车道可读性优先”，这是有意的规范修正；若产品坚持 L\*49，需要重新评估敌人明度（会失败）。
8. **只有 Intel HD 6000 数据**：更低端/Windows/移动端未知；Q/死亡 VFX 没有成品证据。

## 仍不足（即使 P0/P1 全过）

1. **音频仍为空**：攻击/命中/建造/波次/音乐全无；必须单开任务。
2. **单地图/单生物群系**：余烬荒原之外没有第二张图；环境复用会在长局中显重复。
3. **动画仍是程序化/简单节点**：即使补前摇/支撑脚，近距离特写仍达不到“表演”级；无 mocap/骨骼。
4. **无 LOD/烘焙光照/贴图**：全部顶点色/原语；远中近三层仍可能跳变；低端 GPU 风险。
5. **无本地化/色盲/字号调节**：DALTON/色盲模式、UI 缩放、字体替换未做。
6. **无手柄/存档/设置/重绑定**：相机固定 52°，不是完整产品。
7. **无真实玩家盲测**：25%/兵种/塔型/阵营识别的 5/5 仍是推断。
8. **第 4 敌型未签字**：执灯者仍是提案；3 型是否满足“4 敌人”口径需 designer 决定。
9. **无商店物料/Key art/合规检查**：当前是 vertical slice，不是发行包。
