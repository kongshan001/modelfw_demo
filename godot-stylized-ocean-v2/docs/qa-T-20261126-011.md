## 4. Bug 列表（含复现）

### P0-1 · 太阳高光/闪点在 1280×720 与 1920×1080 不可见（视觉验收阻塞）

- **复现 A（官方证据镜头）**：打开 `godot-stylized-ocean-v2/docs/shots/05_sun_glint.png`（1920×1080，`sun_glint=1.5`，相机 orbit 90/44/55，目标 (0,62,0)）。画面是均匀蓝面，看不到高光带或闪点。
- **复现 B（QA 独立镜头）**：

  ```bash
  godot --path godot-stylized-ocean-v2 -s tools/qa_acceptance_stylized_ocean.gd
  # 末段：
  # QA shot qa_17_sun_glint_1280 1280x720
  # QA sun_glint_water_bright_px_sampled=0
  # QA FAIL: sun glint should show visible sparkles on water (sampled bright px=0)
  ```

- **期望**：参考视频海面有可辨的太阳高光/闪光纹理（参考 key_30 左侧水面有细碎亮斑/亮面）。
- **实际（实测像素）**：

  | 图像 | 尺寸 / 参数 | 水面亮度 p50 / p99 / max | >0.8 亮像素 |
  | --- | --- | --- | --- |
  | `docs/shots/05_sun_glint.png` | 1920×1080，glint 1.5 | 0.378 / 0.478 / **0.641** | **0** |
  | `docs/qa/qa_17_sun_glint_1280.png` | 1280×720，glint **2.0** | 0.378 / 0.476 / 0.966* | **0**（*0.966 为鼠标光标环） |
  | 参考 `key_30` 左侧水面 | 1280×720 | 0.405 / 0.641 / 0.824 | 可辨亮斑纹理 |

  05 全图 4805 个 >0.9 亮像素全部落在 y=0–97（顶部沙滩/泡沫），水面为 0。QA 镜头在 glint 拉到 2.0 后水面仍无可计亮斑。
- **补充：8 方位开阔水面扫描**（`tools/qa_glint_sweep.gd`，目标 (0,0,150)、distance 70、pitch 35、glint=2.0、无海岛/岸边进入画面）：

  ```text
  GLINT_SWEEP yaw=0   bright_gt_0.8=0
  GLINT_SWEEP yaw=45  bright_gt_0.8=0
  GLINT_SWEEP yaw=90  bright_gt_0.8=1
  GLINT_SWEEP yaw=135 bright_gt_0.8=2
  GLINT_SWEEP yaw=180 bright_gt_0.8=0
  GLINT_SWEEP yaw=225 bright_gt_0.8=0
  GLINT_SWEEP yaw=270 bright_gt_0.8=0
  GLINT_SWEEP yaw=315 bright_gt_0.8=0
  STYLIZED_OCEAN_GLINT_SWEEP_OK
  ```

  8 个方位下 >0.8 的水面亮像素仅 0–2（光标/采样噪声量级），没有可读的太阳闪点；**不是“05 机位选错”**，而是闪点在该实现中视觉不可见。
- **根因提示（只读定位）**：`shaders/water.gdshader` 293–304 行：
  - `sp1`/`sp2` 以 `p.xz * 9.0` / `*14.0` 采样 256² 噪声，在 45–95 m 相机距离下为亚像素；
  - 宽闪 `glitter` 仅 0.04；
  - `sun_tight = pow(ndh,900)*0.4` 在海面法线接近朝上、相机俯视时 `ndh` 远小于 0.998，幂函数实际恒为 0；`sun_sheen = pow(ndh,36)*0.06` 也只有 ~0.001 量级。
  - 结论：当前高光链路在目标机位下视觉上无输出，不是“闪光太弱”，而是没有可读高光场。
- **修复方向（给实现者）**：降低闪点空间频率/放大闪光核、加入屏幕空间稳定闪点或提升宽闪系数、给一个可读的太阳高光带；在 720/1080 重拍 05 与 `qa_17`，要求水面出现可见亮斑（例如 >100 个 >0.8 像素且非 UI 元素）。
- **严重度**：P0（验收项 1 的“太阳高光”子项不通过；不是崩溃/性能问题）。

### P0-2 · 礁石泡沫环过亮/过完整，呈白色甜甜圈/平板光晕（视觉验收阻塞）

- **复现**：打开 `docs/qa/qa_01_wide_1280.png`、`qa_03_rock_isle_1280.png`、`docs/qa/qa_18_rock_collar_crops.jpg`、`docs/shots/10_night.png`、`docs/shots/11_rain.png`。每块离岸礁石（包括四周都是深蓝水、以及夜景/雨天）都带一圈完整、高亮白环；近看还有向下的白色“滴痕”。
- **期望**：泡沫只在水线与礁石相交处局部出现，被噪声打散、低透明度，深水/夜间显著减弱；不应是“完整环 + 发光边”。
- **实际**：环完整且亮（`qa_04` 右侧离岸礁石裁剪区 0.6% 像素 >0.8，周围开阔水面 0%；夜景白色环更醒目），在广角下呈重复的白色甜甜圈图标。
- **根因提示（只读定位）**：`shaders/water.gdshader` 218–224 行：`ring` 由 G 掩码生成，`collar` 只用局部水深淡出；礁石高度场把礁石周围海床垫浅，局部 depth 始终很浅，淡出失效；且 `shore_foam = max(shore_foam, collar * 0.75 * foam_amount)` 强制保留高亮环。
- **修复方向**：用“离水线距离 / 环境水深（考虑 bump 前的基准深度）/ 夜间权重”门控；降低 `collar` 最大强度；用更强噪声打散成局部斑块；重拍 01/03/10/11/14/16。
- **严重度**：P0（视觉门禁；与“不要把旧版平板光晕当通过”的口径直接冲突）。

### P1-2 · 浅水沙底以暗色海草网为主，亮焦散偏弱

- 证据：`qa_02`、官方 `15_shallow_caustics.png`；参考 9–14s 的浅水是亮色光网。
- 现状：水下可见大面积暗绿“海草/纹路”，焦散加法项仅 0.07–0.10，静帧几乎不亮。建议提升焦散亮部阈值/强度，降低暗色海草覆盖。

## 8. 残留风险 / 已知限制
