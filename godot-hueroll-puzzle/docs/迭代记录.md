**判断与取舍**：
- 参考中的玩家块在多个关卡是 **1×2 多米诺**（逐单位面板上色，站立/平躺），不是简单的 1×1 方块。
  任务规格明确要求“单方块 / cube / 先做单方块 MVP”，因此本工程实现 **1×1×1 六面方块**；
  这是外形维度的有意简化，已写进 TECH；未把多米诺的逐单位规则硬塞进 cube。
- 漆池染色可确认“接触面/底面”会变；但无法从预告片确定“连续蘸两次如何混”的完整规则。
- 盖章不消耗颜料（盖章后滚块的彩色面仍在）在 2–4s、33–35s 可见。
- 目标用“颜色 + 图案”标识；本工程不复用参考的 dots/dashes/ring，改为原创的
  花/日/滴/编织/叶/星印记，颜色 + 中文名同时出现在 HUD。
- 参考的关卡是窄石径；本工程改为开放等轴花园格，支持点击、绕行、撤销和更多路线；未复制任何参考关卡。
- 参考的雾/石材/角色没有复用；本工程是奶油陶瓷浮岛 + 粉彩云 + 花/水晶的原创低模语言。

## 2. 规则落地（自洽约定）

1. 面颜色以世界方向（上/下/北/南/东/西）记录；滚动 90° 用固定的面置换矩阵（TECH 表）。
2. 进入漆池后，**底面**与池色混合：
   - 空白 + X = X；同色不变；
   - 红+黄=橙、黄+蓝=绿、红+蓝=紫；
   - 干掉的间色再蘸原色 → 原色覆盖（可修复，避免死局）。
3. 到达未锁定的目标砖：底面非空则盖章；正确锁定；错误可再盖；空面不盖；盖章不消耗。
4. 全部目标锁定 = 胜利；步数 + 参考步数 + 星级；参考步数 = 存储解的长度。
5. 撤销/重置恢复完整快照（位置、六面、印章、锁定、步数、胜利标志）。
6. 目标锁定是我们的宽容设计；参考是否允许错误永久未确认。

## 4. 视觉迭代与问题记录

方向：**奶油陶瓷浮岛 + 粉彩云**，避免参考的灰石/窄道/霓虹漆视觉；方块是白瓷 + 深李子色框；印章图标原创。

关键问题与修复：
1. **背景 quad 盖住所有不透明物体**：最初 backdrop 使用 `depth_test_disabled` + 负 priority，在本机 GL Compatibility 下把所有
   不透明几何盖掉，只剩透明漆池/目标/精灵。改为保留深度测试、仅禁用深度写入（quad 在相机局部 z=-80），
   3D 场景恢复。该问题是在诊断截图里发现的，详见下。
2. **砖顶颜色/网格读不出**：最初用 tile spatial shader 的 `NORMAL.y` / `VERTEX.y` / 顶点色 top mask 三种方式，
   在本机 GL Compatibility 下 top mask 被读成 0（整盘变 side 色，深色），或阈值误伤；同时单个圆角砖的圆角
   让缝隙只在小角落露出。最终**去掉 tile shader**，改为：
   - 每格深色 rim（MultiMesh）+ 奶油陶瓷 inlay（MultiMesh，两种极轻色差）；
   - 单块深色岛底；
   - 缝隙 + 圆角 + 顶部填充/emission，得到清晰的瓷砖网格；draw calls 也从大量单 mesh 降到 119/128。
3. **UI 底部右侧按钮/FPS 跑到屏幕外**：`button()`/`label()` 已做 design→pixel 缩放，调用处又传了 pixel 坐标；
   改为 design 坐标（vw/ui_scale - x），修复。
4. **关卡卡的“未完成/当前”文字跑到面板外**：`draw_string` 的右对齐宽度从 x 向右扩展；把 x 改为
   `card_width - margin - width`；调试网格左侧坐标同样修正。
5. **关卡选择被胜利面板压住**：打开选择时显式隐藏 win overlay。
6. **1080p 初始只有 ~35 FPS**：默认方向光 4096 shadow map + 软过滤过重；改为 2048 + filter 1 后
   同一探针约 62/48 FPS；最终光照/材质版本测得 1080p 离屏 avg 84.7/71.4（draw 119/128）。
   视觉上几乎无感；blob shadow 与 rim 保留接触感。
7. **烘焙光的灰色**：环境/补光偏冷、砖顶缺少自发光；增加暖中性环境、顶部方向填充、砖顶 emission、云 emission，
   得到明亮粉彩；截图与 GIF 均基于最终版本。

## 6. 已知风险 / 后续可做

- 参考块是 1×2 多米诺，本工程是 cube（任务 MVP 规格）；如果要更贴近参考，可增加“多米诺模式”（两格占位、
  按单位面板颜色、站立/平躺姿态），但会显著增加状态空间和路线设计成本。
- `par` 非严格最优；只保证“有解 + 可重放”。若做排行榜，需要更严格的 A*/IDA* 求解。
- 混色/漆池接触面的完整规则来自推断；若后续获得更明确的参考信息，应更新混色表与关卡。
- 系统字体差异；存档格式无版本号；音效为程序化合成，不是商业音色。
- 截图中的 HUD FPS 行被隐藏（离屏抓图会拉低读数），性能以 probe 为准；游戏内默认显示。
- 触屏只做点按相邻格/按钮，没有拖拽或双指缩放；镜头固定等轴（Q/E 90°）。
