# 迭代记录

## 2026-11-15 · 第 1 轮：从视频拆解到可玩切片

**目标**：按 B 站视频 BV1kPxP6jEbr 的五个技术点，做一个纯 2D 等距地牢切片；
程序化美术、可跑、可截图、可录 GIF、有无头验收。

**技术方案**：

- Godot 4.6 + GL Compatibility，1280×720，128×64 菱形瓦片，14×14 房间（196 格地面、36 格墙）。
- 美术全部由 `tools/gen_art.py` 生成（4× 超采样 + LANCZOS，不退回像素风）。
- TileSet 由 `tools/build_tileset.gd` 生成：等距形状、Y-Sort、脚底碰撞菱形、光照遮挡层。
- 玩家脚本 50 行，移动/朝向/动画切换；相机跟随 + 房间边界。
- F1 切换 Y-Sort、F2 切换烛光，作为教学开关。
- 验收：无头 smoke + 5 张截图 + 112 帧 GIF。

### 本轮实际踩到的问题

| # | 现象 | 根因 | 修复 | 效果 |
| --- | --- | --- | --- | --- |
| 1 | 地砖菱形之间有空隙，房间像散开的棋盘 | 生成 TileSet 时只设了 `tile_size`，忘了 `tile_shape=Isometric` / `tile_layout=DiamondDown`，退回矩形堆叠 | `tools/build_tileset.gd:33-34` | 地砖连续，房间成为完整菱形 |
| 2 | 墙比地砖低一格，角色站在墙顶、遮挡全错 | `texture_origin` 符号反了；`-48` 把图集内容整体下推 | 改成 `(0, +48)`（`build_tileset.gd:20`） | 墙脚与地砖中心对齐，Y-Sort 立即可用 |
| 3 | 角色“正后方”没有墙 | 等距屏幕正上方是 map 的 `(-1,-1)` 对角，不是 `-y` | 截图站位从 `(7,5)` 改为 `(6,5)` | 截图能清楚看到“墙挡住角色” |
| 4 | 角色/道具阴影完全不可见 | 阴影 `z_index=-1` 被整张画布的地板盖住（z_index 会压制 Y-Sort） | 去掉 z_index；阴影先 add_child，同 y 先画 | 脚下出现软阴影，角色落地 |
| 5 | 画面整体过暗，远角全黑 | CanvasModulate 压得太低、灯光范围偏小 | `DARK` 0.19→0.23，灯光 energy 1.35→1.5、scale 2.3→2.5 | 地砖可读，烛光氛围保留 |
| 6 | 木箱像“放在柱子上” | 木箱 (3,9) 与孤柱 (4,10) 在屏幕 y 上相邻，柱子按 Y-Sort 画在木箱前 | 木箱移到 (3,7) | 道具与柱子的层次不再打架 |
| 7 | 第一版相机取景偏移、边界夹住 | 手算 `(x-y)*64` 当世界坐标；实际 `map_to_local((0,0))=(64,32)` | 相机/道具/粒子全部改用 `map_to_local()` | 相机边界正确，开局构图稳定 |

### 验证结果

- `godot --headless --path godot-iso-slice -s tools/smoke_iso.gd` → `ISO_SMOKE_OK`（退出码 0）。
- 截图 5 张：起始、墙后遮挡、Y-Sort 关闭、灯光关闭、墙前。

- `docs/iso_slice.gif`：112 帧脚本录制（15fps 采集，12fps 编码）。

## 2026-11-15 · 第 2 轮：规则 → 离线资产 → 运行时导入 PoC

**目标**：证明 `rules.json` 的同一套规则可以离线烘焙、运行时执行、逐像素一致，
并且能把运行时产物写盘再导入，作为 mod/无限变体的基础。

**方案**：

- `sigil_v1`：128×128 纯整数规则（菱形/金边/6 符文/中心眼/稀疏噪点），无浮点、无抗锯齿；
- `rules.json` 作为唯一数据源（尺寸/调色板/菱形/符文/眼睛/噪点参数）；
- Python 离线烘焙 → `assets/generated/sigil_<seed>.png` + `manifest.json`（`sha256_rgba`）；
- GDScript 运行时执行 → 字节数组 → `Image` → `save_png("user://...")` → `load_from_file` → `ImageTexture`；
- 演示场景 `pipeline_demo.tscn`（地牢 F3 进入）：离线 vs 运行时 vs 缓存回环；
- `pipeline_check.gd`：5 个 seed 哈希 + `user://` 缓存回环。

**结果**：

- `PIPELINE_OK seeds=5`，5 个 seed 的 Python/GDScript RGBA 哈希全同；
- `CACHE ROUNDTRIP OK seed=7`；
- 演示 `MATCH · 0 px diff`；新 seed 走 `RUNTIME ONLY` + 缓存导入；
- 截图：`docs/shots/pipeline_match.png`、`docs/shots/pipeline_runtime.png`。

**本轮问题**：

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | seed 列表显示成 `[1.0, 2.0, …]` | JSON 数字解析为 float，`str(Array)` 直接显示 | 显示前逐个 `int()` |
| 2 | Godot 导入的 PNG `get_image()` 哈希与原始 PNG 不同 | 编辑器导入会做色彩空间/格式转换 | 逐像素证明只用原始 PNG 读取；导入纹理只用于显示；写进 PIPELINE.md |
| 3 | `Image.load_from_file("res://...")` 导出后不可用 | 源 PNG 不一定进包 | PoC 从源码跑；生产改用导入 Texture2D 或外部目录/PCK |
| 4 | GDScript 变量名 `match` 报错 | `match` 是保留字 | 改名 `same` |
| 5 | 跨语言浮点风险 | 浮点/噪声库实现差异 | 规则纯整数 + 显式 32 位掩码 |

**下一轮可选**：

- GLB/mod 运行时导入 PoC（manifest + GLB + pivot/尺寸校验）；
- 把 sigil 作为游戏内真实道具（旗帜/徽章）走同一管线；
- 规则扩展到瓦片/角色部件，验证“一次规则，多处资产”。

## 2026-11-16 · 第 3 轮：GLB + manifest 的运行时 mod 导入

**目标**：把上一轮的 PNG 导入升级成真实模型导入：GLB + manifest + 运行时校验 +
3D 展示；合法资产导入，造假资产拒绝。

**方案**：

- `tools/make_mod_glb.py` 手写 GLB（六边形石座 + 八面体晶体，26 tris，2 meshes，顶点色）；
- 三个夹具：`crystal_lamp`（合法）、`bad_scale`（bounds 造假）、`bad_hash`（sha256 造假）；
- `ModLoader`：安装到 `user://mods` → 扫描 manifest → sha256 → `GLTFDocument.append_from_file`
  → 测量 tris/meshes/bounds → 校验 bounds/footprint/pivot/max_tris → 通过才实例化；
- `mod_demo.tscn`：3D 转台（unshaded + 顶点色，绕开 GL Compatibility 的 3D 灯光限制）+ mod 列表/详情 UI；
- 地牢 **F4** 进入，Esc 返回。

**结果**：

- `MOD_CHECK_OK`：valid 26 tris / 2 meshes；`bad_scale` 被 “bounds exceed manifest” 拒绝；
  `bad_hash` 被 “sha256 mismatch” 拒绝；
- 3D 演示：合法模型上转台；失败的 mod 不实例化，详情里同时显示“实测值 vs 声明值”；
- 截图：`docs/shots/mod_import.png`、`mod_reject_bounds.png`、`mod_reject_hash.png`。

**本轮问题**：

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 合法 GLB 的 manifest bounds 只覆盖晶体，不含底座 | Python 生成器在循环里覆盖了 min/max，最终取到最后一个 mesh | 合并两个 mesh 的 bounds 后再写 manifest |
| 2 | 3D 演示左右两个面板不显示 | `_panel()` 创建了 PanelContainer 但没挂到 UI 父节点 | `_panel(parent, …)` 里 `parent.add_child(p)` |
| 3 | GL Compatibility 下 3D 灯光不工作（本机 Intel 核显） | 项目沿用 2D 的 GL Compatibility，3D 直射光问题已知 | mod 材质统一改 unshaded + 顶点色，不依赖 3D 灯光 |
| 4 | 无头截图退出时 RID/ObjectDB 泄漏警告 | 截图工具 `quit()` 时 3D 场景/纹理未完全释放 | 截图是外部工具，属已知退出告警；运行时切换用 `queue_free` |
| 5 | UI 里 1/2/3 与列表顺序对应关系不直观 | 列表按 id 字母序，合法的 `crystal_lamp` 在第三个 | 列表标 `[1] [2] [3]`，默认选中第一个通过的 mod |

**下一轮可选**：

- mod 签名 / allowlist（sha256 只证明没变，不证明作者）；
- 外部纹理 URI 限制在 mod 目录内 + 文件大小/纹理尺寸上限；
- 首次导入 GLB 后缓存为 `.res`/`.scn`，后续直接加载；
- 把 mod 模型接入等距地牢（渲染成 sprite 或做 3D 道具）。

## 2026-11-18 · 第 4 轮：跨引擎核心层（portable-core）

**目标**：把技术总览里的「B 层可移植」从文档约定变成代码：同一组算法三语言实现，
引擎侧只留适配层。

**方案**：

- 新增仓库级 `portable-core/`：`spec/functions.md` 契约 + `spec/golden.json`
  （15 iso + 9 hash 向量）+ Python/GDScript/JS 三份实现 + 三端测试；
- `sync.py` 把 GDScript 实现与 golden 同步进本工程（`src/core/`、`tests/`），
  `--check` 检漂移，已接入 `tools/verify.sh`；
- `src/iso_math.gd` 改为适配层（Vector2 → 标量），数学移入核心层；
- `src/sigil_rules.gd` 的 `hash32` 委托核心层；`tools/bake_pipeline.py` 也改为
  import 同步的 Python core，Python 烘焙端与 GDScript 运行时继续逐字节一致。

**结果**：

- `PORTABLE_ALL_OK`：Python / JS / GDScript 三端 golden 全过；
- `ISO_SMOKE_OK`、`PIPELINE_OK seeds=5`、`MOD_CHECK_OK` 无回归；
- 等距移动与哈希现在有跨语言单一事实源，换引擎只需重写 `IsoMath` 适配层。

**本轮问题**：

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | GDScript golden 在 0.3 / -0.8 / 0.7071 上失败 | `Vector2` 组件是 float32，核心返回时精度丢失 | 核心改返回 `Array`（float64），适配层再转 Vector2 |
| 2 | 同步副本可能被手工改动 | 引擎工程需要自包含副本 | `sync.py --check` 接入 `tools/verify.sh`，漂移即失败 |

**验证命令**：

```bash
bash portable-core/verify.sh
bash godot-iso-slice/tools/verify.sh
```
