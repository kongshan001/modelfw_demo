### 1.3 技术可行性探针（为 brief 负责）

在 `/tmp/mm2d_test` 用 Godot 4.6 GL Compatibility 实测：

- `MultiMesh.use_custom_data = true` + `canvas_item` 顶点着色器读 `INSTANCE_CUSTOM` **可用**；两个实例分别设 custom.x=0 / 0.3，像素分别落在 x=20 / x=118（`PIXEL_118_50=(0,1,0,1)` 绿色），证明逐实例 atlas 偏移/帧号可行。
- 逐实例 color 也生效（实例 0 红、实例 1 绿）。
- 结论：**1 个 MultiMesh + INSTANCE_CUSTOM 做「卡索引/帧/闪白/变体」** 在目标渲染器上成立；若片元 atlas UV + 变体层实现受限，退回 10 个 MultiMeshInstance2D（10 draw calls）仍是可用后备方案。

> 注：探针不是游戏代码，未进入仓库；目的只是避免给工程一个未验证的 shader 方案。

## 3. 生产级标准（Definition of Production-Ready）

**生产级定义（本项目的验收合同）**：100% 截图下，第一眼能读出**阵营 / 兵种 / 稀有度 / 当前阶段**；50% 缩略下层级不乱；25% 缩略下仍有「战役画面」而非数据面板；3000 单位在 Intel HD 6000 / 1080p 平均 ≥30fps；任一新资产可追源（原创/许可），console 零 ERROR。

#### 3.1.3 帧、atlas、实例化预算

| 项 | 规格 |
| --- | --- |
| 源单元 | 64×64 px / 帧；4px 内边距 + 1px extrusion；线性过滤 + mipmaps |
| 帧表 | **12 帧/卡**：0–1 待机（0.5s 循环）、2–3 移动（0.25s）、4–6 攻击（0.24s：0.08 预备 / 0.06 命中 / 0.10 收招）、7–9 死亡（0.18s）、10 生成（0.3s）、11 精英/变体覆盖 |
| Atlas | **768×640 RGBA**（12 列 × 10 行 × 64px，10 张卡各一行）≈ 2MB；按卡一行便于变体与图鉴复用 |
| 朝向 | 只画右向；左向用 transform X 取负（镜像）；不增加帧 |
| 实例数据 | 1 个 MultiMesh，`transform_format=TRANSFORM_2D`、`use_colors=true`、`use_custom_data=true`；**16 floats/实例**（8 transform + 4 color + 4 custom）；3000 实例 ≈ 192KB |
| custom 编码 | `R=卡索引 0–9`、`G=帧 0–11`、`B=闪白 0–1`、`A=变体 0–3`；shader 用 `INSTANCE_CUSTOM` 算 UV；已实测可用（见 §1.3） |

#### 3.1.4 动画与可读性细则

- **攻击**：预备帧向后 1px（蓄力）→ 命中帧向前 2px + 白闪 0.06s → 收招回位；远程单位不位移，只做 1px 后坐。
- **死亡**：3 帧缩小/淡出（1.0→0.85→0.6），叠加 4 个 1–2px 碎片；0.18s 后隐藏；不可「瞬间消失」。
- **生成**：1 帧 + 24px 环（0.3s）+ 门侧 6 个火花；让「1,500 单位从门里涌出」可读。
- **次级运动**：触角/翼/尾滞后 1 帧；8px 下可省略，16px 下必须有。
- **禁止**：同帧全场同步攻击（至少按单位索引错开 0–0.2s 相位）；死亡与攻击共用帧；纯缩放不做帧。

#### 3.1.5 验收（单位）

1. 8px 纯黑剪影：打印/展示 8 族 × 各 3 个朝向/变体，3 名未参与绘制的人盲测，**每人 ≥7/8 正确**；12px 时 ≥8/8。
2. 灰度 + deuteranopia：阵营识别 100% / ≥90%；底座形可辨。
3. 25% 缩略：不需要单兵可读，但**阵营、重型/群兵团块、金卡**仍可辨。
4. 3000 单位 1080p 平均 ≥30fps；unit/shadow/FX draw calls ≤4；无每单位 Node。

### 3.4 VFX：6 类 + 命中闪白，实例化低成本

| 效果 | 资产/帧 | 时长 | 池/上限 | 颜色 | 触发 |
| --- | --- | --- | --- | --- | --- |

- **性能降级**：先关雾，再降粒子池 50%，再关胜利碎片；不降命中闪白与死亡消散（战斗可读性核心）。

### P0-1 单位同形：10 张卡一个六角 token，3000 单位读不出兵种

## 8. 仍不足（必须写）

即使 P0/P1 全部完成，仍有以下问题，不应被「通过」掩盖：

1. **3000 单位在 10px 仍会糊成团块**：目标只能是「两片可读的洪流 + 边缘兵种 + 金卡」，不是「每个单位都像立绘」。25% 缩略下更不可能单兵可读；这是分辨率与物理尺寸的硬限制。
2. **卡牌 stats 在 25% 缩略仍不可读**：25% 只保证稀有度/费用/×N 与插画识别；详细数值必须在 50% 或 tooltip 读。
3. **AI 插画的 10 张一致性仍是风险**：即使有 seed/风格锚点，也可能出现材质/光照漂移；需要人工统一（色板/轮廓光/背景）。
4. **UI draw calls 仍是 ~670–740 的大头**：新环境/卡牌会把总数推到 800 边缘；真正的下一步是 UI 文本批处理/图集化，不在本次 P0 范围。
5. **没有音频、本地化、设置面板、商店页构建**：这些是「生产环境」的组成部分，但不属于本次美术评审；本报告不把它们算作通过，也不假装已覆盖。
6. **本次评审基于 debug 场景与 10s 视频，不是 30 分钟真实对局**：长局节奏、重复观看疲劳、不同编队组合的可读性，需要在美术接入后做一次 30 分钟 playtest + AD 复评。
7. **可访问性未认证**：deuteranopia/125%/reduced motion 只做设计验收，不等于 WCAG/平台认证。
8. **性能余量薄**：当前 3000/1080p 47fps，新美术后若掉到 30–35fps，仍属「刚好达标」；若共享主机负载升高，保守下限可能低于 30。降级路径必须实测，而不是写在文档里。
