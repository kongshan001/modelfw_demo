## 3. 性能优化：从 20 步/秒到可交付

逐项定位与修改：

| 修改 | 效果（100 体，headless 单步） |
| --- | --- |
| 类型化 `Array[Agent]`、typed 循环、热路径障碍 PackedArray | 21 → 13ms |
| 行为门控改为每步位掩码，去掉逐行为字典查找 | 13 → 9.5ms |
| 邻域缓存（每 8 步刷新）、扫描上限 24、候选上限 10、Separation 用前 6 | 稠密人群显著下降 |
| 避障宽相位 + 共享命中变量（去掉逐射线字典分配）+ 非热单位每 2 步重算 | 避障 4.1 → ~0.5–1ms（均摊） |
| 分离力每 2 步重算 | 分离均摊约减半 |
| 单位绘制改为 3 个 MultiMesh + 12 个高亮环 MultiMesh | 200 体：绘制 53 calls / 约 5900 prims；paused 渲染 94fps，替代原先每单位 6 次 draw 的 ~4fps |
| `max_physics_steps_per_frame=1` | 消除单步超时导致的“物理死亡螺旋”；200 体从 4fps → 32–33fps |

真实 GPU（1280×720、vsync off、Intel HD 6000）最终记录：

## 4. 冒烟测试发现的真实缺陷

### 4.1 追逐场景 6 帧穿墙

- 首轮 smoke：视频/走廊/羊群 0 穿墙，追逐出现 **6 帧 / 6 次** 超过 0.6px 的穿透。
- 定位：单位 18 在方块 `Rect2(790,400,130,96)` 上沿缓慢滑入（距离从 8.48 降到 4.28，半径 9.10）。
- 根因：碰撞解析的矩形宽相位写成 `r.grow(4.0)`，应至少按单位半径扩张；当单位中心距表面 4–9px 时完全不进入解析。
- 修复：改为 `r.grow(a.radius + 4.0)`；重新运行追逐 1200 步 → 0 穿墙。
- 备注：这正是“逐帧距离检查”存在的价值，纯截图无法发现。

### 4.2 目标处群体塌缩 / 分离失效

- 重新录制时发现视频后段单位“变少”；密度探针显示 150 体在 13s 时全部挤在约 48×53px 的方块内，速度 <3px/s。
- 进一步检查：所有单位 `neighbors = 0`。
- 根因：加入“邻域每 8 步刷新”时，循环开头仍保留 `a.neighbors.clear()`；非刷新步把缓存清空，Separation 实际只在 1/8 的步生效。
- 修复：只在刷新步清空并重填；其余步复用缓存。
- 修复后：13s 时目标附近形成正常人群环，40s 内 149/150 进入 160px 目标区；视觉上也恢复“绕障—合流—围拢目标”的形态。

### 4.3 目标区口径

- 有了分离力后，150 体不可能全部进入 30px；将“到达”定义改为 **160px 目标区**（画面中以细环标出），并在 UI 中显示“目标区 N”。
- 最终 smoke：视频 98%、走廊 99% 的到达率。

## 5. 视觉迭代

1. 第一版：流场箭头过密（3 格 → 4 格）、箭头过长且箭头头部像“鸟爪”（改为 ±0.55 rad 的干净 V 头）。
2. 单位原为 `_draw` 逐单位画圆/线；为性能改为 MultiMesh 后，第一版高亮环因缩放公式 +5px、纯黄高不透明而像“靶环”；改为贴近身体 +2.2px、透明度 0.62，单位改为“粉圆 + 深色小箭头 + 细描边”。
3. 选中单位的三须：未命中浅蓝、命中红色、法线黄色；力向量：速度白、总转向力粉、避障分力橙、流场分力青。
4. 目标区 / 移动猎物环 / 预设提示配色沿用视频的青+粉。

## 7. 已知风险与后续可做

- 200 体单步约 15ms；虽然 FPS 33.4 达标，但极端密度下模拟时间会略慢于实时（`max_physics_steps_per_frame=1` 的代价）。若要 200 体全实时，需要进一步压缩 GDScript 热路径或改为 30Hz 专用档。
- 流场为静态 BFS；移动障碍、动态目标持续重算只实现了“双击改目标”，未做流场插值。
- 追逐的静态目标环与移动猎物环同时存在（目标点在 1240,450，猎物自由逃跑）；如后续要更贴近“追逐”语义，可隐藏静态目标环。
- Leader 是链式 i→i−1，未作为预设展示；属于已完成但低使用率的功能。
- 300 体为 UI 上限，不承诺 30fps。
