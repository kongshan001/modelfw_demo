# 迭代记录 · 边境制图台

> 2026-11-22 · T-20261121-021（T-20261121-020/T-040 调研的 follow-up）
> 机器：MacBook Air 2015 / Intel HD Graphics 6000 / Godot 4.6 GL Compatibility
> 说明：本机同时运行其他 worker，绝对耗时受 load 影响；下表均为当次实测，保留 median/p95 与采样条件。

## 0. 交付摘要

- 两种完整管线：BSP 地牢（5 阶段）+ FastNoiseLite 群岛（6 阶段，Hero）。
- 统一查看器：种子/子随机流、算法切换、尺寸、参数、速度、暂停/单步/完成、五个调试叠加、阶段/统计/签名/FPS、鼠标平移缩放、中文 UI。
- 7 张 1920×1080 截图 + 10s MP4/GIF；smoke 末行 `PROC_MAP_SMOKE_OK`；600 帧 headless 0 ERROR；GPU 探针 77–131 FPS（两轮）。
- 生成耗时：地牢 median 17.45ms / p95 24.67ms；群岛 median 63.22ms / p95 74.21ms（100 seeds）。

## 1. 第一版：先把两条算法管线跑通

**做法**

- `gen_utils.gd`：seed 文本/数字 → `mix32` 子流；BFS 距离/连通分量；FNV-1a 32-bit 签名。
- `gen_dungeon.gd`：根矩形 (1,1,62,46)，最小叶 10×8，深度 6；房间 5×4 起；最近距离并查集 + L 走廊；BFS 修复/回填；最远点对起点/终点；火把/陈设。
- `gen_biome.gd`：Simplex/Perlin 海拔/湿度/温度；岛屿遮罩；8 类群系；最陡下降河；Poisson 植被/POI；区域最近点。
- `tile_art.gd` 第一版先出可读的地板/墙/水/沙/草/林/岩/雪/河 + 树/POI；`map_view.gd` 用 TileMapLayer 分层，先不做水色/hillshade。

**首个数据检查（10 个 seeds）**

- 地牢 14–19 房间、100% 可达；后期把最大叶从 18 降到 16，平均 15.5 房间，走廊更透气。
- 群岛陆地 44–50%、最大陆块 100%、河流 1–5、树 96–208、POI 8（后改为 6）。
- 早期雪原占比过大（36% 陆地）：雪线 0.56 → 0.70 → 0.755 → 最终 0.69 ± 0.025（配当前海拔分布）。当前版本 seed 9001 雪格约 442（约占陆地 15%），既有雪帽又不吞掉山地；噪声 octave 调整期间曾一度只剩 51 格，已回补。

## 2. 视觉第一轮：从“调试噪声”到可交付地图

**问题**

1. 海面有 32px 深度块硬边，像马赛克；
2. 海岸是硬切口，泡沫几乎不可见；
3. 群系过渡的 alpha 渐隐只有 3px，缩小后仍是方格；
4. 中央雪帽是一整块纯白，没有山体体积；
5. POI 图标/标签太小，地图没有“世界感”；
6. 地牢偏暗，墙体和地面的对比不足，火把光晕太弱；
7. 截图里 FPS 被 PNG 落盘拖到 2–32，容易被误读。

**改动**

- **海面**：全部水格改用同一组 mid 瓦片提供波纹纹理；新增地图分辨率连续深度色 overlay（deep→mid→shallow，alpha 0.64）+ 两层平滑 value noise 明暗，消除深度硬边。
- **海岸**：泡沫从 3.5px 扩到 7px，白色不透明边 + 5px 海水带；陆地格按水方向、水格按陆地方向各画一层，形成双面岸线；沙 overlay 边缘抖动 9px。
- **群系**：沙/森林/岩/雪边缘渐隐从 3.2–3.6px 扩到 9–10px，dither 0.4；雪脊增加蓝色雪痕与露岩点，雪线加 hash 抖动，避免整块白。
- **山体**：新增 hillshade（海拔 1 格 + 3 格梯度，西北光，白/暗 RGBA 叠层，LINEAR），在山脊/山谷产生体积；雪帽/岩地不再平。
- **装饰**：森林 Poisson 间距 1.85→1.62，树量 186→241（其他种子 100–250）；树尺寸 1.02–1.38；POI 图标 ×1.35。
- **标签**：POI 名称从 world 空间改为 **chrome 屏幕空间**，固定字号，自动避开标题/图例；这样就解决了“标签掉到图例下面/被裁掉”的问题。
- **地牢**：地板 `#54564f→#62645a`，墙高光加宽到 3px，阴影 0.36→0.46；火把光晕 140→164px、alpha 0.34→0.52；起点/终点标签靠近右边界时自动向左排；地牢图例只在 BSP 调试时出现，避免遮挡起点。
- **capture mode**：截图/视频工具打开后 FPS 标签显示 `FPS · 录制`；真实帧率由 probe 单独测，避免把抓帧停顿当性能。

**视觉迭代的代价**

- 地牢/群岛的 tile atlas 生成时间增加（更多变体/更高对比纹理），但仍只在首次切换模式时发生。
- hillshade/水色是 96×64 的纹理，一次性生成；后续按生成缓存，不参与每帧。

## 3. 性能第二轮：从 160–250ms 到 62ms

问题不是算法复杂度，而是主线程 GDScript 的额外调用/重复遍历：

| 优化 | 原因 | 效果 |
| --- | --- | --- |
| 纬度/气候等的噪声 octaves 4→3、3→2、2→1 | FastNoiseLite 每次 `get_noise_2d` 都是成本 | 海拔+气候阶段从约 25–40ms 降到 9–15ms |
| 海拔去掉第二个 ridge 噪声和 macro 噪声调用 | 每个格 5 次噪声 → 3 次 | 保留海岸不规则性的同时进一步降本 |
| 分类不再为每个格调用两次 hash 抖动 | 只保留雪线抖动 | 地形阶段从 27–65ms 降到 5–13ms |
| 合并小岛清理 + 陆地统计（一次 BFS） | 原来做了两次连通分量 | 少一次 O(N) BFS |
| 河流不再无条件计算全图水体距离场 | 只有保底入海时才需要 | 河流阶段从 40–90ms 降到 1–4ms（正常路径） |
| 地标不再做全图水体距离场 | 改为每个 POI 的局部 6 格扫描 | 地标阶段从 60–70ms 降到 9–16ms |
| 河流层只在 stage 3 增量写入 | 原来 stage 2/3 各重建全部 8 层 | 应用耗时约减半 |
| relief/water tint 纹理每局只生成一次 | 之前按 stage 缓存导致重复 | 应用阶段更轻 |
| 河源扫描所有格（不再 step 2） | step 2 会漏掉奇数坐标的局部最高点，导致 0 条河 | 修复了 seed 12345 无河的 bug |

**最终 smoke（100 群岛 + 40 地牢）**

```text

BIOME   median 63.22ms / p95 74.21ms / largest_min 95.9% / rivers_min 1
```

**残留成本**

- 阶段切换的 TileMapLayer 批量写格：高负载实测应用耗时总和约 100–200ms（分散在 6 个阶段，不是每帧）。
- 如果地图继续放大，下一步是 WorkerThreadPool 生成纯数据 + 主线程应用；当前不做，以避免线程/场景树错误。

## 4. UI 第三轮：1280×720 必须完整显示

- 第一版 HUD 在 1920 下正常，但在 1280×720 下底部被裁掉（子随机流/提示不可见）。
- 处理：面板 padding 12→9px；根 separation 5→4；种子/按钮/尺寸行 28–30→26–28；统计行固定 16px、字号 9.4/9.2；移除重复的“签名”统计行（签名改到状态行）；保留一行快捷键提示；恢复“子随机流”小标题但压到 8.5px。
- 结果：1280×720 下 HUD 完整显示，1920×1080 下仍有充足留白。
- 相机 fit：群岛按陆地包围盒 +5 格、地牢按地板包围盒 +6 格，岛/地牢填满画面且起点/终点标签不贴边。

## 6. 未做/放弃的选项

- **第三个算法（CA 洞穴）**：调研明确已有 CA 拆解/交互演示，且 `godot-wfc/` 已覆盖 WFC；再加一个容易稀释视觉质量。
- **TileSet Terrains**：见 TECH §4.4；运行时多层 alpha + 双面泡沫与 Terrain 单层模型不匹配。
- **WorkerThreadPool**：当前 62ms median 已满足 brief；先保证阶段播放视觉与确定性。
- **道路/桥梁/锁钥**：brief B 不强制；本轮优先地形轮廓、群系过渡和光照。
- **3D 体素/岛屿**：属于 T-022，本轮不做。

## 7. 可复用经验

1. **“看起来像地图”主要靠过渡和光照，不是算法数量**：连续海色、hillshade、双面海岸、POI 屏幕空间标签，四项比加第三种算法更有效。
2. **运行时烘焙的 TileSet 也能做 16 向自动过渡**：只要预生成所有 mask，执行语义与 Terrain 一致，复杂度可控。
3. **屏幕空间标签是地图 UI 的正确层**：world 标签会随缩放被图例/边框裁切，world→screen 后自动避让非常值得。
4. **生成耗时先分清“算法”与“应用”**：TileMapLayer 写格成本高但可分阶段；不要把它混进噪声/算法的预算。
5. **抓帧时不要展示实时 FPS**：要么 capture mode 显式替代，要么在外部 probe 里测；否则截图会传播错误性能结论。
