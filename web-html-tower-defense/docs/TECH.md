# 余烬堡 / Emberhold · 技术方案

> 单 HTML、零后端、零外部美术资源、程序化抖动像素 + 可无人值守的 AI 指挥官塔防。

## 1. 目标与硬约束

- 一个可双击打开的 `index.html`；HTML + CSS + 原生 JavaScript 全内联。
- **无** CDN、外部图片、Web 字体、音频文件、第三方运行时库、`fetch` / XHR / WebSocket / 网络请求。
- 内部分辨率 **640×360**，CSS 最近邻整数倍放大（1280×720 = 2×，1920×1080 = 3×）。
- 低分辨率 Canvas 2D、固定调色板、Bayer 有序抖动、程序化精灵与几何。
- 两张原创地图 + Bayer 抖动换图过渡；4 种塔、5 种敌人（含 Boss）、12 波、金币/生命/升级/出售/暂停/倍速/胜负/重开。
- AI 指挥官自动经济、建造、升级、技能和存钱；可切换手动；HUD 显示 AI 决策和原因；AI 与玩家共用金币与冷却，不作弊。
- 浏览器 1280×720 / 1920×1080 可用；目标 60 FPS。

**运行文件统计（最终验证）**：`index.html` = **124,212 bytes / 3,497 行**，运行时请求为 0 个外部资源。

## 2. 运行时结构

```
index.html
  <style>                 页面黑底、canvas 居中、pixelated、无外部字体
  <script>
    ├─ 常量 / 调色板 / Bayer / 随机 / 数学
    ├─ 地图定义 + prepareMap()：路径、采样、可建造格、道具阻挡
    ├─ drawTerrain()：一次性烘焙背景（地形/路径/装饰/暗角）
    ├─ 游戏对象 / 波次 / 敌人 / 塔 / 弹道 / 技能 / 特效
    ├─ AI 指挥官（决策循环 + 建造/升级选点评分）
    ├─ 渲染层（世界、塔/敌、HUD、菜单、暂停、结算、转场）
    ├─ 输入层（pointer + keyboard）
    └─ 固定步长模拟 / 60 FPS 渲染循环 / QA 与自动测试钩子
```

### 帧循环

- 模拟固定步长 **1/60 s**；渲染循环独立于模拟。
- 正常游戏：`requestAnimationFrame` 驱动，使用时间累加器把渲染封顶在 **60 FPS**（高刷/无头环境不会无限刷帧）。
- 倍速：`1× / 2× / 3×`，通过 `dt × speed` 的累加与固定步进实现；暂停时不推进模拟，但允许建造/升级。
- 目标 60 FPS；高刷屏与无头环境由时间积分节流，HUD 显示实际呈现帧率。
- 模拟与渲染分离，便于 QA 的 `fastForward()` 离线取景。

## 3. 像素渲染

### 分辨率与缩放

- 内部 **640×360**：左 464×336 为战场（29×21 个 16px 格），右侧 176px 为 HUD；顶部 24px 为资源栏。
- `fitCanvas()` 计算整数比例：`floor(min(innerWidth/640, innerHeight/360))`；小于 1 时允许非整数比例避免小窗溢出。
- Canvas 使用 `imageSmoothingEnabled = false`；CSS `image-rendering: pixelated`。
- 无 CSS 滤镜/叠加层（避免无头合成器取景时的偶发黑场，也降低合成成本）；暗角烘焙在背景中。

### 调色板与抖动

- 固定调色板集中在 `PAL`：深墨黑、夜紫、苔绿、琥珀/余烬橙、霜青、骨白、金。
- **Bayer 4×4** 用于地形色阶、暗角、射程填充、粒子光晕等。
- **Bayer 8×8** 用于地图切换的块状抖动遮罩。
- 背景烘焙：
  - 双频值噪声 + Bayer 阈值 → 4 级地表色阶；
  - 细噪点/苔痕/裂纹/残砖/发光菌/冰晶等装饰；
  - 路径用 3 层圆角描边（18/13/8 px），再叠加随机碎石、磨损、苔痕与方向标记；
  - 8 个大型道具（枯树/立石/骨堆/冰晶）占用不可建造格；
  - 永久缓存成 640×360 canvas，每帧只 `drawImage` 一次。
- 动态精灵使用整数像素 `fillRect` 组合，低分辨率下放大后保持块状边缘。
- 路径可建造性：格中心到路径折线距离 ≥ 15px 且未被道具占用。

### 世界绘制顺序

`背景缓存 → 传送门/灯塔动态火光 → 选中/悬停/建造预览的射程 → 塔 → 敌人（按 y 排序） → 弹道 → 粒子/文字/环 → 环境余烬 → HUD/弹层 → 转场遮罩`

- 选中/建造预览的射程用 4×4 稀疏点阵图案而非平滑半透明圆，保持抖动风格。
- 塔/敌人/弹道均有程序化层级、阴影、血条、受击闪白、减速标记。
- Boss 使用更大的暗色巨躯 + 熔火裂纹 + 角冠 + 顶部全局血条。

### 地图过渡

- `beginTransition()` 先把当前 canvas 抓成快照，快照整体压暗 38%。
- 新场景立即在下方渲染；每 4px 块按 Bayer 8×8 阈值决定是否用旧快照覆盖。
- 时长 **0.88s**，每帧约 14,400 次块级判定、约一半实际 `drawImage`，仅发生在转场期间。
- 开局/换图/改变地图卡均复用它。

## 5. AI 指挥官

### 原则

- **不作弊**：AI 没有独立金币、折扣、免费塔或额外冷却。所有操作都走与玩家相同的 `tryBuild` / `tryUpgrade` / `castSkill`。
- 决策频率：每 **0.55s** 一次；暂停/转场/冻结时不行动。
- 日志：动作后写一条 `建 / 升 / 技 / 存` 记录，包含坐标、目标和原因；HUD 显示最近 3 条，新到旧。`存` 日志会自动清理上一条，避免刷屏。

### 决策优先级

1. **技能**：波次 ≥3 且场上 ≥5 敌，或 Boss 出现时，若冷却就绪则施放烬雨。
2. **起手火力**：攻击塔 <2 → 燧石哨塔。
3. **必需控制**：第 3 波仍无霜苔环 → 霜苔环；仍无焰心炉 → 焰心炉。
4. **经济**：第 2–7 波、无圣坛且金币 ≥ 造价+28 → 铸币圣坛（最多 1 座）。
5. **数量目标**：`min(11, 2 + ceil(wave×0.7))` 座攻击塔；按当前/下一波构成选择霜/焰/燧石。
6. **升级**：优先覆盖路径长、等级低、类型为焰/霜的塔；留 16–18 金备用。
7. **扩展**：最多 12 塔；若暂时买不起目标，按目标记录“存 X/Y · 攒ZZ”的原因。

### 选点

- 以 6px 间隔采样路径；对每个可建造空位计算其射程覆盖的采样点。
- 每个采样点的权重为 `1 / (1 + 已有塔覆盖数×0.8)`，鼓励把塔铺在尚未覆盖的路段。
- 距离已有塔 <26px 扣分；贴路径的格子再加少量分。
- 铸币圣坛选择覆盖最低的角落位置，不占用高价值火力位。
- 评分相同按坐标稳定排序；无随机，可复现。

### 验证

- `?autotest=1&map=ashen|frost` 会启动同款 AI，并用独立 setTimeout 批次推进模拟，与玩家等待等价。
- 两张地图均在无人操作下 12/12 波获胜：
  - 灰烬小径：204 击杀，20 生命，559.67s 模拟时间；
  - 冻苔回廊：204 击杀，20 生命，444.75s 模拟时间；
  - `cheats: false`、`timeout: false`。
- AI 在终局会积累剩余金币，因为已把 12 座塔基本升满并停止扩张；这是防御饱和而不是资源作弊。

## 6. QA / 自动测试与采集

### 命令

```bash
/opt/anaconda3/bin/python tools/verify_and_capture.py
# 或：--skip-video
```

脚本使用 Playwright headless Chromium，从 `file://` 与本地 `http.server` 加载，捕获：

- console error / pageerror / 所有网络请求；
- 菜单、暂停、建造、升级、出售、AI 切换、换图、键盘快捷键；
- 两张图的 AI autotest；
- 1920×1080 截图 10 张；
- 固定步进渲染的 10s MP4 + GIF；
- 最终 `captures/verification.json`。

### QA 钩子（不参与 AI）

| 钩子 | 用途 |
| --- | --- |
| `Emberhold.freeze(true/false)` | 停止/恢复常规模拟，保留渲染，便于稳定截图 |
| `Emberhold.fastForward(seconds)` | 直接按固定步长推进模拟；不改变金币/冷却规则 |
| `Emberhold.holdTransition(p)` | 冻结换图遮罩在指定进度，便于截取过渡帧 |
| `Emberhold.finishTransition()` | 立即结束当前转场 |
| `Emberhold.benchmark(n)` | 同步测量渲染吞吐（ms/帧、理论 FPS） |
| `Emberhold.state()` | 返回场景/波次/金币/生命/塔/AI 日志/性能等 QA 数据 |

这些钩子不影响游戏内 AI 的决策；AI 只在 `simulate()` 内运作，没有金币/冷却/免费单位接口。

### 最终实测（2026-11-26）

- **48 项检查全部通过**；0 console error、0 pageerror、0 外部请求。
- `file://` 与本地 HTTP 均可运行；HTTP 仅请求同源 `index.html`。
- 渲染基准（Playwright headless，1920×1080）：约 **1.85–2.03 ms/帧**（约 **493–542 FPS** 的 JS 渲染吞吐）；游戏主动 60 FPS 封顶。
- 截图 HUD 实际显示 **33–64 FPS**；autotest 结束后待机 47–53 FPS；测试机为共享环境，当时 loadavg ≈ 9.7，因此 HUD 会低于 60。
- 10 张截图均为 1920×1080；MP4 10.0s / 1280×720 / 30fps / 约 540KB；GIF 10.0s / 960×540 / 16.67fps / 约 985KB。
- 单文件 124,212 bytes；源码 SHA-256：`fb038d3391cf74d69d54b146e2d18bb848e0d7a792e28df67d306249b7bdf7b1`。

### 视频采集方式

无头 Chromium 的 `requestAnimationFrame` 在共享环境下会受限，因此视频不使用实时录屏：

1. 用 AI 快速推进到第 6 波、15 个敌人的战斗状态；
2. `freeze(true)` 停止实时模拟；
3. 连续 300 次 `fastForward(1/30)` + 截图 → 10 秒、30fps 的确定性帧序列；
4. ffmpeg 合成 MP4（libx264）和 GIF（palettegen/paletteuse，Bayer 抖动）。

该方式不改变游戏规则，只解决无头环境的帧节流；真实浏览器中用正常实时循环。

## 7. 性能与资源

- 运行时没有图片解码/音频解码/字体下载；首帧前一次性烘焙 2 张背景，之后每帧主要是 1 次 `drawImage`、几十个精灵和少量文字/矩形。
- 渲染基准 1920×1080 下约 2ms；60 FPS 预算 16.7ms，余量充足。
- 模拟（塔/敌/AI）在同一测试中 `<0.1ms/帧`（典型值）。
- 内存：背景缓存 2×640×360×4B ≈ 1.8MB；场上实体/粒子上限 420；日志上限 48 条；弹道/敌人做周期过滤。
- 单文件大小 124KB，不含截图/文档。
- 无外部网络请求；无持久化存储、无 Cookie。

## 8. 已知限制

- 无音频；没有移动端专属手势/布局优化（触摸仍以 pointer 事件能玩，但主要面向桌面）。
- 12 波节奏较长：AI 1× 模拟约 9:19（灰烬小径）；建议 2×/3× 或观看模式。
- AI 后期会存下大量金币（12 塔/升级饱和），HUD 中会显示“存钱”但无更多高价值支出；不影响胜负与公平性。
- 无头 Chromium 的实测 FPS 受共享 CPU 负载影响，截图中 HUD 可能低于 60；渲染基准和 60 FPS 封顶是更可靠的性能指标。
- 参考 Cinderwatch 仅用于概念与体验对照；同名/同素材/同代码均未复用，详见 `CREDITS.md`。
