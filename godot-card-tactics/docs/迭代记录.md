- 真实 GPU 截图 5 张（1920×1080，SubViewport 1.5× 离屏渲染）。

### 截图目检后修正

1. **卡面数字显示成 `5.0` / `3.0`**
   - 原因：`JSON.parse_string` 的数字是 float，`str()` 直接带小数点。
   - 修正：`CardView` 的费用/攻击/生命统一 `str(int(...))`。
2. **胜负覆盖层挡不住单位**
   - 原因：UnitView 的 `z_index` 是 10–15，而 Overlay 默认 z_index 0；Godot 的 z_index 跨父节点生效，单位画在覆盖层之上。
   - 修正：Overlay `z_index = 1000`。
3. **切换选中卡后旧卡仍然放大**
   - 原因：`set_selected(false)` 只重置描边，没有重置 scale/z_index。
   - 修正：CardView 记录 `_hovered`，取消选中且未悬停时恢复 scale 1.0、z 0。
4. **展示局面牌库/手牌/回合不自洽**
   - 演示局面原为“牌库 16 + 手牌 6”（超过 20），显示“第 4 回合”却有 9 法力。
   - 修正：摆拍时从牌库移除 2 张、`started_turns=[9,9]`，显示“牌库 14 · 手牌 6 · 第 9 回合”。
5. **法术截图看不到特效、残留蓝色目标圈**
   - 原因：截图脚本在 0.38s 抓帧，刚好落在凤火的低信息帧；`demo_cast` 没有清除选中状态。
   - 修正：抓帧延后到 0.8s；`demo_cast` / `demo_attack` 等演示接口按真实玩家流程清除选中。

## 2026-11-21 · 第 3 轮：演示视频与性能

### 完成

- `tools/demo_card_tactics.gd`：约 10 秒脚本演出（召唤 → 走位 → 近战 → 凤火 → AI 回合 → 胜利）。
- `tools/record_card_tactics.sh`：Godot Movie Maker（1280×720 @30fps）→ ffmpeg MP4 + GIF。
- `tools/perf_card_tactics.gd`：真实 GPU 待机 + AI 行动 FPS 采样。

### 过程中发现并修正

1. **Godot 首次 headless 运行找不到 class_name**
   - 新项目还没有生成全局脚本类缓存，`CardView` / `BattleCore` 等被报“未声明”。
   - 处理：先跑 `godot --path godot-card-tactics --headless --import`，后续正常运行。这不是运行时问题。
2. **GDScript `inference_on_variant` 警告被当作错误**
   - 例：`for offset in [Vector2i...]` 的 `offset` 是 Variant，`var next := pos + offset` 无法推断类型；`Array.find()` 返回 Variant。
   - 处理：循环变量显式 `: Vector2i`，Variant 返回值用显式类型/`int()`。
3. **`UnitView` 字段名 `owner` 与 Node2D 内置属性冲突**
   - 处理：改为 `owner_id`。
4. **录像脚本解析失败导致 Godot 退出崩溃**
   - 首次录像时 `phoenix_index` 从 `Array.find()` 推断失败，SceneTree 脚本未加载，Movie Maker 仍启动后 Godot 在 cleanup 阶段 abort。
   - 处理：`var phoenix_index: int = int(...find(...))`；之后录像正常，10.43s / 313 帧。
5. **性能脚本等待一个已经 emit 的信号导致挂起**
   - 脚本在摆拍局面（玩家回合）直接 `await ai_turn_finished`；AI 回合未启动/信号已发，等待永远不返回。
   - 处理：新增 `demo_end_turn()` 真正切到 AI 回合；采样不依赖信号，并在退出前释放场景。
6. **截图/视频被 Godot 当资源导入**
   - 处理：`docs/.gdignore`；清理 `docs/shots/*.import` 与孤立 import 文件。

## 2026-11-21 · 第 4 轮：动作期性能整理

### 现象

在第 3 轮后期，系统同时有多个 Godot/Claude worker 运行（load average 11–13）时，AI 行动期采样一度降到 `action_avg=30.5 / min=17`；而空闲时 CPU render time 约 9ms/帧，说明不是渲染管线瓶颈，而是并发负载与重复 CPU 工作叠加。

### 修正

1. `AtlasAnim.load_sheet()` / `static_frame()` 增加进程级静态缓存：
   - 帧 JSON 只解析一次；
   - 卡面静态 `AtlasTexture` 只创建一次；
   - 不再在每次刷新时重复读 16 张卡的 JSON / PNG。
2. 手牌内容签名：`_hand_signature` 相同且卡数不变时，不销毁/重建 CardView，只更新选中态。AI 行动、走位、攻击时手牌通常不变，避免每次动作 churn 一组 Control。
3. 性能采样预热从 1.5s 提高到 2.5s，避免把首次采样算进冷启动。

### 结果

| 日期/轮次 | 场景 | 平均 | 最低 | 最高 |
| --- | --- | ---: | ---: | ---: |
| 空闲复测 1 | 待机 | 92.2 | 90 | 97 |
| 空闲复测 1 | AI 行动 | 91.3 | 86 | 98 |
| 空闲复测 2 | 待机 | 118.0 | 115 | 122 |
| 空闲复测 2 | AI 行动 | 92.0 | 86 | 101 |
| 负载 13.4 最新 | 待机 | 86.0 | 79 | 90 |
| 负载 13.4 最新 | AI 行动 | 77.7 | 73 | 85 |

结论：在更高系统负载下仍保持 AI 行动 avg 77.7 / min 73，高于 30 FPS 目标。早期 `min=17` 属于高并发 + 冷启动的瞬时采样；预热后未复现。

## 2026-11-21 · 第 5 轮：干净 clone 可运行性

### 问题

把项目复制到 `/tmp`（排除 `.godot/`）后直接 `godot --path .` 会失败：

1. `BattleCore` / `CardView` 等全局 `class_name` 在编辑器生成 `global_script_class_cache.cfg` 前无法解析；
2. PNG 依赖 `.godot/imported/*.ctex`，干净 clone 没有导入缓存，`load()` 报 “Unable to open file … .ctex”。

### 修正

1. 所有跨脚本依赖改为 `const X = preload("res://scripts/x.gd")` 别名；保留 `class_name` 供编辑器使用，但运行时解析不依赖全局类缓存。
2. 新增 `scripts/asset_loader.gd`：`FileAccess.get_file_as_bytes` + `Image.load_png_from_buffer` + `ImageTexture`，按 path 做进程级缓存。`AtlasAnim`、`CardView`、`BoardView` 全部改用它。
3. 冒烟测试的资产存在性检查改用 `FileAccess.file_exists`（不依赖导入）。
4. 这避免了 `Image.load()` 对未导入资源发出的 “will not work on export” 警告。

已知边界：原始 PNG 运行时加载适用于源码运行；如果导出 PCK，需在导出过滤器中包含 PNG，或换回导入资源加载。
