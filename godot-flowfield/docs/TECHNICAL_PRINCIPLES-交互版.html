结论先行

一页看完

WFC · 生成

约束满足

每格保留候选瓦片，按 Shannon 熵选最低熵格坍缩，再用栈传播邻接约束；矛盾时快照回溯，超预算则同种子确定性重开。

候选叠加熵回溯

Steering · 局部

期望速度 − 当前速度

Seek / Arrive 给出期望速度，差值就是转向力；叠加分离、对齐、聚合与三须避障，限力限速后积分。没有全局路径，容易局部极小。

力合成分离三须

Flow Field · 全局

一次建场，N 个单位共享

从目标做多源 BFS 得积分场，每格选积分最小的邻格形成流场；单位双线性采样方向，再叠加分离与碰撞。单调性可证明，不会成环。

多源 BFS最陡下降可复现
选型一句话：要“生成地图”用 WFC；要“一小群单位灵活避让/追逐”用 Steering；要“一大群单位绕静态迷宫去同一目标”用 Flow Field；要“大群 + 自然避让”就把 Flow Field 当全局层、Steering 当局部层。

性能结论 · T-011

1000 体，1280×720

初版 B：11.0 FPS / P95 145.4 ms；默认 ALL：26.4 FPS / P95 57.9 ms；同轮归一 2.17×。

单因排序：关拖尾 AA（1.65×）> 半采样（1.25×）> 大群 10Hz（1.13×）。

性能结论 · 代价

平均 FPS 会骗人

1280 ALL 合并 1500 帧仍有 56% 的帧 >33.3 ms、26% >50 ms；worst 218.1 ms。1080 ALL 为 74% / 48%，worst 428.7 ms。

验收看 P95 + hitch，不只看平均 FPS；绝对数在共享机器上不可跨会话比较。

WFC 性能

42.6 / 73.8 FPS

算法视图 / 成品地图（16×10，本机另一会话）。第一版候选几何直画只有 8–9 FPS，改图集 + 掩码拼贴缓存后到 62+。

Steering 性能

33.4 FPS @200 体

50/100/200 = 73.5/45.9/33.4 FPS；200 体单步 15.2 ms。瓶颈是 GDScript 每单位力计算与射线，不是 draw call（53 calls / 5900 prims）。

Flow Field 性能

26.4 FPS @1000 体

T-011 默认配置，1280×720，高负载环境；同轮归一 2.17×。瓶颈从拖尾 AA 转到箭头层。

何时用哪个

  • WFC：约束是局部的、可枚举的；可以接受回溯/重开；内容在加载期生成。
  • Steering：单位少到中等、目标会动、需要追逐/逃离/编队/群体感；障碍局部且动态。
  • Flow Field：大量单位共享少量目标、地图以静态障碍为主、需要确定性的全局绕行。
  • 组合：Flow Field 给期望方向，Steering 做到达减速、分离、贴墙滑行与硬碰撞；动态障碍交给局部避让，或重建代价场。

可点击编辑 · 实时重算

为什么积分场不是“距离”而是“步数”：本实现是均匀代价 BFS，所以积分值就是 8 邻接步数；换成加权地形时改 Dijkstra，流场输出格式不变。对角步也记 1 步，所以热力色在斜向通道里看起来“走得快”，这是离散网格的语义。

04

机制 → 成本 → 验收

把消融讲成因果链

01 · 关拖尾 AA

最大单因

机制：抗锯齿线段被展开成大量屏幕空间图元。成本：objects 138,088→58,087、primitives 151,438→71,436。收益：同轮 1.65×/1.46×；P95 145.4→98.7 / 181.1→109.0 ms。

验收：objects/primitives 显著下降；1.1 px 线宽视觉可接受。

02 · 拖尾半采样

AA 关后才显现

机制：5,000→2,500 段。成本：AA 开减约 45k primitives，AA 关只减 5k。收益：仅半采样 1.25×/1.35×；先关 AA 再开半采样 +71%（15.7→26.9）。

验收：>700 才生效；500 档与 baseline 计数相同。

03 · 大群 10Hz

买 CPU 余量

机制：方向/分离/拖尾 15Hz→10Hz，移动仍 30Hz。成本：图元不变；逻辑步长 18.28→16.17 / 22.84→16.92 ms。收益：同轮 1.13×/1.22×。

验收：逻辑预算 55%→48% / 68%→51%；帧渲染受限时 FPS 增幅有限是预期。

04 · 500→1000 变平

是策略，不是免费

500 档 2,500 条拖尾、15Hz；1000 档半采样后仍是 2,500 条、10Hz。500 的 -AA 计数 53,086/64,434 与 1000 ALL 的 53,087/66,436 几乎相同。

关闭策略的初版：500→1000 为 26.0→11.0 FPS，仍然明显变慢。

常见坑（点开）
  • Y 轴：Godot 2D 是 Y-down，Unity/Three.js 是 Y-up；只在渲染适配层取反，不要改算法 y。
  • 单位：Unreal 厘米、Unity/Three.js 米；cell/速度/半径/分离必须一起缩放。
  • 锚点：Unity Sprite 默认中心、Unreal pivot 可能脚底；统一到格心/单位中心。
  • 实例化上限：Unity DrawMeshInstanced 每批 1023；Godot MultiMesh 无此限制，不能照搬 draw call 数。
  • 线宽：Three.js LineBasicMaterial.linewidth 多数平台被忽略；用四边形条带/自定义 shader。
  • AA 语义：各引擎抗锯齿线成本差异大；把拖尾 AA 做成独立参数并实测。
  • 随机数：不要用全局 Random；用可序列化状态，否则同 seed 不可复现。
  • 浮点确定性：整数网格 + 固定顺序保证算法确定；浮点位置验收用容差（参考引擎 0）。
