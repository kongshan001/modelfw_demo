# 绯星弹幕 · 迭代记录

## 2026-11-24 · 参考研究与范围界定

- 参考：B 站《Godot 弹幕怎么做？从一颗子弹到 10 种弹幕》BV1B4yRzEE9x（UP：还没醒er）。使用 `yt-dlp` 下载到 `/tmp/bullet_ref/`（B 站提供的是 360×640 竖屏录屏，30fps，172s），用 `ffmpeg` 抽 10s/关键帧审阅；**只放 /tmp，不复制进仓库**。
- 从教程中确认的“方向 + 速度 + 行为”结构：
  - 单发：`dir = player.position - position; fire(dir.angle(), 300)`。
  - 扇形：`k = i-(n-1)/2; fire(aim + k*spread, speed)`。
  - 环形：`for i in 24: fire(TAU/24*i, 250)`。
  - 螺旋：每 0.05s，`angle += deg_to_rad(10); fire(angle, 250)`。
  - 多层速度：`for j in 5: fire(aim, 200 + 60*j)`。
  - 花瓣：`speed = 300*abs(cos(3*a))`；教程里 k=3 → 6 瓣。
  - 停顿转向 / 追踪：子弹自身脚本，`rotate_toward` 限角速度后朝玩家。
  - 分裂：延迟 0.5s 后 `TAU/12*i` 环形生成 12 发。
  - Boss 时间轴：按 beat 调不同弹幕；判定点是视觉大圈 + 极小实心点。
- 本项目按任务书的 10 项清单重新映射为：单发瞄准、三向扇、五向扇、环形、双翼螺旋、连射加速层、正弦花瓣、追踪、定时分裂、旋转弹幕墙。参数与视觉均为独立调校，角色名/UI/贴图原创（“辉庭守望者 · 环”、“萤舟”、“绯星弹幕”）。

## 2026-11-24 · 第一轮：核心系统

- 新建 `godot-bullet-hell/`（Godot 4.6、GL Compatibility、1280×720、canvas_items 拉伸）。
- `BulletPool`：14 条平行定长数组、容量 4096、写指针压实；直线/正弦/追踪/分裂行为；圆形命中 2.6px、擦弹 20px；单次 hit/graze 标志。
- `PatternRunner`：10 种 pattern 数据化参数；教程节奏映射（0.05s 螺旋、24 发环、5 层速度、cos 花瓣等）。
- `BulletField`：MultiMesh + additive glow shader；全部敌弹 1 个 draw call。
- 初次 headless smoke 发现“螺旋角度推进”断言误判：首尾弹恰好跨 360° 同角，改为统计不同方向数（≥6）后通过。不是运行时 bug。
- headless smoke 最初 55 checks 全过；`BULLET_HELL_SMOKE_OK`。

## 2026-11-24 · 第二轮：时间轴、玩家、UI

- `BossTimeline`：120 BPM、三阶段（10s/12s/16s）、每 phase 4 个 pattern 事件；时间轴总 38s + 两次 1.5s 切换。
- Boss HP 1200/1450/1900；阶段切换清弹、1.5s 无敌、横幅、环和屏震。
- 玩家自动射击 0.10s/发、10 伤害、900px/s 锁定 Boss；自动演示 Lissajous 走位 + 附近弹斥力；方向键/WASD 即时接管；TAB 切换。
- 1–0 观察、Q 返回、P 暂停、R 重开、Shift 聚焦；FPS/弹数/seed/BPM/残机/擦弹中文 HUD；暂停/胜利/GameOver 覆盖层。
- 被弹：5 残机、2.2s 无敌、132px 清弹屏障、红色闪屏/爆炸/屏震。
- 截图第一版发现阶段横幅在观察模式仍残留，遮住弹幕；修复：`set_inspect()` 清 HUD transition/FX/shake，观察模式立即可见。

## 2026-11-24 · 第三轮：视觉与截图

- 视觉方向：紫黑舞台、青/品红/金色霓虹、白色核心发光弹、同心环、星屑、绯瓣、细边框；教程只提供“发光圆点/圆形 Boss/俯视深色舞台”的视觉语言，具体配色与图形原创。
- Shader 调整：缩小白色核心、提高实例色光晕权重，使颜色在密集场景更可读。
- 星屑从 92 个/较亮降为 64 个/低 alpha，避免被误认为白色核心弹；背景去掉与 HUD 冲突的底线。
- HUD 底部提示上移，消除 720 逻辑高度下的裁切；加入 REC 模式标签。
- 1920×1080 截图：18 张（10 pattern + 时间轴 + 阶段切换 + 擦弹 + 命中 + 1200 弹 + 暂停 + 胜利）。
- 生成 10s 展示视频：Movie Maker 600 帧 @60（项目窗口 1280×720，源 AVI 39.9MB），ffmpeg → 1080p H.264 MP4（3.8MB）和 800×450 GIF（6.3MB）。

## 2026-11-24 · 性能迭代

- 最初 1920p/1200 弹独立采样平均 38–43 FPS；一两次采样低到 25 FPS，判断与 Intel HD 6000 温度/采集环境有关。
- 优化 1：HUD `queue_redraw` 20Hz（动态文字 50ms 粒度足够），背景 30Hz；仍逐帧推进逻辑和 MultiMesh。
- 优化 2：截图/调试模式强制 HUD 重绘，避免静帧缺更新。
- 最终独立采样（vsync off，预热 2.5s，测 4s；preload/静态类型重构后）：
  - 1280×720 / 200 弹：avg **74.13**，worst frame 25.91ms；
  - 1920×1080 / 200 弹：avg **67.98**，worst frame 20.92ms；
  - 1280×720 / 1200 弹：avg **51.34**，worst frame 24.89ms；
  - 1920×1080 / 1200 弹：avg **46.88**，worst frame 29.12ms。
- 结论：压力场景均值 ≥30；1200 弹为验收压力，不是常规难度。四组最终采样最坏帧 29.1ms；历史运行曾出现 73ms 单帧，故文档同时记录 worst frame 并强调运行间波动。
- 截图 HUD 最终读数：base 90 / 1200 弹 49（会随采集状态波动）；视频 HUD 改为 `REC 60FPS`，表示成片节奏。

## 2026-11-24 · Fresh-clone 兼容修复

- 在排除 `.godot/` 的干净副本上测试，发现直接 `godot --headless` 启动会因 `global_script_class_cache` 缺失而报 “Identifier Art/HaloBoss not declared”。这会影响未打开过编辑器的全新 checkout。
- 修复：所有跨脚本引用改为文件头 `const XxxRes = preload("res://scripts/...")`；跨脚本变量/参数使用 preload 常量作为静态类型（如 `var boss: BossRes`、`func update(..., pool: Pool, ...)`）。`class_name` 仍保留供编辑器使用，但运行时不再依赖全局类缓存。
- 重新测试：干净副本 headless boot 无 ERROR、69 项 smoke 全过；同时静态类型恢复后，最终性能采样优于重构前（1200 弹 1080p avg 46.88、720p avg 51.34）。
- 日志：`docs/logs/fresh_clone_boot.log`、`docs/logs/fresh_clone_smoke.log`。
