# 迭代记录 — Blender HB-7

## 2026-11-19 · 第 1 轮：用 Python/Bpy 生成 10 秒产品短片

**参考**：B 站《这居然是 Fable5.2 用代码做出来的视频？怎么实现的？》
（BV1VXsU6bEx3）。视频讲的是 Agent 通过 **BlenderMCP** 写 Python 驱动 Blender，
再渲染成片。本次按同一思路落地：先装 Blender + MCP，再用 `bpy` 直接生成一段
机械蜂核心的 10 秒产品短片。

**环境**：

- 原有 Blender 3.4.1；新装 **Blender 4.2.9 LTS** 到 `/Applications/Blender-4.2.app`；
- `mcp-for-blender` 2.3.1：插件装进 3.4/4.2，server 用独立 venv；
- Claude Code MCP 配置 `blender` 已 Connected。

**实现**：

- `scripts/build_scene.py` 程序化构建 17 类部件：白陶瓷胸腔、黑色光学镜头、
  红/黑环、黄铜尾齿轮、4 片带叶脉的透明翼、6 条腿、深色转盘与红环；
- 4 盏面光（暖主光 / 冷补光 / 红轮廓 / 顶部柔光）+ 近黑世界；
- 相机固定在 orbit 空物体上，关键帧做 116° 轨道 + 轻微推近，52mm / f2.8 景深；
- 4 翼 3.6Hz 拍动（每 2 帧线性烘焙）、机身漂浮、镜头环脉冲、尘埃旋转；
- Blender 3.4.1 EEVEE Legacy，960×540 / 24fps / 240 帧 / 8 samples，
  ffmpeg 输出 MP4 + GIF。

### 本轮问题与修复

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 身体在地面、翅膀悬空 | `matrix_parent_inverse` 保留世界位置，身体零件留在世界原点 | 身体按 root 局部坐标建模，直接 parent |
| 2 | 相机对不准物体 | Track To 约束叠在动画父级上 | 固定相机局部朝向，只旋转 orbit 父级 |
| 3 | 镜头被白壳挡住 / 黑镜头变白球 | 起始机位在尾部一侧；黑色金属高光过强 | 轨道反向从头部开始；镜头改哑光黑 |
| 4 | 翅膀像竖着的薄片 | 网格建在 XZ 平面 | 改 XY 平面，加 14° 上反角 + 后掠 |
| 5 | 红环被埋进白壳 | torus 主半径小于壳体截面 | 主半径加到 0.63/0.65 |
| 6 | 4.2 一渲染就崩 | EEVEE Next 在 Intel HD 6000（Metal GPUFamily 1）崩溃；Workbench 也崩 | 最终用 3.4.1 EEVEE Legacy |
| 7 | Cycles 太慢 | CPU 640×360/8 samples ≈7.5s/帧 | 不作为成片路径 |
| 8 | `uvx mcp-for-blender` 连接失败 | uv console script 的 shebang 依赖 macOS 缺失的 `realpath` | 建独立 venv，用 `python -m blender_mcp.server` |
| 9 | 渲染时间过长 | 16 samples + 720p + 玻璃罩 + 46 尘埃 | 8 samples / 960×540 / 去玻璃罩 / 18 尘埃 |

### 验证
