# 坍缩花园 · 迭代记录

日期：2026-11-21 · Godot 4.6 · GL Compatibility · Intel HD Graphics 6000（1280×720）

## 0. 任务与验收口径

按 B 站 BV1Br421M7Vm 的实际演示做 WFC 交互 demo：4×4 教学网格换成可调尺寸庭院地图；
每格精确候选、权重熵、栈传播、矛盾回溯、固定种子可复现；算法视图/成品地图切换；
1920×1080 截图至少 4 张、10 秒 GIF/MP4；Intel HD 30 FPS+；不复制视频素材。

先拉 720p 视频（`yt-dlp`）→ `ffmpeg` 1s 抽帧/分段接触表。确认视频核心是
2D 瓦片 + 边约束 + 熵 + 快照回溯；片头片尾的 3D 城镇只是效果展示。取证时间线见 `TECH.md`。

## 1. 首个可运行版本：瓦片与求解器

- 设计原创庭院瓦片：草甸、花圃、林地、池塘、石屋、温室、废墟、石径。
- 第一版石径带 4 种断头（END）瓦片；用 16×12 / 24 颗种子跑下来 **一次矛盾也没有**，
  因为任何路臂都可以随时收尾，回溯路径无法演示。
- 改为「无断头石径」：横/竖/四拐/十字；每条路臂必须接下一个路臂，天然形成环路。
  这下 seed 会产生真实矛盾；但少数 seed 进入几千步的深回溯。
- 加 `BACKTRACK_BUDGET = 48`（每次尝试的回溯上限）+ `MAX_RESTARTS = 48`（确定性重开）。
  seed 2718（16×10）变为 147 步、7 回溯、4 矛盾、0 重开；关闭回溯时 9 次重开仍合法。
- 单步、暂停、速度、视图、键盘控制接上；事件流把坍缩/传播/回溯/重开写出来。

## 2. 性能诊断 1：第一版绘画直接卡在 Intel HD

第一版把每个候选小瓦片都画成 `draw_circle/draw_line`，每格最多 14 个候选，300 格；
地图视图每格再画草叶、树冠、池塘等几何。

| 状态 | 首版实测（1280×720，vsync off） |
| --- | --- |
| 初始叠加态（20×12 压力图，300 格 ×14 候选） | 8–9 FPS 静态 |
| 成品地图动画 | 2–9 FPS |
| 隐藏棋盘 | 约 98–121 FPS |

诊断：不是求解器，是 CanvasItem 每帧提交太多小图元；初始态近 300 格 ×14 候选，
并且地图视图每帧重绘大量草叶/树冠/水纹。首次优化：

1. 新增 `tile_baker.gd`：SubViewport 把 14 种瓦片 ×4 个变体烘焙进 1024×1024 图集；
   成品格/已坍缩格变成 1 个纹理区域。
2. 候选改为每类瓦片一个 MultiMesh；但每步重建 4200 个实例变换，仍会在早期掉帧。

## 3. 性能诊断 2：候选拼贴缓存

观察：同一候选掩码的熵和候选集合完全一样，视觉也一样；一张地图从开始到结束只出现
约 20–50 个不同掩码（实测 16×10 seed 2718：39 个；20×12 压力图：41 个；seed 3：48 个）。

做法：

- 启动烘焙时把 14 张 128×128 瓦片缩成 24×24 的小图标。
- 首次遇到某个掩码时，在 CPU `Image` 上画 128×128 拼贴：背景是该掩码的熵热力色，
  4×4 格子里放精确候选缩略图；`ImageTexture` 缓存。
- 算法视图每格只需 `draw_texture_rect` **一次**；精确候选信息保留。
- 地图视图限制环境动画：屋灯 + 全图 12 个萤火，地图重绘封顶 12 FPS。
- 默认速度从 24 降到 20 步/秒；HUD 刷新与模拟步进解耦（约 6.7 Hz）。

性能前后（同一台 Intel HD，关垂直同步；测试期间机器并发负载较高，数值按采样窗口记录）：

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 初始叠加态静态（20×12 压力图） | 8–9 FPS | 62–64 FPS（后续采样） |
| 成品地图动画（20×12 压力图） | 2–9 FPS | 51.5 FPS 平均（第一段 23 FPS 为预热） |
| 默认 16×10 生成 | — | 见最终 probe |

## 4. 视觉迭代

- 棋盘从“小 tiles + 大留白”改为宽屏 16×10 / 18×10，让 1280/1920 下地图尽量铺满卡片；
  （开发中曾做 20×12 压力图，最终为避免 Intel 集显掉帧，大图档位收敛到 18×10。）
  地图保持正方形格，三种尺寸都贴近 16:10 构图。
- 算法视图：
  - 熵热力背景从高饱和红棕调成深绿→暖褐；
  - 取消每格所有几何图元，候选变为精确缩略拼贴；
  - 当前熵最低格用琥珀角标和脉冲波；
  - 传播只保留最近一步的琥珀描边 + 扩散圆点；
  - 回溯时棋盘顶部弹出「冲突 → 回溯一格」横幅，并给恢复格/冲突格珊瑚色边框；
  - 右侧 HUD 显示坍缩/传播/回溯/重开四宫格、进度、下一个熵最低格、最近 3 条事件。
- 成品地图：
  - 1024 图集 + 4 个变体；草甸/花圃/林地/池塘/石屋/温室/废墟/石径；
  - 石径 90°/十字接口按邻接连续绘制，视觉是闭合庭院环路；
  - 屋灯和萤火只保留很轻的环境生命；截图/视频里仍能读出格尺度。
- 默认种子定为 `2718`，不用反复试 seed 就能看到一次回溯；
  留了“随机”按钮探索其它 seed。

## 5. 自测与证据

- `WFC_SMOKE_OK`：24 张地图（12×8/16×10/18×10）逐边独立校验 6384 条关系 100%；
  同种子签名/步数/回溯/重开完全一致；seed 2718 有可观测回溯；关闭回溯进入重开路径；
  UI 场景单步/切视图通过。
- 600 帧 headless 启动：无 SCRIPT ERROR / ERROR。
- 6 张 1920×1080 GPU 实拍，见 `docs/shots/`。
- 10 秒 30fps 过程视频，MP4 1280×720 / GIF 960×540，见 `docs/wfc_garden.*`。
- FPS 探针（Intel HD 6000，1280×720，vsync off）：默认 16×10 / 20 步/秒的生成
  `avg 42.6 / min 38`，成品地图 `avg 73.8 / min 46`；18×10 大图临时压力约
  `avg 38.3 / min 25`，成品约 `avg 77.3`。
  运行命令：`godot --path . --resolution 1280x720 -s tools/probe_wfc.gd`。

## 6. 已知问题 / 下一步

- 2D 瓦片是程序化几何，缺少视频片尾 3D 城镇的体积感；如果后续要做 3D，需改为体素/glTF 版。
- 没有可玩性后处理（连通道路、建筑入口、POI 分布）；当前主要是算法可视化。
- 18×10 大图与高速度组合对 Intel 集显更重；默认 16×10 / 20 步/秒是推荐档位。
- 极端 seed 可能耗尽 48 次确定性重开，界面会显示失败；目前不做完全 SAT 搜索。
- WFC 只保证局部边约束；地图的整体叙事（水系贯通、路网连接建筑）需要更高层规则。
