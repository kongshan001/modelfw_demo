# 坍缩花园 · 技术说明

> 目标：按视频实际讲到的 WFC 流程，做一个能暂停/单步/调速/回溯/固定种子的 2D 地图生成交互 demo。
> 引擎：Godot 4.6，GL Compatibility，1280×720；原创程序化瓦片；不复制视频素材。

## 1. 取证：视频实际演示了什么

参考：B 站 BV1Br421M7Vm《〈地图随机生成〉波函数坍缩算法是如何实现的》，4:50，UP：SLi97（发布时间 2024）。
采集：`yt-dlp 2026.08.19` 拉 720p（1280×720/30fps，AV1，289.77s）+ `ffmpeg` 全程 1s 抽帧与
关键段接触表。只把结果写在文档里，视频画面/字幕没有进入仓库。

| 视频时间（±2s） | 画面与讲法（转述） |
| --- | --- |
| 0:00–0:48 | 片头是若干 3D 体素城镇/城堡的生成结果展示，属于效果 montage，不是交互教程本体。 |
| 0:48–1:05 | 标题后引出 5 张绿/橙抽象瓦片；从空白 4×4 网格开始，每格出现「5 个候选」的组合小图标。 |
| 1:05–1:22 | 某格随机坍缩为一张瓦片；邻格的候选集合随之缩小，形成最初的传播。 |
| 1:22–1:36 | 「约束规则」：以瓦片1 为例，其上方可接 2/3/4/5，右方可接 1/3/4/5；规则按方向分别给出。 |
| 1:36–2:30 | 引入权重与 Shannon 熵；高熵格子保留更多可能，选熵最低的格继续坍缩，并按权重抽取。 |
| 2:30–3:40 | 「回溯」：路径走进无解 U 形时，读取上一步保存的快照回退；用栈保存每次坍缩前的状态。 |
| 4:10–4:35 | 总结三步：制定约束并传播；算熵选最低；每次坍缩保存快照，无解时回溯。片尾再接 3D 生成 montage。 |

结论：视频是 **2D 网格 + 简单边邻接瓦片**（不是重叠模型），演示了叠加态、约束传播、带权熵、
快照回溯；3D 城镇只是片头/片尾效果。本工程据此做 2D 庭院交互版；**没有**把视频的 5 张图或画面复制进仓库。

## 2. 状态与整体结构

```
wfc_solver.gd     纯逻辑：掩码叠加态 / 熵 / 约束传播 / 快照回溯 / 确定性重开
wfc_tileset.gd    14 种瓦片的边接口、权重、名称、基础色
tile_art.gd       程序化瓦片图形（草地/水/路/建筑/树/温室/废墟）
tile_baker.gd     启动时把 14×4 个瓦片变体烘焙成 1024×1024 图集
board_view.gd     两套视图：算法叠加态/熵热力/波前；成品地图
main.gd           生成循环、速度、暂停/单步/重开、视图、键盘
hud.gd            中文参数面板、统计、事件流
```

固定种子路径完全在 `wfc_solver.gd` 内，不依赖渲染或 UI 状态。

## 3. 瓦片集与约束格式

每格是 `width × height` 位图，每格一个 `int` 位掩码，第 `t` 位表示瓦片 `t` 仍可能；
14 种瓦片只使用 32 位整数的低 14 位。

每条边只有一个「接口」值：

- `0` = 草地/陆地接口
- `1` = 石径接口

邻接规则：对相邻格 A、B，A 在方向 `d` 的接口必须等于 B 在反方向 `opposite(d)` 的接口。
外边界另有约束：最左列不允许西侧石径接口，最右列不允许东侧、顶行不允许北侧、底行不允许南侧，
防止「断头路」伸到地图外。

| # | 瓦片 | N/E/S/W 接口 | 权重 |
| --- | --- | --- | --- |
| 0 | 草甸 | 0,0,0,0 | 4.20 |
| 1 | 花圃 | 0,0,0,0 | 1.55 |
| 2 | 林地 | 0,0,0,0 | 2.55 |
| 3 | 池塘 | 0,0,0,0 | 1.20 |
| 4 | 石屋 | 0,0,0,0 | 0.82 |
| 5 | 温室 | 0,0,0,0 | 0.48 |
| 6 | 废墟 | 0,0,0,0 | 0.52 |
| 7 | 石径·横 | 0,1,0,1 | 0.62 |
| 8 | 石径·竖 | 1,0,1,0 | 0.62 |
| 9–12 | 石径·四拐 NE/ES/SW/WN | (1,1,0,0) 等 | 各 0.38 |
| 13 | 石径·十字 | 1,1,1,1 | 0.14 |

重要的设计取舍：**石径没有断头瓦片**，每条路臂必须接到下一格；路网因此会闭合成环。
这既让地图更像庭院环路，也在边界/路径拥挤时产生真实的局部矛盾，从而能演示回溯。
地形/建筑/池塘的边都是陆地接口，它们之间可自由相邻，石径只会被边界和其它石径约束。

兼容表在 `wfc_tileset.gd::build_compat()` 预计算：`compat[direction][tile]` 是该瓦片在
该方向允许的邻格瓦片位掩码。

## 4. 熵与带权随机

候选掩码 `mask` 内的瓦片权重为 `w_t`，总权重 `W = Σ w_t`，Shannon 熵：

```
H(mask) = ln(W) - (Σ_t w_t ln w_t) / W
```

- `H = 0` 表示已经只剩一个瓦片；已坍缩格不参与选择。
- 每次选 **候选数 > 1 且 H 最小** 的格；每格另有一个由 RNG 生成的一次性 jitter（0–0.0008），
  只用于打破完全相同熵的平局，随种子确定。
- 坍缩时按 `w_t / W` 加权抽一个候选。
- 未坍缩格的背景热力色由 `H / H_max` 映射：低熵深绿、高熵暖棕。

伪代码：

```
mask[cell] = 全部瓦片 & 边界允许
while 有未坍缩格:
    cell = argmin(H(mask), jitter)
    tile = weighted_choice(mask[cell])
    snapshot = (board.copy(), cell, mask[cell], tile)
    压入回溯栈
    mask[cell] = {tile}
    传播波前(cell)
```

## 5. 栈式邻接约束传播

```
stack = [collapsed_cell]
while stack:
    i = stack.pop()
    for d in N,E,S,W:
        j = neighbor(i,d)
        allowed = OR compat[d][t]  for t in mask[i]
        narrowed = mask[j] & allowed
        if narrowed == mask[j]: continue
        if narrowed == 0:       # 矛盾
            conflict_cell = j; return
        mask[j] = narrowed
        if j not in stack: stack.push(j)
```

- 每个域变化只向四邻传播一次（用 `queued` 去重）；发生交集变化才重新入栈。
- 传播过程中被缩小的格用琥珀色波前高亮；当前步骤的 `wave` 数组由求解器返回给 UI。
- 这个传播相当于在「边约束」上的弧一致传播（AC-3 的简化版本）：每次坍缩后把新的约束
  局部闭合后再进入下一轮熵选择。

## 6. 快照回溯与确定性重开

每次坍缩前保存：

```
{board: PackedInt32Array.duplicate(), cell, candidates(mask), chosen}
```

出现矛盾时：

1. 若回溯开启，弹出最近快照，恢复格与棋盘，把 `chosen` 从该格候选中删掉；
   让 `_pending_cell = cell`，下一次 `step()` 优先在该格继续尝试剩余候选。
2. 若那次选择已是最后候选，继续弹出更早的快照（时间顺序回溯）。
3. 单次尝试累计回溯超过 `BACKTRACK_BUDGET = 48`，或回溯关闭，则进入自动重开：
   `attempt += 1`，用同一基础种子与新的 attempt 做 splitmix 式混合重置 RNG 与棋盘；
   最多 `MAX_RESTARTS = 48` 次。
4. 重开仍使用同一基础种子，整个重开序列与结果都可以复现；因此「同种子完全一致」包括回溯路径。

默认种子 `2718`（16×10）的实测路径：
`147` 次推进、`7` 次回溯、`4` 次矛盾、`0` 次重开，生成唯一合法地图。
关闭回溯测试同一 seed：`9` 次确定性重开、`0` 次回溯，仍生成合法地图。

## 7. 复杂度

设 `N = width × height`，`T = 14`，`S` 为坍缩/回溯步数。

- 初始化：`O(N·T)`。
- 选最低熵格：每步扫描 N 格、每格最多 T 个候选 → `O(N·T)`。
- 传播：每格的域变化最多触发 4×T 位运算；一般传播闭合远小于 `O(N·T)`。
- 快照：最坏每次坍缩复制一个 N 元素 `PackedInt32Array`，总内存 `O(S·N)`（18×10、约 200–300 步
  仍是几百 KB 级）。
- 理论最坏情况仍可能指数回溯；本地用 48 次预算 + 48 次重开上限把病态 seed 变成确定性重试，
  保证交互 demo 能在有限时间内结束。

## 8. 可视化与渲染优化

- **算法视图**：候选叠加、熵热力、当前最低熵格、波前、回溯红框和事件流；每格可悬停查看。
- **成品地图**：同一棋盘换成完整瓦片纹理；保留轻微屋灯/萤火，但把粒子限制为全图 12 个，
  并把地图动画重绘上限压到 12 FPS。
- **启动烘焙**：`tile_baker.gd` 用 SubViewport 把 14 种瓦片 ×4 个变体画进 1024×1024 图集，
  之后成品格是一个 `draw_texture_rect_region`。
- **候选拼贴缓存**：熵只由掩码决定，同一掩码的视觉完全一致。每次遇到新掩码，用 128×128
  `Image` 把该掩码的候选图标拼成一张纹理并缓存；一般整张地图只会遇到 20–50 个不同掩码。
  这样每格从最多 14 个候选绘制命令降为 **1 张纹理**，保留精确候选信息。
- **运行节奏**：默认 20 步/秒；模拟步进与 UI/HUD 刷新解耦（HUD 约 6.7 Hz），
  `pause` 后仍可单步；回放工具用固定 1/30 秒手动推进动画，不受录帧耗时影响。

这一层是性能上的关键：第一版把几何原语直接画在 CanvasItem 上，1280×720 的初始 300 格叠加态
只有 8–9 FPS；改为图集和掩码拼贴后，初始静态画面提升到 62+ FPS（同一台 Intel HD，见迭代记录）。

## 11. 已知风险与限制

- 这是边约束 WFC，不是重叠模型（Overlapping WFC），不使用样图统计 patch。
- 没有连通性/可玩性后处理；道路可能形成多个环路，建筑之间未必由道路连接。当前需求是算法演示，
  不是关卡生成器。
- 回溯预算与重开上限是工程折中；极少数病态 seed 可能耗尽 48 次重开并显示生成失败。
- 2D 美术为程序化几何，不追求商业资产级细节；运行分辨率固定 1280×720（可用 SubViewport 出 1920 截图）。
- 中文界面依赖系统 CJK 字体，不打包字体文件。
- 性能测试受本机并发负载影响；正式报告会注明是否关闭垂直同步及采样窗口。
