## 1. 参考研究（只抽象机制）

参考视频：B 站《这是解谜游戏史上最富有想象力的关卡之一》，`BV1o9pQz2EWm` / `b23.tv/dM7vHb6`，4:47，UP **A宝OVO_**；游戏 Monument Valley。视频标注 4K，本机用 `yt-dlp` 取 1080p 版本研究，未进入仓库。

用 `ffmpeg` 抽帧 t=0/20/40/60/90/120/150/180/210/240/270 s，观察到的**抽象机制**：

- 固定等轴视角的单体建筑 diorama；章节之间整体旋转/升降，玩家不能环绕相机。
- 角色沿建筑上的路径点行走；点击目标，角色自己沿路走。
- 屏幕空间错觉：两个不同高度/深度的平台端点在画面上拼在一起，角色可以“走上去”，实际是在屏幕上连通。
- 有些构件（转盘/桥/建筑段）可被拖动旋转；旋转改变端点屏幕位置，从而改变连通。
- 关卡末端有一个明确的终点标记；走到即完成；过关后进入下一段。
- UI 有手摇柄/旋钮样的旋转提示；本作不复刻该视觉。

**没有**复制其具体关卡布局、角色（Ida）、建筑、神圣图案、配色、音乐、品牌或 UI。项目名、角色、关卡、几何、色板、UI、文案均为原创。参考帧只放在 `/tmp/monument_ref`，未入库。

## 2. 原创决策

| 项 | 决定 |
| --- | --- |
| 名称 | **Foldpath · 折径** |
| 主题 | 折纸/纸片建筑 + 黄铜刻线 + 苔绿/奶油/陶土色板；天空渐变与雾，漂浮纸片、纸鸟、纸环 |
| 角色 | **小折狐**：低模折纸狐狸，围巾、折耳、卷尾；不是 Ida，不是人类女孩 |
| 关卡 | L1 纸阶（预对齐教学）、L2 旋桥庭（单桥两阶段）、L3 环折塔（环桥+折塔双旋转、三段跨层） |
| 相机 | 固定正交等轴，仅允许轻微 zoom；不做 orbit |
| 交互 | 点击节点行走；拖动构件/Q E 旋转；撤销/重置/提示/关卡选择；中文 HUD；F1 调试 |
| 屏幕缝 | JSON 声明的 `fold_pairs`，运行时用投影距离+深度差判定；不是预烘焙连通 |

## 3. 实现时间线

### 3.1 核心数学与关卡（先保证机制成立）

- 实现 `FoldMath`：固定 YXZ 相机基、屏幕不变方向 `BACK=(1,1,1)/√3`、正交投影、屏幕 ray、Y 轴 OBB 拾取、15° 吸附。
- 实现 `FoldLevel`：JSON schema、节点世界坐标 `pivot + R_y(angle)*local`、折环候选/激活、BFS 路径图。
- 关卡用 Python 小工具从“旋转平台 + 端点对齐”反推静态平台坐标；初始 L1–L3 JSON 生成。
- 发现并修复：
  - Godot 4 没有 `ConeMesh` 类（用 `CylinderMesh` 的 `top_radius=0` 代替）；`const BACK := Vector3(1,1,1).normalized()` 不是常量表达式，改为字面常量；
  - 如果自动配对“所有度数为 1 的端点”，L3 在 15° 网格上会出现 `r1–t2` 24 px、`l–t1` 等偶然对齐，产生绕过旋转的捷径；改成显式 `fold_pairs` 后仍由屏幕投影实时开关，并把阈值收到 18 px；
  - 初始 smoke 把“L3 在环 90°+塔 90° 同时有两条缝”当预期，实际塔旋转会带走 t1，只剩 t2–c；按真实阶段修正 smoke 和场景；
  - 正交投影测试中，世界垂直 1 单位在屏幕上不是 `720/size` 而是 `0.816497 * 720/size`（相机 up 与 Y 的夹角），修正测试。
- 第一版 smoke 150 checks 通过；加入键盘移动/最终验收后为 154 checks；`--headless --quit-after 600` 无 SCRIPT ERROR。

### 3.2 第一次真实渲染：可读性与构图

- 首版 1280×720 渲染（draw calls 251–369）：画面过曝、纸片与背景对比度低，画面发灰；L1 高台正好盖住低庭路径；L3 的圆盘环与折塔/高冠堆叠。FPS 约 30–42。
- 措施：
  - 色板加深（奶油/苔绿/陶土/黄铜），天空与雾分层；开启 Filmic tonemap + 轻 adjustment；
  - 路径改为深松底色 + 奶油上带，节点 pad 改为深松 + 亮色菱形；
  - L1 高台从“向屏幕右上方延伸”改为“向屏幕左上方延伸”，把跨层端点留在原地、只让平台的其余部分避开低庭路径；
  - L3 的环桥从直径 3.6 的圆盘改为 3.1×0.95 的窄梁，移除多余立柱/大块 teal addon，相机 zoom 至 7.0；
  - 加入 `soft_shadow` 贴片、深色底面、无缝天空渐变（`sky_gradient.gdshader`）、背景漂浮纸片/纸鸟/大圆环。
- 方向光 shadow map 在 Intel HD 6000 / GL Compatibility 上测试无可见结果（shadow probe 场景也没有）；详见 TECH 5.3。最终采用艺术化软阴影贴片；方向光保留塑形，shadow map 关闭。

### 3.3 性能合批与交互修正

- 首版的每个小构件都是独立 MeshInstance；平台主体/路径/节点/黄铜线/软阴影约 118–171 个 mesh，draw calls 251–369。
- 加入平台本地空间的按材质 + 阴影分组 SurfaceTool 静态合批；飘带/宝石/旗杆/折环等动态节点用 `fold_dynamic` 排除。draw calls 降到 144–184（普通场景），调试/胜利 UI 约 261。
- 屏幕折环原先把 3D halo 放在节点上方、overlay 却画在节点位置；改为 overlay 也上移到 halo 高度，并把 open 端点的点击区域同时接受 pad 和 halo 两个位置，避免“看得到环却点不到”。
- 修正角色 blob 阴影过大遮住 start pad 的问题（缩小到 0.50×0.34，alpha 0.40）。
- 实窗探针验证真实点击/拖动/undo/reset/胜利；`--headless --quit-after 600` 与 154 checks smoke 均通过。

## 5. 未做 / 已知不足

- 固定等轴、单 Y 轴旋转；没有自由相机、没有声效或存档。
- 软阴影为贴片近似；真实 shadow map 在本机 GL Compatibility 驱动不可见。
- 屏幕拾取无前景遮挡判断；L3 的视觉密度仍高于 L1/L2（三层堆叠 + 两个旋转件），但三阶段路径与折环提示可完成。
- 下一步若扩展：增加更多旋转轴/构件、音效、触屏手势、关卡编辑器、基于解析几何的自动对齐求解器，以及可选 forward+ 的物理阴影画质档。
